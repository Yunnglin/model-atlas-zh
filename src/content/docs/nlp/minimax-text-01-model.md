## 先想象一本很长的工作手册

假设要阅读一家公司的三万条维修记录，再回答“去年哪几次故障出现同一种报警，而且最终的修复措施是什么”。这里不能只找到一个关键字：系统还要把不同日期、设备和措施对应起来，再组织一段可核查的解释。材料越长，普通注意力需要处理的历史信息越多，缓存和计算都可能成为负担。

MiniMax-Text-01 是 MiniMax-01 系列里的文本模型，着重研究如何在长上下文下使用混合注意力与稀疏专家网络。它仍然是逐 token 预测的语言模型，不会因为能接收很多文字就自动保证每句话都被正确理解。上面的维修场景是教学例子，不是模型实测。

## 结构与数据流

输入文本先被切成 token，转成向量后进入 80 层主干；模型根据输入与已经生成的内容逐步预测下一个 token。每 8 层可以看成一组：前 7 层使用 Lightning Attention，第 8 层使用 Softmax Attention，重复 10 组。每一层还有专家网络与其他必要模块。这个“7 加 1”是整个深度上的层次安排，不是对同一 token 在同一层做两次互相替代的注意力。

### 两种注意力像两种整理笔记的方式

普通因果 Softmax 注意力在生成时比较当前查询与允许访问的历史位置，再根据权重汇总历史值。为了重复使用历史，服务一般保存键和值形成 KV 缓存。输入越长，缓存需要保存的历史位置越多；更多背景可以先读 [注意力机制](/foundations/attention/) 和 [KV Cache](/foundations/kv-cache/)。

Lightning Attention 所依赖的线性注意力可以把过去的键和值逐步整理成一个状态。粗略想象，一位助手边读材料边更新一张摘要表：接下来回答时先查询这张表，不需要在该线性层为每次计算重新读取所有原始位置。这个状态是数学计算中的张量，不是模型先写出的自然语言摘要；状态容量和数值精度依然有限，不能保证任意长文本里的每个细节都完整保留。

论文的 Lightning Attention 使用分块计算处理因果约束：块内和历史块之间采用不同的计算组织，以兼顾训练中的并行与设备内存访问。推理时可以递推更新历史状态。它不是普通 Softmax 注意力通过调换矩阵乘法顺序就能完全等价得到的实现：两者的归一化和计算方式不同。也不要把 Lightning Attention 和 FlashAttention 叫法相近就当成同一个算法；后者是优化精确 Softmax 注意力的实现，前者对应另一种注意力计算方式。

这套模型并非所有层都是线性注意力：10 层 Softmax 注意力仍需要处理历史信息。对整模型说“缓存绝不随文本增长”就不准确。实际内存还包括 Softmax 层的 KV、激活、权重和运行工作区；批量、精度、并行方式与推理框架都会影响结果。混合结构是一个设计选择，效果应结合模型、任务和测量条件比较。

### 一层里为什么又有很多“专家”？

每层的前馈网络使用 MoE：论文给出 32 个专家，每个 token 选择其中 2 个。可以把专家理解为一组可训练的加工模块，路由器为当前 token 选择参与的模块，再组合输出。不能假设第一个专家永远负责代码、第二个永远负责合同；路由是模型学习到的数值计算，不是人工给每个专家贴的岗位标签。

456B 指整套模型的总参数，45.9B 是每个 token 参与计算的参数规模。选择两个专家可以减少每次计算需要使用的专家数量，但部署时通常仍要保存或调度全部专家权重。比如把模型分布到多张卡上，输入 token 要送到被选中的专家所在设备，结果再收回来；通信、负载不均衡和长上下文缓存都可能影响真实速度。看型号时别把“45.9B 激活”直接当成一张卡只需装下一个 45.9B 稠密模型。

论文报告每个注意力模块有 64 个查询头、每头 128 维；Softmax 层采用分组查询注意力 GQA，多个查询头共享键值头。位置编码应用在注意力头的一部分维度。论文的初始配置和长上下文阶段使用不同的 RoPE 基频，所以查看配置时要对应训练阶段与最终权重，而不要把两个数字混成矛盾。

## 数据与训练

### 先学语言，再逐步拉长材料

预训练以网页、书籍、论文和代码等多种文本为来源，进行清理、去重、质量评估与数据混合；模型通过已有上下文预测后续 token。论文也讨论质量和重复使用：数据重复多少次会影响学习效果，不能简单认为“越重复越好”或“所有重复都必须删除”。论文中关于小模型数据实验的观察，应放在其数据和预算设置下理解。

初始训练使用 8192 token 序列，随后逐步扩展到 128K、512K 和约 1M。长上下文扩展并不是简单把位置上限改大：论文描述按长度混合短、中、长数据，并在各阶段后期混入长文本问答，让模型练习根据材料回答，同时关注短文本能力。不同阶段的数据比例与 token 数各不相同；模型训练时见过一百万 token，不代表所有短、中、长任务都能稳定解决。

例如训练数据中，一份长文包含多个设备维修记录，问题要求找出指定设备在某次故障后的措施。系统要保证问题、原文证据和答案匹配，避免把 A 设备的措施贴到 B 设备上。若同一份记录只是换了格式或切分方式，就同时出现在训练和测试集，评测会高估对新资料的能力；更好的做法是按来源、设备或时间划分并检查近重复。

### 后训练：示范、偏好与多种反馈

论文介绍先进行 [SFT](/training/sft/) 示范学习，再使用离线偏好优化与在线强化学习；奖励框架从正确性、真实性、有帮助和安全等方面评价回答，并在短上下文与长上下文之间分阶段训练。代码任务可在隔离环境中运行测试，事实性则需要不同的核对方式；不能把所有奖励都说成一道固定规则，更不能把后续 MiniMax-M1 的 CISPO 训练流程直接套给 Text-01。

具体看后训练的长度安排：论文先用最长 8,192 token 的样本做 SFT，再用最长 1,032,192 token 的样本训练；接着分别用短、长上下文做 [DPO](/training/dpo/) 偏好优化，最后用短上下文进行在线强化学习。离线 DPO 使用事先构造的优选与劣选回答，在线阶段则由当前策略继续生成并根据反馈更新。这样做是为了同时照顾短问答与长材料，不能将每个阶段都称作同一种强化学习。

对于一个合同摘要问题，示范数据可以展示如何列出条款、引用位置并说明缺失信息；偏好数据可以比较“凭空填一个违约金额”和“指出原文未提供金额”哪种回答更合适。这个例子说明训练信号如何帮助回答风格与事实约束，并不是论文披露的具体样本。奖励模型或规则都可能误判，所以还要抽查原文依据、错误类型和评分器本身的表现。

## 评测怎么看

论文表 8 报告 MiniMax-Text-01 的 MMLU 为 88.5、GPQA Diamond 为 54.4、HumanEval 为 86.9；其中带星号项目采用零样本思维链设置，论文说明使用贪心解码。这些分别考查知识、研究生级问题和代码任务，数值来自论文指定模型与协议，不能直接解释成真实业务的整体成功率。比较其他模型时还要查看提示、版本、采样和公开测试条件。

长上下文不能只看“输入窗口”一个数字。论文在简单的 Needle-in-a-Haystack 测试中展示了外推至 4M token 的检索；这类测试像把一句特殊口令放进长书，然后问口令是什么，能检测某些检索能力，却不能证明模型能正确综合整本书。论文还使用 RULER、LongBench v2 与多轮检索任务考查更复杂的能力。官方表中 Text-01 在 RULER 的 1M 设置下为 0.910，而 LongBench v2 的 CoT 设置下 overall 为 56.5；它们任务与统计方式不同，不能互相换算。

拿维修记录举例，先准备来源隔离的独立测试集：有些题只找一个日期，有些题要求跨多条记录关联设备、原因和修复措施，还有些题故意不提供答案。分别记录证据位置是否找对、归因是否正确、是否编造缺失数据，并测试同样问题的短输入与不同长度材料。测试时记录实际 token 长度、服务限制、响应时间和硬件环境。不要以“材料能塞进去”或者一次找对口令就断定全部长文问答都可靠。

## 应用与错例：从答案回到资料

假设系统正确找到两条报警，却把其中一条的修复人名写成另一个人的名字。先保存输入原文、模型版本、提示、输出和位置；检查是检索遗漏、相同姓名混淆、上下文被截断，还是回答时组合错了。再把容易混淆的设备和人名组织成有证据位置的开发样本，增加不同长度与多来源案例。修改提示或训练数据之后，使用没有参与调整的记录重新测试，同时观察原本做对的短文问题是否退化。

当输出要进入自动化工作流时，可以要求结构化列出每项结论对应的原文片段，再由检索程序或人工核验。模型能提出工具调用不代表自己执行了工具；真实应用要记录实际调用、返回值和失败信息。上下文很长时，还应计算费用、首 token 等待和生成速度，而不是只报一个最大窗口数字。

## 面试追问

**为什么混合 Lightning 和 Softmax 注意力？** 论文尝试结合线性注意力的长序列效率与 Softmax 层的能力；模型具体是 7 层 Lightning 后接 1 层 Softmax，不能由此保证所有长文本任务都准确。

**32 选 2 是两个独立模型投票吗？** 不是。路由器在每层为 token 选择专家网络参与计算，结果汇合后继续流经主干。

**4M 上下文意味着训练时用了 4M 长度吗？** 论文描述训练上下文扩展到约 1M，4M 是特定检索压力测试中的外推结果；复杂任务和具体推理系统应单独评测。

**它和 MiniMax-M1 是同一检查点吗？** 不是。M1 基于 Text-01 继续训练形成推理模型；两者的训练步骤、评测和输出预算要分别看。
