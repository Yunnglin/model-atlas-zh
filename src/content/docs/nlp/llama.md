## 要解决什么问题

一个能在自己环境里部署的通用语言模型，如何从续写器变成助手？Llama 3.1 适合把预训练、后训练、上下文和推理开销连起来学习。本页限定 3.1 文本模型，不把后续家族版本的结构并进来。

## 结构与数据流

它沿用因果 Transformer 语言建模路线，逐步生成 token。官方模型卡说明 3.1 使用 GQA，也就是多个查询头共享部分键和值。直观地说，不必给每个查询头各存一套完整历史，从而减轻生成时的缓存开销。

长上下文仍有代价：[KV Cache](/foundations/kv-cache/)占显存，读入长提示也要计算。模型能接收长材料，并不保证材料每个位置都能被同样准确地利用。

### 一段文档怎样变成回答

假设用户询问“接口返回 429 时该怎么办”，应用先把用户问题、检索到的接口说明和对话边界标记整理成模型输入。分词器把文本变成 token，模型逐层用因果注意力读取前文，再预测下一个 token；生成出的内容接回输入，循环直到停止。模型即使输出了“等待后重试”，也不代表文档里确有这个规则，需要核对它是否引用了当前版本的说明。这个例子为教学构造，不是实测。

3.1 是稠密模型：一次前向计算使用各层相关的权重，不像 MoE 通过路由只调用部分专家。其基础结构与[GPT-2](/nlp/gpt/)同属因果语言模型，但分词、位置表示、数据、训练规模和后训练不同，不能把两个模型的质量差异简单归因于某一层结构。

![Llama 3.1 与 3.3 的 70B 文本骨干：词向量经过 80 个包含因果分组查询注意力、前馈网络和残差的解码层，再预测下一个 token。](/figures/llama-common/llama70b-backbone.svg)

这张教学图以 70B 为例，展示语言骨干。Meta 官方配置也列出 3.3 70B 的相同层数与注意力头数；不同版本的权重及后训练各自发布。

### 用一段缓存解释 GQA

以 Llama 3.1 70B 为例，官方配置使用 80 层、64 个查询头和 8 个 K/V 头，每 8 个查询头共享一组 K/V。每个头宽度为 8192 ÷ 64 = 128。输入越长，需要保存的历史键值越多，而分组共享能减少缓存大小。

假设单条请求已有 8,192 个 token，键值缓存使用 BF16，每个数占 2 字节：`80 层 × 2（K 和 V）× 8 头 × 128 维 × 8192 token × 2 字节`约为 **2.5 GiB**。这是缓存本身的估算，服务还要容纳模型权重、计算临时量和运行时开销；并发请求增加时缓存也会增长。

因果注意力之后，前馈网络继续加工位置表示。RMSNorm、RoPE 等分别涉及数值尺度与位置，它们共同组成语言骨干，却不是单独的“事实检查模块”。聊天模板、工具格式和结束标记在输入输出侧同样重要。

### 窗口变长后，哪里仍可能出错？

位置编码帮助模型表达 token 的顺序和相对位置；Llama 3 系列使用 RoPE，并通过长序列训练支持更长上下文。支持 128K 指模型配置和训练目标允许更长输入，并不等于模型能同样准确地使用材料开头、中间和结尾的每条证据。文档可能包含多个版本的接口规范，模型也可能把旧版本的阈值当成新版本。

验证时可以把同一条限制放在不同位置，在其他位置加入相似但不一致的信息，要求回答并引用正确段落。若始终选错，需分别检查检索、截断、模板以及模型读取证据的表现；一次“大海捞针”成功只说明一类简单检索题，并不覆盖整本手册的冲突消解。

## 数据与训练

先用大量文本做下一 token 预训练，再用指令示范和偏好等后训练步骤调整行为。Base 与 Instruct 是不同交付：前者方便研究或继续适配，后者更适合直接用对话模板提问。应按具体模型卡确认训练与许可条件。

[LoRA](/training/lora/)是适配参数的方法，不是 Llama 独有的训练目标；采用它也不能跳过数据去重、标签核对和独立验证。

官方论文描述网页和其他公开来源数据的抽取、质量过滤与去重，也讨论多语言、代码及数学内容；处理过的训练 token 数不等于去重后的独立事实数。405B 报告中先进行常规预训练，再分六个阶段从 8K 扩展至 128K；长上下文阶段使用约 8000 亿训练 token，之后还有调整数据混合与学习率的退火阶段。这些数字只描述论文中的具体训练设置；其他规格的配置应按对应资料核对。模型卡列出支持语言范围，能处理某语言不代表每种语言、领域和方言都同样可靠。

具体来说，官方模型卡列出的支持语言为英语、德语、法语、意大利语、葡萄牙语、印地语、西班牙语和泰语，并不包括中文。模型可能能输出中文，但这不等于中文已被纳入官方支持范围；要用于中文业务，应自行评测目标领域的数据和错误类型。

### 从基础能力到回答习惯

Llama 3 研究报告描述预训练之后的指令与偏好训练，包括 SFT、拒绝采样和 DPO 等环节。拒绝采样可先产生候选，再筛出适合监督学习的答案；它不等于每个候选都直接产生一次 RL 更新。

业务例子是按仓库文档回答接口用法。SFT 示范应引用真实版本、保留不知道时的行为；偏好对可以区分有依据回答与凭空补 API。开放权重允许适配，但这些业务数据、模型卡里的许可和实际训练资源仍要分别处理。

### 为什么要迭代后训练？

假设模型第一次回答 429 问题时编造了一个固定等待秒数。示范数据可以告诉它：如果文档提供 `Retry-After`，先引用该字段；没有就说明不确定，而不是发明规则。[SFT](/training/sft/)训练模型学习示范的回答形式。[DPO](/training/dpo/)可以利用“有依据”和“编造字段”这样的同题偏好对调整相对倾向。

Meta 报告描述多轮 SFT、拒绝采样和 DPO，并使用合成数据及质量筛选。具体地，团队对人工收集的提示，通常从上一轮较好的聊天模型采样 10～30 个候选回答，再用奖励模型选出最佳候选；后续轮次还用系统提示引导风格或格式。选出的回答与合成、人工整理的数据混合做 SFT，训练时只对目标回答计算损失，提示部分不计入损失。

回到 429 的例子，可以想象先写出多个回答，再让评分器挑选；但分最高的答案仍可能引用了不存在的字段。筛选器有偏差，合成答案也可能把原本错误重复放大，因此仍需要独立事实核查和数据质量控制。429 例子是教学构造，不是官方样本。上述候选数和筛选流程来自论文所述实验，其他团队不必照搬。

## 评测怎么看

分别测知识、推理、代码、指令遵循和目标语言。部署还要记录精度、量化方式、提示长度、首 token 延迟与吞吐。公开基准的能力变化和自己服务的速度变化，来自不同实验。

Meta 对模型报告了知识、代码、推理、多语言、长上下文和指令遵循等多类基准，但每个结果都依赖具体规格、Base 或 Instruct、提示、采样次数与评分规则。模型卡和报告中的多项选择题可能使用不同的示例数；解码式答案与选项概率排名也不一定可互换。报告同时讨论数据污染检查，其结果有误报与漏报，不能证明任何基准都完全没有重合。

看一个具体数字：技术报告表 2 中，Llama 3.1 的指令模型在 MMLU 五样本设置下，8B、70B、405B 分别为 **69.4、83.6、87.3**。这里的“五样本”是指提示里给出五个示例，再让模型回答新题；报告对各子任务准确率取宏平均，并使用生成答案的方式评分。这组数字方便比较同一报告里的设置，但不能直接代表中文业务准确率，也不能与不同提示、评分方法的分数简单比较。

对于接口文档助手，要另建独立的真实版本问题集：检查答案的字段是否存在、是否引用正确版本、资料缺失时是否承认不知道，并分别报告英文和目标语言的结果。多轮测试还要检查用户更换 API 版本后模型是否更新结论。先固定检索来源、问题和评分，才能比较不同模型或微调前后差异。

### 量化与能力，别同时换两个变量

对同一权重分别测试原精度与量化版本，固定 tokenizer、模板、生成参数和样本，比较数字、专名、长文本等切片。若同时换推理框架和提示模板，即使出现退化，也无法直接归因量化。

显存估算至少分成权重、KV Cache、临时激活与运行时开销。就像办公室除了文件柜还需要工作桌，总参数乘字节数只估出一部分，不是服务进程的完整占用。

## 应用与错例

本地助手反复续写用户的话，先检查是不是拿 Base 当 Instruct 用、对话模板是否匹配、停止符是否正确。量化后专名错误增加，应在固定样本上对照原精度结果，再决定是否适配。任务案例见[资料问答](/cases/document-qa/)。

### 从错例回到数据

如果模型把新版接口的限流策略答成旧版，先保留请求、检索文档版本、聊天模板、完整输出和推理配置。核对是检索没找到新版、上下文被截断，还是模型看到了新版仍引用旧内容；三种原因不能都用“加 SFT 数据”处理。若是召回错误，应先修正索引或检索；若是已看到证据却忽略，可在开发集补充版本冲突和“不知道”的示范与偏好对。

之后用从未参与修改的独立版本和问题复测，同时检查正常接口问题和通用回答是否退化。记录成功率、引用准确度、耗时与资源消耗，并保留失败例。这个闭环是教学方案，不代表项目已训练或得到提升。

本地部署还要分辨权重、运行代码、训练数据和许可：开放权重使得本地推理、研究与适配更方便，但不意味着预训练数据全部开放。模型许可可能对特定使用方式或规模有条件，实际项目应查看对应版本文件。

## 比较与面试追问

[GPT-2](/nlp/gpt/)适合理解因果生成的基本机制；Llama 3.1 还能学习现代数据与后训练工程。[Qwen3](/nlp/qwen3/)则可进一步比较 Dense、MoE 与思考模式。

**开放权重意味着完整训练数据和配方都公开吗？** 不意味着；权重、训练代码、数据与使用许可要分别核对。

**为什么不能只按总参数估计显存？** 权重精度、缓存长度、批量与运行时中间量也要计入。
