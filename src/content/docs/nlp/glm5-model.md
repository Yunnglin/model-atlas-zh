## 它想解决什么问题？

想象一个代码仓库里的 Webhook 重试失效了。你把 issue 交给助手，希望它找到问题、修改代码、运行测试，再说明验证了什么。助手面对的不只是一道填空题：它可能要读多个文件、等待命令运行、处理失败日志，并在新证据出现时修改计划。这类任务中，模型生成文字只是其中一步；文件系统、终端和测试程序由外部应用提供。

GLM-5 把这类长流程任务作为重点。它延续 [GLM-4.5](/nlp/glm45-model/) 的混合专家路线，引入来自 DeepSeek 的稀疏注意力，并在训练中加强多步智能体任务。下面用虚构的 Webhook 任务讲解。

## 结构与数据流

文本先被切成 token；模型根据已有 token 预测后续 token。在工具场景里，后续 token 既可能是给人的回答，也可能按照约定格式表达工具请求。外部执行器识别请求、检查权限、运行工具并把结果交回，模型才能继续生成。它不能凭空读取仓库或运行测试。

### 混合专家：容量和每次计算不是一回事

把模型想成一个很大的团队：总参数描述团队全部成员，每个 token 的激活参数描述这一次实际参与计算的规模。GLM-5 配置中有 256 个路由专家，每个 token 选择 8 个路由专家，另有共享专家。路由器根据输入状态决定选择，不是人工给每个专家贴上“Python 专家”“数据库专家”的标签。基础概念可以先看 [MoE](/foundations/moe/)。

按官方配置，语言主干有 78 层：前 3 层使用稠密前馈网络，后 75 层使用 MoE；另有 1 层多 token 预测模块。和 GLM-4.5 的 3 个稠密层、89 个 MoE 层相比，GLM-5 减少主干层数，同时把路由专家数从 160 增加到 256。模型规模与计算成本要结合各层宽度、专家选择和设备布局一起看。

报告中的 744B 包含 MTP 层、不含词嵌入和输出层；Hugging Face 页面按权重统计约为 754B。每次激活约 40B 参数，部署时仍需为其他专家、缓存、通信和计算工作区预留空间。量化和分片方式会影响实际资源需求。

### DSA：先挑线索，再仔细看

当 Webhook 的问题描述和代码、日志累积到很长时，当前生成位置通常不需要对所有历史位置做完整的注意力计算。DSA 使用轻量索引器，为当前 token 选择可能相关的历史位置，再对所选位置进行更精细的注意力计算；公开配置的选择上限为 2,048。可以类比查一本厚手册：先用目录找到可能相关的章节，再读章节，但目录仍有成本，也可能漏掉线索。

这与 MoE 分工不同：DSA 决定**注意力主要读取哪些位置**，MoE 决定**哪些专家参与处理 token**。模型也采用 MLA 来压缩键值表示，它关注缓存与注意力表示；三个机制不能互相替代。DSA 的稀疏选择不等于完全不保存上下文，也不保证每条关键证据都被选中。实际加速取决于序列长度、实现与硬件，不能把某一实验的收益当成所有场景的速度承诺。相关路线也可参考 [DeepSeek-V3.2](/nlp/deepseek-v32-model/) 与[注意力机制](/foundations/attention/)。

例如当前历史有 100,000 个 token，选择上限为 2,048 时，后续精细注意力最多处理其中约 2.05% 的位置。这个比例只是在数位置：索引器仍要筛选候选，实际耗时还取决于缓存、数据搬运和实现，因此不能推算成“速度快了约 49 倍”。如果失败日志中的关键行没被选到，后面的精细计算也无法直接利用该位置。

如果失败日志藏在一段长记录中，索引器要尽量选到与当前问题有关的位置；模型还要正确理解日志。即使支持长输入，应用仍需维护清晰的文件版本、重要证据和工具结果。上下文窗口是容量限制，不是理解正确率的保证。

## 数据与训练：从续写到多步行动

预训练让模型从大量文本和代码中学习预测后续 token；中期训练进一步加强智能体和长上下文能力。两个阶段合计使用 28.5T token。

长上下文不是一次从短文本跳到 200K。报告的中期训练依次使用 32K、128K 和 200K 的最大长度，对应约 1T、500B 和 50B token；后期提高长文档和合成智能体轨迹的采样比例。可以把它理解为先练习阅读较短的项目文件，再逐渐加入跨文件和长任务材料。这里的长度是训练配置，不是说每条样本都恰好填满窗口。

DSA 先让索引器在密集注意力的参考下学习找线索，再让模型适应只读取挑出的历史位置。GLM-5 报告中，预热阶段训练了 1,000 步；接着用 200 亿 token 做稀疏适配。论文分别评测了两个阶段，并使用相同的 SFT 数据比较适配后的模型与原密集注意力模型。

监督微调让模型学习对话、推理和工具交互的形式；强化学习则用反馈进一步优化行为。对代码任务，可以准备仓库、问题描述、可运行环境和验证脚本：模型尝试读取文件、修改代码，环境给出测试反馈。自动验证提高了反馈规模，但“测试通过”不总等于问题解决：删除测试、只适配一个样本或破坏别的功能都可能骗过不充分的检查。需要独立测试、检查补丁以及必要时人工审查。

报告把后训练组织成多任务 SFT、推理强化学习、智能体强化学习和通用强化学习，并在最后用跨阶段在线蒸馏帮助恢复前面阶段的能力。比如模型在工程任务上进步后，仍需回归数学与普通问答：老师检查的是较早阶段的模型，学生则是继续训练后的模型。蒸馏有助于减少能力退化，但不等于每项能力都一定完全保留；仍要用独立任务验证。

### 为什么智能体训练要异步？

假设一个任务的模型生成只花几十秒，但安装依赖、运行测试还要几分钟。若所有训练工作都等最慢的任务，算力会空转。报告介绍的智能体强化学习基础设施将轨迹生成与模型更新解耦：一边与环境交互、记录动作和结果，另一边消费轨迹、更新参数；两边定期同步模型。像厨房和出餐台分别工作，整体等待可能减少。

代价是**数据会变旧**：生成轨迹时用的是旧模型，训练时模型可能已更新。如果忽略这一差别，学习信号可能不稳定。系统需要限制轨迹陈旧程度、处理策略差异并监控训练；异步并不代表所有数据都由当前版本生成，更不意味着所有强化学习阶段都采用同样流程。报告还讨论了保留生成 token 身份，以避免文本重新编码造成不一致。

### 一条工具轨迹里，哪些内容参与训练？

例如模型先输出“运行测试”的工具请求，终端返回 `2 failed`，模型再读取失败信息并修改代码。训练数据要保留这三段的顺序：模型请求、环境结果、模型后续动作。环境返回为模型提供上下文，GLM-5 报告中的智能体强化学习只对**模型生成的 token**计算优化目标，不把终端输出当作模型自己生成的答案。

报告还采用 token-in-token-out（TITO）：推理端生成时就记录实际的 token ID 和相关信息，训练端直接用这份记录。假设模型发出运行测试的请求后，终端返回 `2 failed`：记录里需要分清哪段是模型生成的请求、哪段是环境反馈，后续模型的修改又从哪里开始。训练时只有模型生成的部分参与优化，环境反馈仍作为上下文。

如果只保存最终文本，再重新切成 token，空格、截断或特殊标记的处理就可能改变边界，让训练步骤对不上实际生成的动作。TITO 像保留原始票据而不是事后重新誊写：重点是让“当时生成了什么”和“现在优化什么”对应起来，并不是一种新的奖励算法。报告中的 TITO Gateway 负责记录 token ID 与元数据；异步系统还会定期同步推理端权重，并处理过旧轨迹。

### 训练环境也是数据的一部分

一个可验证的工程任务不仅有“问题”和“答案”，还需要能启动的仓库、依赖、权限范围与测试脚本。模型的完整交互轨迹包括工具请求、真实返回、修改和最终结果。若依赖安装失败，应区分环境故障与模型修复失败；若测试命令没有执行，不能记成测试通过。报告介绍了构造可验证软件工程、终端及搜索环境；具体任务规模和流水线见原文，未披露的原始数据与配比不能自行补全。

## 评测：一个分数背后发生了什么

官方技术报告给出 GLM-5 在 SWE-bench Verified 上 **77.8%** 的结果，使用 OpenHands 和针对 GLM-5 的提示；附录列出温度 0.7、top-p 0.95、最多生成 16,384 token 和 200K 上下文。这个基准让系统为真实软件仓库的问题生成补丁，再用测试检查。比较结果时，需要同时看工具框架、提示和运行预算。

假设我们的 Webhook 样本包括“网络超时后重试”，验证时至少检查正常响应、连续超时、最终失败、重复事件以及异常日志。将仓库按项目或时间分组，留出独立测试，避免相似补丁同时出现在训练和测试里。还要记录运行次数、工具调用、完成时间和成本：一次成功无法说明系统稳定，多次尝试的通过率、失败类别和资源消耗才更有参考价值。

评测智能体还需看它是否遵守权限、是否承认未执行测试、是否能从失败日志恢复。公开基准不一定覆盖你的依赖版本、代码风格和故障分布，因此要用真实场景的独立样本补测。长上下文测试应把证据放在不同位置并加入干扰材料，分别检查找到证据与根据证据作答的能力。

## 一个实践闭环：从错例回到数据

1. **数据**：收集已匿名化的 Webhook issue、对应仓库版本、可运行测试和人工确认的预期行为，按仓库或时间拆分训练与测试。
2. **任务**：给助手只读和受限写入工具，让它先定位重试逻辑，再提交补丁。工具执行结果必须来自真实环境；系统记录每一步。
3. **评测**：运行原有测试和独立补充的超时、重复事件与边界测试，并检查补丁是否改动无关功能。记录运行环境、预算和未能执行的步骤。
4. **错例**：若助手把超时当作永久失败，查看它是否读到异常分支、误解日志、生成错误补丁，还是被环境错误误导。仅看最终失败无法区分原因。
5. **改进**：针对定位不到异常分支的错误，补充带有真实工具反馈的训练或演示样本；针对测试不足，增加验证样本。保留未参与改进的独立集复测，检查同类问题是否改善且正常流程没有退化。

这是一个可复现的教学方案，不代表官方实际使用了同一套数据或奖励。生产应用还应按实际情况限制命令和文件权限、隔离执行环境，并让人审查高风险修改。

## 面试时可以怎么讲

**问：GLM-5 的 DSA 和 MoE 都叫稀疏，它们是一回事吗？** 不是。DSA 稀疏选择历史位置，减少精细注意力需要处理的范围；MoE 稀疏选择专家，控制每个 token 参与前馈计算的模块。两者解决不同瓶颈，也分别有索引、路由与通信等开销。

**问：异步训练为什么有风险？** 轨迹来自较旧的模型，更新时策略可能已变化，导致反馈与当前策略不匹配。要跟踪版本和数据新鲜度，控制差异并检查稳定性；不能只用吞吐提升评价。

**问：上下文 200K 是否说明模型能可靠使用所有内容？** 不能。窗口描述可容纳的 token 范围，实际效果还取决于信息位置、干扰、稀疏选择、提示和应用的历史管理。应针对目标任务在不同位置与长度下测量。
