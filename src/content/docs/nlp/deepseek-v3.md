## 要解决什么问题

想增加模型能存储和处理的知识，又不想让每个 token 都经过全部参数，可以怎样做？原始 DeepSeek-V3 用 MoE 和注意力方面的设计处理这类效率问题。本页区分 V3-Base 与经过后训练的 V3 助手，不把后续同名更新混为一个版本。

## 结构与数据流

[MoE](/foundations/moe/)把部分前馈计算分配给不同专家；路由器给当前 token 选择其中一部分。专家不是人工预先标好的“数学组”“中文组”，它们通过训练形成分工。

MLA 把注意力历史中的部分信息压缩到更紧凑的潜在表示，减少缓存压力。它针对的是注意力计算和缓存组织；MoE 针对的是专家计算，两者可以同时存在。缓存的基本作用见 [KV Cache](/foundations/kv-cache/)。

### MoE 和 MLA 分别省在哪里

例如把系统比作读档案后加工答案：MLA 改变阅读笔记怎样压缩存储，MoE 决定请哪些加工工位继续处理。一个改变注意力表示，一个改变前馈计算，所以可以组合，不是二选一。

MLA 对 K/V 的部分联合信息做低秩压缩，同时单独处理与旋转位置相关的分量。直观上存较紧凑的共同表示，需要时再参与对应计算；不能把它说成截掉一半历史。实际效率还取决于投影吸收和运行实现，只有缓存更小并不能证明所有负载都更快。

路由器对每个 token 选择路由专家，另有共享专家处理共同部分。专家输出按相应权重合成。专家不是一组可单独调用的聊天机器人，“数学 token 总归数学专家”也不是人工标签保证。

## 数据与训练

报告描述预训练、SFT 与强化学习等环节，还加入多 token 预测的辅助训练目标。辅助目标让训练考虑更多后续位置，不代表使用模型时就可以忽略输出依赖、无限并行生成。

专家负载不均会导致一部分设备忙、一部分闲。报告讨论负载均衡与训练系统配合；只读模型参数规模，无法推算一次完整训练的总成本。

### 负载均衡为何影响训练

假设 4 个专家中，几乎所有 token 都挤到同一个，其他设备闲着，热门专家还可能成为瓶颈。V3 的辅助损失自由负载均衡用路由偏置调节选择，另有相应序列级约束；“辅助损失自由”不能扩大解释成整个训练没有任何附加目标。

MTP 让模型训练时还考虑更多后续位置，FP8 等训练系统手段则改变数值与计算组织。目标、路由和数值实现分别核对，不要把训练效率提升只归因于一个专家数。

## 评测怎么看

能力看代码、知识和推理等任务；系统侧看吞吐、通信、缓存和不同序列长度的成本。总参数与每 token 激活参数要分别报告。比较训练费用时还需注明硬件、阶段与统计范围，不能把单次报告数字当成所有研发成本。

### 大容量，小激活，仍要保存大权重

若假设总容量为 100、每步用 5，计算只动用部分参数，不意味着其余参数从存储中消失。部署要看专家分布、通信与精度，不能按激活参数直接估整机内存。

比较 V3 与 Dense 时，同时记录质量、提示长度、并发和设备数；低并发的专家通信开销可能抵消部分收益。数字来自受控实验才有可比性，结构本身不承诺固定倍率。

## 应用与错例

服务高并发后速度下降，先看专家路由、设备通信、批量和上下文长度，而不是立即补训练数据。回答出错则另外查任务数据和对话模板。先保留模型精度与配置一致的基线，再验证优化是否损伤质量。

## 比较与面试追问

[DeepSeek-R1](/nlp/deepseek-r1/)建立在 V3-Base 上，重点是推理后训练；它不是给 V3 助手简单改名。[Qwen3](/nlp/qwen3/)也有 MoE 规格，但具体路由、注意力和训练过程需分别读报告。

**MoE 比 Dense 总是快吗？** 不能保证，专家通信和硬件利用率会影响结果。

**MLA 与量化是同一种节省显存的方法吗？** 不是；前者改变注意力表示与缓存组织，后者改变数值存储精度。
