## 先看问题：只看参数多少，够判断模型能力吗？

假设团队想在自己的研究设备上测试语言模型。一个 175B 模型需要容纳大量参数，推理成本高；另一个 13B 模型规模小得多，但在某些公开题目上可能答得更好。究竟选择谁，不能只看参数量，还要考虑训练数据、训练计算、模型结构、任务和实际推理预算。

初代 LLaMA 论文关注这种权衡：在不同模型规模下，使用大量公开可获得的文本数据训练基础语言模型，并比较下游任务表现。作者希望得到一组更容易供研究人员使用的模型，而不是证明“小模型在所有任务上必然胜过大模型”。论文比较发生在 2023 年的特定评测条件下，不能直接当作今天模型的通用排名。

这里的设备选择是教学案例，不是实际部署记录。模型即便能够装进显存，也可能因为上下文、缓存、批量和运行框架占用额外资源；不同硬件、精度和并发条件会改变速度与成本。

## 模型结构：从已有前文预测下一段

LLaMA 与 [GPT-2](/nlp/gpt/) 一样属于自回归语言模型。输入文本经分词变成 token，模型在当前位置结合已有前文，预测下一个 token，再将结果加入上下文继续生成。因果注意力阻止当前位置看到未来的答案；它也不是把全部文本一次性理解成一个永远不会出错的知识库。

论文的 7B 型号有 32 层、隐藏维度 4,096 和 32 个注意力头；65B 有 80 层、隐藏维度 8,192 和 64 个头。一个注意力头不是一个独立聊天机器人，而是模型在每层处理信息的一组计算。参数规模是需要存储和使用的权重数量，不是训练文本数量，也不是可输入的上下文长度。

每个 Transformer 层都包含注意力与前馈网络。注意力帮助当前位置参考前面的内容；前馈网络再对当前位置的表示进行变换。残差路径把信息沿层传递。初代 LLaMA 在这一通用骨架上采用了先前研究提出的若干设计，而不是凭空发明所有组件。

### RMSNorm、SwiGLU 和 RoPE 分别做什么

第一，论文在每个子层之前使用 RMSNorm 做预归一化。可以把它想成调整进入子层的信号尺度，减少数值过大或过小给训练带来的困扰。它不是给每个 token 判好坏，也不保证训练绝对稳定。论文将这种设计归因于已有工作，不能说 RMSNorm 是 LLaMA 首次提出。

第二，前馈网络使用 SwiGLU 门控形式。可以粗略想成一条路径加工信息，另一条路径对信息进行逐元素调节；但“门”是连续的数值运算，不是人手写的规则或特定专家。论文调整前馈内部维度，设计与参数量之间需要一起考虑；把 SwiGLU 换进去并不单独证明所有能力提升都由它造成。

第三，模型在各层注意力中使用旋转位置编码 RoPE，让位置关系参与注意力计算。例如阅读“甲把书给乙，乙又给丙”，词出现的先后会影响模型如何关联动作与对象。RoPE 不是无限记忆，也不自动保证超过训练长度后仍能准确理解长文；长上下文能力必须按照具体版本和测试条件验证。

## 训练数据：公开来源，不等于每条数据都能无条件使用

论文的数据来源包括 CommonCrawl、C4、GitHub、Wikipedia、书籍、arXiv 和 Stack Exchange。表 1 所列采样比例分别为 67%、15%、4.5%、4.5%、4.5%、2.5% 和 2%。这是训练混合时抽取样本的比例，不是各种来源在互联网上的实际占比，也不代表每个来源只被完整读取一遍。

论文记载 7B 与 13B 训练时处理约一万亿 token，33B 与 65B 处理约 1.4 万亿 token。训练过程中处理过的 token 次数可能包含重复采样，不能说 1.4 万亿是互不重复的文档，也不能把它误认成 1.4 万亿参数。论文表中 Wikipedia 和 Books 的采样轮数高于一，正说明不同来源被重复使用的程度不同。

分词使用 SentencePiece 实现的 BPE，数字被拆成单个数字，未知 UTF-8 字符可以回退到字节。举例说，价格“120”可能对应多个 token，具体拆分应由该分词器决定；把任意一位数字改错都可能改变最终含义。训练集以英文数据为主，个别来源包含其他语言，不能因此假设它对所有中文领域任务都有同样质量。

论文列出来源和主要处理方法，有助于理解与研究，但“公开可获取”不等于每条数据许可一致、可无限制重新分发，也不能证明全部预处理结果和训练过程可一键复现。研究者在自己的数据上训练或评测时，仍应核查来源权利、清洗规则与测试集泄漏。

## 训练：为什么多读数据不等于免费提升？

训练目标是给定前文预测后续 token。假如文本写着“请将会议改到周五”，模型以此前片段为条件预测接下来的文字，用真实后文计算损失，再更新参数。这样可以从未逐句标注的文本中获得训练信号，但模型也可能学到过时信息、错误内容或偏见。

论文使用 AdamW、余弦学习率调度与预热，并介绍针对注意力、激活重计算和多 GPU 并行的工程优化。作者报告 65B 训练时使用 2,048 张 A100 80GB，约 21 天处理 1.4T token；这是论文中的训练配置，不是单用户推理需求，也不是任何硬件都能达到的速度。

具体到论文的训练设置，一次全局批次包含约 400 万个 token，学习率先经过 2,000 步预热，再按余弦曲线下降，结束时降到峰值的 10%。可以把预热理解为开始训练时先逐步加大更新幅度，再逐渐减小；它是优化过程的安排，不是让模型先读完一部分数据再正式学习。批次里的 token 也不是一篇长达 400 万 token 的文章，而是来自多个训练序列。

训练更多数据需要付出训练计算和数据处理成本，可能换来参数规模较小的模型在推理时更容易部署。它不是“模型小所以训练一定便宜”，也不是“只要把数据延长就无限提升”。对一个具体应用，应该同时考虑一次性训练费用、请求数量、响应质量、部署硬件与延迟。

初代 LLaMA 主要发布基础模型，其任务是文本续写；论文也另行讨论一个指令微调实验 LLaMA-I，不能把研究实验结果混成所有基础权重都经过相同的聊天对齐。要制作会遵循业务指令的助手，还需要选择适合的监督数据和训练方案，并对错误、安全行为与事实依据做测试。

## 评测：13B 与 GPT-3 的比较如何读

论文在多项零样本和少样本基准中比较不同规模的模型。以表 3 的零样本常识任务为例，LLaMA-13B 在 HellaSwag 的分数为 79.2，论文引用的 GPT-3 175B 为 78.9；但在 PIQA 上前者为 80.1，GPT-3 为 81.0。两项都是论文指定条件下的指标，不是 13B 在所有题目、语言和业务里都更好。

选择题的评测方式也值得注意：论文对每个候选续写计算给定题目时的似然，再按指定规则归一化后选分数最高的一项；不同数据集的归一化方式并不完全一样。比如两个选项长短不同，直接比较整段概率可能偏向短答案；论文的方法试图控制这类影响。换成让模型自由生成一个选项字母，结果可能不同，复现时应保留原评测方式。

论文还在 MMLU 等任务使用少样本评测。少样本意味着将示范与测试问题一起放进输入，并不意味着针对每一道测试题重新训练权重。不同模型的训练语料、提示格式、样本数量和评测实现可能不同；要比较自己的系统，应记录版本、示例选择、指标、生成预算与数据划分。

准确率高也不能说明输出一定可靠。模型可能流畅地续写错误事实，或在涉及社会群体时呈现偏见。论文专门讨论了毒性、偏见和 TruthfulQA 等限制；在真实使用中，还需考虑训练数据时效、用户请求分布和系统防护。闭卷作答测试的是在该设置下回答，而不是证明训练语料中没有相关答案。

## 开放与许可：研究可访问和可商用不是一回事

Meta 当时宣布以非商业研究许可提供模型，并按申请对研究机构和相关研究人员逐案授予访问。它开放了论文与推理代码，并向获准研究者提供模型访问；这不等于初代权重采用 Apache 2.0，也不能因为后来某些 Llama 型号允许特定商业使用，就倒推初代许可相同。

同样，论文和代码各自的许可证、模型权重条款与训练数据权利是不同问题。下载渠道、衍生模型和使用时间可能不同，实际工作应核对对应版本的权威许可与访问条件。一个社区镜像能够下载，不自动证明拥有重新发布或商用权利。

## 应用与错例：用一组未见问题检验助手

假设研究者在获准的环境中用基础模型完成文档问答：先准备授权的文档和问题，记录对应参考答案与出处；按文档来源划分开发与测试，避免同一篇文章换个问法就同时出现。基础模型不一定自然遵循聊天指令，可以比较原始续写、少样本提示与经允许的任务适配，但必须固定模型版本和每种方法能看到的信息。

如果模型回答“会议在周四”，而文档只写了“预计周四”，先保存提示、文档版本和输出，检查是否发生截断、问题歧义或示范数据把不确定语气改成了确定事实。然后在开发集加入“预计”“待确认”等案例，调整提示或任务数据，再用独立测试检查事实忠实、拒答与延迟。这里是教学流程，没有实际训练或部署。

当资料会更新时，把来源文本提供给系统并核对引用可能比依赖旧权重更有效。检索本身也可能找到错误文档，因此应用应记录数据版本和检索结果；模型回答正确与资料真实、执行工具成功是不同的检查项。

## 面试追问

**13B 在部分基准超过 175B，是否参数越少越好？** 不能。需要把任务、训练数据、提示、训练与推理成本一起比较；论文也列出 13B 不占优的任务。

**RoPE 是否保证任意长文本都能准确处理？** 不能。位置编码提供位置信息，超过具体训练与使用范围时的效果需要专门测量。

**公开数据训练是否等于权重采用开放商用许可？** 不等于。数据来源与权重许可证是不同问题；初版权重采用研究用途的非商业许可。
