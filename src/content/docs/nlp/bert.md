## 要解决什么问题

“这家店服务不错，就是等太久”既有肯定也有抱怨。判断整句情绪，需要一起看前后文。BERT 先学习文字的上下文表示，再把这种表示交给分类、抽取等任务使用。

## 结构与数据流

文字经过[分词](/foundations/tokenization/)变成 token，再送入多层双向 Transformer 编码器。每个位置都能参考两边内容。例如“苹果发布新品”里的“苹果”，需要结合“发布”判断含义。

情感分类可以在句子表示后接分类层；人名抽取则对每个位置预测标签。这个小输出层常叫任务头。双向表示能看到输入的后文，但不能看到尚未给模型的测试答案。

### 从同一条输入得到三种输出

教学句子为“苹果今天发布新品”。每个 token 得到自己的上下文向量，苹果这一位置能参考后面的发布。句子分类常取 `[CLS]` 对应表示接分类器；实体识别对各位置输出实体标签；抽取问答则预测答案起止位置。可以把编码器看成共同阅读器，任务头是不同的答题纸，答题纸不同，标注也不同。

若问题问“谁发布新品”，起止预测必须落回原文范围。子词切分和字符坐标还要对齐，例如一个实体被拆成两个 token，不能把其中一半作为完整实体。BERT 输出向量本身不会替应用处理这些边界。

## 数据与训练

原始 BERT 主要用[遮盖预测](/nlp/masked-modeling/)与下一句预测学习：把输入一部分藏起来，让模型还原，并学习句对关系。随后用带任务标注的数据微调模型和任务头。

遮盖预测会利用左右文；[下一 token 预测](/foundations/next-token/)只能利用此前内容。两种目标的差异比“都用了注意力”更值得记住。不要把原始 BERT 的目标默认套到全部后续编码器模型。

### 被选中预测，不一定都换成 MASK

原始 BERT 在选中预测的位置中，大部分换成 `[MASK]`，少部分换成随机 token 或保持原样，目标仍是恢复原 token。大白话说，学生有时看空格，有时看被写错的字，有时看到原字，但不能事先知道哪一个位置被计分。这样可减少训练时全是 MASK、实际任务却没有 MASK 的差别。

下一句预测判断句对是否按语料关系相接，不等同于任意两个句子语义是否相似。分类微调再提供真实任务标签，通常可以一起更新编码器与任务头；只训练任务头是另一种可比较的基线。

## 评测怎么看

分类要看准确率或 F1，类别不均衡时分别看每类召回；实体抽取要明确按 token 还是完整实体计分；抽取问答可看答案匹配和 F1。论文使用 GLUE、SQuAD 等任务，不是只报告一个预训练损失。

### 漏识别和边界错，怎样计分

构造 5 个人名实体，模型报出 4 个，其中 3 个完整匹配，则实体级精确率为 3/4，召回为 3/5。只把几个 token 分对不代表实体完整，评分必须先确定边界和类别是否都需一致。对于情感混合句，先写清“整体情绪”还是“方面情绪”的标签规则，避免把标注歧义当成编码器故障。

## 应用与错例

客服意图分类把“想退款”和“咨询退款条件”混在一起时，先检查标签定义与难例标注，再看输入截断、类别比例和领域词。把混淆样例补到训练或开发池，保留独立会话做回归，避免同一用户的近重复句子泄漏。

## 比较与面试追问

[BERT 与 GPT-2](/nlp/gpt/)的核心区别是可见范围和学习目标。BERT 的常见用法是理解输入后输出标签；GPT-2 擅长顺着前缀生成。二者都不天然保证事实正确。

**实体抽取为什么不能只拿一个句子向量？** 因为要判断每个位置属于哪一类，还要恢复实体边界。

**微调只改分类层行不行？** 可以冻结编码器做基线，再比较全量或参数高效更新的收益与成本。
