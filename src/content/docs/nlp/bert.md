## 要解决什么问题

“这家店服务不错，就是等太久”既有肯定也有抱怨。判断整句情绪，需要一起看前后文。BERT 先学习文字的上下文表示，再把这种表示交给分类、抽取等任务使用。

## 结构与数据流

文字经过[分词](/foundations/tokenization/)变成 token，再送入多层双向 Transformer 编码器。每个位置都能参考两边内容。例如“苹果发布新品”里的“苹果”，需要结合“发布”判断含义。

情感分类可以在句子表示后接分类层；人名抽取则对每个位置预测标签。这个小输出层常叫任务头。双向表示能看到输入的后文，但不能看到尚未给模型的测试答案。

### 一个句子怎样进入编码器

假设要判断“服务好，但是等了很久”属于什么情绪。分词器先把文本转换为词表编号，前面加 `[CLS]`、末尾加 `[SEP]`。对句子对，常见格式是 `[CLS] 句子 A [SEP] 句子 B [SEP]`。输入向量由 token、位置和句段三类嵌入相加；句段标记告诉模型哪些位置属于 A 或 B，不是说模型自动理解了两句的逻辑关系。

每一层先计算自注意力，让位置之间交换信息，再经过前馈网络等模块。输入被当作完整文本处理：在排除 padding 的前提下，一个位置通常可以关注它左右的其他有效位置。编码器输出与输入位置一一对应；同一个词在不同上下文得到的向量可以不同。Base 的 768 指每个位置的表示宽度，不是最多只能输入 768 个词。

每层前馈网络还有一个更宽的中间层：原论文的 Base 是 3072 维，Large 是 4096 维，分别是隐藏宽度的四倍。可以把它理解成每个位置先在更宽的空间里加工，再投回原来的表示宽度；它不是额外的序列长度，也不等于注意力头的数量。具体规格以[原论文结构说明](https://arxiv.org/html/1810.04805#S3)和所用检查点配置为准。

例如“苹果很甜”和“苹果发布手机”里的“苹果”共享初始词条，但经过上下文交互后，两个位置的表示会受到各自周围词语的影响。注意力权重能展示部分信息交互，不能直接当作模型真实推理过程或因果解释。

### 从同一条输入得到三种输出

教学句子为“苹果今天发布新品”。每个 token 得到自己的上下文向量，苹果这一位置能参考后面的发布。句子分类常取 `[CLS]` 对应表示接分类器；实体识别对各位置输出实体标签；抽取问答则预测答案起止位置。可以把编码器看成共同阅读器，任务头是不同的答题纸，答题纸不同，标注也不同。

若问题问“谁发布新品”，起止预测必须落回原文范围。子词切分和字符坐标还要对齐，例如一个实体被拆成两个 token，不能把其中一半作为完整实体。BERT 输出向量本身不会替应用处理这些边界。

## 数据与训练

原始 BERT 主要用[遮盖预测](/nlp/masked-modeling/)与下一句预测学习：把输入一部分藏起来，让模型还原，并学习句对关系。随后用带任务标注的数据微调模型和任务头。

遮盖预测会利用左右文；[下一 token 预测](/foundations/next-token/)只能利用此前内容。两种目标的差异比“都用了注意力”更值得记住。不要把原始 BERT 的目标默认套到全部后续编码器模型。

### 预训练信号从哪里来

原论文的英文预训练语料包含 BooksCorpus 和英文维基百科。训练时不需要人给每一句写情绪标签：文本本身就可以构造填空题和句子对，但依然需要筛选、分词和构造样本。论文将约 15% 的 WordPiece 位置选为预测目标；在被选中的位置里，80% 替换成 `[MASK]`，10% 换成随机词，10% 保留原词。以恰好选中 100 个位置的教学例子说明，平均约 80 个变成掩码、10 个随机替换、10 个保持原样；具体一次抽样不会保证刚好这个比例。损失针对被选中位置的原始词，而不是只针对真正出现 `[MASK]` 的位置。

下一句预测的训练样本中，约一半正例是语料中实际相邻的句段，另一半负例从语料中取随机句段。模型用 `[CLS]` 对应的表示学习判断这两种构造方式。随机负例往往比较容易识别，因此这个目标的贡献要结合实验看待；不能声称它直接保证了常识推理能力。后续模型也有修改或移除该目标的做法。

例如，A 是“外面开始下雨”，真实接续 B 是“她拿起雨伞”，这是正例；如果 B 随机抽到“鲸鱼生活在海洋中”，训练时就标为负例。这里的标签说的是**采样时是不是原文接续**：随机抽来的句子即使语义上也说得通，仍然是按采样方式标出的负例；正例也不保证一定存在严格的因果关系。

先做通用预训练，再用少量标注任务数据微调：例如收集客服句子和“退款／咨询／投诉”标签，将 `[CLS]` 向量送进三分类头，计算预测与标签的交叉熵，再更新任务头和编码器。微调后的模型能输出类别分数，但分数是否可靠还需要在独立数据上检查，尤其是未见过的新业务类型。

### 训练设置与任务边界

原论文预训练使用每批 256 条序列、共 100 万步；为降低计算量，其中 90% 的步数使用 128 token 的序列，最后 10% 使用 512 token。这是论文的实验设置，不是所有 BERT 衍生模型的默认值。被选中位置有时保持原样，是为了减少预训练中大量出现 `[MASK]` 而实际任务中通常没有该标记的差异。

下一句预测判断句对是否按语料关系相接，不等同于任意两个句子语义是否相似。分类微调再提供真实任务标签，通常可以一起更新编码器与任务头；只训练任务头是另一种可比较的基线。

## 评测怎么看

分类要看准确率或 F1，类别不均衡时分别看每类召回；实体抽取要明确按 token 还是完整实体计分；抽取问答可看答案匹配和 F1。论文使用 GLUE、SQuAD 等任务，不是只报告一个预训练损失。

### 基准分数该怎样读

GLUE 是由多个自然语言理解任务组成的集合，不是一个统一的单题考试；不同任务可能用准确率、F1 或相关系数。SQuAD 抽取问答要求模型从给定文章中找答案，通常分别报告精确匹配和 token 级 F1；正确答案不在给定文本中时，是否允许“不知道”还依赖具体版本和评分协议。读论文表格时要核对模型大小、是否有额外训练、开发集还是测试集，以及是否做了集成。

例如论文 SQuAD 1.1 测试 F1 为 93.2 的结果，来自 BERT-Large 的七模型集成，并先使用 TriviaQA 做额外微调；它不是单个 Base 模型开箱即用的成绩。同一表格中，单个 Large 模型开发集 F1 为 90.9，开发集和测试集也不能直接当成完全相同的实验。

### 下一句预测究竟有多大作用？

原论文用 BERT-Base 做过一组消融实验：保留掩码语言模型，只去掉下一句预测。QNLI 开发集准确率从 88.4 降到 84.9，SQuAD 1.1 开发集 F1 从 88.5 降到 87.9；两项的变化幅度并不相同。这说明在作者的这组设置里，下一句预测有帮助，但不能把这两个差值当作所有任务的固定收益。

后来 [RoBERTa 论文](https://arxiv.org/abs/1907.11692)用不同的文本组织方式重新实验：去掉下一句预测，同时把输入改成连续文本块，其结果与原来的句段对设置相当或略好。这里输入格式也变了，不能把差异全归因于“是否使用下一句预测”。比较两篇论文时，要一起看训练样本怎么组织，而不是只记住“NSP 必须保留”或“NSP 一定有害”。

例如英文参考答案是 `Friday at 3 pm`，模型回答 `3 pm`。按空格切分并忽略大小写，这两个答案不完全一致，精确匹配为 0；预测的两个词都在参考答案里，精确率为 1，召回率为 2/4，词级 F1 约为 0.67。虽然自动指标体现了部分重合，实际门店服务仍缺少星期信息，需要结合具体错误一起判断。

### 漏识别和边界错，怎样计分

构造 5 个人名实体，模型报出 4 个，其中 3 个完整匹配，则实体级精确率为 3/4，召回为 3/5。只把几个 token 分对不代表实体完整，评分必须先确定边界和类别是否都需一致。对于情感混合句，先写清“整体情绪”还是“方面情绪”的标签规则，避免把标注歧义当成编码器故障。

## 应用与错例

客服意图分类把“想退款”和“咨询退款条件”混在一起时，先检查标签定义与难例标注，再看输入截断、类别比例和领域词。把混淆样例补到训练或开发池，保留独立会话做回归，避免同一用户的近重复句子泄漏。

## 比较与面试追问

[BERT 与 GPT-2](/nlp/gpt/)的核心区别是可见范围和学习目标。BERT 的常见用法是理解输入后输出标签；GPT-2 擅长顺着前缀生成。二者都不天然保证事实正确。

**实体抽取为什么不能只拿一个句子向量？** 因为要判断每个位置属于哪一类，还要恢复实体边界。

**BERT 双向看上下文，是否意味着它能看到隐藏答案？** 不意味着。掩码预测看到的是被破坏后的输入，目标词作为标签参与计分；下游评测仍必须防止数据泄漏。少数被选位置保持原样是预训练设计的一部分，不等于测试时提供正确标签。

**为什么不直接让 BERT 像 GPT 一样连续写文章？** 原始模型的训练方式主要是预测被选中的位置，没有作为自回归生成器那样的因果续写流程。可以设计额外的生成方案，但不能因此把原始 BERT 等同 GPT。

**微调只改分类层行不行？** 可以冻结编码器做基线，再比较全量或参数高效更新的收益与成本。
