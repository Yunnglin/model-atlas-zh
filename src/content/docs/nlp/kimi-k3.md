## 要解决什么问题

长工程任务既要记住大量上下文，又要在很多步骤后继续执行。K3 将高效历史处理、层间信息融合、稀疏专家与视觉能力放进同一模型。[返回 Kimi](/nlp/kimi/)。

## 结构与数据流

官方模型表给出 2.8T 总参数、104B 激活参数与百万 token 上下文。理解时不要只背规模，先拆出三个部分：

- **Kimi Delta Attention（KDA）**用门控机制更新有限状态记忆，可以先理解成有选择地保留和遗忘历史；不是逐字保存整段上下文。
- **Attention Residuals（AttnRes）**改变不同网络深度的信息融合方式；粗略说，不再只依靠固定的残差相加路径。
- **Stable LatentMoE**围绕专家稀疏计算与训练稳定性设计；官方说明每步选择部分专家，激活规模仍不同于总存储规模。

原生视觉让模型能结合图片与文本处理问题，但不自动意味着具备语音波形输出。上面是教学概括，部署配置与具体层路径应查官方模型配置，不能拿示意图替代实际实现。

### 三种“选择”发生在不同轴上

KDA 沿序列时间更新记忆，回答过去哪些信息值得保留；AttnRes 沿网络深度融合信息，回答当前层应如何利用先前层表示；MoE 则选择当前 token 的加工专家。可以类比做长题时的工作笔记、回看不同解题阶段、挑选不同计算工具，但这些不是模型里真的有三位独立助手。

普通残差把子层结果与原路径相加；Attention Residuals 引入依内容选择的深度聚合。它不等于对更长文本做检索，也不表示绕过全部中间层。Stable LatentMoE 处理另一项专家结构与稳定性问题，不能拿它解释所有长历史记忆。

假设，对三个较早网络层的表示分配 0.6、0.3、0.1 的聚合权重，就是有选择地利用不同深度，而不是所有阶段固定等权相加。数字只用于说明加权含义，不是 K3 实测权重。AttnRes 原论文还以分块方式减少完整深度聚合的开销；具体型号采用哪条路径仍按实现核对。

官方 K3 配置列出 69 个 KDA 层和 24 个 Gated MLA 层，视觉编码器为 MoonViT-V2。混合层仍包含全局读取路径，不能把 KDA 的固定状态特点扩大成全模型零历史缓存；这些数值也不能套回 Kimi Linear 或 K2。

## 数据与训练

多模态预训练建立共同表示，面向代码、研究和长程任务的训练进一步改善执行。公开 README 并不等于完整数据配方；未公开的奖励函数、混合比例和训练阶段不补写。

理解 KDA 可以先对比 [Kimi Linear](/omni/kimi-multimodal/)与 [Qwen3-Next](/nlp/qwen-next/)，再看它们各自怎样处理长历史。结构相似不证明训练和权重相同。

### 学到能力与系统保存信息，分别检查

多模态预训练让图文信息共同参与学习，任务后训练改善执行与推理；调用时的工具输出裁剪、历史摘要与记忆管理则在系统侧。即使模型训练支持长输入，外层应用若先删掉关键约束，模型也无法从被删内容里取证。

本页不补写官方未公开的各阶段样本比例。业务教学轨迹可保存最初要求“不要改接口”、多轮工具反馈与最终补丁，让这一约束在长任务中持续可检查，而不是只奖励最后一段解释。

## 评测怎么看

同时观察长上下文定位、跨段推理、视觉任务与工具任务完成，记录资源、延迟和预算。官方报告的任务表现不等于所有使用环境都相同，尤其要核对 harness 与工具配置。

### 一条约束从开头放到结尾

构造相同代码任务，将“函数名不能变”分别放在前、中、后段，加入无关日志，再看最终接口是否保持。还要有明确修改函数名的反向对照，避免模型只是固定不改名。

把未截断输入、关键证据位置、工具输出处理与生成预算保存下来。单条针检索成功说明能找到某个细节，不证明能综合一整段工程约束；两者应分题统计。

## 应用与错例

长任务中丢失要求，先检查截断、工具输出压缩和记忆管理，再看模型是否在证据存在时忽略约束。用不同距离和干扰条件构造测试，避免把系统丢数据误认为模型必然遗忘。

## 比较与面试追问

**AttnRes 是给 token 做普通自注意力吗？** 它关注深度之间的信息聚合，不能与序列历史读取混为一谈。

**百万上下文意味着能稳定完成百万 token 的所有推理吗？** 不是，上限、定位与复杂理解是不同能力。
