## 它解决什么问题？

想象你在做一张语言试卷。一道题让你读句子中间的空格，另一道题给你一句开头，让你接着写下去。BERT 式的遮盖训练擅长利用左右文，GPT 式的续写训练则天然适合从前往后生成。GLM 尝试让同一个模型练习两类题：既读懂保留下来的文字，也能逐步写出缺失内容。

GLM-130B 把这一思路扩展到 1300 亿参数和中英文语料。它是基础模型，不等同于一个经过现代助手式对齐的聊天产品。想从最小例子了解这条路线，可以先看 [GLM 原始论文](/nlp/glm-original-model/)；想知道之后怎样变成易用的助手，可以继续看 [ChatGLM](/nlp/chatglm/) 与 [GLM-4-9B](/nlp/glm4-9b-model/)。

## 结构与数据流

例如“北京是 [MASK] 的首都”，把“北京是”和“的首都”保留下来，两边一起提供线索，模型再生成“中华人民共和国”等合适答案。更贴近续写的题目则是“出门前记得带 [gMASK]”：只给前文，要求模型把后面的内容接上。

这两种输入都经过同一套 Transformer 主干。关键不是摆了两个独立模型，而是利用**注意力掩码**决定每个位置可以看什么：保留的上下文可以互相看见，生成答案时则能看上下文和已经写出的答案，不能偷看后面的正确答案。就像老师允许学生阅读完整题干，却不允许翻看尚未作答的答案页。具体的注意力机制可以参见 [Transformer](/foundations/transformer/) 和[注意力](/foundations/attention/)。

训练时，原文被切分成 token，再构造空位和答案。模型收到上下文和此前的目标内容，预测下一 token；实际输入还包括特殊标记和位置处理。上面的中文例子只是帮助理解，不表示每个汉字或词必然对应一个 token，也不表示模型一定生成唯一正确的填法。

### 为什么不直接称为普通 GPT？

普通因果语言模型通常按从左到右的可见范围训练。而 GLM-130B 的保留上下文可以双向互看，生成部分仍然自回归。这使得它既不同于只给每个空独立预测一个 token 的做法，也不同于将两个独立编码器和解码器连接起来。首页把它归为混合可见性结构，是为了提示这一区别；不意味着每个后来的 GLM 模型都沿用完全相同的掩码。

## 数据与训练

论文介绍约 4000 亿 token 的中英双语数据，其中多任务指令预训练（MIP）占训练 token 的 5%：将有任务格式的数据混入预训练，让模型不只见过普通文章，也见过问题和回答。它和后来的聊天指令微调有相似的“让模型接触任务格式”的目的，但训练阶段、混合比例和具体数据并不相同。不能仅凭“MIP”就断言模型已经完成 RLHF。

短空位 `[MASK]` 让模型恢复文中缺失片段；`[gMASK]` 则将末尾较长一段当作生成目标。论文将自监督填空部分的 30% 序列用于 `[MASK]`，其遮住的片段合计占输入的 15%；其余 70% 序列使用 `[gMASK]`，保留前缀并遮住后续内容。这里的 30% 和 15% 分别描述不同对象，别把它们当成同一个比例。训练配置中，`[gMASK]` 使用 2048 token 上下文，而 `[MASK]` 和多任务样本各用 512 token，再将四个样本拼成一个 2048 token 的训练序列。不同空位长度、题目比例和可见范围都会改变模型收到的学习信号，所以讨论训练配方时，要分清“多少训练样本采用某一目标”和“每条文本被遮掉多少”，这不是同一个数字。

把模型做大也让训练更容易出现不稳定。论文讨论 DeepNorm、位置编码和激活函数等选择，并报告训练过程中观察到的梯度问题。可以把深层网络想成几十人接力传递信息：每一棒若都把信号放大一点，最后可能变得难以控制；归一化与残差设计是帮助信息在深层传播的工具。它们降低特定配置的训练难度，不是对任何规模都自动有效的开关。

训练使用模型并行和流水线并行，把参数及计算分散到多张设备。参数量除以设备数只是非常粗略的起点：优化器状态、激活值、通信和设备间分配也会影响实际显存与速度。论文的资源和吞吐结果应放回当时的硬件与软件环境理解。

## 评测怎么看

LAMBADA 要求模型根据一段上下文预测最后一个词。论文报告 GLM-130B 使用双向注意力设置时的零样本准确率为 **80.2%**。这里预测的是最后一个词，模型并没有看到答案右侧的正文；“双向”指已给出的上下文 token 之间可以互相注意，而答案仍按顺序生成。比较普通因果模型时，需要区分这种上下文内部的可见范围，而不是误以为模型拿到了额外的答案后文。这个分数属于论文指定的数据和判分方式，不是聊天成功率，也不能直接说明企业知识问答表现。

论文还报告 Pile、MMLU 和中文任务，并讨论测试数据污染。论文披露，MIP 早期曾误将部分原计划留作零样本任务迁移的数据纳入训练，约 2.3 万步时修正；因此阅读相关零样本成绩时，还要看论文列出的数据筛选与任务类型。做自己的实验时，先固定数据版本、提示模板、示例数量、采样和答案提取规则，再报告准确率及错例。中英文任务应分开看：英文阅读分高，不能直接推断中文专业问答也一样好。

论文讨论了 INT4 量化：将高精度权重压缩到更低位宽，减少存储和推理成本；其特定设置在 LAMBADA 上从 80.21% 到 79.47%，下降了 0.74 个百分点。这说明论文中的量化方案在该任务上的损失较小，并不代表所有量化方法、全部任务或所有输入都不会受影响。量化还要评估实际延迟、显存、长文本和业务错例。

具体来说，论文主要量化线性层的权重，保留输入输出嵌入、归一化和偏置等部分；激活仍使用 FP16，运行时再将量化权重动态转换为 FP16。可以把它想成把仓库里的材料压缩存放，使用时再解压：省下的是一部分权重存储，解压也会带来额外计算。因此“INT4 模型”不意味着所有计算、缓存和权重都只有四位，也不自动意味着在每种硬件上更快。

## 应用与错例：让改进形成闭环

假设做中文合同条款抽取，准备合同及人工标注的字段，按合同来源或客户划分训练集与独立测试集，避免同一份合同的相似片段同时出现在两边。先用基础模型和明确的抽取模板建立基线，再考虑用标注样本做监督微调。

不要只看平均分。若“付款期限 30 天”被抽成 3 天，可能是数字识别或输出格式错误；若把“签约后 30 天”误解成“发票后 30 天”，则涉及上下文关系。把错误分组，补充相应训练样本，再用独立测试集复测，并检查原来做对的样本是否退步。遇到专业事实需要外部证据时，应用可检索合同原文并要求模型引用，而不是把模型的流畅输出当作事实。

### 填空任务为什么需要设计题目

同一段话可以挖成不同的题：挖掉一句话中间的短片段，模型能利用两侧线索；把结尾整段藏起来，模型主要依据开头续写。假如原文是“顾客买了雨伞，因为下午有雨”，短空可挖掉“雨伞”，长空则可保留“顾客买了”并让模型接下去。前一种比较像阅读理解，后一种比较像写作练习。两种题混合训练，会让模型看到不同的条件和输出长度，但比例变化可能影响各项任务的表现。

评估时也要给模型和对照组相同的信息。如果在中间填空任务里，填空模型看到了空格右侧文字，而续写模型只看到了左侧，分数的差异既可能来自模型本身，也可能来自提供的线索。LAMBADA 的末尾词预测不属于这种给出右侧正文的情形。合理做法是单独说明可见上下文，并在可以统一条件时做补充对照。这样读者才能知道数值比较到底回答了什么问题。

## 面试追问

**GLM-130B 的双向注意力是否意味着生成时看到了未来答案？** 不是。双向可见的是保留下来的上下文；答案仍按顺序生成，并用掩码禁止看到后续目标。

**它与 BERT 的填空有什么区别？** GLM 可以把连续、长度不固定的片段作为生成目标，逐 token 补全；而不是把所有空都视作独立的单 token 分类。两个模型的训练任务与推理使用方式都要结合具体实现。

**130B 一定比 9B 更适合业务吗？** 参数量不是唯一指标。还要看模型时代、训练数据、指令能力、部署成本、上下文和业务评测。一个更新、针对任务微调的小模型可能更实用，必须用相同测试集与预算比较。
