## 为什么要做小模型

假设手机要把用户写的一长段备忘录整理成三条提醒。把请求送到云端可以使用更大的模型，但需要网络，还需要考虑请求内容如何传输和保存。如果模型能在设备上运行，一部分任务就可以留在本地；代价是手机的内存、功耗和计算能力有限，模型也可能比大模型更容易遗漏重要信息。

Llama 3.2 的 1B 和 3B 是为轻量部署设计的文本语言模型。它们通过文本输入产生文本或代码，不具备直接读取照片的能力；同次发布的 11B 和 90B 则是 [视觉分支](/omni/llama32-vision-model/)。一个名字相近、参数更小的模型不会自动继承另一分支的图像输入接口。

本文的备忘录、模型概率和部署实验都是教学例子，没有实际在手机运行。当地运行并不自动保证应用安全：日志、遥测、备份和其他联网组件仍可能传出内容，必须检查完整应用的数据流。

## 结构：小模型依然怎样生成文字

两款模型都是自回归 Transformer。系统先将输入文本切成 token，模型根据已有内容预测下一个 token，选出后追加，再继续预测。例如给出“明天记得带”，可能续写“伞”；若提示要求总结备忘录，指令版会尝试按要求输出条目。token 不等于汉字数，输入、系统提示、历史对话和输出都需要计算到上下文预算中。

结构中的注意力让当前位置利用前面的信息；GQA 让多组查询共享部分键值表示，有助于减少推理时需要保存的键值缓存。共享嵌入则复用部分词表示参数，帮助控制模型规模。两者解决的是不同问题：前者主要涉及注意力计算和缓存，后者涉及参数共享。实际速度还取决于芯片、推理框架、量化精度和输入长度。

模型卡对原始文本模型列出 128K 上下文，但 Meta 后续发布的指定量化版本列出 8K；官方说明这是为有限移动内存优先优化的短上下文应用，不意味着量化算法必然只能处理 8K。能接收多少内容也要看所用检查点和服务设置；不要把 128K 直接写进所有量化部署的使用承诺。即使一份长备忘录能完整放入，模型仍可能漏掉中间的“不要安排周五”，所以还要测答案是否真的引用了正确内容。

## 剪枝：先把网络做小

官方介绍，两款轻量模型从 Llama 3.1 8B 出发，采用一次性的结构化剪枝：系统地移除网络的一部分，并调整权重和梯度幅度，得到较小网络。可以把它想成整理一张大型办公桌：拿走成组的柜子，使新的桌面布局更紧凑，而不是只把零散文件涂黑。

结构化剪枝与把个别权重设为零不同。删除结构之后，模型形状确实变小，更有机会让常规硬件直接受益；但具体速度仍取决于被删除的结构、实现和设备，并非“参数少一半就必然快一倍”。剪掉的部分也可能承载有用能力，因此模型缩小之后，需要继续训练和评测，确认哪些能力得到保留、哪些退化。

Meta 发布说明介绍了剪枝的总体方式，但没有公开足以从原始 8B 权重、数据和全部参数完整重建每个细节的配方。不能根据一个框图推断精确删除了哪些注意力头、每层通道或每一步调参，也不能声称剪枝不会造成知识损失。

## 蒸馏：让小模型学习老师的判断

剪枝之后，Meta 在预训练阶段使用 Llama 3.1 8B 和 70B 的 logits 作为 token 级训练目标，帮助小模型恢复能力。logits 是模型给各个候选 token 的未归一化分数，经过相应变换可得到概率分布。它携带的不是只有“老师最终选了哪个词”，还包含其他候选相对得分的信息。

例如训练文本前缀是“下雨了，记得带”，真实后续是“伞”。老师可能同时认为“雨衣”也是合理候选。小模型除了学习真实文本，也可以从老师对候选词的分数中学习这些关系。这个例子只帮助理解软目标，不是官方公布的具体概率、样本或损失权重；模型也不是真的在理解老师讲课。

蒸馏和剪枝承担不同职责：剪枝改变网络规模，蒸馏通过训练信号帮助较小网络学习或恢复能力；两者也不同于量化。量化主要改变权重或计算的数值表示，以降低存储和运行成本。三者可能组合使用，但任何一项都可能影响任务质量；不能把“经过蒸馏”理解为小模型在所有任务上和 70B 老师一样好。

官方称模型预训练使用最多 9 万亿 token，来源是公开可得在线数据的新混合。这里的“最多”应保留，token 数也不等于独立网页数。数据完整清单和复现所需的全部混合比例并未公开，不能由这个数字推断两种规格看到的每条数据完全一致，也不能从教师模型规模直接推导学生模型表现。

## 后训练：让它更像一个助手

基础模型学会续写文本后，Meta 描述通过多轮监督微调、拒绝采样与直接偏好优化得到对话模型。监督微调让模型学习示范答案；拒绝采样会生成多个候选并选择较合适的结果用于后续训练；偏好优化则利用偏好数据调整回答倾向。这些方法针对输出行为，不等同于前面把网络变小的结构化剪枝。

拿手机备忘录来说，示范样本可以要求模型保留日期、事项和负责人，并在原文没有时间时写“时间未提及”。好的数据不是只给一个流畅答案，还要忠实于原文。假如教师生成的摘要把“可能周三开会”写成“周三必须开会”，未经检查就作为训练目标，学生同样可能学到错误。

指令版可能更擅长遵循格式，但它不是事实核查器。离线模型的预训练数据截止到 2023 年 12 月；关于之后的事实，需要可靠外部信息。模型卡的八种官方支持语言不包含中文，中文备忘录需要单独进行任务评估，不能把英文报告成绩套用过来。

## 评测：把分数和运行条件一起看

官方模型卡分基础版、指令版和不同量化方式报告英文测试。以指令版 BF16 为例，MMLU 五样例设置的宏平均准确率中，1B 为 49.3，3B 为 63.4；IFEval 零样例、按模型卡所列多种严格与宽松口径平均的结果分别为 59.5 和 77.4。这是 Meta 使用其内部评测库报告的历史结果，并非本文复现；不能将其解读为所有中文任务的准确率。

同样的模型名后面可能跟着不同精度。Meta 后续发布的是指令版量化模型，采用 SpinQuant 和量化感知训练加 LoRA 两条路线。模型卡中的这套面向 ExecuTorch 和 ARM CPU 的量化方案，Transformer 块线性层使用 4 位分组权重和逐 token 动态 8 位激活，嵌入及分类输出层采用 8 位权重；因此不应把它笼统描述为“所有计算都是 4 位”。模型卡对量化模型列出了多个对照结果，其中 Vanilla PTQ 标为仅供比较、未发布，不能把这个表格列当成一定可下载的官方检查点。量化模型的成绩可能随方法和任务变化，不应只根据文件缩小比例判断实际质量。

例如模型卡的英文 MMLU 五样例对照中，1B BF16 为 49.3，1B SpinQuant 为 47.3，而 1B 量化感知训练加 LoRA 为 49.0。三者是同一表中的不同模型与量化设置，说明换一种压缩方法可能改变质量；这并不是对所有题型的统一损失，也不能只凭这三个数判断手机上哪个版本最合适。

模型卡也给出特定设备的端侧基准：在 OnePlus 12 的 ARM CPU 和 ExecuTorch 条件下，1B BF16 与 SpinQuant 的解码速度分别报告约 19.2 和 50.2 token/秒。它们是特定设备、软件和测试设置下的结果，不是任何手机都能达到的速度；模型卡注明首 token 延迟按 64 token 的提示测量，不能将这一条件误认为长输入的表现。首 token 延迟、长输入预填充、运行内存、持续发热和电量消耗也需要分别测；“每秒多少 token”无法概括全部体验。

评测手机摘要时，应固定样本、模型检查点、输入模板、量化方式、推理框架和设备状态，统计事项是否漏掉、日期和否定词是否保留、无依据的信息是否增加，并记录时间、峰值内存及能耗。不同任务的结果可能不同，3B 在一种任务上优于 1B，不说明它对每位用户都更合适。

## 应用与错例：从错误摘要回到数据

先准备已获授权、经过脱敏的备忘录，人工标注事项、日期、负责人和原文依据。按来源或记录人划分开发集与独立测试集，避免同一条备忘录改几个字就同时出现在两侧。分别运行 1B 和 3B 的相同任务，要求模型对不明确的日期明确写“未提及”，并保存模型版本、精度与输出。

假如原文是“周三讨论是否延期”，摘要写成“周三延期”，先把它记为不确定性丢失，再检查提示、原文是否被截断、标注是否正确和模型输出。可以添加保留条件词的示例、改进提示或设计人工审核规则；然后在没有参与调整的新备忘录上复测。修复条件词后也要回归日期、负责人和否定词，避免只改善单一错例。

如果 1B 运行速度适合手机但经常漏项，可以对比 3B 或让应用只处理较短片段，再将结果与原文核对；分段会影响跨段关系，必须针对新流程重新测试。最终应同时报告准确性、无法确认比例、延迟和资源消耗，不把“可以离线运行”直接等同于“适合所有任务”。

## 面试追问

**剪枝和量化有何区别？** 剪枝减小网络结构；量化改变数值表示。两者都可能降低资源需求，但质量和加速要在实际设备验证。

**蒸馏只学习老师最终生成的答案吗？** 不一定。Meta 介绍这两款模型利用 8B 和 70B 教师的 token 级 logits 作为训练目标，包含候选 token 的相对信息。

**128K 能直接用于官方所有量化版本吗？** 不能。模型卡列原始模型为 128K、所列量化模型为 8K，还应核对具体实现和服务限制。
