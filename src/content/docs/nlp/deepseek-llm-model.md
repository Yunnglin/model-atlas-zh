## 要解决什么问题

假设你想让一个助手整理售后对话：“顾客说杯子破了，商家同意补发。”一个刚学会续写的模型，可能接着编造下一句对话；经过对话训练的模型更可能按照“请概括”的要求，输出一句摘要。两者都使用语言模型，但学习目标和使用方式有区别。摘要即使流畅，也可能漏掉“同意补发”，所以还需要检查。

DeepSeek LLM 是 DeepSeek 早期通用文本模型系列，报告公开于 2024 年 1 月，包含 7B 与 67B 基础模型及对话模型。它也常被称作初代或 V1，但不能把后来的 [DeepSeek-V2](/nlp/deepseek-v2-model/) 的 MoE 与 MLA 直接套给它。以下场景、数值算例均为教学构造，不是模型实际运行结果。

## 结构与数据流

模型接收文本后先进行分词：一个 token 可能是汉字、词的一部分、符号或空格，并不保证一个 token 等于一个字。token 转成向量并加上位置信息，进入多层因果 Transformer 解码器；模型基于之前的 token 预测下一个，再把生成结果接回上下文继续预测。[Transformer](/foundations/transformer/) 与 [分词](/foundations/tokenization/) 分别解释这两步。

比如输入“顾客说杯子破了，商家同意”，模型可能续写“补发”。这里的“预测”是对词表中候选 token 分配概率，不等于模型在后台查询真实订单。若问题涉及实时物流、退款或库存，必须由外部系统提供数据与权限；模型生成“已经退款”不能证明退款操作真的发生。

初代使用稠密前馈网络：每个 token 经过同一套相关层参数，并非让路由器从许多专家中挑一部分。7B 模型有 30 层，67B 有 95 层。论文报告 67B 使用分组查询注意力 GQA：多个查询头共享一部分键和值头，可以减少推理时相关缓存。可以把它想成几个不同的问题共用一组可查阅的笔记；查询仍可以不同，并不是所有注意力头变成一个头。

以报告中的配置为例，7B 是 32 个查询头和 32 个键值头；67B 是 64 个查询头共享 8 个键值头，相当于每 8 个查询头共用一组键值头。这里是头数关系，不等于整机显存会缩小 8 倍；两种模型的层数、维度与权重规模也不同。两者原始配置的上下文长度均为 4096 token，后来框架的扩展设置需要单独验证。

GQA 与 [DeepSeek-V2](/nlp/deepseek-v2-model/) 的多头潜在注意力 MLA 是不同设计；GQA 减少 KV 头数，MLA 使用潜在表示组织注意力缓存。缓存节省并不等于总显存按同一比例下降：模型权重、输入长度、并发请求、精度和中间工作区都要计入。7B 与 67B 的注意力配置不同，不能把 67B 的结论未经核对推广到全部型号。

## 数据与训练

### 先学习续写

论文描述用约 2 万亿 token 的中英文语料预训练。语料经过去重、过滤和混合；token 是文本计量单位，不是两万亿篇文档或互不相同的事实。重复网页、机器生成文本和错误内容都可能影响模型，数据处理要兼顾质量、领域覆盖与语言比例。论文公开了处理思路，但没有给出可以完整重建所有训练样本的清单。

模型训练时看到上下文，例如“商家同意”，目标是预测后续 token。一次预测失败后，优化器根据损失调整参数，经过大量样本逐渐学习语言规律。它可能学到中文表述、代码格式和常见知识，但单靠续写任务不保证听从用户指令，也不会自动知道某个来源是否真实可靠。

### 怎么分配计算预算

论文还研究缩放规律：在一定计算预算下，模型大小、训练数据量和超参数怎样分配更合适。比如预算固定时，把所有钱用于扩大模型，可能没有足够训练数据让它学好；反过来，模型过小也可能无法充分利用更多数据。论文用多个规模的实验拟合趋势，而不是宣称所有公司、任务和硬件都能套用同一组最优数字。

作者特别研究数据质量与缩放结论的关系。高质量材料可能让模型在相同训练预算下获得不同收益，因此计算公式并不能替代对语料的抽样检查。学习率、批量、序列长度、模型结构和优化器也会改变实验结果。报告使用多步学习率调度等工程设计；这不意味着换用其他调度器就一定更差。

### 让模型更像助手

监督微调 SFT 把“问题—期望回答”样例作为示范，让模型更倾向按指令完成任务，例如要求总结时写摘要，而不是接着编造对话。论文还讨论直接偏好优化 DPO：对同一问题比较更受偏好的回答与较差回答，通过成对数据调整模型。它不等于让人工检查每次用户请求，也不能保证所有回答符合事实。

论文说团队收集了超过 100 万条 SFT 样例，覆盖不同类型的任务；这个数量指训练样例，不是独立用户或模型参数的数量。比如同一条售后对话可以对应“概括问题”和“提取商家承诺”两种指令，示范答案也应随任务变化。示例讲解的是数据格式，并非论文公开的原始样本。

论文对 7B 对话模型使用两阶段 SFT，并讨论代码、数学数据与对话能力的取舍。直观地说，如果示范数据长期偏向某类解题格式，模型可能变得不够自然或出现重复；通过不同阶段的数据安排试图缓解这种问题。这个观察来自特定训练设置，不是所有小模型都必然如此。数据中标准答案、权限边界和安全示例有误，也可能把问题带进模型。

67B 的情况不同：报告称第一阶段后其重复比例已低于 1%，而第二阶段影响了基准成绩，所以该型号只做一阶段 SFT。不能把 7B 的两阶段配置直接当作全系列统一配方。

该实验的第一阶段使用全部可用微调数据，第二阶段聚焦对话数据。报告表 12 中 HumanEval 从 48.2 保持 48.2，重复比例从 0.020 降至 0.014；同表 GSM8K 则从 63.9 降至 63.0。重复比例是在温度为零时计算的。这是该论文中 7B Chat 检查点及其特定评测设置的对照，不能只看代码结果就说所有能力没有变化；单次分数变化也不能脱离采样和统计误差断言必然退化。DPO 是论文另行讨论的偏好训练方法，不应把这个两阶段 SFT 例子误写成 DPO 的必经步骤。

## 评测怎么看

论文把选择题、自由生成与语言建模分开评估。选择题可比较选项文本的得分；生成题让模型输出答案再解析；代码题还需要实际执行测试。题目格式、示例数量和答案解析方法都会影响成绩，不能把同一个数字当作所有任务的表现。

例如论文的 Base 模型表中，67B 在 HumanEval 以零样本评测得到 42.7，7B 得到 26.2；这是其内部评测框架和对应测试设置下的结果，不表示真实项目中 42.7% 的缺陷会被自动修复。Chat 表的数字是经过后训练的另一个检查点，也不应直接与 Base 混为一谈。代码看上去合理，仍可能在空输入、依赖版本或异常处理上失败。

论文还有一个值得注意的对照：给 7B Chat 增加 2000 万条中文选择题数据后，C-Eval 从 47.0 升到 71.3，CMMLU 从 49.7 升到 73.8；但自由生成的 TriviaQA 在同一表中仍为 57.9。就像学生大量练习选择题后更熟悉选项格式，不代表写开放式回答的能力也提高了同样多。两种任务的评分方式不同，而且这是一个特定实验的观察；论文最终没有将这批选择题数据纳入常规训练。

对于售后摘要，可先建立人工标注的独立样本，分别检查商品、问题、商家承诺和时效。假设 20 条教学样本中 16 条保留了所有关键事实，但只有 13 条没有增加原文未提到的承诺，两项比例分别是 80% 与 65%；这不是模型实测。评测时固定提示、输出长度、抽样方式与模型版本，并按普通、长对话、矛盾信息和无依据问题分组观察。

同样要提防测试泄漏：若用于调提示的对话模板与最终测试几乎一样，成绩可能高估对新业务的适应。预训练网页可能出现相似文本，不能仅凭题目存在于公开基准就认定完全独立；需要保留时间、来源和数据划分说明。

## 应用与错例闭环

假设模型把“商家同意补发”总结为“已退款”。先保存原始对话、提示、实际输入、模型版本和输出；检查前文是否被截断、是否有其他订单干扰，还是模型把两种售后操作混淆。若来源文本本身混乱，应先改善数据；若证据清楚但模型仍编造，再调整提示、检索或收集高质量训练示例。

随后收集补发、退款、拒绝和待确认等相似案例，按客户对话或来源分隔开发集与独立测试集。修改后重新测事实保留、无依据时承认不知道、不同措辞和延迟；对高影响业务由人或可靠系统核验操作状态。这里是可复现的实验方案，并未实际执行训练和测试。

## 比较与面试追问

**初代 DeepSeek LLM 是 MoE 吗？** 本页讨论的 7B、67B 是稠密模型；不要把后续 V2 的专家路由套过来。

**GQA 和 MLA 是同一件事吗？** 不是。GQA 让多个查询头共享键值头；MLA 使用不同的潜在表示设计。

**两万亿 token 等于两万亿篇文章吗？** 不等于。token 是文本的计量单位，训练还可能重复使用内容。

**SFT 和 DPO 有什么不同？** SFT 学习示范回答；DPO 利用偏好对比较回答。两者都依赖训练数据质量。

**基准得分代表所有实际业务吗？** 不能。模型版本、提示、数据分布、判分方法及工具环境都可能不同。
