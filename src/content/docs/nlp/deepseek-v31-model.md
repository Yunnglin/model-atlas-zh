## 要解决什么问题

想象一个文档助手接到两种任务：第一种是“把这段话改成邮件标题”，第二种是“比较三个版本的合同，找出付款条件变化并给出出处”。前者通常希望回答快；后者需要读长文、比较细节，必要时查找原文。对所有问题都生成很长的推理可能浪费时间，但直接凭印象回答复杂问题也容易漏证据。

DeepSeek-V3.1 于 2025 年 8 月发布，官方称它在一个模型中支持思考和非思考两种模式，并通过后训练加强工具使用。模型卡同时公开了 Base 和后训练版本；这里介绍初版 V3.1，而不是之后的 V3.1-Terminus、V3.2 或当前线上服务的某个未固定版本。下面的文档例子与评测方案均为教学构造。

“混合思考”说的是同一个模型通过输入模板切换生成方式，不是把两个独立模型的输出拼起来，也不是保证模型能自行判断所有任务该用哪种模式。思考模式会生成专门的推理内容；非思考模式直接进入回答格式。输出更长不自动等于更可靠，模式、提示、问题难度和预算都应通过实际任务检验。

## 结构与数据流

V3.1 属于自回归解码器模型：把对话转换成 token，利用前面的上下文逐步预测后续内容。模型卡列出约 671B 总参数、每个 token 约 37B 激活参数，支持 128K 上下文。[DeepSeek-V3](/nlp/deepseek-v3/) 介绍这一系列的混合专家网络和多头潜在注意力，能帮助理解基础结构。

MoE 像一组按需参与的工作台：每个 token 的路由会选择部分专家参与前馈计算。MLA 则组织注意力的压缩表示与缓存。两者解决不同的问题；37B 激活参数并不意味着部署只需要保存 37B 权重。完整权重、数值精度、输入长度、缓存和设备间通信都影响实际显存与速度。

### 一份权重，两种回答方式

官方模型卡描述，通过对话模板中的标记和前缀切换模式。同一份输入使用官方聊天模板时，`thinking=True` 在助手回复开头加入 `<think>`，引导模型先输出思考内容；`thinking=False` 则用 `</think>` 进入直接回答格式。应用使用对应版本的 tokenizer 和模板，才能正确传递模式。

官方多轮模板还会从历史回答中去掉上一轮的思考内容，保留最终回答和 `</think>` 标记；新一轮是否开启思考由本轮前缀决定。这能减少历史中重复携带的推理文字，但也意味着应用不能默认模型能看到此前完整思考过程。需要留存审计记录时，应由应用单独记录，且注意隐私与数据保存规则。

对于“合同中的付款期限变了几天”，思考模式可能先提取旧合同期限、新合同期限再计算差值；如果它提错了日期，写得再详细也会得出错误结论。非思考模式也并非不能完成推理，它表示采用不同的输出模式。两种模式的实际延迟和质量要在相同硬件、输入、输出预算和任务上测量，而不是按名字预设。

### 工具是模型外的另一套系统

当用户要求查找指定版本的文件时，模型可生成符合约定格式的工具请求，例如搜索文件名及关键词；应用负责解析请求、检查权限、执行搜索，并把结果按协议返回，让模型继续回答。没有执行器、网络或文件权限时，模型输出“搜索请求”不等于真的查到了资料。配图把外部执行器单独画出，工具调用也不是每次回答都必经的步骤。

例如搜索工具返回两条结果：旧合同写“30 天”，新合同写“45 天”。应用应保留两条来源和版本，再让模型回答增加 15 天；如果返回结果缺少新合同，合理的行为是提示证据不足，而不是把旧合同当成新合同。工具结果也可能包含错误、过期文本或恶意指令，应用应将其视为待处理数据，限制工具权限并记录实际执行情况。

初版模型卡将普通 ToolCall 格式用于**非思考模式**：工具名称必须匹配已提供的工具，参数应是符合约定结构的 JSON；思考模式的搜索 Agent 则使用单独的搜索调用格式。例如，给文件搜索提供 `query` 参数时，应用既要检查它是不是合法 JSON，也要检查查询值和权限是否符合自己的接口。不要把这两种格式混成一套万能模板。

不同模式对工具接口的支持会受模型版本、模板和服务实现影响。接入时应核对对应版本文档与解析器，做实际调用验证，不把后续 V3.2 的能力或某个框架的实现细节直接归给初版 V3.1。

## 数据与训练

### 从 V3 扩展长上下文

模型卡说明 V3.1-Base 从原始 V3 Base 检查点出发，沿用原报告的两阶段长上下文扩展方法，并增加长文档数据：32K 阶段约 630B token，128K 阶段约 209B token，合计约 839B，官方发布概括为约 840B。这里是继续训练的 token 使用量，不是从零训练 V3.1 的全部语料，也不是 840B 篇独立文档。

为什么分阶段？可以先让模型适应较长序列，再进一步扩展到更长序列；但模型卡披露的规模不足以重建全部数据、采样和训练配方。长上下文上限说明一次输入可以容纳多少 token，不保证模型一定读到、记住并正确使用每个位置的信息。对于多份合同，还应测试关键条款在开头、中间或末尾时的表现，以及无关条款干扰。

### 后训练与公开边界

官方说明 V3.1 在 Base 之上进行后训练，以支持两种模式并改善工具与智能体任务。后训练可以理解为让模型更贴近使用方式：不仅看到大量文本，还要学会按指令回答、输出约定格式，并根据工具结果继续工作。完整的专有数据构成、每一步损失、比例及全部训练轨迹没有在模型卡中逐项公开，不能把其他版本的配方当作 V3.1 的事实。

一个教学构造的训练样本可以包含“查找新合同”请求、模拟的搜索调用、工具返回和最终引用；数据还应覆盖搜索失败、返回冲突或没有权限的情况。模型可能学到何时尝试调用、怎样使用结果，但不能凭这样一个示例推断官方实际样本。工具正确性既取决于模型，也取决于应用接口是否提供了真实、可用且安全的操作。

模型卡还描述权重及激活采用 UE8M0 的 FP8 缩放格式，以适配微缩放数据格式。可以把缩放理解为在有限数值精度下为一组数值选择合适的表示范围；它不是凭空减少参数量，也不保证任何设备都会按同一倍数加速。驱动、内核、精度支持和模型加载方式都需要实际验证。

## 评测怎么看

官方模型卡提供了代码智能体任务的数字：V3.1 **非思考模式**的 SWE-bench Verified 为 66.0、Terminal-Bench 为 31.3；前者使用官方内部代码智能体框架，后者标明使用 Terminus 1 框架。这些是当时报告的评测结果，不是模型独立完成所有真实软件工作的概率。要复现或比较，需要记录评测版本、工具框架、提示、尝试次数、执行环境和预算；若不知道完整协议，就不要把数字当成跨系统的严格排名。

在需要查网页的 BrowseComp 上，官方给出思考模式 30.0 的结果：它使用官方内部搜索框架、商业搜索 API、网页过滤器和 128K 上下文。这更像一支“模型 + 搜索 + 网页处理”的队伍参加开卷考试；更换搜索源、页面过滤或检索预算，结果可能变化，不能把 30.0 当成裸模型闭卷分数。同表的 R1-0528 为 8.9，但模型卡注明它采用预先定义的工作流；因此 30.0 和 8.9 是不同系统设置下的结果，差距不能直接归因于模型权重。

同一模型卡还列出了思考与非思考模式的对照：在 AIME 2025 上分别为 88.4 和 49.8（Pass@1），在 MMLU-Pro 上分别为 84.8 和 83.7。前者差距明显，后者接近，说明额外推理的收益随任务变化。比较两种模式时，还应记录生成长度和耗时，看看提升花费了多少计算。

SWE-bench 类任务通常给出软件仓库与问题描述，要求系统提出补丁并通过测试；终端任务需要与外部环境交互。模型本身负责生成内容，框架负责文件操作、命令执行和结果反馈。一个会写代码的模型如果使用不匹配的工具解析器，可能根本没有成功运行测试；同样，工具环境配置不同也会改变分数。

评测合同助手时，建议分别统计：是否找到正确文档、引用是否支持答案、数值比较是否正确、工具请求是否成功，以及整项任务是否完成。假设 20 个构造任务中 16 个结论正确，只有 13 个既正确又引用了有效来源，两项比例分别是 80% 和 65%；这只是计分示例，不是模型实测。还应测搜索无结果、版本冲突和提示注入等场景，避免只评估理想情况。

比较思考与非思考模式时，应固定模型版本、输入、系统提示、工具、采样设置和最大输出，分别记录正确率、首字时间、总耗时、生成 token 和工具次数。长思考可能提高某些难题表现，也可能让简单任务更慢；官方与 R1-0528 的速度比较只适用于它给出的测试条件。

## 应用与错例闭环

若助手说付款期限由 30 天改成 60 天，首先保存原始问题、合同版本、检索结果、工具调用、模型输出和引用。逐步检查：搜索是否找到了新合同？返回文本是否被截断？是否有另一个“60 天”条款？模型是否读对两处数字却计算错误？最终页面是否引用了错误段落？这些原因分别对应检索、输入管理、理解和展示问题。

随后收集不同合同模板、版本日期、相似条款以及缺失证据的样本，按文档来源划分开发集与独立测试集。可以先改善检索和来源展示，再根据证据考虑补充训练；修改后不仅看原错例，还要复测无变化、旧版本干扰、无权限访问和拒答表现。记录质量、延迟及工具成本；这是一套可复现方案，尚未实际训练或运行评测。

## 比较与面试追问

**混合思考是两个模型拼接吗？** 官方描述是一份模型通过对话模板支持两种模式；具体服务实现仍需看使用的版本。

**128K 能保证找到长文里的信息吗？** 不能。窗口大小只是容量，检索、位置、干扰和生成策略都会影响结果。

**模型输出工具请求就完成了操作吗？** 没有。外部执行器需要解析、授权和实际运行，并把结果返回。

**671B 总参数和 37B 激活参数哪个用于算显存？** 激活参数描述每个 token 参与的计算规模；部署还要考虑完整权重、缓存和精度等。

**后训练数据与算法都公开了吗？** 官方说明了目标和部分训练信息，完整配方与数据明细不能从模型卡推断。
