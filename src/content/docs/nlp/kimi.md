## 要解决什么问题

Kimi 产品早期以长文本对话为人熟知，后来的开放模型则覆盖推理、代码、多模态与长程任务。学习时要分清产品入口、论文里的方法和真正可下载的权重，不能把“公开报告”当成“完整开源训练”。

如果只知道一本教材的标准答案，遇到变形题时可能不知道从哪儿下手。k1.5 的核心问题是：能否让模型先尝试解题，再根据结果反馈练习，从而学会处理需要多步推理的数学、代码与图文问题？这不是训练时请人把每道题的完整标准思路逐字写出来，而是利用可以验证的结果提供一部分学习信号。

## 结构与数据流

### k1.5 怎么读题、看图和给答案

报告将 k 系列描述为带多模态能力的 Transformer decoder 变体。图片首先经过视觉编码得到视觉表示，再与文本信息一起供语言模型处理；模型按序生成文字，长推理版本可在回答前生成较长的推理过程。可把视觉编码器想成“整理图表信息的读图助手”，语言模型再结合题目推理。这个类比不能保证模型真的理解图中每个像素，也不意味着视觉输入只是文字 OCR。

例如题目给出一张柱状图，问“第二季度比第一季度增长百分之多少？”模型需要先辨认两个柱子的数值，再判断应使用差值除以第一季度数值。如果读图错，即使计算公式正确，最终答案仍然错误。报告并未完整公开各层参数与结构尺寸，不要从 K2 的 MoE 配置反推 k1.5。

## 数据与训练

K1.5 报告适合学 RL 与推理预算扩展，但报告的方法不能自动套给所有 K2、K3 型号。K2 强调大规模预训练稳定性和工具相关训练；K2.5 加入视觉文本持续预训练。涉及某代具体奖励或样本比例，只写报告已公开内容。

工程任务的训练数据不只是问题与最终代码，还包括环境反馈和恢复过程。长推理也不天然等于正确，必须能检查结果或过程中的关键约束。

### K1.5：长思考怎样帮助短回答

可以把长推理想成做题草稿，最终短答案像整理后的解答。K1.5 报告研究扩大 RL 和推理上下文，并讨论 long2short 迁移：利用较长推理带来的学习信号，改善较短生成预算下的表现。这不是简单把长输出截到前几行；截断可能丢掉关键结论。

教学对照可让同一题分别使用短、长预算，记录正确率和实际 token。若长预算只是反复改写原句，没有更好结果，就没有证据说明这笔计算值得。该报告的训练探索不自动成为 K2、K3 所有检查点的共同配方。

### 奖励怎样变成学习信号

可以想象让学生对同一道题写出多个解法。对于答案明确的数学题，检查器比对最终答案；对代码题，运行测试并检查输出。模型产生的完整解答称作一次 rollout；奖励告诉训练程序结果是否满足要求，策略优化再调整模型，让获得较好反馈的解答更可能出现。概括地说，预训练教模型接着写，监督微调给它看示范，强化学习则让它试做并根据反馈调整。

比如一题正确答案是 24，模型试出答案 18、24、24。检查器可以给最终答案正确的结果更高奖励；但如果第二份解答中途推理错误，只是碰巧猜中 24，单凭最终答案也识别不出来。这就是结果奖励的局限。报告的核心框架不依赖过程奖励模型、价值函数或蒙特卡洛树搜索，并不意味着这些技术对所有任务无用。

奖励不等于真理。代码测试只覆盖一部分输入时，模型可能写出只通过已知测试的程序；数学答案格式稍有不同，也可能让简单比对误判。实际使用要设计可靠检查器，收集误判和边界情况；无法自动验证的问题，还需要人工判断或其他评价方法。

### 长上下文、部分采样与训练成本

难题可能需要较长草稿：模型检查假设、尝试方案、发现冲突，再换一种解法。报告把 RL 训练的上下文扩展到 128k，并观察到在研究设置中，增加可用长度能改善困难推理任务。这是实验结果，而不是“越长越好”的定律；长输出可能重复、跑题，也增加等待和计算费用。

长草稿采样很贵。报告中的 partial rollout 为每次采样设置输出 token 预算：某条轨迹没写完，就把已生成部分保存在缓冲区，之后从那里继续，而不是每轮从头生成。想象学生一次没写完草稿，把写好的部分保存下来，下次接着做；这主要解决长短任务混合时的采样调度和效率，不是要求对同一个前缀反复重试。报告还说明，跨迭代复用的旧片段与当前策略生成的片段需要区别处理，某些片段可不计入损失。它也讨论长度惩罚和采样策略，用于在探索、效率之间取舍。

例如把一次 rollout 的预算设为 1,000 个 token：一个简单题在 300 个 token 内完成，就可以进入后续评分；一道难题写到 1,000 个 token 仍未结束，系统保存当前前缀，下一轮从这一前缀继续。假如又生成 600 个 token 后才结束，这次完整解答一共包含 1,600 个生成 token，而不是对两个片段各自独立计算一次正确答案奖励。不同迭代的片段由不同时间点的策略生成，论文说明训练时可以排除某些旧片段的损失；完成后的答案仍要按任务规则评分。

报告中的长 CoT 监督微调也分两步：先用 32K 序列长度训练一个 epoch，再用 128K 训练一个 epoch；这样模型先接触较短推理，再适应更长的训练序列。这里的阶段描述的是报告中的长 CoT SFT，后面的强化学习另有 rollout 和奖励计算。

### long2short：把长解法变成更省时的回答

长推理有时像老师先写满一张草稿纸，之后才能总结出简洁讲法。报告研究用长推理改善短推理模型，包括模型合并、选较短的正确解答做监督、DPO 和带长度惩罚的 RL 等方法。它们是不同实验策略，不是每个 k1.5 回答都经过这一串步骤。

一个例子是从多个正确解答中选择较短者作为训练样本。要注意：短答案可能遗漏读者需要的解释；答案恰好正确也不代表中间过程可靠。合理比较需要同时统计正确率、输出长度、时延和失败类别。将长回答直接裁到前几行通常会丢掉结论，不能等同于 long2short。

## 评测怎么看

将数学推理、代码测试、多模态理解和 Agent 任务完成分开。固定思考模式、工具、时间预算、上下文与采样次数。模型排行榜里的 harness 差异可能影响分数，不能从一个总榜推导所有场景优势。

### 沿一项工程任务比较代际

教学目标“读取表格，修复缺失值处理，生成结果文件”，可拆成读懂输入、正确修改、执行成功、产物验收四项。K2 的文本与工具路线、K2.5 起的视觉信息、K3 的历史处理与层间融合，可能作用于不同环节；不能凭版本号认定每一项都改善。

同一工具环境、相同失败恢复次数和总预算下比较，再按失败环节回到相应详解。这样家族表提供路线，具体页面负责机制，不必让读者在每个版本里重复读一遍注意力定义。

### 读报告中的分数

报告给出的 long-CoT 结果包括 AIME 2024 的 77.5、MATH 500 的 96.2 和 MathVista 的 74.9；short-CoT 报告的 AIME 结果为 60.8。两种模式的计算预算不同，不能把长推理成绩当作短回答的成绩。Codeforces 使用百分位描述，与上述准确率也不是同一指标。引用时必须保留模型模式、数据集、采样方法和报告版本，不要据此断言模型在所有数学题上都正确。

以报告中的 short-CoT 强化学习版本为例，AIME 2024 的 60.8 是八次运行的 Pass@1 平均值，平均输出约 3,272 个 token。这里的“短”是与长推理方案相比较，并不是每道题都只回答几句话。比较方案时，可以把正确率和平均输出长度放在一起：如果两种方法正确率接近，却有一种使用更多 token，就还要看等待时间、费用和错误类型，才能决定它是否适合自己的场景。

要评估图表题，可以准备未参与调参的测试集，记录读图是否正确、算式是否正确、答案是否正确，并区分文字模糊、图例复杂和计算失误。代码题除了通过率，还要观察隐藏测试、运行时间和环境是否一致。同一道题分别试短与长预算，记录真实输出 token、成本、时延和成功率，才能判断长推理是否值得。

## 应用与错例

长任务失败，保留完整轨迹：什么时候遗漏要求、哪个工具报错、错误反馈是否被读到。把输入缺失、决策错误、工具执行和验证不足分开，补充相应样本，再在未见任务上回归。可结合[训练全流程](/training/pipeline/)与[RLVR](/training/rlvr/)学习。

### 一次完整错例复盘

一张营业额图显示一月 100 万元、二月 120 万元，问题是“增长了多少？”模型回答“增长 120%”。先核对它读出的两个数字，再看是否把 120/100 当作增长率；正确计算是 (120−100)/100=20%。保留原图、问题、输出、测试配置和人工结论，将这个错误归为“比例基准错误”，而非一律归为视觉问题。

接下来补充不同基数、图表样式及下降场景的样本，并保留未见图表作为回归集；如果数字本身经常读错，再单独处理图像清晰度或视觉数据。不要把同一张图的改写题同时放进训练集和测试集，否则容易高估改进。以上是教学流程，并非已经运行过的实验。

## 比较与面试追问

**RL 和 SFT 有什么不同？** SFT 学习示范回答；RL 利用奖励调整生成策略。实际系统通常结合两者，奖励设计错误时 RL 也可能学到错误捷径。

**128k 是否意味着每个问题都要输出 128k token？** 不是。它是报告所述 RL 训练上下文的扩展规模，不等于每次输出长度，也不保证不同产品接口提供相同限制。

**最终答案正确就说明推理过程正确吗？** 不一定，可能碰巧猜对。需要检查步骤、设计更有区分度的测试，尤其要防止验证器误判。

**K2.5 的视觉能力等同于把 Kimi-VL 接上 K2 吗？** 官方描述是原生多模态持续训练，不能凭名称推断简单拼接。

**Agent Swarm 是一个模型内部长出很多独立权重吗？** 它涉及模型与外部协作系统，子任务数量与效果必须连同系统设置看。

与 [Qwen](/nlp/qwen/)和 [GLM](/nlp/glm/)比较时，先对齐任务与公开程度，再比较结构和训练路线。
