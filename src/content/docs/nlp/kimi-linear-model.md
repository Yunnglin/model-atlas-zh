## 要解决什么问题

想象一个助手要阅读几十万字的会议记录，最后回答“上次同意的交付日期是什么”。普通自回归模型在生成后续文字时，需要借助历史信息；常见全注意力实现会保存历史 token 的键和值，序列越长，缓存通常越大。对长对话或大量并发请求来说，缓存会占用可观内存。

另一种思路是在读入内容时持续更新一份固定大小的状态，后续生成时从状态中提取信息，像边读边整理笔记。笔记节省空间，却可能丢掉原文细节；如果后来有人问精确日期或一段原话，单靠压缩笔记可能不够。Kimi Linear 采用混合方式：大多数层使用 Kimi Delta Attention（KDA）更新有限状态，周期性保留使用 MLA 的全注意力层。

这里的“线性”是指特定注意力计算随序列长度的伸缩方式，不是说整个模型每项成本都始终严格线性，也不是一份状态能无损记住无限长度的文档。下面会议记录和计算示例均为教学构造，不代表真实运行结果。

## 结构与数据流

[查看论文原始架构图（Figure 3）](https://arxiv.org/html/2510.26692v2#S3.F3)：图中分别展示 KDA、MLA 和专家层；论文描述按约 3:1 交替 KDA 与 MLA；具体排列可见下面的官方配置。原图保留英文，可结合下方说明阅读。论文图的使用限制请查看原文许可。

模型仍然是自回归语言模型：根据输入和已生成的 token 预测下一个 token。主要区别在于层内如何处理历史信息。论文描述约三个 KDA 层配一个 MLA 全注意力层的混合结构；图是教学简图，不按比例绘制所有实际层。各层还有前馈网络、残差等组件；论文实验模型第一层使用稠密前馈，后续层使用 MoE，不能把每层都当成专家层。[注意力机制](/foundations/attention/) 可帮助理解查询、键和值的关系。

公开的 [48B-A3B-Instruct 配置](https://huggingface.co/moonshotai/Kimi-Linear-48B-A3B-Instruct/blob/main/config.json)列出 27 层：20 层 KDA、7 层 MLA。前 24 层可以按“三层 KDA 加一层 MLA”分成六组；最后三层是两层 KDA 加一层 MLA。每层都配有自己的前馈模块：第一层是稠密前馈，其余层使用 MoE。这样看图时，就不会把 MoE 误当成整个网络最后才执行的一次操作。

### KDA：边读边更新状态

KDA 使用递归状态来概括过去的信息。处理新 token 时，它先根据门控衰减已有状态，再结合新信息及预测误差进行更新；后续查询从更新后的状态中读取。可以想象一张不断修订的工作笔记：新消息确认了旧结论，就更新对应内容；旧信息不再重要时，可以降低它的影响。

KDA 在 Gated DeltaNet 的基础上采用更细的通道级遗忘门：不同特征通道可以有不同的保留程度，而不是对整个注意力头只有同一个遗忘速度。这是对状态更新机制的描述，不代表模型真的按人类理解的“日期”“姓名”建立了独立抽屉。有限状态容量仍会限制对复杂、冲突或大量细节的表达；遗漏早期合同条款时，不能仅凭现象断定具体哪一个通道出了错。

Delta 更新可以用一个教学例子理解：旧笔记预测交付日期是 6 月 1 日，新信息写 6 月 15 日，更新应考虑新旧差异而不是无限叠加两个日期。真实模型中的键、值、门控和状态是向量与矩阵，网络没有直接执行人类写出的日期替换规则。它是否保留正确版本，仍需通过任务评测。

### 没有给 MLA 加 RoPE，位置就丢了吗？

报告指出，Kimi Linear 的全注意力 MLA 层使用 NoPE：这些层不额外加入显式位置编码。它并不是说整个模型完全不知道顺序。KDA 的状态更新有方向和衰减，其位置相关机制会影响交给后续层的表示；例如“先审批、再付款”与“先付款、再审批”虽然包含相同的词，按顺序处理后可能形成不同状态。

这只是理解顺序信息如何进入混合网络的例子，不意味着模型一定能正确辨认两份流程。报告作者把 KDA 视为主要的位置感知算子，并在消融实验中比较了 MLA 层使用 NoPE 与 RoPE；短文本与长文本结果有差异。具体原因属于论文给出的解释，不能由此推断任何采用 NoPE 的模型都更擅长长文本。

### 为什么还要保留全注意力

论文指出纯线性结构受有限状态容量限制，因此周期性加入全注意力层，让模型在部分层保留直接访问历史位置的能力。MLA 通过压缩键值表示减少缓存开销，但它仍是这些全注意力层的一部分；随着上下文变长，保留的历史缓存仍会增长。[KV 缓存](/foundations/kv-cache/) 可帮助理解生成阶段的存储。

把“固定大小”换成一个数字：论文给出的 KDA 状态按每个注意力头计，是 $d_k\times d_v$ 的矩阵，实验中两维都为 128。假设用 FP32 存放，一个头的这部分状态为 `128 × 128 × 4` 字节，即 64 KiB；把上下文从 8K 增加到 128K 时，这个矩阵的形状不变。它只是单头状态的教学估算，具体实现还可能需要卷积状态、临时空间和不同精度；整个模型还要累加各层各头，并计算 MLA 缓存。论文的状态大小和效率讨论见[第 6.3 节](https://arxiv.org/html/2510.26692v2#S6.SS3)。

因此，单个 KDA 层的状态大小不随历史长度增长，并不等于整个混合模型的内存恒定。权重、MLA 缓存、批量、临时激活、推理框架和上下文长度都影响总显存。MoE 则决定前馈网络里哪些专家参与计算，和 KDA 管理历史信息是不同维度；[MoE](/foundations/moe/) 有对应解释。

### 训练并行与生成速度

递归更新看起来必须从头到尾逐个处理，硬件却擅长并行。论文设计分块算法，利用特定的对角加低秩结构组织计算，在保持相应递归关系的同时提高硬件利用率。这里的分块是计算实现，不是把文档分块后各自总结再拼接；具体吞吐取决于内核、设备和输入形状。

模型生成常分为预填充和逐 token 解码：前者处理已有提示，后者逐步生成回答。两阶段瓶颈不同，不能只报一个“速度”。论文图 7 的解码对照使用批量为 1：报告在 1M 上下文下，相比全 MLA 基线约有 2.3 倍的解码加速。论文讨论部分还给出利用缓存节省支持更大批量时，最高约 6.3 倍吞吐的理论估计；摘要概括为最高 6 倍。它们描述的比较条件不同，阅读时应区分单批次解码速度与吞吐估计。论文也报告该混合结构可减少最多约 75% 的 KV 缓存。

## 数据与训练

论文采用受控的架构比较：在相同规模和训练配方下，以约 1.4T token 训练 Kimi Linear、全注意力 MLA 和混合 Gated DeltaNet 等基线，比较短上下文、长上下文及强化学习相关任务。这个对照有助于观察架构差异，但仍局限于论文的训练预算、实现与评测设置。

论文还报告公开模型使用约 5.7T token 的扩展训练，随后给出 Base 和 Instruct 的成绩。5.7T 是训练使用的 token 数，不是独立文档或用户数量；重复采样也可能计入。公开报告不足以列出所有数据来源、精确配比和每条样本，不能据此推测某本书或某个仓库一定参与训练。长文本训练也需要检查重复、来源分布和测试集泄漏。

监督微调让模型更好地遵循指令，强化学习实验则考察模型在数学推理等任务中的训练扩展表现。注意 KDA 是网络里的注意力模块，不是 SFT 或 RL 算法；训练方法相同不代表不同架构在所有任务都同样有效。合成推理数据和奖励信号可能出错，仍需对独立题目核验。

报告中的 SFT 采用多阶段训练：先用覆盖广泛任务的指令数据培养通用回答能力，再安排数学、代码等推理任务加强训练。可以把它理解为先练习各种题型，再针对需要多步推理的题做专项练习。论文比较 RL 时，给 Kimi Linear 和 MLA 基线使用相同的数学训练集、算法和超参数，再观察训练过程和独立测试集；这种设计有助于比较两种架构，但不能保证换一套数据和奖励后仍得到同样差距。

报告还提到生成训练样本的推理引擎与训练引擎之间可能存在精度差异，导致两边计算的策略概率不一致；因此实验引入截断重要性采样，并动态调整 KL 惩罚与小批量更新设置。直观地说，如果“出题并生成回答的系统”和“根据回答更新模型的系统”对同一回答的概率判断不完全一样，就需要控制由这种差异带来的训练偏移。这里说的是报告中的实验方法，具体效果取决于实现和训练条件。

## 评测怎么看

论文 1.4T 对照表中，Kimi Linear Base 的 MMLU 为 73.8，对应 MLA 基线为 71.6；但 EvalPlus 上 Kimi Linear 为 60.2，另一混合基线为 63.1。这说明受控对比有助于观察趋势，也说明不能简化成“线性注意力在每道题上都更好”。分数受模型规模、采样、提示和评测版本影响。

### 同样训练预算，长文本成绩如何读？

[论文表 5](https://arxiv.org/html/2510.26692v2)把几个经过相同 1.4T token 训练的架构放在 128K 长上下文设置下比较。可以先看两列：

| 测试任务     | 全 MLA 基线 | Kimi Linear |
| ------------ | ----------: | ----------: |
| RULER        |        81.3 |        84.3 |
| LongBench V2 |        36.1 |        35.0 |
| RepoQA       |        63.0 |        68.5 |

这几项任务侧重点不同：RULER 涵盖合成的长上下文检索等任务，RepoQA 关注代码仓库中的定位，LongBench V2 覆盖复杂长文本理解。在这组实验里，Kimi Linear 在 RULER 与 RepoQA 上分数更高，LongBench V2 则略低；应结合任务读分数，不要把一次基准的表现写成“所有长文任务都更好”。这些比较使用的是论文所列实验模型和评测设置，不是对不同厂商线上服务的实测。

论文附录还报告 5.7T 的 Instruct 在 RULER 1M 设置下得到 94.8；RULER 测试的是一组长上下文任务，不能把它解释为所有百万 token 文档都能 94.8% 准确理解。它也不等于公开模型与不同厂商模型在相同训练成本下进行了公平比较；附录里的 Moonlight 基线总参数和上下文能力都不同。

构造一个长会议记录测试：文首写“交付日期 6 月 1 日”，中间出现多条旧消息，文末更新为“6 月 15 日”。评测应检查是否找到最新版本、是否引用正确来源、能否处理日期冲突，还要把更新放在开头、中间和末尾。假设 20 条测试中 15 条答案和引用均正确，通过率为 75%；这是计分示例，不是模型实测。

性能对比需要固定同一设备、精度、框架版本、批量、输入输出长度和并发，分别报告首字时间、解码 token 吞吐、总显存以及结果质量。在 1K 输入、128K 输入和接近 1M 输入下重复测量，才能看到收益怎样随长度变化；若只比较不同批量的每秒 token，不能直接推断单用户等待时间。

## 应用与错例闭环

如果助手回答旧日期，先保存原始文档、完整提示、模型版本、输入长度、系统日志和答案。检查是否由于检索没有送入最新段落、文档顺序颠倒、输入被截断，还是模型看到了更新却使用了旧信息；如使用外部检索，检索错误并不自动是 KDA 的错误。

收集脱敏的日期变更、相似项目名称、冲突消息和信息缺失样本，按项目或文档来源划分开发集与独立测试集。可以先改善检索、时间标记与引用要求，再根据结果考虑微调。调整后同时检查准确率、引用、拒答、延迟和内存；这是可复现的实验方案，尚未实际运行模型训练或评测。

## 比较与面试追问

**KDA 的固定状态是否等于模型完全没有 KV 缓存？** 不是。混合架构的 MLA 全注意力层仍保留随历史增长的缓存。

**3:1 是专家数量吗？** 不是。它描述论文中 KDA 与全注意力层的混合比例；MoE 是前馈网络的另一种设计。

**最高 6 倍代表单请求延迟缩短六倍吗？** 论文将约 6.3 倍描述为考虑缓存节省后可支持更大批量的理论吞吐估计；图 7 批量为 1 的 1M 解码对照约为 2.3 倍。

**1M 上下文能保证记住每条事实吗？** 不能。容量不等于可靠检索，需用位置、冲突及来源变化的独立样本验证。

**KDA 是强化学习算法吗？** 不是。KDA 处理历史信息；SFT、RL 是用于训练模型的不同方法。
