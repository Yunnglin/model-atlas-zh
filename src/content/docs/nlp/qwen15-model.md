## 要解决什么问题

想做一个旅游咨询助手：用户先用中文询问签证材料，又用英文补充出发日期，最后要求输出清单。系统不仅需要看懂两种语言，还要记住前面的条件，按要求给出可阅读的结果。若材料不完整，助手应该指出缺少的信息，而不是补造某个国家的实时政策。

Qwen1.5 在 2024 年 2 月作为 Qwen 系列的后续版本发布。官方提供不同规模的 Base 和 Chat 权重，后续也发布了专家模型。它是文本模型：模型能理解文字中的图片描述，不等于能直接看到用户上传的图片。开放权重不代表所有训练数据与完整训练流程都可下载，具体许可按各型号模型卡核对。例如 [Qwen1.5-7B Base 模型卡](https://huggingface.co/Qwen/Qwen1.5-7B)标示 Tongyi Qianwen 许可，不能据此推断同系列所有型号均采用相同许可。[第一代 Qwen](/nlp/qwen1-model/)、[Qwen2](/nlp/qwen2-model/)和 [Qwen2.5](/nlp/qwen25-model/)可用于串起代际变化。

下文的旅游场景、任务样本和评测数字都是教学构造，未实际运行模型，也未验证签证政策。

## 结构与数据流

图为依照官方公开说明绘制的文本生成教学简图，展示输入文字、因果注意力、前馈网络和下一个 token；省略位置编码、归一化、残差及具体模型层数。不同规模以及后续 MoE 型号的实现细节不能混成一个固定配置。

### 一段对话怎样进入模型

使用 Chat 版本时，对话模板先把用户和助手的消息标明角色，再由 tokenizer 切成 token，并映射成向量。Base 模型也能续写文本，但不能把 Chat 的对话格式和指令遵循能力直接视为 Base 的固有行为。经过多层因果 Transformer，模型在已有上下文条件下给出下一个 token 的分布，逐个生成回复。例如用户说“我明天出发”，模型可能先生成“请确认”，然后继续写需要确认的材料；这个过程不等于模型已经连接航空公司或核对政策。

因果注意力允许当前位置查阅前面的中文问题、英文补充和已有回答，但不能使用未来尚未生成的结果。前馈网络进一步加工位置上的表示。把注意力比作查找笔记有助于理解它如何联系信息，但注意力分数不等于自动生成的引用证据，也不能证明答案确实来自可靠网页。[Transformer](/foundations/transformer/)和[下一 token 预测](/foundations/next-token/)分别解释通用结构与训练目标。

### 相同系列不代表所有规格都相同

官方博客列出从小模型到较大模型的多种规格，后续还有 MoE。Base 与 Chat 的区别是训练与使用方式；参数规模则影响资源和可能达到的能力。量化格式是权重的另一种存储或计算表示，并不是新增的一代模型。学习一个具体模型时先记完整名称、尺寸、是否经过对话训练和权重精度，避免把不同选项揉成一个“Qwen1.5”。

例如，两台机器分别运行较小和较大的 Chat 模型：较大模型可能更占显存，也可能在一些任务表现更好，但业务收益需要在同一批题、相同工具和预算下测。把一份不同提示的榜单直接贴在一起，既不能隔离规模影响，也不能说明实际响应时延。量化后的资源是否降低、输出是否退化，同样要针对目标硬件与任务测量。

### 一个 110B 部署观察

[程序锅锅的部署记录](https://www.53ai.com/news/OpenSourceLLM/2268.html)使用 Qwen1.5-110B-Chat，比较未量化、LLM.int8 和 NF4 双重量化，分别报告约 215 GB、113 GB 和 62 GB 显存。可以把这些数字当作同一次部署中不同表示方式的观察：它们不能直接套用到另一台机器，也不是所有输入长度和并发下的最低显存。文章公开了加载代码，但未完整说明测量时的输入长度、并发和运行环境；做自己的比较时，要另外记录权重版本、硬件、量化库、上下文长度和峰值显存。

### GQA 和专家计算要按型号区分

后续 Qwen2 报告明确区分不同代际的分组查询注意力配置。官方 Qwen2 发布说明回顾：Qwen1.5 稠密系列只有 32B 和 110B 使用 GQA；Qwen2 发布的五个型号都采用 GQA。这里讨论的是该说明对稠密型号的对照，不把后续 MoE 规格混进同一个断言；具体型号仍要查配置。GQA 主要改变查询头如何共享键值表示，与上下文缓存有关；它不是多语言翻译开关。[KV Cache](/foundations/kv-cache/)解释权重与缓存为何需要分别估算。

例如 [Qwen1.5-7B 的官方配置](https://huggingface.co/Qwen/Qwen1.5-7B/blob/main/config.json)列出 32 层、32 个查询头和 32 个键值头，隐藏维度为 4096，每个头是 128 维。这一规格的查询头和键值头是一一对应的；32B 和 110B 的 GQA 配置则采用共享键值头。虽然该配置的实现名称写成 `qwen2`，模型本身仍是 Qwen1.5-7B。

用 7B 配置估算缓存：一条 8,192 token 的序列，假设每层的 K、V 均采用 BF16 的 2 字节存储，大小约为 `2 × 32 层 × 8,192 × 32 头 × 128 维 × 2 字节`，即 **4 GiB**。这是常规 KV 缓存的计算示例；模型权重和其他运行空间还要另算。它说明为什么相同的上下文长度下，键值头数量会影响内存占用。

MoE 把部分前馈计算分配给专家，和 GQA 处理的是不同部件。总参数表示模型持有的参数规模，激活参数表示一次计算实际涉及的部分；部署仍需考虑所有需要存储或调入的权重与通信。初版稠密模型的结构不能因为后续发布了同系列 MoE，就都写成专家模型。

### 以 Qwen1.5-MoE-A2.7B 为例

2024 年 3 月发布的 MoE 版本可以想成一间有共享岗位和专门岗位的工作室。官方介绍中，一个 MoE 层包含 64 个细粒度专家：4 个共享专家始终参与，另外 60 个路由专家中，每个 token 由路由机制选择 4 个参与。不同 token 可以走不同路线，但不应把某个专家想成固定负责英语或签证的人工部门：路由由模型学习，专家的功能不一定能用简单标签解释。

名称中的 A2.7B 指约 27 亿激活参数，并不表示完整检查点只有 27 亿参数。官方把 Qwen-1.8B 的已有稠密模型改造成 MoE 的初始化方法称为 upcycling，再继续训练；这和完全从零训练一个专家模型不同。官方对比 7B 模型时报告了较低训练成本，但这一数字依赖训练起点与实验设置，不能理解为任何 MoE 模型训练都能省下同样比例的成本。

推理速度也要带上条件：官方用单张 A100 80GB、vLLM，以及输入和输出各 1000 token 的设置，报告 MoE Chat 版本请求吞吐量约为 7B Chat 的 1.74 倍。它是特定测试的吞吐对比，不保证单条请求延迟或其他硬件也提升同样幅度。选型时仍要测目标负载下的显存、吞吐、延迟和任务质量。

## 数据与训练

### 基础训练解决什么

基础模型通过下一 token 预测学习语言、知识和代码模式。公开报告与博客介绍了能力方向，但并没有让外部读者看到每条训练样本、全部筛选规则和完整算力环境。不能凭一项榜单或某个模型大小反推出所有数据来源，也不能把后续 Qwen2、Qwen2.5 的数据配方倒填到 Qwen1.5。

在旅游咨询例子中，通用文本可能帮助模型理解“行程”“入境”和日期表述，但政策会变化。将最新资料通过检索提供给模型，和用历史语料训练基础模型是不同步骤；回答时还要保留来源、地区和生效日期。若系统没有提供相关国家与出发日期，模型无法可靠确定适用条件。

### 对话训练解决什么

Chat 模型进一步学习按角色和指令组织回答。一个教学样本将问题、已知行程和资料作为输入，示范输出分成“已确认”“还需确认”和“资料来源”。监督微调通过这样的示范帮助模型学习回答形式；偏好反馈可以比较准确但格式一般的答案，与格式漂亮却编造材料的答案，不能只奖励后者的外观。[SFT](/training/sft/)和[RLHF](/training/rlhf/)分别说明示范与偏好信号。

Qwen 团队的发布说明介绍了用 DPO 和 PPO 对齐对话模型。DPO 用偏好样本调整模型输出，PPO 则可以利用奖励信号进行策略优化；二者都是后训练方法，详细过程可分别看 [DPO](/training/dpo/)与 [PPO](/training/ppo/)。官方没有在这份发布说明中逐一公开每个尺寸的完整训练配方。

业务适配材料应包含信息不足、用户纠正前文、中文英文切换和政策资料过期等情况。若所有示范都把日期写在同一行，模型可能学会模板位置而不是关系。应将近重复行程按来源或对话分组，避免训练和测试只是改了人名与目的地。

### 长窗口也要配合数据和运行环境

官方博客介绍系列支持最多 32768 token 上下文。这个数字表示具体型号和配置提供的输入能力，不代表每条用户请求都能保留所有历史，也不保证模型一定找到深处的证据。消息过多时，系统可能因预算截断；检索结果如果未进入上下文，模型就不能从它获取事实。

可以准备一份包含多个旅客的长行程，在前半部分给出某人的护照类型，在后半部分更新出发日期。改变证据距离和干扰旅客数量，分别检查能否找到事实、是否把两个人的信息混在一起，以及能否依据给定资料作答。记录实际输入长度和截断情况，才能区分系统预处理与模型使用上下文的能力。

## 评测怎么看

先将业务任务拆成几项：是否识别目的地和日期、是否保留用户更正、回答语言是否符合要求、是否引用了提供的资料、缺信息时是否主动询问。假设 20 条教学样本中，18 条清单格式正确，15 条事实完整，只有 13 条同时满足所有规则，则三项比例分别是 90%、75% 和 65%。这些数字用于理解评分，不是对 Qwen1.5 的模型实测。

官方发布说明中的 MT-Bench 由模型裁判评分：Qwen1.5-7B-Chat 使用不同随机种子运行三次，分别为 7.58、7.55、7.66，平均 **7.60**，报告的标准差为 0.05。它说明同一设置也会有分数波动；该结果反映多轮对话评审，不能直接替代签证材料是否准确的业务检查。

比较不同尺寸或量化版本时，固定文本、模型版本、模板、输出长度、温度和硬件。模型生成更快但省略证据，不应只看响应时间；全部回答都转人工可能降低错误，却也改变了自动化覆盖率。应同时报告任务成功、格式、延迟、资源占用与需要人工处理的比例。

多语言任务不能用“答得流利”代替事实准确。可以在同一行程中分别用中文和英文提问，核对日期、国家、人名是否一致，再加入代码或特殊字符等容易被清洗破坏的输入。如果语言版本的题目并不等价，应先修订测试，避免将翻译差异误计为模型差异。

## 应用与错例

一个实际应用可先查目的地和日期，再读取可靠资料，要求模型在答案中区分“来自资料的内容”和“需要用户补充的信息”。业务规则、网页获取、模型生成与人工确认应分别记录。政策和法律类信息可能变化；系统需要用户自行核实或由专业人员复核，而不能把训练语料中的旧答案当作当日规则。

若助手在后续回合忘记用户修改的日期，先检查模板是否保留新消息、上下文是否截断、检索是否返回了旧资料；如果这些输入都正确，再针对状态更新和多语言指代建立对照样本。改动进入开发或训练池后，保留未见过的新行程做回归，不用同一批题反复调提示后宣称泛化提高。

## 比较与面试追问

**Qwen1.5 Chat 和 Base 是两个版本吗？** 它们对应不同训练状态和权重，用途与模板不同；不能仅靠修改系统提示将 Base 变成同一个 Chat 检查点。

**32K 上下文等于模型总能读懂 32K 中的每句话吗？** 不等于。实际结果与截断、位置、证据距离、干扰和具体任务有关，必须按条件测试。

**模型名字相同，GQA 与 MoE 配置一定一样吗？** 不一定。要查完整的尺寸和检查点；注意力共享和前馈专家是两个不同问题。

**如何比较 Qwen1.5 和 Qwen2？** 尽量选可比规模和任务条件，分别记录数据、结构、对话模板和推理配置；不可将所有收益归因于参数量或某个结构部件。
