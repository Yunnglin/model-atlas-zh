## 要解决什么问题

假设一个助手收到一份长设备手册和一张仪表照片，用户问：“照片中的读数是否超过手册规定的范围？”系统既要识别图片中的数字，也要在长文档中找到对应型号与阈值，最后解释依据。输入可能很长，而最终回答只有几句话；此时读取输入、保存上下文和生成答案的开销并不相同。

DeepSeek-V4.1-Flash 是 2026 年 9 月发布的图文输入模型，生成文字。官方模型卡列出 552B **主干参数**、约 1M token 上下文，并列出额外的 196B Engram 条件记忆参数；两者访问方式不同，部署时都应核算。本文讨论该版本，不把 [V4-Flash](/nlp/deepseek-v4-flash-model/) 的结构直接套用过来。仪表场景和算例是教学构造。

## 结构与数据流

图像先由视觉编码器处理，经过投影变成视觉表示，与文字表示一起进入语言主干。主干由 20 层**因果编码器**和 20 层解码器组成，输出仍逐 token 自回归生成。教学图省略局部注意力、跨层共享细节、残差和条件记忆内部结构；[官方模型卡](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)提供模型配置。

### 因果编码器不是 BERT

常见的编码器—解码器模型可能用双向编码器读取完整输入；这里的编码器是**因果的**：每个位置只能使用当前位置及之前的信息。它更像把同一条自回归处理路径分成前后两段，而不是把 BERT 接到一个普通聊天模型前面。模型卡称这种设计为 Causal Encoder-Decoder（CED）。

编码器最后的隐藏状态可用于构造解码器的全局键值缓存。处理长输入时，主干可以利用这种组织方式减少完整执行后半部分的计算；生成新 token 时仍需要解码器参与。官方模型卡按阶段给出约 8B 输入激活参数和 16B 输出激活参数，这两个数字不是模型权重总量，也不能据此断定任何设备上延迟都减半。

例如手册有很长的历史记录、助手只输出一行结论时，输入侧计算占比较高；如果任务需要生成大量代码，输出侧的成本就更值得关注。比较模型时应分别测首 token 延迟、输出速度、缓存命中和总耗时，而不是只看一个“每秒 token”。

### 全局缓存如何复用

CSA2 把注意力层划分为 Full、Reindex 和 Reuse 三种模式。直观理解：有的层生成全局键值并选择候选；有的层复用键值但重新选择；还有的层复用已有的键值和选择结果。各层仍有自己的计算与局部窗口，不是把整个 40 层模型折叠成一层。分层索引可以先建立较大的候选池，后续层在其中重新筛选，降低反复扫描长上下文的开销。

把这三种模式想成查阅一座资料库：Full 层先准备压缩后的资料并挑出相关位置；Reindex 层沿用已准备的资料，但根据自己要回答的问题重新挑位置；Reuse 层连上一次挑好的位置也一起沿用。这样后面的层仍能处理不同的隐藏状态，但不必层层重新制作和搜索同一批长资料。解码器中的分层索引还把后续筛选限制在首个 Full 层提供的候选池内；这降低的是后续索引的工作量，并不意味着模型只看最初挑出的一个词。

局部窗口是另一份“最近记录”：恢复会话时，SWA Bounded Replay 重新处理最近窗口内的 token 来重建缺失状态，而不是把整段百万 token 的输入都重算。这个办法用少量重算换取较少的持久化存储；官方对比的是持久化 KV 大小，和下文的全局 KV 口径不同。

模型卡称全局 KV 缓存约 890 字节／token，约为 V4-Flash 的四分之一；另有针对滑动窗口状态的有限回放，用少量重算恢复状态以减少持久化缓存。**全局缓存、持久化缓存和全部显存不是同一指标**：模型权重、视觉输入、局部状态、临时张量和系统开销仍要计算。回放是具体实现方案，实际收益依赖会话与缓存命中情况。

把缓存指标换成具体数字：如果按 1,000,000 个 token 和每 token 890 字节估算，全局缓存约占 **890 MB**，也就是约 **849 MiB**。这是模型卡所述的全局 KV 口径；运行时还要为局部状态、模型权重、图片处理和其他临时数据留出空间。比如同时服务多条不同的长会话，还要考虑它们各自的缓存，以及系统是否能复用共同前缀。

### 图像是怎么进入模型的

官方说明使用从头训练的 DeepSeek-ViT 视觉编码器，对图像提取表示，再经过 3×3 pixel-unshuffle 和两层 MLP 投影，与文字表示一起处理。可以把视觉编码器理解成把图片整理成模型能接收的特征，投影器负责对齐表示尺寸；它不是直接把图片转成一段完全准确的文字。

如果仪表刻度很小、反光严重，模型可能读错数字；如果手册里有多个型号，也可能把正确读数与错误阈值配对。图片分辨率、裁剪、文本提取与任务指令都可能影响结果，必须分别检查。原生图像理解不意味着模型能直接生成图片或音频。

### 专家与条件记忆

模型卡描述每个 MoE 层有一个共享专家和 384 个路由专家，每个 token 激活六个路由专家；[MoE](/foundations/moe/)解释了总参数、激活参数和专家路由。Engram 是另一种稀疏访问的条件记忆，与 MoE 专家不是同一个概念。报告还介绍推测解码方案：先提出草稿，再由主模型验证；候选接受率和实现决定最终收益，不能把草稿数量直接当作速度倍数。

## 数据与训练

### 预训练：图文一起进入主干

模型卡称该模型从头在约 45T token 的多模态语料上训练，稀疏注意力在 64K 序列长度下训练，并在训练进程中扩展到 1M。T 表示万亿 token，不等于网页或图片的数量；具体来源和各类数据比例仍应以官方公开材料为准。视觉编码器和投影器的训练也不是“把图片直接塞进文本分词器”。

官方卡指出模型在累计训练到 34T token 时把上下文扩展到 1M；34T 是训练进度，不是单次输入的长度。1M 上下文和 45T 总训练量也分别属于输入窗口与累计语料两个维度，不能直接相除得到训练步骤或实际显存。

在仪表例子中，教学数据可以包含图片、对应型号手册片段和正确结论，但这不是官方训练样本。数据准备时需要覆盖反光、模糊、不同刻度与缺少阈值的情况；否则模型可能记住某一种仪表的外观，却无法处理真实设备差异。

### 后训练：任务、环境和验证

模型卡描述 SFT、强化学习和在线策略蒸馏（OPD）流程，并强调大规模合成智能体任务与环境。一个可验证任务除了问题，还需要明确工具环境和判分方式：例如先读取图片，再查找型号对应阈值，最后给出带出处的结论。环境报错、工具结果缺失和验证器误判都应作为失败类别，而不是自动归咎于语言模型。

OPD 可以理解为学生在自己产生的上下文上接受教师信号；[蒸馏](/training/distillation/)介绍更一般的知识迁移。模型卡列出可控制的推理强度范围，较高强度通常意味着更大的计算预算，但实际输出长度与质量仍依赖任务和运行配置，不能保证每次都更好。

## 评测怎么看

模型卡的基础模型表中，V4.1-Flash-Base 的 MMLU-Pro 5-shot 为 74.1，V4-Flash-Base 为 68.3；这两者结构、数据和规模不同，不能把差距全部归因于 CED。图文任务表中还有 DocVQA 等结果，但官方实验中的图片处理、提示、模型版本和判分方法都影响分数；不要把它当成工厂仪表任务的实际准确率。

模型卡在指令模型表格中还报告 Terminal-Bench 2.1 的 pass@1：V4.1-Flash 为 90.6，V4-Flash 为 82.7。这里使用模型卡所述的智能体框架和 1M 上下文，V4.1 设置 `reasoning_effort=100`、温度 1.0、top-p 0.95。这个分数衡量模型与工具系统共同完成基准任务的表现；换成自己的仓库或不同调用预算，需要重新测量。

对实际问题可分别记录读数识别、型号匹配、阈值查找、结论正确性、引用是否支持答案，以及无法判断时是否承认不确定。假设 20 条构造样本中，16 条识别读数正确，13 条同时找对型号和阈值，分别为 80% 和 65%；这些是计分例子，不是实测。再按图片清晰度、刻度大小、语言和手册长度分组，检查错误集中在哪里。

做成本比较时固定模型检查点、提示模板、图片分辨率、上下文长度、硬件、精度、框架和并发。分别统计 prefill、decode、缓存与工具时间；输入长而输出短的场景，可能与输出很长的场景得出不同结论。官方 API 的模型别名也可能随服务更新指向新检查点，复现实验应记录实际版本。

## 应用与错例

假设模型把 0.8 MPa 读成 8 MPa，或把另一型号的阈值套到当前设备。先保存图片、实际送入模型的尺寸、手册片段、型号、提示和输出；检查裁剪后刻度是否清晰、检索是否返回正确型号，以及答案是否引用真实段落。若证据未进入输入，先修检索或预处理；若证据存在却读错，再针对图片识别与推理分别分析。

下一轮收集反光、相似型号、单位不同和手册缺页的样本；按设备或文档来源划分开发与独立测试集。调整裁剪、检索或训练后，比较读数、结论和引用，并回归原有文字任务。这个数据到评测的流程是实验设计，尚未实际运行训练或评测。

## 比较与面试追问

**CED 的编码器能看到未来 token 吗？** 不能按双向编码器理解；官方称其为因果编码器，遵循因果约束。

**552B、196B、8B／16B 分别是什么？** 前者是模型卡列出的主干参数，196B 是额外 Engram 条件记忆规模，8B／16B 是输入和输出阶段的激活口径，不能互相替代。

**缓存缩到四分之一，显存就一定减少四分之三吗？** 不是。该比例针对报告中的全局 KV 缓存，完整显存还包括权重、局部状态及运行时开销。

**它支持图像输入，就能生成图像吗？** 模型卡描述的是图片和文字输入、文字自回归输出；应按具体模型卡核对能力。
