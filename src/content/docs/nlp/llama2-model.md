## 先看问题：会续写，为什么不一定会聊天？

假设你对模型说：“帮我把会议记录整理成三条行动项。”基础语言模型读过大量网页和文本，善于根据上下文猜接下来的字；但它可能接着模仿另一份会议记录，而不是按用户要求整理。它从预训练中学到的是语言与世界知识的统计规律，并没有自动学会每一种用户期望的交互方式。

Llama 2 的基础版与 Chat 版展示了从“续写”到“按指令回答”的区别。前者通过大量文本预训练获得通用能力；后者进一步用示范答案和人类偏好训练，倾向于提供有帮助、符合安全要求的回复。两者共享家族基础，但不能把某个基础模型的考试分数直接标成 Chat 模型的对话成绩。

论文由 Meta 在 2023 年发表。它重要的一点是发布可获取权重的语言模型及比较详细的训练和安全研究，推动了研究、微调和本地应用。公开权重不等于公开完整训练语料，也不等于许可没有使用限制。

## 结构：从一串词到下一段文字

将“帮我总结这段会议记录”输入模型时，分词器先把文本切成 token。一个 token 可能是词、词的一部分或其他符号，不能简单认为一个 token 等于一个汉字或英文单词。模型把它们转成向量，经过多层 Transformer，再预测下一个 token 的概率；选出一个之后，将它追加到已有上下文，继续预测，直到结束。

这像写作时一次只落下一个词，但不是从头重新看一遍整本书：推理系统通常缓存已计算的注意力键和值，后续生成可以复用。缓存会随并发、上下文长度和模型结构增长，所以能装下模型权重不一定代表能支持大量长对话。权重大小、缓存、运行框架和显存使用要分开计算。

### 因果注意力与位置

Llama 2 是 Decoder-only 架构。预训练中，位置只能利用当前及之前的 token，不能偷看后面的正确答案；这叫因果遮罩。预测“今天下雨，所以带一把……”时，模型利用前文预测后续词，而不会看到训练文本里实际出现的“伞”再假装猜对。

网络中的注意力帮助每个位置结合之前的内容，前馈层进一步变换表示，残差连接帮助信息在层间传递。论文沿用初代的预归一化、RMSNorm、SwiGLU 和旋转位置编码 RoPE 等设计。RoPE 帮助模型表示位置信息，但不能单靠它保证模型在训练窗口以外同样可靠。原版 Llama 2 的 4096 token 上限是输入、系统提示、历史对话与输出共享的预算，不是“每次可以额外输出 4096 token”。

### GQA：让大模型少存一些历史信息

注意力可以想成多个读者分别带着不同问题翻阅前文：查询是各自的问题，键帮助定位相关内容，值提供可用信息。多头注意力中，各头可以有各自的键和值；分组查询注意力 GQA 让一组查询头共享键和值，从而减少需要缓存的键值数据。它不会把所有查询变成同一个，也不是把历史文本删掉。

官方模型卡中公开的 70B 版本使用 GQA，7B 和 13B 没有；论文还报告实验中的 34B 使用 GQA。GQA 的收益主要体现在缓存和推理扩展性，实际速度还与设备、并发、上下文长度及实现有关。不能说“所有 Llama 2 都采用 GQA”，也不能把某设备的测速直接作为通用结论。

## 预训练：两万亿 token 教会模型什么

预训练通常把大段文本作为连续序列，每一步根据前面内容预测下一个 token，并用正确答案计算损失、更新参数。例如输入“北京是中国的”，目标可能是下一 token“首都”的一部分。模型重复这个练习，逐渐学会语言模式、知识关联与部分推理规律；它并非在维护一个保证实时准确的百科数据库。

官方称 Llama 2 用公开可得的在线数据混合进行预训练，各规格训练 token 数为 2 万亿。论文说明比 Llama 1 增加约 40% 的训练数据，并将窗口从 2048 扩展到 4096。公开可得不代表数据集已经完整公开，论文没有提供足以由外部重建每条训练样本的完整清单，因此无法复现完全相同的数据混合，也不应推断特定网站一定被使用或完全排除。

数据质量和去重影响模型质量与评测可信度。比如同一会议纪要复制多份会让训练重复，同一篇文章同时进入训练和测试可能抬高分数。论文分析了基准污染；这不证明所有测试都不可信，但提醒我们不能把一次公开基准分数当成对未知任务的保证。英文为主要训练语言，中文能力要根据目标任务单独测试。

## 对齐：怎样从基础版走到 Chat

第一步是 SFT，即监督微调。可以把数据想成“用户问题 + 较好的示范回答”：给定会议纪要，人工示范如何列出负责人、事项和时间。模型学习在类似指令下给出符合格式的回答。示范答案质量很关键；如果把未经核实的负责人写入标准答案，模型也可能学到这种错误。

第二步收集偏好并训练奖励模型。同一个问题下，标注人员比较两个候选回答，判断哪个更有帮助或更安全。奖励模型学习给候选打分，尽量让人更喜欢的回答分数更高。论文表 6 报告 Meta 自采的安全与有帮助性偏好比较约 141.8 万条；这是一组比较记录，不应叫作 141.8 万名标注员，也不等同于 SFT 示范数量。

论文分别训练了有帮助性和安全两个奖励模型。比如用户问正常的会议安排，有帮助性评委可以比较哪个回答更完整；遇到危险请求，安全评委关注的是回答有没有给出不安全的操作。分开训练有助于分别学习两套标注标准，但实际产品仍需要同时检查正常请求是否被过度拒绝。

第三步是迭代改进。论文讨论两种方法：拒绝采样微调和 PPO。在拒绝采样中，先对一个问题生成多个答案，用奖励模型选较优的答案，再用选出的答案继续监督训练；这是一种基于打分筛选再训练的方式，和 PPO 在线更新策略的细节不同。论文早期迭代主要用拒绝采样，之后将 PPO 与其结合；不要把所有版本描述成只做了一次 PPO。

论文还说拒绝采样由 70B Chat 进行，较小模型使用从大模型筛出的数据微调，因此可以看作利用大模型结果帮助小模型的一种蒸馏。奖励模型只是人的偏好代理：如果它偏爱看似自信的长回答，模型可能为了高分而写得更长，却不一定更准确。所以需要人评、事实检查和独立任务共同约束，而不是把奖励分数当作真实质量。

多轮对话也有难点：开始要求“始终用简洁中文”，几轮之后模型可能忘了。论文提出 Ghost Attention 数据构造方法，在多轮训练数据中合成地重复指令，以帮助模型持续遵循。它是训练方法，不是新增硬件注意力层，也不保证模型永远不会遗忘。

具体怎么做？先在一段训练对话的每条用户消息前临时加上同一条要求，让已有模型根据这个上下文生成最后一轮回答；然后构造训练样本，将中间轮次额外重复的要求去掉，只保留开头的要求。为避免先前回答与删掉重复指令后的上下文不匹配，论文在训练时不对之前轮次的 token 计算损失，只用最后生成的回答提供学习信号。可以把它理解为：先反复提醒老师生成遵守要求的示范，再让学生练习只看开头的要求也能延续同样的做法。

这个过程与每次线上调用都把要求附在每一轮消息里是两种做法。论文在其测试中观察到多轮一致性改善，但实际对话仍受上下文长度、任务类型和训练数据覆盖影响。

## 评测：分清基础能力、对话和安全

论文对基础模型报告多项学术基准，也对 Chat 模型做人工偏好与安全评估。例如论文表 3 的 Llama 2 70B 基础模型在 MMLU 上报告 68.9，表 4 标明这是 5-shot 设置，即题目前给了五个示例。这个数字是特定模型和评测流程下的历史结果，不代表它能答对现实中 68.9% 的任意问题，也不能直接当作 Chat 版成绩。

同一论文表 4 报告基础 70B 的 HumanEval 为 29.9，采用 0-shot；附录说明此处 pass@1 使用温度 0.1、top-p 0.95。代码题关注程序能否通过测试，和判断会议纪要是否忠实、回复是否安全是不同问题。对比其他模型时，题集版本、提示示例数量、解码配置及评分方式都需要一致；只看榜单上一个数字容易误判。

对聊天助手，还应检查用户是否拿到了想要的答案、回答是否基于材料、无根据的细节是否被拒绝或明确标注。安全测试也要同时检查危险请求的拒绝和正常请求是否被过度拒绝。论文采用人工与自动方式做多类评估，但它们覆盖的是特定时间、题集和标注标准，不能保证部署后所有用户、语言和提示下都安全。

## 应用与错例：会议摘要如何建立闭环

准备有授权的会议记录，按会议或项目切分开发集和独立测试集，先列出行动项的事实依据、负责人和截止时间。用 Chat 版本生成摘要，要求每项引用原文；没有明确负责人时应写“未提及”，而不是凭职位猜。记录模型权重、提示词、上下文截断方式及解码参数，以便复查。

如果某条摘要把“下周讨论是否上线”写成“下周上线”，先保存原始输入和输出，归类为不确定性被抹掉。核查是原文被截断、提示词没要求保留条件、模型自行补全，还是标注标准有误。随后可以修改提示、加入相似训练示例或增加规则检查，再在未参与调整的会议上重新测试，并同时回归负责人和时间抽取。

报告时分别计算行动项是否找全、事实是否正确、引用能否支持结论，以及每份记录的处理时间与资源消耗；真实部署还要处理权限和敏感信息。这个例子是实验设计，不是本文实际训练或测试的结果。对于不断变化的事实、中文任务和较长文档，应考虑模型的年代、语言覆盖和 4096 token 窗口限制。

## 面试追问

**SFT 和 RLHF 有什么区别？** SFT 学习示范回答；论文中的 RLHF 利用人类偏好训练奖励模型，再通过拒绝采样微调与 PPO 等方法迭代。偏好数据和示范数据不是同一份东西。

**GQA 为什么能降低缓存？** 多个查询头共享较少的键值头，推理时需要保存的键值表示减少；它不保证任何设备上的固定加速倍数。

**开放权重是否等于没有许可限制？** 不是。Llama 2 有专门社区许可及使用政策；条款对特定超大规模用户有额外授权要求，使用前应阅读原文。
