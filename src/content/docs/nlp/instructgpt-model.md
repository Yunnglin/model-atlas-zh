## 先看问题：为什么会写文章，却听不懂要求？

假设你让一个语言模型“用三句话给孩子解释登月”。它读过很多相关材料，因此可能熟悉月球、宇航员和飞船。但如果它主要学的是续写网页，它也可能继续写“用三句话解释引力”“用三句话解释太阳系”——看上去像同一张练习题的下一道题，却没有回答你。

[GPT-3](/nlp/gpt3-model/) 的预训练目标是根据前文预测下一个 token，模型从大量文本学会了语言模式和知识关联。它可以借助提示完成许多任务，但“续写合理”与“按用户要求完成任务”不是同一回事。InstructGPT 的思路是保留 GPT-3 的语言模型架构，再通过人写示范和偏好反馈，把它朝更符合指令的回答方式调整。本文的教学例子只是构造例子，并非论文实验原样，也不是实际运行结果。

它是 2022 年围绕指令遵循开展的一组研究和模型，不是一个新设计的注意力架构，也不是 ChatGPT 整个产品的同义词。模型使用同一类 GPT-3 架构，但权重会在不同微调阶段发生变化。ChatGPT 是后来面向对话的产品，不能把后来产品的界面、模型版本和全部训练方法倒填进这篇论文。

## 一张图看懂训练：三种人类反馈角色

这张图是依据论文流程制作的教学示意，不是官方逐层网络图。人类在第一阶段写出好答案，在第二阶段比较候选答案；第三阶段没有要求人对每一次采样都现场评分，而是用第二阶段训练出来的奖励模型提供代理信号。这样做节省了每一步都找人评价的成本，但也把奖励模型的错误带进了优化过程。

例如用户问：“请把会议纪要压成两条待办，缺失负责人就写待定。”基础模型可能写出一段漂亮的总结，但没有两条待办。我们真正想要的是任务格式正确、事实不编造、未明确的信息诚实留空。三阶段训练分别从示范、比较和优化三个角度处理这个问题，不能互相混为一谈。

## 第一步：SFT，让模型先看示范

监督微调（SFT）收集“提示与人写答案”的配对，用这些答案作为学习目标。比如标注员把上面的会议纪要写成“核对报价——负责人待定；安排复盘——负责人小李”。训练时模型学习在给定提示和上文条件下，提高示范答案中各 token 的概率。论文用于初始化 PPO 的 SFT 模型还混入 10% 预训练数据；这与后面 PPO-ptx 阶段混入预训练梯度是不同阶段的做法。SFT 并不是在这一阶段根据奖励模型试错，也不是通过判断最终业务成功率自动学习。

论文的 SFT 训练集约有 13,000 条提示，来自 API 与标注员编写的提示。提示的任务包括生成、问答、对话、摘要与信息抽取等。示范质量很重要：如果标注员把原文没有的负责人补出来，模型也可能学到这种看似有帮助、实际编造的行为。高质量数据需要明确标注规则、保留来源并抽样检查；数据量只是其中一个因素。

可以把 SFT 想成学习驾驶时，先看教练如何操作。看完示范后，模型已经更像一个能回应任务的助手，但它仍会遇到示范未覆盖的新情形。更多细节见 [SFT](/training/sft/)；在 InstructGPT 论文里，SFT 模型也为后续 PPO 提供起点和比较参考。

## 第二步：奖励模型，学习人类怎么比较

给同一个会议任务生成几个候选答案，让标注员按整体质量排序。例如 A 按要求列出两项并忠实保留“待定”，B 虽然格式正确却猜了负责人，C 则忽略待办只写概述。标注员可能给出 A 优于 B、B 优于 C 的排序。奖励模型接收提示和回答，学习给更受偏好的回答更高分；这些分数主要用于比较，不是具有客观单位的“正确率”。

论文约有 33,000 条用于奖励模型训练的提示，这个数是提示数，不能直接当成比较对数量。一个提示下有多个候选回答，排序可以形成多个成对比较。作者将来自同一提示的比较适当组合训练，以避免高相关样本造成效率与过拟合问题。具体的标注准则、评审人群和提示来源会影响得到的偏好，不能把一批标注员的判断自动等同于所有人的价值观。

比如同一问题有四个答案 A、B、C、D，标注员把它们排出先后后，最多可以形成 6 个不同的两两比较；如果其中某些答案被判为并列，论文的奖励模型训练会丢弃这些并列对。多个比较共享同一个问题和答案，因此不是六条互不相关的新问题。论文每个提示提供 4 到 9 个候选，训练时按提示组织同组比较，减少重复计算。这个数字是论文的设置，并非训练奖励模型的通用要求。

奖励模型像是根据老师批改记录训练的“评分助手”：它能帮助大规模给候选答案提供学习信号，但未必真的理解每一个事实。一个回答可能又长又客气，看着像好答案，实际上误写了负责人。若评分器过度偏爱表面特征，生成模型就可能学会讨好评分器而不是完成任务。这就是为什么要检查评分依据和独立测试，而不能只看奖励分数持续上升。

## 第三步：PPO，用评分信号调整生成策略

PPO 阶段先从 SFT 模型出发，对提示采样回答，再由奖励模型评估回答。模型利用奖励信号更新自己的生成策略，使较有利的行为更容易出现。论文将这一过程表述为单轮的 bandit 环境：给一个提示，生成一个回答，评分后本轮结束；这不是说真实助手已经具备长期规划和工具操作能力。

论文在不同大小的策略模型上使用同一个 6B 奖励模型，并以其初始化 6B 价值模型。奖励模型负责给回答打分，价值模型帮助估计后续奖励，二者职责不同；它们也不是用户最终调用的那个生成模型。统一这两个组件有助于论文比较不同大小的策略，但不意味着奖励模型必须比生成模型小或必须采用这个规格。

为了降低对奖励模型的过度优化，论文还针对生成的 token 加入与 SFT 参考策略之间的 KL 惩罚。直觉上，评分器给高分虽然有吸引力，但策略偏离原来会正常说话的模型太远，也可能钻评分规则的空子。这个惩罚有助于约束分布偏离，但不是绝对保证：它的效果依赖系数、数据和训练配置，不能说它让所有输出必然安全或正确。

论文还观察到，单纯 PPO 在一些公开 NLP 数据集上出现表现下降，称为一种“对齐税”。作者尝试把预训练数据上的梯度混入 PPO 更新，得到 PPO-ptx；未特别注明时，论文所称 InstructGPT 指这一版本。它缓解了论文所测多项退化，但在 DROP、SQuADv2 和翻译上仍落后于 GPT-3，不能说已经完全消除了所有能力损失。PPO 的裁剪机制、价值估计等另见 [PPO](/training/ppo/)；它与上面提到的参考模型 KL 惩罚是不同设计，不要当成同一个东西。

PPO 数据集约 31,000 条训练提示，论文说明这些提示来自 API，本身没有逐条人工答案标注。注意没有逐条标注不意味着整个过程没有人工监督：奖励模型恰恰来自前一阶段的人类偏好数据。数据超过 96% 为英文，因此看到某些非英语示例能完成任务，也不能据此推断所有语言都达到相同质量。

## 评测：人更喜欢，具体是什么意思？

论文让标注员针对 API 提示比较不同模型的回答。一个受到广泛引用的结果是：在论文测试集和标注条件下，1.3B 的 InstructGPT 输出整体上比 175B GPT-3 的输出更受偏好。这里比较的是回答偏好，不是说 1.3B 在所有知识、推理和语言任务上超过 175B。不同模型的提示方式、采样、评审规则和测试分布会影响结论。

对同为 175B 的模型，论文报告 InstructGPT 相比基础 GPT-3 的输出被偏好比例为 85% ± 3%；相比带 few-shot 提示的 GPT-3 为 71% ± 4%。论文误差线是 95% 置信区间。few-shot 提示给模型额外示例，让对照组更容易理解任务；即便如此，这个结果仍是论文中的特定样本与评审结果，不应写成“任何用户 85% 的时候都会更喜欢”。论文图一还用 175B SFT 作为共同参照，读图时要区分参照对象。

人类偏好不是唯一维度。论文还检查回答是否跟随指令、是否包含幻觉等，并用 TruthfulQA 和公开 NLP 数据集做补充。作者报告某些真实性评估有改善，但也发现模型仍会编造事实、接受错误前提，或在简单问题上过度含糊。安全相关结果同样取决于测试设置；论文在 Winogender 和 CrowS-Pairs 上没有观察到显著偏见改善，所以不能把“更受偏好”直接翻译成“已经消除偏见”。

## 从错例到下一轮：怎样用在自己的项目里？

假设团队要训练会议纪要助手，先不要急着把一个评分模型接进训练。应先整理具有使用授权的会议记录与任务，将资料按会议或来源分组，划出独立测试集，避免同一会议的改写同时落入训练和测试。评价至少分开看：待办是否遗漏、负责人是否来自原文、两条限制是否满足，以及缺少信息时是否明确写待定。

如果模型把“负责人尚未确定”改成了某个人的名字，先检查输入是否被截断，再检查示范里是否存在类似编造。如果信息完整而答案仍然编造，可以补充多种含缺失信息的示范和候选比较；改完后用未参与挑选的数据重测。也可以让人工评审看到原始材料和评分标准，记录评审之间的分歧，而不是只统计一个总分。涉及真实客户的任务还需要隐私处理与适当的人工复核。

这种闭环并不要求复制原论文的全部算力和数据：用开源模型时可以先做少量 SFT 或离线评测，确认问题所在再决定是否需要更复杂的偏好训练。不同实现的算法细节也可能不同；本文只描述论文中具体使用的方案，不声称每一个现代 RLHF 系统都必须采用同样的三步流程。

## 面试追问

**SFT 与奖励模型分别学习什么？** SFT 学习示范答案的生成；奖励模型学习对同一提示的候选回答作偏好比较。前者是生成策略的起点，后者提供偏好代理信号。

**PPO 阶段没有人工答案，为什么还是人类反馈？** 因为奖励模型通过人工排序训练。它将已有反馈推广到新采样答案，但预测可能出错，所以不能替代人工审查。

**PPO-ptx 中的 ptx 有什么用？** 在 PPO 更新中混入预训练数据的训练梯度，缓解论文观察到的部分基准表现下降；它不是重新从零预训练模型。

**1.3B 受偏好高于 175B 能证明小模型全面更强吗？** 不能。这个结论针对论文测试分布、对照方式与人工偏好；容量、知识测试和其他任务需要分别测量。
