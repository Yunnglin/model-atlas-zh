## 要解决什么问题

一位工程师要让助手阅读很长的设备维护日志，回答“更换轴承后，哪次检测首次恢复正常”。文档前面有设备型号，中间有维修记录，后面还有多次检测。助手既要比较远处的信息，又要分清相邻日期和相似设备。把整份文档塞进上下文只是第一步，怎样控制计算与缓存成本、又尽可能找到正确线索，是另一道题。

DeepSeek-V4-Flash 是 2026 年发布的开放权重文本模型。官方模型卡列出总参数 284B、每个 token 激活约 13B，支持 1M token 上下文。这里讲 Flash 初版；V4-Pro、V4.1-Flash 以及后续服务更新是不同版本，不能把它们的配置或成绩直接套用过来。日志场景与下文数字算例为教学构造。

## 结构与数据流

输入经分词后进入因果 Transformer，模型按已有上下文预测下一个 token，再逐步生成回答。[DeepSeek-V3.2](/nlp/deepseek-v32-model/)介绍了上一代的稀疏注意力；V4-Flash 进一步在**序列维度压缩历史表示**，并混合不同注意力方式。下方教学图概括层级组织，省略残差、归一化、投影和位置编码；完整架构请看[官方技术报告](https://arxiv.org/html/2606.19348)。

### 局部窗口：先保留身边的信息

Flash 有 43 层，前两层使用纯滑动窗口注意力，后续层交替使用 CSA 和 HCA；后续层还有处理局部窗口的分支。报告给出的窗口大小为 128。可以把局部窗口想成写答案时随手查看最近几行记录：它有利于处理附近上下文，但只靠一个有限窗口不能保证看到很久之前的关键记录。

“128”是模型配置中的 token 数，不是固定的 128 个汉字或 128 行文字；同一段文字切出的 token 数取决于分词方式。长文测试应记录实际 token 长度和截断位置。

### CSA：压缩后再挑选

CSA 是压缩稀疏注意力。它先把历史信息按序列位置形成更少的压缩键值条目，然后由轻量索引器筛选候选，主注意力再对候选作计算。Flash 的报告配置里，压缩步长为 4，索引选择上限为 512 个压缩条目。粗略看可以理解为“更少的条目，再挑重点”，但真实 CSA 使用可学习的加权压缩和相邻块重叠，不能简单理解成每四个词独立做一次普通平均。

用一段恰好 8,192 个 token 的历史做粗略估算：按步长 4 压缩，会形成约 2,048 个压缩位置；如果这些位置都已可供当前查询使用，索引器最多选择其中 512 个。局部窗口另提供最近的 128 个位置。实际实现还有块重叠和序列边界处理，所以这个算例用于理解数量级，而不是直接计算最终耗时。

假设维修日期恰好跨越两个压缩块，信息如何被表示可能影响后续选择。索引器选错或压缩后细节不足时，相关内容即使在输入里也可能没有被正确利用；这需要按实际任务和位置测评，而不是把压缩等同于无损摘要。

### HCA：更高压缩比例

HCA 使用更高比例的序列压缩，Flash 的报告配置为 128；它对可用的压缩条目进行注意力计算，不使用 CSA 那套索引筛选。可以把它想成保留粗粒度的长期记录，CSA 提供另一种较细的检索路径，局部窗口保留邻近内容。这个类比不意味着某一层一定“负责记日期”，或压缩记录等同于人工摘要。

长上下文的账还包括索引器计算、压缩操作、权重、缓存、设备通信与框架实现。模型支持 1M token，也不保证每个长度和任务都有同样的准确率或速度，更不保证服务端没有额外的输出长度限制。测量时必须固定模型检查点和实际配置。

### 专家网络与残差路径

Flash 的每个 Transformer 块使用 MoE；论文列出每层一个共享专家、256 个路由专家，每个 token 激活其中六个路由专家。总参数 284B 与 13B 激活参数分别影响存储和单步计算；未激活的专家并没有消失，部署还需考虑权重放置、通信和精度。[MoE](/foundations/moe/)有更详细的入门解释。

报告还说明前 3 个 MoE 层采用哈希路由。它们仍然是 MoE 层，不能据此当作稠密前馈层；专家选择方法与后训练时独立训练的任务专家模型也是不同概念。

V4 还使用流形约束超连接（mHC）组织残差流。初学时可以先把它看成多条信息传递路径上的受约束混合方式：目标是让深层训练保持稳定；这不是新增一个独立的知识检索工具，也不能仅凭名字判断实际任务一定更准确。

## 数据与训练

### 预训练与长上下文

报告称 Flash 使用约 32T token 预训练，数据包括网页、代码、数学和长文档等；这里的 T 是万亿，token 不是文档篇数。报告描述序列长度从 4K 逐步扩展到 16K、64K 和 1M，并在训练中引入稀疏注意力与索引器热身。先学习语言和不同长度的上下文，再适应长序列的计算方式，不等于模型会自动记住用户私有日志。

报告还提到把不同来源的文档打包进同一条训练序列，并在样本之间加注意力掩码。可以想象把两份互不相关的维修单装订在一本册子里：虽然它们共用一次送入模型的长度预算，第二份单子的预测不能直接偷看第一份单子的内容。这样可以减少截断，也让不同样本之间保持边界；它并不代替训练集与测试集去重。

训练配置上，Flash 的大多数参数采用 Muon 优化器，而词嵌入、预测头和 RMSNorm 权重采用 AdamW；论文中的批量调度逐渐增加到约 7550 万 token，学习率先预热，再在训练末期衰减。这些数字描述一次大规模预训练，不是普通微调应直接照搬的参数。

论文还描述针对数据质量的过滤与长文档整理。不同来源和许可证、重复文档、过时版本都可能影响训练与评测；官方未公开每一条训练样本时，不能把虚构的维修日志写成官方数据。中文、代码与专业文本的覆盖情况，也需要用各自任务样本检验。

### 后训练与推理方式

报告描述预训练后继续进行后训练，并以在线策略蒸馏（OPD）替换其所述 V3.2 流程中的混合强化学习阶段。直观上，学生从自身生成的上下文出发，借助教师信号学习；具体目标和训练数据需要按报告实现理解，不能把它简单等同于“拿一份老师答案做普通 SFT”，也不能据此推断模型完全没有使用任何形式的反馈。

具体来说，报告先针对数学、代码等领域分别训练专门的教师模型：先做领域 SFT，再用 GRPO 和相应奖励进一步优化；然后让统一学生沿自己生成的轨迹，对齐多个教师的输出概率分布。报告采用反向 KL，并描述十余个教师参与。这里的“教师专家”是独立模型，不是一个 MoE 层里的 256 个路由专家；OPD 替换的是原流程中混合 RL 阶段，并不表示训练过程中完全没有 RL。

产品支持思考和非思考等使用方式时，要区分模型能力、服务参数和实际计算预算。对维修问题，可以要求助手先核对设备与日期再给结论；如涉及外部查询，模型生成工具请求后仍需要应用实际执行，不能把文字里的“已检查”当作工具运行记录。

报告的后训练还使用量化感知训练：对 MoE 路由专家权重和 CSA 索引器的查询、键路径采用 MXFP4，并让训练适应精度损失。可以把它想成在练习时就用较少刻度的尺子，提前适应测量误差；这不意味着模型所有权重和运算都变成 4 位。实际显存与速度仍取决于所用权重、硬件和推理框架。[量化](/training/quantization/)介绍相关权衡。

## 评测怎么看

官方模型卡的基础模型表中，Flash-Base 的 MMLU 5-shot 为 88.7，表内 V3.2-Base 为 87.8；它们的规模、架构和训练数据不同，不能把差距全部归因于某一个注意力模块，也不应把基础模型结果当作对话模型的业务成绩。模型卡还分别列出其他知识、代码和推理评测，比较前应核对版本与协议。

对于长日志，可以分开测证据定位、设备归属、日期顺序、最终结论和引用。假设 20 条构造样本中 17 条找对设备，但只有 13 条同时找到正确日期并给出正确结论，对应 85% 和 65%；这只是演示计分，并非模型实测。还应把同一证据放在不同位置，加入相似编号、日期反转和证据缺失样本，避免只测试一个容易的位置。

效率评测要固定硬件、精度、框架、输入与输出长度、并发和缓存策略，分别记录首 token 延迟、生成速度、吞吐量和显存峰值。论文中某一配置下的计算量或缓存比例不是任何服务都能复现的端到端加速倍数；索引、网络和工具耗时也可能成为瓶颈。

## 应用与错例

假设助手将另一台同型号机器的正常检测记录当作目标设备的结果。先保存完整输入、设备编号、文档版本、检索片段、模型配置和回答；检查相关段落是否进入上下文、日志是否按时间排序，以及引用是否支持答案。若数据在检索前就选错，先修数据筛选；若输入包含证据却答错，再分析位置、干扰和模型输出。

收集设备编号相似、检测日期反转、日志缺页及无法确定的例子，按设备或工单来源分离开发集与独立测试集。调整检索、提示或训练后，回归正确率、引用和延迟，同时保留不需修改的常见任务。该流程是实验设计，尚未实际运行模型训练或评测。

## 比较与面试追问

**Flash 的 CSA 和 HCA 有什么区别？** 二者都压缩历史表示；CSA 使用较小压缩步长并通过索引筛选，HCA 使用更高压缩比例并对可用压缩条目计算注意力。

**1M token 就保证能找到所有信息吗？** 不保证。输入截断、位置、干扰、压缩和任务形式都可能影响效果，需要独立测试。

**13B 激活参数能按 13B 稠密模型估算显存吗？** 不能。完整专家权重、缓存、精度、并行方式和运行开销都影响部署。

**V4-Flash 和 Pro 结构参数相同吗？** 不完全相同。报告中 Flash 有 43 层、CSA top-k 为 512；Pro 有 61 层、top-k 为 1024。要分别核对型号。
