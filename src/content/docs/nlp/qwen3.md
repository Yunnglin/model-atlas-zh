## 模型卡

| 项目         | 信息                                                                        |
| ------------ | --------------------------------------------------------------------------- |
| 发布时间     | 2025 年 4 月 29 日发布初版；后续另有 2507 版本                              |
| 类型         | 文本解码器；初版包含稠密与 MoE                                              |
| 参数         | 稠密 0.6B 至 32B；MoE 包括 30B-A3B 与 235B-A22B                             |
| 模态与上下文 | 文本输入与输出；初版原生 32K，4B 及以上稠密型号和 MoE 可用 YaRN 扩展至 128K |
| 权重         | 初版稠密和 MoE 均公开权重，采用 Apache 2.0；不同版本的思考模式见下文。      |

例如，初版 [Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B) 与 [Qwen3-30B-A3B](https://huggingface.co/Qwen/Qwen3-30B-A3B) 模型卡都标注原生 32,768 token、使用 YaRN 可扩展至 131,072 token。模型卡中的默认配置值为 40,960，并以 32,768 的输出预算和 8,192 的提示预算举例。128K 扩展需要启用 YaRN。初版 0.6B 和 1.7B 在[技术报告表 1](https://arxiv.org/html/2505.09388v1#S2.T1)中列为 32K，不应套用较大规格的 128K 上下文说明。

4B 有一个版本口径差异：[首发博客](https://qwenlm.github.io/blog/qwen3/)将其列为 32K，而技术报告和[4B 模型卡](https://huggingface.co/Qwen/Qwen3-4B)列出经 YaRN 扩展至 128K。部署时以上线使用的检查点、配置和推理框架为准。

## 要解决什么问题

“3 个箱子，每箱 4 瓶，一共多少瓶？”适合快速作答；带多个约束的排程题则值得多花一些计算。Qwen3 初始系列希望在统一模型中兼顾快速回答与较长推理，同时提供 Dense 和 MoE 规格。

本页区分 **2025 年初版**与 **2507 更新**。下面题目、概率和候选答案都是教学例子，并非官方训练样本或实测结果。[返回系列](/nlp/qwen/)。

## 结构与数据流

文本分词后变成向量，加入位置相关处理，经过多层因果 Transformer，输出下一个 token 的分布。Dense 与 MoE 共享这条总体路径，但部分前馈计算的组织不同。配图是依据报告绘制的教学图，不是官方完整层图。

## 一道题怎样变成逐步生成

### 注意力与前馈部分，各自负责什么

可以把一层想成两道工序：注意力先让“3 个箱子”“每箱 4 瓶”“一共”等位置交换线索，前馈模块再加工每个位置的表示。这两道工序在模型中重复多次。

其中，GQA 让若干查询头共享 K／V 头，主要影响[注意力缓存](/foundations/kv-cache/)；RoPE 处理位置，RMSNorm 与 QK-Norm 等帮助控制数值尺度。

与 Qwen2.5 的稠密结构相比，初版 Qwen3 报告特别列出两项注意力变化：移除 Q、K、V 投影中的偏置，并引入 QK-Norm。后者对查询和键的表示做归一化，帮助稳定训练。与上一代相比，数据和后训练也有变化。

例如 [Qwen3-8B 的官方配置](https://huggingface.co/Qwen/Qwen3-8B/blob/main/config.json)列出 36 层、32 个查询头和 8 个键值头：四个查询头共享一组键值头。这是稠密型号的注意力配置。

用长对话举个例子：生成新字时，模型需要反复读取先前文字对应的键和值。把这些数据保存在 KV Cache 中，就不用每次从头计算。Qwen3-8B 的四个查询头共用一组键值头，因此每一层需要保存的键值组数少于查询头数；对话越长，缓存占用越值得关注。具体显存还受层数、序列长度、批量和数据精度影响，可以结合[缓存算例](/foundations/kv-cache/)估算。

初版 MoE 报告给出每个 MoE 层 128 个路由专家、每 token 选 8 个，没有共享专家。可以把路由想成每一步挑选部分加工模块；这里的数字对应 Qwen3 初版。[MoE](/foundations/moe/)说明总参数和激活参数为什么不同。

以 Qwen3-30B-A3B 为例，型号里的 30B 和 A3B 是便于识别的近似名称；[官方模型卡](https://huggingface.co/Qwen/Qwen3-30B-A3B)列出约 30.5B 总参数、每个 token 约 3.3B 激活参数。每层选择 8 个专家不意味着只计算专家：注意力等共享计算也要参与；模型部署还要存放或调度其他专家的权重，不能直接按 3.3B 稠密模型估算全部显存。

### 训练能并行，生成为什么还要接着写

SFT 样本把答案写成“3×4＝12，因此共 12 瓶”。训练时已知正确前缀，可同时计算多个答案位置的损失；推理时没有标准答案，要把刚生成的 token 接回去，才能预测后一个。

假设，某一位置正确 token 是 `12`，模型给它概率 0.8，对应负对数项约 0.223；概率只有 0.2，约为 1.609。降低损失会鼓励正确目标，但这里假设 `12` 是一个 token，**实际切分以模型 tokenizer 为准**。

## 数据与训练

### 预训练并非只是一大桶材料一次读完

初版技术报告称预训练使用约 36 万亿 token，覆盖 119 种语言和方言。报告区分三个阶段：先在 4,096 token 长度上学习通用语料，再增加 STEM、代码和推理材料，最后用长文本将训练长度提升到 32,768 token。对于更长的输入，官方模型卡提供了使用 YaRN 扩展上下文的方案；静态缩放可能影响短文本表现。

### 大模型的四段后训练，分别补什么

| 阶段          | 学习信号                         | 本例怎样理解                                |
| ------------- | -------------------------------- | ------------------------------------------- |
| 长 CoT 冷启动 | 筛选的较长推理示范               | 先学会把条件组织成可检查步骤                |
| 推理 RL       | 问题与验证器，初版报告采用 GRPO  | 候选 12 符合答案，候选 7 不符合；按反馈更新 |
| 思考模式融合  | 思考／非思考材料与模板的持续 SFT | 简单题快答，复杂题能进入较长推导            |
| 通用 RL       | 多类任务反馈                     | 同时改善指令、格式和通用帮助程度            |

这张表描述原报告的大模型后训练主线。报告还为较小模型使用强到弱蒸馏：先学教师生成的材料，再让学生生成自己的回答，将其分布与教师对齐。仅说“Qwen3 全靠 RL”会漏掉示范、融合与蒸馏。

同一题采样多个候选、用奖励更新，是[GRPO](/training/grpo/)的场景；“奖励能检查”描述的是 [RLVR](/training/rlvr/)。二者分别回答更新算法和反馈来源。

### 初版与 2507 的开关不能混用

初版可通过模板控制思考行为；2507 分别发布 Instruct 与 Thinking 权重，包括 235B-A22B、30B-A3B、4B。Instruct-2507 只做非思考，Thinking-2507 只做思考。因此使用时应区分初版的模式切换与 2507 的独立权重。

## 评测怎么看

### 思考到底值不值，要做同条件比较

固定权重和题集，分别记录思考模式、生成上限、温度、每题尝试数、答案提取与耗时。简单题比较正确性与成本；多步题再看预算增加是否换来成功率改善。

| 教学候选                  | 最终答案 | 结果检查 | 仍未证明什么             |
| ------------------------- | -------- | -------- | ------------------------ |
| A：3×4＝12，共 12 瓶      | 12       | 本题正确 | 不代表会处理额外约束     |
| B：写了很长推导，最后给 7 | 7        | 本题错误 | 文字长不代表推理对       |
| C：答案 12，但解释是乱猜  | 12       | 结果正确 | 结果奖励不能认证全部过程 |

报告 [pass@1 与 pass@k](/evaluation/llm-benchmarks/)时，分别记录候选数量和生成预算。

报告也展示了权衡：表 22 中，Qwen3-32B 的思考模式从推理 RL 阶段到通用 RL 阶段，IFEval 严格指令遵循从 73.0 升到 85.0；同表 AIME 2024 则从 83.8 降到 81.4。两个检查点之间还经过思考模式融合阶段，因此不能把这段变化全部归因于最后的通用 RL。这里比较的是报告中特定检查点和评测模式，不代表所有任务都会有相同变化。

这两个分数衡量的事情也不同。IFEval 的严格提示级准确率要求一个提示中的**所有可检查要求**都满足：例如要求回答包含指定词、又限制字数，漏掉其中一项，这条提示就不算全部通过。AIME 2024 包含 30 道题；Qwen3 报告对每题生成 64 个回答并计算平均准确率，反映的是该采样设置下单次作答的平均表现，不是从 64 个答案中挑一个正确答案后的成绩。比较其他模型时，要一起看计分方式、采样数量和生成长度。[IFEval 论文](https://arxiv.org/abs/2311.07911)介绍了提示级与单条指令级指标的区别。

数学、代码、多语言、工具与格式分开切片。输出达到长度上限，应区分答案本身错误、未完成和解析失败；不能只删除长回答失败项来提高平均分。

## 应用与错例

简单问题长篇推导，先核对型号、模板和模式；复杂题中途截断，先看输出预算；算对却评分错，查答案提取；所有样本都模板失常，先检查是否把 Base 或不匹配 tokenizer 当助手用。

只将确认属于能力缺口的题补到开发／训练池，独立测试继续留出。改奖励时同时查看真实任务正确率，避免奖励上涨只是迎合验证器。

### 把一条错误沿链路往回追

假设用户问：“仓库里有 3 箱饮料，每箱 4 瓶；送出 2 瓶后还剩多少？”助手回答 14。先不要马上说“模型不懂乘法”。可以把任务拆为读取数字、识别动作、计算和按要求输出四步：正确关系是先算 3×4，再减去 2；如果回答 14，可能是把“送出”误当成“收到”，也可能是算术运算出错。只看最后答案，无法判断是哪一环出了问题。

排查时做几个对照：把“送出”换成“收到”，观察答案是否跟着改变；把 3、4、2 换成其他数，检查是否记住了固定组合；让答案带简短计算式，再检查中间式与最终数字是否一致。解释文字也可能是事后拼出来的，因此需要单独检查计算式，不能把一段看起来顺畅的解释自动当成可靠证据。

### 为什么不能只挑最好的十次之一

另一个教学实验让模型对每题独立回答一次，另一个系统则允许尝试十次、再用外部程序选择正确答案。后者多了采样和选择器的预算，结果有参考价值，但不能直接称为同样条件下模型本身更准确。应该分别报第一次的正确率、多次采样的成功率、选择器如何工作以及总生成量。代码任务还要保留执行环境、测试覆盖和超时结果；程序跑过示例，不等于满足所有边界条件。

这些检查同样适用于上线回归。把失败的题按照“读错条件、计算错、格式错、评分器错”分组，在开发集修改提示或数据，再用没有参与调整的样本复测。若只反复盯着同一批失败样本，最终记住的是题目，未必学会了同类问题。

## 比较与面试追问

**思考模式就是 MoE 开关吗？** 不是，前者影响生成行为，后者决定部分计算如何分配。

**开了思考就等于用了 RLVR 吗？** 推理开关不能证明训练反馈来源。

**小模型能从教师蒸馏，为什么不直接复制教师权重？** 结构和规模可不同，迁移的是学习信号。
