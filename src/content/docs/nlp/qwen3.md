## 要解决什么问题

“3 个箱子，每箱 4 瓶，一共多少瓶？”适合快速作答；带多个约束的排程题则值得多花一些计算。Qwen3 初始系列希望在统一模型中兼顾快速回答与较长推理，同时提供 Dense 和 MoE 规格。

本页区分 **2025 年初版**与 **2507 更新**。下面题目、概率和候选答案都是教学例子，不是官方训练样本或本站实测。[返回系列](/nlp/qwen/)。

## 结构与数据流

文本分词后变成向量，加入位置相关处理，经过多层因果 Transformer，输出下一个 token 的分布。Dense 与 MoE 共享这条总体路径，但部分前馈计算的组织不同。下图是本站依据报告绘制的教学图，不是官方完整层图。

## 一道题怎样变成逐步生成

### 注意力与前馈部分，各自负责什么

可以把一层想成两道工序：注意力先让不同位置交换线索，前馈模块再加工各位置的表示。工序会在很多层重复，不能把专家理解成外部工具或人工命名的学科老师。

注意力让“3 个箱子”“每箱 4 瓶”“一共”这些位置交换信息；前馈部分继续加工每个位置的表示。GQA 让若干查询头共享 K／V 头，主要影响[注意力缓存](/foundations/kv-cache/)；RoPE 处理位置，RMSNorm 与 QK-Norm 等帮助控制数值尺度。它们没有哪一个单独等于“数学推理模块”。

初版 MoE 报告给出每个 MoE 层 128 个路由专家、每 token 选 8 个，没有共享专家。这些是初版特定配置，不能套到 Next 或 3.8。可以把它想成每一步挑部分加工模块；专家不是被人工指定为“乘法专家”“中文专家”。[MoE](/foundations/moe/)说明总参数和激活参数为什么不同。

### 训练能并行，生成为什么还要接着写

SFT 样本把答案写成“3×4＝12，因此共 12 瓶”。训练时已知正确前缀，可同时计算多个答案位置的损失；推理时没有标准答案，要把刚生成的 token 接回去，才能预测后一个。

假设，某一位置正确 token 是 `12`，模型给它概率 0.8，对应负对数项约 0.223；概率只有 0.2，约为 1.609。降低损失会鼓励正确目标，但这里假设 `12` 是一个 token，**实际切分以模型 tokenizer 为准**。

## 数据与训练

### 预训练并非只是一大桶材料一次读完

初版报告区分通用阶段、增加 STEM／代码／推理等高质量材料的阶段，以及长上下文阶段。长上下文还涉及训练长度与位置设置，不能仅改配置中的最大长度就宣称等价于官方训练。

### 大模型的四段后训练，分别补什么

| 阶段          | 学习信号                         | 本例怎样理解                                |
| ------------- | -------------------------------- | ------------------------------------------- |
| 长 CoT 冷启动 | 筛选的较长推理示范               | 先学会把条件组织成可检查步骤                |
| 推理 RL       | 问题与验证器，初版报告采用 GRPO  | 候选 12 符合答案，候选 7 不符合；按反馈更新 |
| 思考模式融合  | 思考／非思考材料与模板的持续 SFT | 简单题快答，复杂题能进入较长推导            |
| 通用 RL       | 多类任务反馈                     | 同时改善指令、格式和通用帮助程度            |

这张表描述原报告的主线，**不是所有规格各自完整重复四段**。报告还为较小模型使用强到弱蒸馏：先学教师生成的材料，再让学生生成自己的回答，将其分布与教师对齐。仅说“Qwen3 全靠 RL”会漏掉示范、融合与蒸馏。

同一题采样多个候选、用奖励更新，是[GRPO](/training/grpo/)的场景；“奖励能检查”描述的是 [RLVR](/training/rlvr/)。二者分别回答更新算法和反馈来源。

### 初版与 2507 的开关不能混用

初版可通过模板控制思考行为；2507 分别发布 Instruct 与 Thinking 权重，包括 235B-A22B、30B-A3B、4B。Instruct-2507 只做非思考，Thinking-2507 只做思考。不能以为任何名字带 Qwen3 的型号都能用同一个开关切换。

## 评测怎么看

### 思考到底值不值，要做同条件比较

固定权重和题集，分别记录思考模式、生成上限、温度、每题尝试数、答案提取与耗时。简单题比较正确性与成本；多步题再看预算增加是否换来成功率改善。

| 教学候选                  | 最终答案 | 结果检查 | 仍未证明什么             |
| ------------------------- | -------- | -------- | ------------------------ |
| A：3×4＝12，共 12 瓶      | 12       | 本题正确 | 不代表会处理额外约束     |
| B：写了很长推导，最后给 7 | 7        | 本题错误 | 文字长不代表推理对       |
| C：答案 12，但解释是乱猜  | 12       | 结果正确 | 结果奖励不能认证全部过程 |

这不是实测对比。实际报告 [pass@1 与 pass@k](/evaluation/llm-benchmarks/)时，还要记录候选数量和预算，不能把十次中一次成功写成用户首次必成功。

数学、代码、多语言、工具与格式分开切片。输出达到长度上限，应区分答案本身错误、未完成和解析失败；不能只删除长回答失败项来提高平均分。

## 应用与错例

简单问题长篇推导，先核对型号、模板和模式；复杂题中途截断，先看输出预算；算对却评分错，查答案提取；所有样本都模板失常，先检查是否把 Base 或不匹配 tokenizer 当助手用。

只将确认属于能力缺口的题补到开发／训练池，独立测试继续留出。改奖励时同时查看真实任务正确率，避免奖励上涨只是迎合验证器。

## 比较与面试追问

**思考模式就是 MoE 开关吗？** 不是，前者影响生成行为，后者决定部分计算如何分配。

**开了思考就等于用了 RLVR 吗？** 推理开关不能证明训练反馈来源。

**小模型能从教师蒸馏，为什么不直接复制教师权重？** 结构和规模可不同，迁移的是学习信号。

下一步读 [Qwen3-Next](/nlp/qwen-next/)了解混合注意力，[3.5 → 3.8](/omni/qwen38/)了解主线后续变化；不要把初版 128／8 专家配置继续套过去。
