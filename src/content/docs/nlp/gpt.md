## 要解决什么问题

以前要做摘要、翻译和问答，常为每个任务收集标注数据，再单独训练模型。GPT-2 论文提出一个值得研究的问题：如果一个语言模型只学习预测互联网上文本的下一个 token，看到“文章：……摘要：”这样的提示后，它能否在不针对该任务再训练的情况下接着给出合理摘要？

关键不是说训练数据中没有任何任务示范：网页自然会出现问题、答案、翻译和说明。这里的“零样本”指不使用该任务的标注样本专门训练或微调参数；评测提示中仍可能包含任务描述或上下文。比如论文的 CoQA 设定会提供已有对话，提示、测试协议和可能存在的数据重合都仍需检查。它也不是 ChatGPT 那样经过专门指令对齐的对话助手。

## 结构与数据流

GPT-2 使用一叠因果 Transformer 模块。输入先经字节级 BPE [分词](/foundations/tokenization/)，变成 token 编号，再通过词嵌入和位置嵌入变成向量。每一层的自注意力从允许看到的前文中收集信息，再由前馈网络加工；残差连接与层归一化帮助训练。GPT-2 把层归一化放在每个子模块的输入端，并在最后一个模块后再加一次归一化；这类安排常称为 Pre-LN。最后一层将各位置表示映射成词表上的分数，用 softmax 转成下一 token 的概率。

GPT-2 最大版本有 48 层、隐藏维度 1,600、25 个注意力头；论文表 2 中另外三个规格分别为 12 层、768 维；24 层、1,024 维；36 层、1,280 维。不同版本的参数量口径见模型卡，不能把最大版的结构套用给较小版本。它没有原始翻译 Transformer 的独立编码器及编码器交叉注意力。[Transformer](/foundations/transformer/) 与[注意力机制](/foundations/attention/)解释了通用组件；“decoder-only”说的是结构组织，不是说它只能做翻译的解码部分。

### 从一句话走到输出

假设输入为“会议决定延期，因为”，这是教学例子，不是实际推理结果。模型先计算前缀中每个位置的表示，最后位置给下一 token 的候选打分。解码策略可能选出“场地”，系统把它接回前缀，再根据新的前缀预测下一 token；如此重复，直到结束或达到预算。token 可能是英文子词、字节片段或其他单元，不必等于一个汉字或完整词。

如果模型接着写“场地冲突”，这只是生成的一种可能续写。假如输入没有提到原因，模型并没有证据证明会议因场地延期。续写的流畅度与事实正确是两件不同的事，特别是原始 GPT-2 的目标不是保证遵循用户指令或提供可验证证据。

### 因果掩码为什么重要？

在训练一段“今天 天气 很好”时，模型可同时计算多个位置的预测，但因果掩码限制每个位置只读取当前及之前的 token：预测“天气”不能先看到“很好”。这使训练条件与生成时的条件一致，避免从未来答案抄题。输入中若包含整段会议记录，模型生成摘要时当然可以看完整个已给定记录；“不能看未来”不意味着不能看用户输入的后半段。

生成过程中，[KV Cache](/foundations/kv-cache/)可以缓存旧 token 各层的键和值，避免每一步重复计算旧位置的投影；新 token 仍要与允许范围内的历史交互。缓存会占显存，窗口长度也有限；它不是用来保证事实正确的知识库。

以最大 GPT-2 的 48 层、隐藏维度 1,600 为例，假设单条序列已有 1,024 个 token，键和值都用 BF16 存储，每个数占 2 字节。只算键值数据，约需要 `48 × 2 × 1024 × 1600 × 2` 字节，也就是 **300 MiB**。长度减半时，这部分大致减半；实际内存还包括模型权重、工作区和其他运行开销。这个估算有助于理解缓存和上下文长度的关系。

## 数据与训练：让网页变成预测题

WebText 从 Reddit 上达到至少 3 karma 的帖子外链收集网页，再抽取正文、去重和清理。论文中的早期版本只取 2017 年底以前的链接；其所说的约 4,500 万条链接，与清洗后超过 800 万篇文档是两个不同口径。论文还移除了 Wikipedia 文档以减少和常用评测集的重合风险，并在筛选时剔除非英语网页。这种互动门槛只是网页选择的启发式，不证明内容真实、无偏差或适合所有用户；数据的来源、发布时间和覆盖范围也会限制模型。

一段文本“今天 天气 很好”可以拆成多个预测位置：给“今天”预测“天气”，给“今天 天气”预测“很好”。训练使用文本本身的后续 token 作为监督信号，最小化预测真实后续 token 的负对数似然；它不需要为每条新闻额外标注“摘要”或“翻译”。这叫自监督训练，但数据中仍可能自然包含人写的答案和示范。

$$
p(x_1,\ldots,x_n)=\prod_{t=1}^{n}p_\theta(x_t\mid x_{<t})
$$

$x_t$ 是第 $t$ 个 token，$x_{<t}$ 是它之前的 token，$p_\theta$ 是模型给出的条件概率。训练相当于提高真实后续 token 的概率，通常以负对数损失计算。生成时每一步选出的 token 会进入下一步的前缀；错误一旦写入，后面可能继续围绕错误内容续写。

字节级 BPE 从字节序列出发学习常用片段，既能处理多种文本字符，又不必把所有 Unicode 字符都作为基本词表。论文使用 50,257 个词表项；能编码多种文字不等于不同语言都有足够训练数据或同等表现。用户用中文提问时，不能仅凭它“支持编码中文”推断中文摘要质量。

## 评测：零样本和困惑度怎么看

论文在零样本设置下测试语言建模，并报告最大模型在当时测试的 8 个语言模型数据集中有 7 个取得所报告的领先结果；这描述的是论文使用的任务、指标与时代条件。它不是说 GPT-2 解决了所有语言任务，也不等于今天各类任务的表现。

例如，论文表 3 中最大模型在 WikiText-103 上的困惑度为 17.48，低于表中当时的 18.3；但在 One Billion Word 上是 42.16，高于当时对照的 21.8。这里两行是在同一数据集内比较，困惑度越低通常越好；不同数据集的绝对数值不能互相比较。论文对这些测试使用可逆的去分词处理，数据处理方式和当时的模型对照都会影响解读，不能把数字当作后来模型的直接排名。

困惑度可以理解为模型对测试文本下一个 token 有多“意外”：在同样数据和可比的计算口径下，通常越低越好。但分词方式、测试文本处理和归一化方式会影响结果；低困惑度也不直接证明回答忠实、无害或适合业务。论文还研究阅读理解等任务：在以文档及既有对话为条件、使用贪心解码的 CoQA 开发集设定下达到 55 F1；这不是所有问答均有 55% 准确率。论文指出新闻领域约 15% 的 CoQA 文档已出现在 WebText，相关样本表现较好；这一观察提醒我们检查数据重合，不能简单视为所有任务都没有见过相关材料。

用会议摘要举例，应固定原始模型版本、提示、截断和生成策略，拿独立会议记录检查信息覆盖、日期和责任人是否有证据。把记录中“延期一周”改成“两周”，看输出是否随之变化；再把延期原因删掉，检查模型是否承认没有说明。逐条记录遗漏、编造、格式错误和无法结束，而不是只看一两个顺口的例子。以上均为可执行的评测设计，没有声称已经运行。

## 应用与错例：模型不等于完整助手

如果模型给出错误的会议延期原因，应先核对输入是否包含正确记录、是否因 1,024 token 窗口而被截断、提示是否明确要求只依据材料，再检查模型是否读错或凭常见模式补写。针对事实更新问题，检索系统可提供可核查资料；针对格式问题，可以增加示范或做 [SFT](/training/sft/)。这些方案各有成本，也都需要独立评测。

如果团队决定用示范数据训练摘要助手，应收集已获许可的会议记录，标注事实忠实的摘要，按会议或项目划分训练和测试；保留“原因未确认”等示例，防止把猜测写成事实。复测时检查目标格式与通用能力是否变化。此处是在 GPT-2 基础上构想的后续应用方案，原始 GPT-2 论文的零样本评测不等同于已经做了该 SFT。

## 比较与面试：从 GPT-2 到后续模型

GPT-3 研究更大模型及上下文中的少样本示范；把例子放进提示不等于更新权重。InstructGPT 研究用示范与人类反馈调整行为；不能因为后来的助手使用 [RLHF](/training/rlhf/)，就说 GPT-2 原始训练也用了它。GPT-4 技术报告未完整披露参数规模和训练配方，不能套用 GPT-2 的层数或数据。

[BERT](/nlp/bert/) 的原始掩码语言模型利用双向上下文学习表示；[T5](/nlp/t5/) 以编码器—解码器处理文本到文本任务。不同任务和条件下各有适用范围，不应把早期对比当作所有后续版本的绝对排名。闭源路线可参考 [Claude](/nlp/claude/)、[GPT-4o](/omni/gpt4o/) 和 [Gemini 1.5](/omni/gemini/) 的公开材料。

## 面试追问

**预测下一个 token 为什么能用于问答？** 如果提示把问题写成文本前缀，答案就是后续文本；预训练可能学到相关模式，但结果受数据、模型和提示影响。

**零样本是否意味着训练数据里完全没有相关信息？** 不是。这里指不针对目标任务的标注数据训练或微调参数；提示可能包含任务说明或已有对话，训练语料也可能含有相关材料，数据重合应单独检查。

**温度调低能消除幻觉吗？** 不能。温度改变采样分布，并不会补充缺失证据；需要结合来源、任务评测和必要的外部验证。
