## 先看一个问题

请助手修一张网页：用户上传截图说“手机上结算按钮被底部栏挡住了”。可靠的助手需要理解截图、查看相关样式、修改代码，再打开页面验证。只写一段看上去合理的 CSS，却没有检查实际界面，无法证明问题已解决。

GLM-5.3-Flash 能接收图片或视频与文本，并生成文本和工具请求。官方将它定位于代码、视觉理解和智能体任务：模型分析截图，浏览器、文件系统及代码执行器则负责实际操作。下面的截图场景是教学构造，不是官方案例或实际模型运行记录。

它不是把 [GLM-5.3](/nlp/glm53-model/) 简单缩小或量化得到的版本。官方明确称 Flash 使用新训练的基础模型，重新设计结构和训练方案；GLM-5.3 的官方说明则称其沿用 5.2 基座并通过后训练改进。名称相近，基座与支持的输入模态却需要分别看。

## 看图之后发生了什么

视觉输入先经过图像处理与视觉编码，转化为可供模型使用的表示；文字也转为 token。语言模型根据任务和已有上下文生成后续内容。对截图例子，模型可以识别底部栏与按钮重叠的线索，再请求外部工具读取样式，提出修改方案。

工具请求本身只是一段符合协议的输出。执行器负责检查权限、读取文件或启动浏览器，再把结果返回模型。截图里的按钮看起来没有遮挡，不代表点击后付款流程一定正常；实际验证还应检查不同屏幕、键盘操作和业务测试。模型输出“已验证”时，应对照工具截图、执行日志和退出状态。

官方配置含 24 层视觉编码结构与图像、视频标记。支持视频输入不表示模型能直接生成视频，也不表示每个服务支持同样的采帧、分辨率和文件大小。若应用只接收文字，即使权重支持图像，用户也无法在该接口直接上传截图。

## 结构：混合两种注意力

![GLM-5.3-Flash 主干示意：视觉编码和文字表示进入 45 层语言骨干，线性与稀疏注意力交替，前馈网络前 3 层稠密、后 42 层为混合专家。](/figures/glm53-flash/backbone.svg)

_图：根据[官方配置](https://huggingface.co/zai-org/GLM-5.3-Flash/raw/main/config.json)绘制的简化主干。注意力负责从上下文取信息；前馈网络进一步处理信息，两者是每层中不同的部分。_

语言部分配置为 45 层，采用线性注意力与稀疏注意力混合：配置中常见三层线性注意力后接一层稀疏注意力，最后还有一层线性注意力。可以把线性注意力想成一边阅读一边维护压缩状态，用于高效处理序列；稀疏注意力则通过索引选择部分历史位置，再做细致计算。它们是不同的信息处理方式，不要简单理解为“一个永远只看附近、一个保证找到所有远处信息”。

按配置数一遍：11 组“3 层线性注意力加 1 层稀疏注意力”共 44 层，再加末尾的 1 层线性注意力，一共 45 层。视觉编码器另有 24 层；两者处理的输入和职责不同，不应把它们相加后当作全部语言层数。不同注意力层仍有各自的前馈网络和其他模块，图为简化示意。

把注意力和前馈网络分开看，就不容易把它们混成两套模型：例如第 4 层使用稀疏注意力来挑选历史位置，再用 MoE 前馈网络处理信息；第 5 层换成线性注意力，前馈部分仍是 MoE。前 3 层则各自使用线性注意力和稠密前馈。

长项目中，助手可能需要同时理解刚才的报错和很早之前的订单规则。压缩状态帮助控制长序列处理成本，稀疏检索提供访问部分历史内容的路径；但压缩可能丢失信息，索引也可能漏掉关键材料。能把长内容放进窗口不代表每个细节都被准确检索，因此仍要测试位置变化、干扰和跨文档综合。

### IndexPool：先压缩索引，再找位置

官方介绍 IndexPool 将四个索引器的键向量通过加权池化压缩为一个，降低长上下文索引的计算与内存开销。可以把它想成给一叠资料先做分组索引，再根据索引寻找值得细看的材料；这是索引表示的压缩，不等于简单把原文四个 token 合并或删除，也不是把最终回答的正确性保证提高四倍。

它与 [GLM-5.2](/nlp/glm52-model/) 的 IndexShare 有别：IndexShare 让多个注意力层复用位置索引；IndexPool 针对索引器键表示做池化压缩。两种设计针对不同的重复或规模成本，不能因都带 Index 就当作同一个方法。

### MoE 和 mHC 是什么

官方配置包含 288 个路由专家，每 token 选择 8 个，并有共享专家。专家是神经网络中的计算模块，不是被人工分别指定为前端、数据库或安全专家的程序员。总参数约 320B、激活约 18B 有助于理解每次计算，但部署仍要考虑全部权重、缓存、通信和并发，不能当成完整的 18B 稠密模型。

模型还采用 mHC，即带约束的超连接。普通残差连接像在层与层之间保留一条信息通道；mHC 使用多条通道并约束它们之间的混合，目标是帮助深层信息传递和规模扩展。它不是外部记忆，也不是专门处理图片的模块；官方报告整体结构和训练数据共同影响效果，无法从榜单分数单独算出 mHC 的贡献。

官方比较在统一口径下的每头每层注意力计算与平均每层 BF16 缓存，称相较 GLM-5.3 分别约低 3.0 倍与 4.4 倍。这不是整个推理服务必然快 3 倍或显存必然减少 4.4 倍；视觉编码、模型权重、批量、硬件与软件实现都会影响实际结果。

## 数据与训练：哪些公开，哪些仍不知道

官方称模型使用约 30T token 多模态预训练语料，并从新基座出发。预训练可帮助模型学习文本和视觉材料中的规律；后训练进一步围绕任务完成、指令和工具交互塑造行为。具体数据来源比例、图片视频构成、去重、完整阶段顺序、奖励函数及超参数未在发布说明中逐项公开。不要把“30T”理解为全部都是图片 token，也不要把前代模型的训练数字直接套到此版本。

用网页截图任务举例，一条训练样本可能包含用户要求、界面图、代码环境和目标行为：模型找出遮挡、提出修复并请求运行测试。若有验证环境，可以检查页面是否渲染、按钮是否可点以及其他页面是否回归；视觉评分还可能检查是否覆盖目标控件。这是便于理解的训练设计示例，并不声称官方用了这条样本。

监督微调可以让模型学习高质量示范，强化学习可以利用可验证结果进一步优化。无论采用哪种方法，奖励都有盲区：如果只按截图判断按钮位置，模型可能把按钮移走却破坏付款；如果只看测试退出码，测试本身可能没有覆盖真实页面。应把不同信号和人工抽查结合，并把训练数据与最终测试按项目来源隔离。

多模态数据还有标注歧义：截图可能是旧版本，视频采样可能错过问题出现的瞬间，界面文字在缩放后可能不清晰。训练和评估都应记录图片预处理、分辨率、视频采帧与工具环境，否则“模型看错了”可能是输入已经丢失了关键证据。

## 评测：先问清楚测的是什么

官方发布文章给基座模型报告 MMLU **88.1**、LiveCodeBench-Base **37.6**；这些是基座评测，不应与已经后训练的聊天模型分数混为一谈。官方还有面向代码、智能体和办公工作的测试；比较时必须查看基准版本、输入模态、工具框架、输出预算和评分方式。

例如，官方在 Terminal-Bench 2.1 上报告 Flash 为 84.3、GLM-5.2 为 81.0；Flash 的模型卡注明使用 Claude Code 2.1.207、温度 1.0、top-p 1、最多生成 65,536 token 和 6 小时时限；而 5.2 的 81.0 来自 Terminus-2，脚手架与预算不同，不能把分差全部归因于模型。这是一套带终端工具的任务评估，不是模型单次输出代码的正确率。若自己的执行器、网络权限或超时不同，成绩和成本都需要重新测量。

模型卡提供 `reasoning_effort` 参数：`low`、`high` 和 `max`；官方称复现基准时使用默认 `max`。同一模型若改用其他思考预算，其时延、成本和效果可能变化，不能拿一次低预算调用直接对照官方高预算成绩。不同提供商也可能改变图像预处理与工具配置。

聊天模板还有一个不同的设置 `clear_thinking`：模型卡说明它默认是 `false`，聊天场景建议显式设为 `true`。可以把这两个设置看作不同问题：`reasoning_effort` 选择思考预算，`clear_thinking` 影响模板如何处理历史思考内容。比较多轮任务时，最好同时记录二者及实际传入的历史，避免把上下文变化误认为模型权重的差异。

对于网页截图修复，可以准备互不重叠的项目，覆盖窄屏、长文案、键盘导航与多浏览器。分别记录问题定位、可运行补丁、实际界面、回归测试与耗时。假设 30 个案例中 21 个通过功能与视觉检查，成功率为 70%；这是教学计算，不是实测。视觉评分器也会漏掉细节，需要人工复核样本及失败原因。

想看别人怎么记录实验，可以参考 [DigitalOcean 的小型任务评测](https://zhuanlan.zhihu.com/p/2078886952426852372)：文章提供了提示、重复次数、预算和原始代码链接。它使用服务商的特定部署和小型任务，结论不能直接推广到其他硬件、任务或价格；结果尚未独立复现。阅读时可以先对照自己的任务和配置，再判断结果是否有参考价值。

## 应用与错例闭环

假设助手修复了截图里的遮挡，但把“确认支付”按钮挪到屏幕外。先保存原始截图、屏幕尺寸、需求、模型版本、工具日志、代码补丁及修复后的截图；判断是截图裁切、需求不明确、视觉识别错误，还是测试只覆盖了页面渲染。

接着收集脱敏的同类案例，补充窄屏、滚动、焦点和点击的独立回归测试，并按项目划分开发与测试数据。可以先改进浏览器截图方式、权限约束和验收规则；若仍有系统性问题，再考虑构造训练样本。最后在未参与调整的项目上检查完成率、误改率、耗时和人工复核成本。

外部网页、截图和文件都可能包含误导性文字。工具执行、网络访问和敏感操作应由应用设置边界并记录证据；模型能识图不意味着它天然拥有桌面控制权或可以自行授权操作。

## 面试追问

**Flash 是 GLM-5.3 的量化版本吗？** 不是。官方描述它从新训练基座出发，采用不同的混合注意力与多模态结构。

**IndexPool 与 IndexShare 有什么区别？** 前者压缩索引器的键表示，后者跨层复用选出的索引；应结合各自实现和适用条件分析。

**18B 激活参数是否意味着只需要存储 18B 权重？** 不一定。不同输入会路由到不同专家，完整部署还要考虑全部权重和缓存。

**看到截图就代表能控制浏览器吗？** 不是。识图是模型能力；点击、运行和访问文件由外部执行器提供并受权限控制。

**1M 上下文是不是保证整个视频或项目都能看懂？** 不是。位置数、图像处理、服务限制和实际检索准确率是不同问题。
