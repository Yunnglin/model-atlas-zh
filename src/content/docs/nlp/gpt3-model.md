## 先看问题：新任务一定需要重新训练吗？

假设你要给一批客服问题打标签，分类只有“退款”和“物流”。传统做法可能是准备大量已标注的问题，用它们微调模型；如果下周增加一种新标签，还要更新数据与训练流程。GPT-3 论文研究另一种办法：把任务说明和几个已经标好的例子直接写进提示，再让同一个语言模型续写新问题的标签。

例如给模型看“包裹什么时候到 → 物流”“我想申请退钱 → 退款”，再写“快递一直没有更新 →”。如果它续写“物流”，就像临时拿到几道例题后模仿答题格式。注意，这里是教学例子，不是我们运行 GPT-3 得到的结果；例子也不能证明它理解了每一条真实业务规则。

[GPT-2](/nlp/gpt/) 已经探索过从文本提示直接完成任务。GPT-3 将这一思路放到更大模型上系统研究，比较不同规模、不同示例数量与不同任务的表现。论文并没有说 GPT-3 发明了所有上下文学习，也没有说少样本永远优于微调。

## 结构：仍是一台按顺序续写的文本模型

先把提示拆成 token，再转换成向量。模型读到当前位置时，通过带因果限制的自注意力利用前面已经出现的文字；随后前馈网络加工表示，层与层之间通过残差连接传递信息。最后模型给词表里的候选 token 分配分数，按某种生成策略选出下一个，再把它接到上下文后继续预测。

因果限制像阅读一份从上到下展开的文件：预测某个位置时，不能偷看后面的标准答案。模型可以阅读提示里的两个已知例子，因为它们出现在待回答问题之前；但它不能在生成答案前看到测试集为这个问题准备的标准标签。这样的结构与训练目标也解释了它为什么适合续写，并不保证续写一定符合事实或用户意图。

论文中的 175B 版本包含 96 个 Transformer 层，每层隐藏维度 12,288、96 个注意力头。论文明确继承 GPT-2 的许多设计，但并非所有细节都相同：它在层中交替使用密集注意力与局部带状稀疏注意力模式。密集注意力和局部注意力的区别在于某一层可连接哪些位置；不能把“有局部稀疏注意力”误说成所有层只能看附近的词，更不能把它与后来的混合专家结构混为一谈。

论文训练了从 125M 到 175B 的八种模型，用它们研究规模和能力的变化。这里的 175B 表示约 1750 亿个可训练参数，不是上下文长度，也不是训练数据条数。论文写的 2,048 token 窗口既要装说明、例子和待答问题，也要为输出留位置；例子放得越多，留给新问题和答案的空间就越少。真实调用还受具体接口、版本和计数方式影响，不能把 2020 年论文的窗口直接套到后续所有 GPT 产品。

## 训练：先学续写，再用提示指定任务

GPT-3 的预训练数据混合了经过过滤的 Common Crawl、WebText2、Books1、Books2 和英文 Wikipedia。论文不是把所有数据简单拼成一份之后均匀读一遍：它给来源设置不同采样权重。表 2.2 中，过滤后的 Common Crawl 采样权重为 60%，WebText2 为 22%，两个图书来源各为 8%，Wikipedia 为 3%。这些是论文表中的近似比例，因四舍五入相加并不恰好为 100%。

注意区分三个数字：某来源仓库有多少可用 token、训练时从该来源抽样的比例，以及模型训练过程中总共处理多少 token。论文列出过滤后的 Common Crawl 约 4,100 亿 token，但所有来源合起来的采样过程让每个模型处理约 3,000 亿 token；某些较小来源被重复采样，另一些数据不到一遍。不能说模型看过 3,000 亿个互不重复的词，也不能把可用语料大小当作模型参数量。

自回归预训练会拿到一段已有文本，根据前面的 token 预测下一个 token，计算损失后更新参数。例如见到“快递预计明天”，模型可能提高“送达”等续写的概率。训练中反复接触不同文本，使它学到语言模式和部分世界知识；这种能力来自参数与训练数据，不能保证它能追溯某一知识来源，也不能保证语料中的信息仍然正确。

论文中的下游评测不对目标任务做梯度更新。它把例子放在上下文中，改变当前输入，而不是把例子通过反向传播写入权重。模型当然可以在其他方案中被微调，但不能因为后来存在 GPT 系列指令模型，就给 2020 年原论文的基础 GPT-3 自动补上一套 SFT 或 RLHF 流程。

## 零样本、单样本和少样本：例子放在哪里？

仍以客服分类为例。零样本可以只写“把问题归为物流或退款：包裹未送到 →”；单样本在问题之前加一条已标注示例；少样本则放入几条不同的示例。这里的“样本”是提示中给出的示范，不是用来更新权重的训练批次。示例的措辞、顺序、覆盖范围和标签是否正确都会影响输出。

对一个没有明确业务规则的案例，例如“收到的商品破损，快递很慢”，模型可能学到示例里的表面格式，却无法知道究竟应该按商品问题还是物流问题归类。更可靠的做法是先明确标签定义，准备覆盖边界情况的示范和独立测试，再检查模型在同义改写、长文本和缺失信息上的结果。少样本是一个接口，不会替业务补齐规则。

把例题放进提示也不意味着模型永久学会了它们。下一次请求如果没有这些上下文，模型可能不再采用同一规则；即使相同上下文下，多次采样也可能得到不同回答。相比之下，SFT 是根据示范更新参数的一种训练方式。两者可以组合，但成本、数据留存和错误传播的方式不同。

## 评测：示例确实有用，但不是处处都赢

论文对零样本、单样本和少样本设置做了多项比较。以 TriviaQA 的闭卷问答为例，GPT-3 175B 报告的准确率分别为 64.3%、68.0% 和 71.2%；少样本结果来自论文所述的 TriviaQA Wiki 划分测试服务器。闭卷表示回答时没有外部检索文本，不表示模型训练前从未见过相关事实。结果属于特定数据集、提示和评测条件，不能理解成模型回答任意事实问题有 71.2% 的概率正确。

也不能只展示有利结果。论文的 ARC-Challenge 测试中，175B 零样本、单样本、少样本结果分别为 51.4%、53.2%、51.5%，并没有随着示例增加单调提升；表中当时微调后的最佳对照为 78.5%。同一篇论文中不同任务的表现有很大差异，说明“放例子”不是普遍有效的魔法。比较时要说明数据划分、示例数量与选择、指标、提示格式和是否允许检索；不同方法采用不同输入信息时，不应只拿分数排榜。

选择题的评测并不是只让模型自由输出一个选项字母。论文把题干与每个候选答案分别拼接，比较语言模型给候选续写的概率，再选得分最高者。多数任务按候选长度做归一化；ARC 等少数任务还用通用“Answer:”提示下的候选概率作校正，以减轻候选本身常见程度带来的影响。例如某个选项本来就很常见，校正后的得分关注的是它在这道题的条件下变得多合理，而不是只奖励它常见。这个例子帮助理解评分，并不表示所有后来的 GPT 评测都沿用相同方式。

数据污染是另一项重要限制。论文作者尝试去除训练资料和评测集的重叠，却发现过滤程序有错误，一些重叠没有成功移除；由于重新训练成本高，作者没有重新训练，而是分析残余重叠的影响。部分语言建模基准因此被排除。污染不自动意味着每个结果都无效，但也不能把所有成绩都当成完全未见过测试内容的证明。

## 应用与错例：把演示变成可靠流程

如果要把上述方法用在真实工单系统，先在开发数据里定义标签：例如“退款”必须明确表达退款诉求，“物流”关注运输状态；如果一条工单同时涉及两者，应允许多标签或转人工，而不是强行假装只有一个答案。记录输入来源与授权情况，保证示范与未来线上文本的类型接近。

随后按客户、会话或订单划分开发集和测试集，避免同一订单的改写同时出现在提示示例和测试中。选择若干开发样本构成提示，固定格式与示例顺序，再在独立测试上统计每类的精确率、召回率、无法判定的比例，并抽查相互混淆的案例。记录每条请求的上下文长度与成本；一个示例很长时，可能挤掉问题中最关键的细节。

假设系统把“不要退款，只想知道物流”误分成退款。先看示例中是否把“退款”关键词直接当作标签，再检查否定词是否被截断，最后用包含否定、改口和多诉求的开发样本扩充示例。选定新提示后，回到保留的独立测试集重新测量，而不是只验证刚刚发现的那条错例。以上流程是可复现的实践设计，不是已运行的线上实验。

## 面试追问

**少样本学习和微调有什么关键区别？** 论文的少样本评测把示范放在模型输入中，推理时不更新权重；微调通过训练改变部分或全部参数。两者都需要关注示范质量和任务划分。

**参数更多是否保证任何任务都更好？** 不能。论文展示了不少随规模改善的结果，也保留了阅读理解、常识和其他任务上的不足；任务、提示、评测预算和训练数据都影响比较。

**闭卷问答能证明模型没有记住网页吗？** 不能。闭卷只说明评测时没有提供外部检索内容；训练语料可能含有相关资料或测试重叠。

**为什么 GPT-3 生成流畅文本仍可能答错？** 训练目标鼓励预测文本续写，而流畅续写与事实核查是不同目标。对可核验的知识应引入来源、验证或人工复核。
