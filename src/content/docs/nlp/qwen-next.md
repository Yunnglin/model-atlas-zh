## 要解决什么问题

历史越来越长，每生成一个 token 都查全部历史会越来越贵。Qwen3-Next 研究怎样兼顾成本和信息读取。80B-A3B 分别描述总参数与每步激活参数，不是只有 3B 权重要存储。[系列位置](/nlp/qwen/)。

## 结构与数据流

核心是**混合注意力**：组合 Gated DeltaNet 与 Gated Attention。前者可以粗略理解为持续更新压缩记忆，后者保留直接查阅历史的能力。压缩怎样影响细节保留，需要具体任务验证。

[MoE](/foundations/moe/)让每个 token 只调用部分专家，与处理历史的注意力不同。多 token 预测 MTP 增加预测后续位置的训练目标，也能支持推理加速，但依赖框架实现，不是所有运行方式都会自动启用。

### 用读会议记录理解两种记忆

想象一份会议记录：开头说“预算 20 万”，中间反复讨论，结尾改成“预算 18 万”。普通注意力像保留逐页材料，提问时按相关性翻查；线性递推像边读边更新一块工作板。工作板大小不随记录逐字增长，但它不是原文的无损压缩，能否保留数字、覆盖旧值，要靠学到的更新规则。

Gated DeltaNet 不只是把新信息不断累加。Delta 更新会比较“当前片段的键（key）对应的已有记忆值”与“现在应写入的值”，用差值修正；门控再控制旧状态保留和新信息写入。类比是把预算从 20 改成 18，而不是把 18 接在 20 后面。实际记忆是连续矩阵，没有人工编好的“预算”字段。

80B-A3B 的 48 层按 12 组组织，每组 3 个 Gated DeltaNet 层加 1 个 Gated Attention 层，每层后面还有 MoE。全注意力层仍有历史 K/V，所以整个混合模型并非没有 KV Cache。门控注意力对注意力输出作数据相关的筛选，和线性层的记忆更新不是同一个门。

该型号每层有 512 个路由专家，每 token 选 10 个，另有 1 个共享专家。把它想成有很多加工工位、每次只开部分工位；工位属于前馈计算，不能拿“10 个专家”去解释“记住 10 段历史”。这些数值只对应此型号。

头数也要分层看：官方 Instruct 模型卡列出 Gated Attention 的 16 个查询头、2 个键值头；Gated DeltaNet 则是 16 个 QK 头、32 个 V 头。它们属于两种不同的注意力路径，不能把一个路径的头数套进另一个路径，也不能只根据头数判断效果。

全注意力的每头维度为 256，其中旋转位置编码作用于 64 维。可以把一头的表示想成一排 256 个数字：位置编码处理其中约四分之一，而不是把每个数字都旋转。这个比例描述的是配置，并不意味着剩下的维度无法参与注意力；它们仍与其他维度一起用于计算。

以 8192 个 token、单条序列和 BF16 缓存为例：48 层中有 12 层 Gated Attention，每层 2 个键值头、每头 256 维，K 和 V 各存一份。仅这些注意力层的缓存约为 `12 × 2 × 2 × 256 × 8192 × 2` 字节，即 **192 MiB**。DeltaNet 的递推状态、模型权重和框架工作空间要另算；混合结构让我们能清楚地分别观察两种历史处理方式的资源开销。

## 数据与训练

Base 学习基础知识与生成；后训练版本影响指令和思考行为。Instruct 模型卡列出预训练 15 万亿 token，而[初版 Qwen3](/nlp/qwen3/)技术报告列出约 36 万亿 token；两者对应不同模型和训练记录。训练 token 数不是模型参数量，也不能只据此判断哪个模型更适合某项任务。官方没有在模型卡逐项公开此版本的所有数据配方。

复现应用要固定模型 ID、模板与框架。模型卡指出部分实现不普遍支持 MTP，不同运行方式的速度差不能全算在架构上。

例如总结长手册，先定位章节，再基于证据回答，能帮助区分“没找到”与“找到但推错”。

### 一种训练目标，可能有不同计算方式

基础生成仍学习正确的后续 token。线性层训练可以使用分块并行算法，生成时逐步更新状态；“生成采用递推”不等于训练只能一个字一个字串行。

MTP 增加后续位置的预测学习信号。用于投机解码时，可以先提出多个候选，再让目标路径验证；接受率、额外计算与实现共同决定收益，不能把提出几个 token 写成无条件快几倍。Next-Instruct 是非思考检查点，Thinking 是另一个检查点，先选对权重再比较。

## 评测怎么看

同时测长文定位、跨段推理、首 token 延迟、生成速度与显存。控制输入长度、批量、精度和硬件。短问答速度不证明长上下文能力，单个检索题也不证明能理解整本书。

### 设计一道能检查记忆的题

在构造记录中固定“最终预算 18 万”，分别把修改放在前、中、后段，再加入相似项目的预算。先问最终金额，再问“旧预算比新预算多多少”。第一题检查定位与更新，第二题还要保留旧值并比较；前者答对，不代表后者也会。

把同一记录的 token 数、实际输入是否截断和逐题答案保存下来。效率分开记录读取长输入的 prefill 和后续 decode，显存分开看权重、全注意力缓存和递推状态。只有这些条件相同，才适合讨论结构省了哪部分成本。

例如 Instruct 模型卡在 MMLU-Pro 上列出 80.6，在 BFCL-v3 上列出 70.3。它还列出原生上下文 262,144 token、可扩展到 1,010,000 token；扩展需要兼容框架和配置，能装下不等于模型能准确找回所有信息。前者侧重多学科问题，后者涉及函数调用，两者不是同一份题的成绩，不能把差额解释成能力退步；不同模型或部署环境的提示、工具和评分也需要核对。模型卡另一项长输入吞吐比较针对 Base 与 Qwen3-32B-Base、长度超过 32K 的官方实验，不能写成任意设备或任意长度都快 10 倍。

### 一百万 token 是怎样配置的？

上下文窗口要同时容纳输入和输出：假设提示占 250,000 token，原生 262,144 的窗口就只剩 12,144 个位置给后续生成；如果提示、历史和预留回复超过原生窗口，应用必须缩短内容或启用可用的长上下文配置。这里忽略模板等额外 token，是帮助计算预算的例子。

[Instruct 官方模型卡](https://huggingface.co/Qwen/Qwen3-Next-80B-A3B-Instruct#processing-ultra-long-texts)给出的扩展方案使用 YaRN：以 262,144 为原始位置长度，配置缩放因子 4，并在支持的推理框架里将最大长度设为 1,010,000。YaRN 调整位置编码的处理方式，不会替你压缩输入，也不会去掉混合架构中 Gated Attention 层的 KV 缓存。启用后还要让模型配置、服务长度限制和输出预算一致，再用目标任务检查准确率与资源占用。

## 应用与错例

远处信息丢失，先排除截断与位置配置，再改变证据距离和干扰数量测试。局部正确、跨段组合错误时，补关系推理样本，而不只是继续拉长输入。保留旧错例，并用未见过的同类样本回归。

### 长文本失误要区分读取、记忆与计算

假设会议记录分三处写了预算：第一处为 20 万，后来改成 18 万，最后批准的版本又附加“其中 3 万是税费”。如果问“最终预算是多少”，答案需要优先使用后来更新的数；如果问“未含税预算”，还要按题目提供的规则判断能否计算。模型给出 20 万，可能是忽略更新、截断了最后一段，也可能把相似项目的旧值当成当前项目。先查看实际送入模型的完整文本，再把更改位置提前或后移，才能找到发生问题的环节。

一个有用的对照是保持所有数字不变，只调换更新顺序；再保持顺序不变，把干扰预算放在更靠近问题的位置。每次只改变一个条件，并保存分词后的长度、模板、模型版本和完整输出。如果系统先把文本压缩成摘要，摘要丢了最后一次修改，就应先查摘要过程；不能把缺失的信息当成线性记忆机制单独造成的错误。

### 线性状态与 KV Cache 为什么不能混成一个数字

DeltaNet 层用固定形状的递推状态更新历史表示；一层状态大小不按每个历史 token 一直增加。这个特征有助于理解长序列成本，但固定大小不等于绝不会覆盖旧信息，也不保证模型能原样恢复每个细节。混合结构中的 Gated Attention 层仍需处理自身的历史键值，运行框架还会占用模型权重和工作空间。因此应分别报告权重显存、全注意力缓存、递推状态、输入长度与并发，而不是看到“线性”就写成整套服务显存完全不随上下文增加。

### 提速要看候选是否被接受

多 token 预测可以让系统一次提出一组可能的后续，再交给目标路径核验。假设一次提出三个候选，核验发现前两个符合要求、第三个不符合：能接受的前缀长度、额外提出候选的代价和核验开销共同影响速度。这个过程是教学说明，不代表某个框架一定这样配置，也并非实际测得的接受率。对照时应固定精度、硬件、批量、提示长度和实际使用的推测解码实现，分别记录首 token 与后续生成速度。

### 如何构造可回归的长记录

将同一教学记录拆成训练／开发和独立测试两组，按会议或项目来源划分，避免只把同一份记录替换数字就作为新测试。对开发集发生的失败标注“输入缺失、更新顺序、相似项目混淆、答案计算、格式解析”，再选择对应方案：截断问题改输入组织，证据齐全但总选旧值才进一步研究提示或训练数据。修复之后，用未见过的新项目与不同修改次数验证，避免模型只记住那个 20 万到 18 万的例子。

## 比较与面试追问

**线性注意力与 MoE 能互相替代吗？** 前者处理历史，后者分配专家计算，不是同一层问题。

**Next 与 3.5 是同一个模型吗？** [3.5 → 3.8](/omni/qwen38/)还涉及原生多模态及后续训练，结构相关不能证明权重、数据相同。
