## 要解决什么问题

你把一张街景发给助手，问“红色雨伞在哪里”，随后又说“画一张蓝色雨伞下的小狗”。前一个任务需要根据现有图片提取物体、颜色和位置，再用文字回答；后一个任务要根据文字创造一张有细节的图片。两个任务都涉及图片，但关心的信息并不完全相同：理解时抓住“这是一把红伞”很重要，生成时还要决定伞面纹理、光影和背景。

Janus-Pro 是 DeepSeek 在 2025 年发布的 Janus 增强版本，使用统一的自回归 Transformer 主干处理文字、图文理解和文生图。它延续 Janus 的思路：把理解和生成所需的视觉表示分开处理，再交给同一个主干。Pro 的重点改进是训练策略、数据和模型规模；不是在原模型之外直接接入另一个现成的扩散画图模型。

这不意味着模型可以可靠地完成任意图片编辑、生成视频或听懂声音。看图回答与文字生成图片是它公开的两类主要视觉任务；下面的街景、计分及排错流程都是教学构造，没有运行模型得到实验结果。

## 结构与数据流

### 一套主干，两个视觉入口

在看图任务里，图片先经过 SigLIP 视觉理解编码器，得到表示图片内容的视觉特征；理解适配器把这些特征转换到语言主干可接收的空间。用户问题的文本表示与图片特征组成输入序列，Transformer 逐步生成文字回答。视觉特征是数字向量，不是先由一个完美识别器变成了“红伞、小狗、街道”的清单。

在画图任务里，训练系统用另一套 VQ 图像分词器把参考图像压缩成离散的图像 token，作为模型学习预测的目标。文字描述送入同一个 Transformer，模型通过专门的图像预测头逐个预测图像 token，最后由对应的图像解码器将 token 序列重建成图片。生成时没有现成的目标图片供模型偷看；目标图片是训练阶段用来构造监督信号的。

两条路径像一个人用不同工具读图和绘图：看图时更关注物体和语义，画图时还要保留可重建画面的细节。这个比喻帮助理解取舍，不意味着编码器只懂语义而完全不含空间信息，也不意味着视觉任务之间的冲突被彻底消除。两者仍共享主干参数，训练配比变化可能影响各项能力。[Transformer](/foundations/transformer/) 可帮助理解共享主干的自回归处理。

两个适配器在论文中都是两层 MLP。画图时，已经预测出的图像编号还要经过生成适配器转换成主干能处理的向量，再接着预测下一个编号。就像逐块拼图：每放下一块，下一步都要参考之前已放好的块，而不是一次直接输出所有像素。

### 图片 token 不是像素文字

论文中生成分词器的码本有 16384 个编号，并将图像的空间尺寸按 16 倍下采样。以 384×384 的实验图像为例，可将其理解为约 24×24 的图像 token 网格，即 576 个位置。每个位置的编号指向码本中的表示，解码器再把整组表示还原成像素。单个编号不是一个直接可读的中文字，也不是某个确定物体的标签。

假如要求画“蓝伞下有一只白狗”，模型要预测的一串图像 token 共同决定画面内容；前面预测偏了，后续还会受到已生成 token 的影响。离散压缩并非无损，论文指出低分辨率和重建误差会使小脸等区域缺少细节。不要把 576 个图像 token 当成图片里有 576 个独立、语义明确的对象。

理解路径则采用 SigLIP-Large-Patch16-384 编码器。论文实验将输入图像长边调整到 384，再给短边填充；生成训练图像的预处理则以短边缩放、裁切长边为主。两种预处理服务于不同任务：前者倾向保留整张图，后者可能裁去边缘。用户上传长发票后，小字可能因缩放而难辨；即便模型能看图，也不能保证清楚读取每一项。[DeepSeek-VL2](/omni/deepseek-vl2-model/) 的动态分块是另一种处理高分辨率输入的思路，不能直接套到 Janus-Pro。

### 它和扩散画图有什么不同

Janus-Pro 使用自回归方法逐个预测离散图像 token；常见扩散模型则通过多步去噪生成图像。两种都是生成方法，但输入表示、训练目标和运行流程不同。[扩散与流](/training/diffusion-flow/) 介绍另一条路线。自回归并不天然意味着更快、更慢或一定更好，比较速度和画质需要固定分辨率、硬件、采样配置和模型规格。

## 数据与训练

训练分三阶段。第一阶段主要训练视觉适配器和图像预测头，同时固定语言模型；Pro 相比 Janus 延长这一阶段，使模型有更多机会从 ImageNet 类别到图片的任务学习图像表示的初步关联。它不是从零训练语言主干，而是在已有语言模型上接入视觉路径。

第二阶段做统一预训练：混合文字、图文理解和文生图数据，训练主干等模块；理解视觉编码器和生成视觉编码器在这一阶段保持冻结。Pro 移除了 Janus 在此阶段的 ImageNet 类别图像训练部分，直接使用普通图文生成数据，更集中地学习根据较丰富的描述画图。第二阶段的多模态理解、纯文本、文生图数据比例为 2:3:5。例如，按这个比例混合 10000 条样本，就分别是 2000、3000 和 5000 条。这个例子只是帮助理解配比；论文还使用序列打包，不能把批次大小简单等同于独立图片数量。不同任务共用主干，样本比例会影响各项能力。

第三阶段是监督微调，用对话等指令数据改善回答体验，并继续混合多种任务。论文将多模态理解、纯文本、文生图三类数据比例从 Janus 的 7:3:10 调整为 5:1:4；这是第三阶段的配比，不能当作所有训练阶段都使用的比例。此阶段解冻理解编码器，生成编码器仍不训练。不同阶段训练哪些模块，是理解这类统一模型时值得追问的细节。

论文表格给第二阶段列出 360K 步，但实现说明注明采用提前停止，实际停在 270K 步；读训练设置时应把表格计划和正文中的执行说明一起看，不能直接把 360K 写成实际执行量。此处是论文报告的训练配置，并非重新训练结果。

训练规模也要一起看：论文报告 7B 型号用了 32 台机器、每台 8 张 40GB A100，整个训练约 14 天；1B 型号使用 16 台同配置机器，约 9 天。它们描述的是论文的完整训练，不是个人使用时必需的推理硬件，也不能只凭机器数量推算实际训练成本。

在数据方面，论文报告第二阶段为图文理解增加约 9000 万样本，涉及图片描述、表格、图表和文档；生成侧增加约 7200 万合成美学样本，在统一预训练阶段将真实与合成数据按 1:1 混合。这里的样本数量、配比各有对应范围，不等同于独立用户数，也不表示所有合成图都正确。若描述写“红伞”，图片却是蓝伞，就会带来错误监督；筛选、去重和检查图文对应关系仍然重要。

论文使用 DeepSeek-LLM 的约 1.5B 与 7B 语言主干，发布对应的 1B、7B 名称型号；更大模型在论文实验中的损失收敛更快，但不能仅凭这一点断言每种应用都应选择 7B。设备、加载精度、上下文长度、图像生成 token 数和响应时间都影响实际选择。

## 评测怎么看

图文理解和图片生成要分开评测：一张好看的图不证明模型能准确读图，一个图文问答高分也不证明它会画图。论文报告 Janus-Pro-7B 在 MMBench 的分数为 79.2，在 GenEval 的综合分数为 0.80；前者测多模态理解，后者关注生成图片与对象、数量、属性等文字要求的匹配。分数只适用于论文的模型、数据和评测设置，不能解读为任意场景的 80% 画图成功率，也不意味着所有生成质量都超过其他模型。

同一张 GenEval 表里，这个型号在单对象子项得到 0.99，计数子项为 0.59；这提醒我们总分会掩盖任务间差异。比如画出一个苹果和画对多个苹果的数量，难度可能不同。两个数字都是论文的基准子项，并非这里实测，也不应理解成任意图片的成功概率。

用“两个红苹果在蓝盘子里”举例，一张图片可能很好看，但只有一个苹果；另一张数量正确却颜色不对。评测可分别记录对象是否存在、数量、颜色、相对位置和画面质量，再检查自动检测器是否漏检。假设 20 条构造提示中 14 条完全符合要求，则该样本通过率是 70%；这是教学算例，并非模型测试成绩。

看图问答还应区分视觉识别错误、问题理解错误和幻觉。例如模型正确看到红伞，却把“左边”说成“右边”，与根本没识别出伞是两类问题。可以固定图片、改写问题，再固定问题、更换图片，比较模型是否真正利用视觉证据。对于小字、密集表格和长图，384×384 输入分辨率可能造成损失；应保留预处理后的图像，确认问题是否在模型推理之前就已发生。

比较不同系统时还要记录模型版本、分辨率、提示词、随机种子、采样策略、生成张数和挑选方式。如果一个系统从十张图里挑最好的一张，另一个只生成一张，最终满意度不能作为相同预算下的公平比较。自动指标也可能漏掉细节，重要场景应结合人工审核与失败样本分析。

## 应用与错例闭环

假设一个商品海报助手要看懂产品照片，再按文字要求生成配图。先分别评估两步：图片中实际商品是否识别正确，生成图是否满足颜色、数量和布局；系统应说明生成图片是新画面，不应把它当作产品真实照片。不要直接假定 Janus-Pro 支持对原图做精确编辑，若产品流程要求这一能力，需要另行选择工具并验证。

如果要求“两个蓝杯子”却只生成一个，保留完整提示、模型规格、随机种子、预处理和原始输出。先检查提示是否清楚，再区分数量理解、图像 token 生成、解码重建与最终展示问题；对同一提示重复采样可看出错误是偶发还是稳定。不要只保存最好的一张，否则会高估能力。

改进数据时，可以收集不同数量、颜色和位置的高质量图文样本，检查标签是否准确，并按图片来源或提示模板划分开发集与独立测试集。调整提示或训练后，在未参与调试的测试样本上同时观察图文理解、数量和属性匹配、画面质量及耗时；如果一项改善而另一项下降，要进一步检查混合训练的取舍。这是一套实验设计，尚未实际训练或评测。

## 比较与面试追问

**统一模型是否意味着理解和生成用同一个视觉编码器？** 不是。Janus-Pro 使用独立视觉路径，共享自回归语言主干。

**生成时是否需要一张目标图片作为输入？** 推理生成时只需给定相应文字条件；训练阶段用参考图片构造图像 token 目标。

**GenEval 0.80 是否意味着所有生成图都有 80% 几率完美？** 不能这么解释。它是特定基准的综合指标，画质和业务要求还要另测。

**它是否是扩散模型？** 论文描述的是自回归预测离散图像 token，再解码为图片；不要与 JanusFlow 等其他系列混淆。

**图像能输入就说明小字一定可读？** 不说明。论文实验输入为 384×384，细小文字和长图缩放会有信息损失。
