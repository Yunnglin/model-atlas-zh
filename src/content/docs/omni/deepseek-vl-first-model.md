## 要解决什么问题

给一张饮料瓶的照片，问“这是什么、标签上写的容量是多少”。回答第一个问题要看整体外形和场景；回答第二个问题，可能要辨认很小的字。如果把图片缩得太小，瓶子依然看得见，容量数字却可能糊在一起；只放大某一小块，又可能丢掉这块文字属于哪个商品的上下文。

DeepSeek-VL 是 DeepSeek 在 2024 年发布的初代视觉语言模型。它将图片变成一组向量，再把这些向量与问题一起送入语言模型，生成文字回答。下面的商品照片和数字只是用来理解机制的例子，不是论文中的测试样本。系列里的 7B 与 1.3B 并非完全相同的视觉架构：7B 使用两路视觉编码器，1.3B 只使用 SigLIP。阅读参数和结果时应区分两者。

## 结构与数据流

### 图片为什么走两条路

7B 使用的两路视觉编码器可以想成两种不同的观察方式。**SigLIP-L** 将图片处理为 384×384 输入，侧重语义表示，例如画面是饮料瓶而不是书；**SAM-B 图像编码器**接收缩放后的 1024×1024 图片，提供更细的空间特征。SAM 在这里提供图像特征，不等于系统先运行分割工具，再把分割结果当作答案。

两路来自同一张图片，却输出不同的特征。论文描述 SAM-B 得到 64×64×256 的特征图，经插值和两层步长为 2 的卷积，变为 24×24×1024；SigLIP 的输出也整理为 576×1024。24×24 恰好是 576 个空间位置。对每个对应位置，把两路 1024 维特征沿**特征维**拼在一起，得到 576 个、每个 2048 维的视觉表示；不是把两条 576 长的序列接成 1152 个 token。随后通过适配器映射到语言模型的输入空间。

可以把每个空间位置想成一本笔记中的一个格子：一条路径记录“这里大概是什么”，另一条补充“这里有什么细节”。将两份笔记放在对应格子里，语言模型才有机会结合用户的问题使用这些信息。这是理解数据流的比喻，不表示某一维度严格对应某个汉字或物体，也不保证位置对齐后就一定能读清全部小字。

**1.3B 只用 SigLIP。** 论文的实验配置表区分了这一点，因此不能把上面的双路结构、1024×1024 SAM 输入和 576×2048 融合描述直接套给小模型。图示描绘的是 7B，详细层次及训练参数应以论文和实现为准。

### 图片如何变成文字答案

视觉适配器处理两路特征，并将其转换为语言模型可以接收的表示；文字问题也会被分词并映射成向量。语言模型把视觉表示和文本上下文一起处理，再按自回归方式预测下一个 token，逐步形成答案。它的语言底座来自 DeepSeek-LLM 的中间训练检查点，采用 RMSNorm、RoPE 与 SwiGLU 等设计；这些术语可以通过 [Transformer](/foundations/transformer/) 和[位置编码](/foundations/position-encoding/)回顾。

例如图片展示“容量 500 mL”，问题是“容量是多少”，训练目标是让模型在此前上下文的条件下生成对应答案。视觉表示本身不是一个可直接读取的“500”字段，也不是保证真实内容完整保存的无损压缩。用户可以要求模型给出读到的文字和结论，再通过独立 OCR、原图核验或人工抽查排错。

模型可以答错的地方有很多：低分辨率字迹被缩放或遮挡；反光让数字边缘消失；画面中有多个瓶子而问题没有指出是哪一个；语言模型把读到的数字写错单位。给出流畅的解释不能代替确认图片里确实有那些信息。

## 数据与训练

论文采用三个阶段，均以语言部分的下一 token 预测为训练目标，但每一阶段更新的模块与数据不同。这里讨论报告中初代模型的流程，不把后续 DeepSeek-VL2 的 MoE 与图像分块方案套进来。

**第一阶段：先教适配器对齐。** 冻结视觉编码器和语言模型，只训练视觉语言适配器。图像配描述、文档 OCR 渲染等图文对让连接层学习如何把视觉特征送进语言模型可用的空间。论文列出 125 万条图文描述配对与 250 万条文档 OCR 渲染配对；这是该阶段论文所述数据规模，不是全部训练数据量。适配器像两种表示之间的接口，但它不会因为“接口接通”就自动获得所有视觉能力。

**第二阶段：图文和纯文本共同预训练。** 视觉编码器保持冻结，训练适配器与语言模型，同时引入多模态和文本数据。论文在 1.3B 的对照中观察到，仅用多模态训练虽能改善视觉指标，语言指标却下降；最终选择的语言与多模态数据比例约为 7∶3。论文图中还展示其他比例，应留意图上采用的是“多模态∶语言”顺序；数据比例也不等于训练时每个任务的最终准确率。

为什么还要加入纯文本？如果模型在这一阶段几乎只见到简短的图片描述，它可能越来越擅长这种格式，却对长篇文字问题不如原来。纯文本样本帮助它继续练习已有的语言能力，但这种混合不是消除遗忘的万能保证。论文还讨论按模态组织批次，以减少不同类型样本计算时间差异带来的等待；实际效率取决于设备与实现。

论文还做了一个“循序渐进”的安排：开始时只用纯文本，随后逐步增加图文数据，直到达到目标比例。可以想成先让语言模型熟悉原来的练习，再慢慢加入看图答题，而不是第一步就把练习内容全部换掉。报告在其对照实验中观察到，这种模态预热减轻了训练初期语言能力的下降；具体效果仍取决于数据和训练设置。

**第三阶段：监督微调。** 使用图文指令和纯文本对话数据训练，使模型更适合回答用户的问题；7B 设置中训练语言模型、适配器及 SigLIP，SAM-B 因显存限制保持冻结。损失只监督回答和特定标记，对系统与用户提示位置进行掩码。比如用户给图问容量，训练时不会要求模型把用户问题也当作自己的答案背出来；实际特殊标记和掩码位置要看使用的训练模板。

数据来源覆盖通用图文、文字识别、表格及截图等场景，也包含纯文本。图片是否清晰、标注是否与图片一致、文本是否包含敏感信息都影响训练效果。对于项目数据，先将相近图片、同一商品或同一文档按来源划分，防止同一个样本不同裁剪同时出现在训练与测试中。

## 评测怎么看

论文表 5 中，DeepSeek-VL-7B 在 MMBench 开发集为 73.2，MMBench-CN 开发集为 72.8，OCRBench 为 456；表 6 中 1.3B 对应 MMBench 为 64.6、OCRBench 为 409。这些是不同基准各自的分数，OCRBench 不是“456%”，不能把不同列直接求平均当作真实产品成功率。论文说明因当时官方测试集下载不可用，MMBench 使用开发集；模型版本、基准版本、提示和计分方式都应一起记录。

多模态测试使用贪心解码生成回答并解析结果；纯文本多选评测中的 MMLU 和 HellaSwag 则按候选困惑度选择。**同一张表中的不同任务可能使用不同协议**。对比时要确认是生成答案、候选打分还是其他方法，不要把两种分数当成同一次开放式问答表现。

论文表 7 里，7B Chat 的 HellaSwag 为 68.4，DeepSeek-LLM 7B Chat 为 68.5；GSM8K 则分别为 55.0 和 63.0。这提醒我们，“加入视觉后某项语言分数接近”与“所有文字能力没有变化”是两件事。这里引用的是论文中的模型与测试设置，不代表后续版本或新数据上的结果。

在自己的商品图片任务中，可以预先准备按图片来源分开的测试集，分别记录物品识别、数字识别、单位识别和最终回答正确率。若 100 张测试图片中 80 张物品识别正确，其中只有 60 张数字和单位也完全正确，那么整体正确与局部识别正确就要分别报告。这里的 100、80、60 是帮助理解指标的构造例子，不是官方测试结果。还要记录图片分辨率、裁剪、提示词和输出预算，才能比较不同模型或不同部署方案。

## 应用与错例分析

假设系统把标签上的“500 mL”答成“50 mL”。先保存原图、输入缩放后的图、用户问题、模型输出、模型版本与推理设置；确认标签是否被裁掉、数字是否因压缩变模糊、图片里是否存在多个容量。再检查错误属于视觉识别、对象选择、单位转换还是后处理解析。只让模型“再仔细想想”并不能告诉我们哪一步出了问题。

数据改进可以包括清晰度不同的同类标签、不同位置的小数字和易混淆单位，同时为错误答案设置可靠标注。调整训练数据或提示后，使用未参与修改的图片检查是否真的改善，并同时关注物品识别等原有能力是否退化。对于医疗、财务等高风险信息，最终结果应经过具备相应能力的人员核验；图文模型的流畅回答不是可靠性证明。

## 面试追问

**7B 为什么要两路视觉编码器？** 报告希望结合较强的语义表示与高分辨率细节；两路各有计算成本，实际收益要看任务和实现。

**两路各有 576 个视觉位置，是否变成 1152 个？** 论文的 7B 方案沿特征维拼接，仍是 576 个位置，但每个位置的特征维度变大。

**1.3B 也有 SAM-B 吗？** 报告配置中 1.3B 使用 SigLIP，7B 使用 SigLIP 与 SAM 的组合。

**为什么图文训练还混入纯文本？** 避免视觉数据训练严重挤占已有语言能力；报告通过实验观察混合比例的影响，而不是保证完全没有遗忘。

**Base 和 Chat 有何区别？** Base 是预训练后的基础检查点；Chat 经过指令微调，更适合按用户问题回答。具体任务表现仍需分别评测。
