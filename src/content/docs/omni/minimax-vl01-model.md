它与 MiniMax-Text-01 共用语言模型路线，但 VL-01 加入视觉输入与专门多模态训练。下文用构造的账单和图表示例解释过程，并不代表已经运行模型。

## 要解决什么问题

想象一张拍下来的水电账单：最上方有收款单位，中间是密集表格，最下面是合计金额。用户问“本月合计是多少？和上月相比多了多少？”模型不仅要知道图片是一张账单，还要找到对应的行、分辨小字、理解哪个数字属于哪个月份，最后做比较。把整张图缩成很小的方块，表格可能糊掉；只盯着放大的数字，又容易忘记它对应的是哪个表头。

MiniMax-VL-01 用两种视角处理同一张图片：一张缩略图照顾整体布局，多个局部块保留细节。视觉编码器把它们变成表示，投影器负责把表示转换到语言模型能使用的空间，语言模型再结合问题生成答案。这个过程让模型有机会同时参考局部与全局，并不保证每一个数字都能看清。

## 结构与数据流

### 一张图片，先分成几份

模型根据预设网格调整输入分辨率，范围从 336×336 到 2016×2016，再按 336×336 切成不重叠的局部图片；另生成一张 336×336 缩略图。比如一张图选择 672×672 网格时，会得到 2×2 共四个局部块，加上一张缩略图，共五份视觉输入。具体网格由预处理规则决定，原始图片尺寸不会自动等于使用的网格。

缩略图像拿在手上的整张账单，可以帮助模型知道标题、表格与页脚的大致关系；局部块像用放大镜查看其中某些区域。两者分别经过同一个视觉编码器，得到的特征再拼接，保留多个尺度的线索。切块边界处的文字可能被分开，缩放也会改变细节，因此处理后仍可能出现误识别。

### 图片怎样变成语言模型可读的线索

视觉编码器采用 ViT-L/14，约 3.03 亿参数。对一块 336×336 图片，按 14 像素的视觉 patch 尺寸，可以理解为每边 24 个小位置，即 24×24＝576 个位置。注意这里的“小 patch”是视觉编码器内部的粒度，上面 336×336 的“局部图块”是对原图预处理时切出的较大图片；两个名字很像，却处在不同层级。

编码器利用注意力在小位置之间交换信息，得到视觉特征。两层 MLP 投影器把视觉特征映射到 MiniMax-Text-01 所需的输入表示；随后模型结合图片表示和用户问题，按自回归方式一个 token 接一个 token 地生成回答。图像特征不是已经确定正确的文字转写，投影器也不是一个保证识别无误的 OCR 程序。

论文强调利用语言模型处理长序列的能力，直接使用编码后的高维特征，而不是把所有特征先池化成少量向量。这样可能保留更多细节，但图块越多，视觉序列越长，计算、显存和输入预算也会增加。具体视觉 token 数还受实现中的特殊标记、处理方式影响，不能仅用“块数乘以 576”当作所有部署的精确计费数字。

### 语言骨干为什么同时使用两种注意力

MiniMax-Text-01 骨干是 MoE 模型，报告说明共有约 456B 总参数、每 token 约 45.9B 参数参与计算。可以把专家想成众多可选的加工模块：一个 token 不需要经过全部专家，但部署仍要存放或调度大量权重，不能把激活规模当作完整模型显存。

注意力部分采用混合设计：每八层中七层使用 Lightning Attention，另一层使用 softmax 注意力。线性注意力通过维护和更新状态来处理序列，长序列计算方式不同于每次都显式比较所有位置；保留的 softmax 层仍有自己的计算与缓存成本。两种结构混用意味着不能把整个模型说成“所有开销都随长度严格线性增长”，更不能把长上下文容量当作每一处信息都能准确取回的保证。

这套语言骨干与 Text-01 同属一代，但 VL-01 的视觉能力还取决于图像编码器、投影器和多模态训练。图像问题的表现不能直接从纯文本模型的长文成绩推断。注意力的基础概念可先读 [注意力机制](/foundations/attention/)，专家路由可看 [MoE](/foundations/moe/)。

## 数据与训练

### 先教视觉编码器看图

报告描述视觉编码器从头训练：使用图像和描述之间的对比学习，并结合文字生成的交叉熵目标。可以把它想成同时做两件事：给一批图片找对应的描述，让不匹配的组合距离远一些；再根据图片生成描述，让表示保留可以说出来的细节。论文报告编码器在 224 分辨率训练经历 370 亿图文对输入，再在 336 分辨率继续训练 12 亿图文对输入；这类训练处理次数不能直接当作互不重复的原始图片数量。

报告也提到训练数据包含图像描述、较长的详细说明与指令数据：短描述帮助辨认图片大意，详细说明可以涵盖多个对象及其关系，指令数据则让模型练习按问题回答。实际资料中的标注会遗漏、模糊甚至写错，应检查图文是否匹配，不能因为样本量大就假设标签完美。

### 多模态四个阶段，各自练什么

第一阶段做模态对齐：训练视觉编码器和图像适配器，让图片信息能被语言模型用于生成描述；报告使用约 800 亿 token 的图像描述数据，并固定 336×336 输入。可以理解为先让两个模块学会“交接”，但这还不是完整的多任务问答训练。

第二阶段增强视觉理解：所有模型参数可更新，加入约 4200 亿多模态 token 的指令数据，并以约 20∶1 的比例混入 Text-01 的后训练数据。比如同一张账单可以配“这是什么文档”“合计是多少”等不同问题；混入文本数据是为了让模型在获得视觉能力时继续练习语言任务，不代表文字能力永远不会退化。

第三阶段聚焦用户体验：构造更接近真实使用的图片与多轮对话，训练约 448 亿多模态 token、一个 epoch。对于上面的账单，用户可能先问“是什么”，接着追问“比上月多多少”；数据需要把追问和前文关联起来，并保证回答确实能从图中找到依据。

第四阶段是偏好优化：构造约四万组图文相关偏好数据，用 [DPO](/training/dpo/) 比较较好和较差的回答，并混入纯文本偏好数据。论文描述使用模型辅助评分，选择高低分差足够大的候选，同时在一个 epoch 完成前提前停止，以减轻过拟合。评分器和候选构造仍会出错：一段很流畅的答案可能把图中金额看错，因此仍需人工抽查。四阶段的数字是不同类型的统计口径，不能简单相加解释成独立图片总数。

## 评测怎么看

报告表 13 将 VL-01 用于不同视觉任务：MMMU 的 val+dev 为 68.5，DocVQA 为 96.4，OCRBench 为 865，MathVista testmini 为 68.6；带星号的项目采用零样本思维链设置。MMMU 检验综合视觉知识，DocVQA 关注文档问答，OCRBench 覆盖图中文字任务，MathVista 包含视觉数学问题。它们使用不同数据和评分方法，865 不是 865%，更不能把各列直接平均成真实业务成功率。

再看长文档：论文的 MMLongBench-Doc 准确率为 32.5，文中还列出单页 47.3%、跨页 28.4%。同一个模型在跨页场景表现较低，提醒我们“可以输入很长的材料”和“能找准跨页证据”是两件事。与其他模型比较时，需要同时核对测试集、版本、提示、是否允许思维链和输出预算；厂商报告的结果不是本地复现实验。

要评测账单场景，可准备来源分开的独立照片：分别覆盖平整页面、倾斜、反光、小字和多个账单同框。逐项记录找对表格、抄对数字、找对月份、运算和最终答案。假设 100 题中 85 题找对数字，但只有 72 题最终回答完全正确，这两个数字回答不同问题；它们只是教学示例。最好保存图片预处理结果和回答，再按错误类型切片，而不只看一个总分。

## 应用与错例分析

假设模型把“本月 128 元、上月 108 元”读成“本月 128 元、上月 180 元”，得出减少 52 元。第一步不要只反复催它“再算一遍”：先检查原图，再看缩放后图块是否保留了上月数字、数字是否跨块、文字与表头有没有被对应错。也要排查模型是否正确读到 108，却在后续运算或单位转换中出错。

如果小字在缩放中丢失，可调整图像裁切与分辨率，在开发集比较不同处理策略；如果同一账单存在多个相似数字，应补充可验证的对象定位和表头对应样例。收集错例时保留原图、预处理版本、提示、模型版本和预期答案。数据调整后要用未参与修改的账单做复测，也关注原本能解决的普通图片问题有没有退化。

## 面试追问

**为什么要保留缩略图？** 它提供整张图片的布局；局部图块保留细节，二者可以互补，但都可能损失信息。

**336×336 的图块和 ViT 的 14×14 patch 是同一件事吗？** 不是。前者是从输入大图拆出的图片，后者是视觉编码器进一步处理的内部位置。

**线性注意力意味着总推理成本与长度完全线性吗？** 不能这样概括。骨干还保留 softmax 注意力，图像块数量、权重读取和实现也会影响成本。

**能直接拿 Text-01 的语言评测证明 VL-01 图像理解好吗？** 不能。VL-01 还依赖视觉处理与多模态训练，应该测对应的视觉任务和版本。
