**名字容易混淆。** [GLM-4.5](/nlp/glm45-model/) 文本主模型约 355B 总参数、32B 激活；GLM-4.5V 使用的是同系列的 GLM-4.5-Air 语言基础，并加入视觉编码器和适配器。106B 和 12B 不是说部署只需要保存 12B 权重。也别把 2024 年的 [GLM-4V](/omni/glm-v-model/) 与此版本当成同一检查点。

## 要解决什么问题

假设你把一张报销系统截图交给助手：“找到提交按钮，看看金额有没有填错。”它要读懂表单中的文字，区分“保存草稿”和“提交”，还要根据问题指出位置。如果截图里有多个相似按钮，模型需要把文字线索和屏幕上的位置联系起来。

这里的模型负责根据输入产生回答或动作描述，**真正点击按钮的是外部程序**。它不能凭一句“提交成功”证明系统状态已经改变：还需要执行器返回操作结果，必要时再读取下一张截图。这个例子只是帮助理解数据流，不是论文中的一条实际测试。

## 结构与数据流

模型可以看作三位协作者：视觉编码器把图片变成一串视觉特征；适配器把这些特征转换成语言模型能接收的表示；语言解码器把视觉表示和用户文字放在一起，逐步生成答案。它们都在一个推理链路里，但各自承担不同工作。可先回顾 [Transformer](/foundations/transformer/) 和 [MoE](/foundations/moe/)。

### 视觉编码器：把图片整理成可用线索

报告说明视觉部分以 AIMv2-Huge 初始化，并将原有二维卷积改为三维卷积，让视频帧在时间维上进行两倍下采样。对单张图片，输入会复制以保持处理形式一致。这不等于“同一张图片看两次就能获得更多细节”；它是适配该输入处理方式。

输入的图片宽高比和分辨率可以变化：例如手机截图又高又窄，表格可能很宽。报告在视觉 Transformer 中加入二维旋转位置编码，保留原可学习的绝对位置嵌入，并用插值适应不同尺寸。可以把它想成给一张地图上的小块标记“第几行、第几列”；这帮助模型处理空间关系，但不保证每个微小文字都能被看清。

视频不是无限长地逐帧完整观看。预处理会按配置选择帧并转成视觉输入，报告在每帧特征后添加时间索引 token，帮助模型理解帧的时间顺序。比如一个人先拿起杯子、后放下杯子：如果只看一帧，可能不知道先后；时间信息让多帧具备顺序线索。但如果抽帧跳过了真正发生动作的瞬间，输入里就可能缺少重要证据。实际采样数量和时长还要看处理器与服务配置。

### 适配器：给两种表示搭一座桥

视觉编码器输出的是向量，而语言模型平时处理文字 token 对应的向量。MLP 适配器把前者映射到语言模型的输入空间；它不是独立的 OCR 工具，也不是把图片先翻译成一篇完整文字再交给模型。语言解码器结合视觉表示与问题，在上下文中预测下一个 token。

例如截图上写着“金额 500 元”，用户问“金额是多少”。模型可能生成“500 元”，也可能因小字模糊或关注到另一行而答错。适配器让信息能够进入解码器，不代表图像中所有细节都会无损地被保存。需要核验时，可以要求系统把原图区域和识别结果一起展示，再对照截图。

### 混合专家：计算多少与保存多少

GLM-4.5V 的语言部分采用混合专家架构。可以把它想成有很多工作台：每个 token 经过路由，选择一部分专家参与处理，注意力等共享计算仍然存在。不同 token 选择的工作台可能不同，但不要把某个专家想成固定负责“表格”或“猫”的人工分类器。 [官方配置](https://huggingface.co/zai-org/GLM-4.5V/blob/main/config.json)列出语言部分 46 层，前 1 层使用稠密前馈网络，后续层使用 MoE；每个 MoE 层有 128 个路由专家，每个 token 选择 8 个，另有 1 个共享专家。这些配置对应本版本，不能拿来描述其他 GLM 模型。

约 106B 的总参数描述模型拥有多少参数；约 12B 激活描述每个 token 的近似参与规模。部署还需要保存或分布式调度大量权重，另有视觉输入、KV 缓存、通信和运行时工作区。一个长视频切成很多帧后，视觉 token 增多，延迟和内存可能明显上升；不能只拿 12B 与一个稠密文本模型的显存简单画等号。

### 思考、定位与实际动作

模型支持思考和非思考两种输出模式。复杂的图表分析可能需要更长过程，简单识别可能适合直接回答，但是否更准确、耗时多少，要在具体任务和预算下比较。思考写得多并不意味着每一步都可靠。

视觉定位可以要求输出目标的边界框，报告附录给出 `[x1,y1,x2,y2]` 形式，坐标分别按图片宽高归一化到 0–1000。假设图片宽 1000、高 500，返回 `[200,100,400,300]`，换回像素后左上角约为 `(200,50)`，右下角约为 `(400,150)`。这只是坐标换算示例：如果图片被缩放、裁剪或旋转，还必须使用与模型输入一致的尺寸和变换关系。格式正确的框也可能框错按钮。

## 数据与训练

论文介绍了多模态预训练、监督微调和强化学习组成的训练框架，也讨论 GLM-4.1V 和 GLM-4.5V 的共同设计。阅读具体实验时要确认它属于哪个版本；不能把 4.1V 的单独消融结果直接说成 4.5V 的实验。

### 预训练：先见过不同类型的图文

报告描述图文交错网页与书籍、文档与图表、自然场景文字、定位、视频及指令等数据来源。图文交错样本像一本图文手册：有时答案需要读图片里的曲线，有时需要结合相邻段落，不能只依赖一张配图的简单标题。对 OCR，论文描述合成文字图、自然场景文字以及论文页面解析等数据构建方式；自动标注与筛选仍可能引入错误，因此标注与页面内容要抽查。

报告的预训练配方先处理多模态数据，再通过包含视频与长序列的数据继续训练：前一阶段序列长度为 8192，长上下文阶段为 32768。报告中另有 GLM-4.6V 延伸到 131072 的阶段，**不要把它直接写成 4.5V 的同一次训练设置**。具体训练样本及各来源完整清单不能由这些概述反推。

### 监督微调：学会按要求回答

[SFT](/training/sft/) 给模型示范“看到这张图、收到这个问题时，怎样组织回答”。比如图上有三根柱子，问题问“哪一年最多”，示范需要先读图例与对应的柱高，再写结论。若示范把颜色对应的年份写错，即使句子流畅，也会给模型错误信号。

报告描述使用多领域推理数据，并在 GLM-4.5V 中混合思考与非思考数据，以支持两种模式。训练数据还应区分任务：定位题需要框的位置，文档题可能要跨页找到出处，代码题要检查生成的界面能否运行。把视觉问题都压成简单的图片描述，可能让模型缺少需要的操作示范。

### 强化学习：挑合适的题，检查可验证结果

报告提出课程采样的强化学习框架 RLCS：先从多领域任务中生成候选回答，再利用奖励信号评估，并根据模型当前表现调整采样。它像练习册里的选题：已经全会的题、怎么试都不会的题，可能都很难提供有区分度的组内反馈；适当选择中等难度的题有助于提高训练效率。具体实现的采样和更新步骤应看报告，不能把它等同于某个固定奖励函数。可结合 [RLVR](/training/rlvr/) 学习奖励来源。

具体怎么挑题？报告先用已有模型或早期检查点多次作答，结合人工标注，为题目划分初始难度；训练时再根据当前模型的作答结果更新难度判断，动态降低过易和过难题目的抽样比例。比如一道读图题最初经常答错，后来模型大多数尝试都答对了，它可能从“有区分度”变成“太容易”。采样调整的是模型练哪些题；真正的策略更新在报告中使用 [GRPO](/training/grpo/)，奖励可以来自规则或模型评分。这个读图题是教学例子，不是报告中的实验样本。

论文强调不同任务需要不同验证器。数学里的 `43` 与 `43.0` 通常表示同一个数；OCR 要求忠实抄写时，原图写的是 `43.0`，漏掉小数可能就不合格。对图表数值，报告讨论相对误差容忍；对文本答案可先做精确匹配，必要时再用模型判断语义是否相近。验证器本身也可能出错：例如模型回答“一个介于 0 到 10 的正确数字”，某些不严谨的评分器会误以为它给出了答案。奖励升高时，应同时检查独立测试和评分器有没有被钻空子。

## 评测怎么看

[报告表 2](https://arxiv.org/html/2507.01006)中，GLM-4.5V 的 **thinking** 列在 MMMU 验证集为 75.4，在 MathVista 为 84.6，在 MMBench V1.1 为 88.2。这些是论文所列任务和评测设置下的结果，不是所有图片问题的正确率，也不应直接套给非思考模式、GLM-4.5 文本模型或 4.6V。MMMU 侧重多学科图文问题，MathVista 侧重视觉数学推理，MMBench 覆盖多种视觉问答，三项测的侧重点不同。

对 GUI 智能体，报告表中 GLM-4.5V 在 OSWorld 为 35.8，脚注使用 **100 步预算**。这衡量的是模型与提示、工具执行器、环境和预算组成的系统；不能理解为“单看截图就完成了 35.8% 的所有电脑任务”。一次真实任务中，模型找到按钮不代表外部程序点击成功；执行失败、等待时间和网页变化都可能影响最终结果。

报告说明图像输入预期上限为 6144 token、视频基准为 48000 token，模型单次回答最大输出为 8192 token；需要模型抽取或评分的基准使用 GPT-4o 作为评审。论文要求每项基准成功请求率至少 95%，并将生成或 API 故障排除在评分外。换用不同提示、最大长度、帧采样、截图尺寸或错误处理，结果不能直接当作同一口径。

如果要做报销截图助手，可准备来源互不重叠的 100 个界面样本，分别检查金额读取、目标按钮定位和最终操作是否成功。假设 85 个金额读对，70 个按钮框正确，真正完整执行成功 60 个，这三个数字回答的是不同问题，也不是 GLM-4.5V 的官方成绩。再按小字体、遮挡、相似按钮、不同缩放比例切片，才能知道系统应该先改哪一步。

## 应用与错例分析

用户问“提交报销”，模型却圈出了“保存草稿”。先保留原图、输入缩放后的图、提示、模型版本、输出框和执行器日志：是图像被裁掉、按钮相似、坐标换算错了，还是网页已经变化？如果模型找对了按钮但工具点偏，应优先修正执行或坐标转换，而不是把所有问题都归咎于模型。

数据改进可以增加按钮相似但含义不同的截图，标明目标框与操作后状态；同一个页面的不同截图尽量按来源分组，避免训练集和测试集只差一个裁剪。训练或提示修改后，在从未参与调参的新页面上同时测定位、动作成功率和误点率。如果任务涉及不可逆操作，应让系统在执行前进行合适的人工确认；模型输出坐标不是操作授权。

## 面试追问

**GLM-4.5V 与文本 GLM-4.5 有何不同？** 前者接收视觉输入，使用视觉编码器、适配器和基于 GLM-4.5-Air 的语言部分；文本主模型的 355B/32B 数字不能套到它身上。

**能否仅用 12B 激活参数估算部署显存？** 不能。还要考虑完整专家权重、视觉编码、缓存和运行时资源。

**输出坐标代表已经点击吗？** 不代表。坐标是模型输出；执行由外部系统负责，结果必须从环境反馈确认。

**RL 的奖励高说明推理每一步都正确吗？** 不一定。结果验证、过程质量和奖励模型误判是不同问题。
