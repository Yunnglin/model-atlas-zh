官方模型卡称图像理解测试最多覆盖 5 张输入图；这不是任何框架的五张硬上限。用户实际可用的上下文、图片数量及精度取决于提供方、实现、资源和输入条件，模型卡数字不保证每种部署都能达到。官方预训练数据知识截止时间为 2024 年 8 月。

## 从一张发票说起

假设你有一张发票照片，问模型：“票面金额是多少，日期是几号？”模型需要把图像内容和文字问题结合：既看见具体字符，也理解问题要找金额而不是税额。输出是文字回答，不是编辑过的发票图片。若照片模糊或关键信息被遮住，它可能读错、猜测或者说看不清；因此不能因为回答流畅就自动相信数字。

Llama 4 的 Scout 和 Maverick 是 Meta 发布的文本与图像理解模型，采用混合专家架构，也称 MoE。它们的开放权重为研究和部署提供了入口，但使用权受 Llama 4 自有社区许可和可接受使用政策约束。多模态在这里指官方模型卡列明的文本、图片输入与文本、代码输出，不能因为名字里有“多模态”，就推断这两份权重能直接收发音频、生成视频或输出图片。

下面用虚构发票说明工作流程。处理真实票据时，需要保护数据隐私，并核对关键金额。

## 两个版本如何选择

Scout 有 16 个专家，总参数约 109B；Maverick 有 128 个专家，总参数约 400B。两者每个 token 的激活参数都约为 17B。可以把它们想象成两家不同规模的顾问团队：每次问题只请其中部分顾问参与，但团队里所有顾问的资料仍需要存放。专家数量、模型层和路由安排不同，因此“激活参数一样”既不代表能力一样，也不代表显存需求相同。

官方列出的窗口是 Scout 10M、Maverick 1M token。窗口只是一次输入与输出可以占用的最大预算，不意味着模型对其中每个细节都理解得一样准确，更不意味着普通设备或每个托管服务都能接受这么长的输入。图片经过处理也会占用模型侧资源，具体折算方式取决于处理器和实现。

Meta 同时介绍了更大的 Behemoth 教师模型及其研发方向，但发布说明中的研发预告不能当作已经发布了可下载权重。本文聚焦可核对的 Scout 和 Maverick，不能把另一个模型的参数、成绩和训练配方直接套在这两款上。

## 图文结构：图片如何参与回答

官方把两款模型描述为使用早期融合的原生多模态自回归语言模型。高层理解是：图像先被视觉组件转换为模型可用的表示，再与问题中的文本信息共同进入语言模型处理；最终以文字 token 的形式逐步输出回答。它不是先把每张图完整翻译成纯文字再交给另一个聊天程序；不过公开介绍不足以据此还原每一层图文交互和每个训练阶段的细节。

以发票为例，文字指令指出“找金额和日期”，视觉表示承载画面中的文字和布局线索，语言模型将两者结合后生成“金额……，日期……”。日期在右上角、合计在底部，这种空间关系也可能影响答案。即使它能识别图片，不等于它输出的每一个字符都经过精确 OCR 校验。图表、手写字、倾斜票面或低分辨率，都可能造成视觉理解错误。

### MoE 和路由：省下哪部分计算

传统稠密网络在每个相关层对每个 token 执行同一套前馈参数。MoE 在相应层准备多个专家，由路由机制为 token 选择部分专家参与计算，再把结果送回后续网络。共享部分仍需运行；并不是只有专家、也不是每次只执行一个完整的独立模型。官方的 17B 是约数，应把它理解为每 token 使用的活跃参数规模，而不是模型文件大小。

Meta 给出的 Maverick 细节更具体：稠密层和 MoE 层交替出现；在一个 MoE 层里，每个 token 都经过一个共享专家，同时由路由器从 128 个路由专家里选出一个。比如四个 token 分别选中 1、7、1、23 号专家，这批输入一共用到三个不同的路由专家；每个 token 仍只走其中一个，加上共享专家。专家编号只是例子，不代表它们被人工预先分成“数学专家”或“票据专家”。

假设 Scout 的总参数用两字节表示，单算参数大约需要 1090 亿乘 2 字节，即约 2180 亿字节；Maverick 同口径约 8000 亿字节。这只是未量化权重的粗略数量级，不是显存配置承诺：视觉组件、运行时、KV 缓存、分布式切分和额外开销都可能改变实际需求。量化可降低权重存储，但也需要验证质量和兼容性。

官方模型卡说明 Scout 的 BF16 权重可通过运行时 INT4 量化装入单张 H100；Maverick 同时提供 BF16 和 FP8 权重，官方称 FP8 版本可放入一台 H100 DGX 主机。这里的量化精度和设备是限定条件，不能简写为“17B 模型能在任何单卡上运行”，更不能据此保证 10M 上下文的实际吞吐。

### 长上下文：能放进去，不等于一定找得到

想象把一本很长的维修手册和一张设备图片一起交给模型，问某个报警灯对应的操作。系统需要接收足够多的上下文，而模型还要在大量相似段落中找到真正相关的页码。即便输入没有被截断，也可能引用邻近型号的说明，或者遗漏否定条件。

Scout 的长上下文还有一处值得认识的设计：Meta 称它为 iRoPE。可以把位置编码想成给每个词贴上位置标签；Scout 交替使用带旋转位置编码和不带位置编码的注意力层，并在推理时调整注意力的温度，帮助模型处理更长的输入。官方说明它在预训练和后训练时使用的上下文长度为 256K，而 10M 是借助长度泛化支持的上限；这不代表训练时每条样本都长达 10M。

因此评测至少分两步：先检查部署接口和处理器实际接收了多少 token、有没有静默截断；再把关键信息放在开头、中间、结尾等不同位置，测试识别、定位和引用。长文检索可以先用搜索缩小范围，再让模型结合原文回答；这改变了实际工作流，应与把整本手册直接塞入模型的结果分别报告。

## 数据与训练：知道什么，不知道什么

Meta 模型卡称 Scout 预训练使用约 40T、Maverick 使用约 22T 多模态 token，数据混合了公开可得、许可数据及 Meta 产品和服务中的信息，包括公开分享的内容和与 Meta AI 的互动。训练 token 数既不是文件数量，也不是唯一内容数量，更不是两款模型一定看过相同数据。两者数据规模的差异本身也不能证明哪个模型在每个任务上更好。

Meta 在介绍 Maverick 时给出的后训练顺序是**轻量监督微调（SFT）→ 在线强化学习（RL）→ 轻量直接偏好优化（DPO）**。SFT 先让模型学习示范答案；在线 RL 让当前模型尝试回答，再依据反馈调整；最后用 DPO 改进回答质量。Meta 还用模型筛掉超过一半被标为简单的训练数据，并在在线 RL 中持续挑选中等到较难的问题。可以把它想成老师先讲例题，再根据学生当前水平不断调整练习难度，最后纠正表达上的问题。这是官方公布的训练思路，具体数据和超参数并未完整公开。

一个可理解的训练例子是：给模型图片和问题，再根据目标回答训练，使它学会把“金额”同图片中正确的数值对应起来。后训练还可以用人类或其他方式提供更符合要求的回答与偏好，帮助模型按指令作答。这个例子仅用于说明任务形式，不表示官方使用了这张发票、某个特定标注规则或由此单独训练。

Meta 还披露，Maverick 在训练时利用了更大的 Behemoth 模型进行协同蒸馏。可以把它理解成学生在训练中参考老师的输出，而不是简单复制整个老师模型；官方发布说明没有给出足以完整复现的蒸馏配方。

如果自己准备数据，需要区分真实票据与合成样本，核实授权并脱敏，检查标注金额是否与票面匹配。把同一模板、同一企业或相近扫描件拆到训练和测试两侧，可能让模型记住版式而高估对新票据的效果。按模板和来源分组保留独立测试集，更有助于观察未见格式上的泛化。

## 评测：一定要带上版本与条件

官方模型卡分别给预训练版和指令微调版列出基准，而且注明报告的测试使用 BF16，而不是默认把量化版本视作同一结果。例如指令版图表问答 ChartQA 的 0-shot relaxed accuracy，Scout 为 88.8、Maverick 为 90.0；DocVQA test 的 0-shot ANLS 两者都为 94.4。这些是官方报告的特定基准结果，不是本文复现实验，也不能解释为实际票据必有相同准确率。

数字也不能脱离评分规则：图表问答的宽松准确率、文档问答的字符串相似度和人工判断各有范围。识别出“1080.00”和“180.00”在某些相似度指标下可能仍有相似字符，但实际金额差了一大截。业务验收应逐项检查金额是否精确、字段是否漏掉、无法读清时是否正确表示不确定，以及是否把图中不存在的信息编出来。

比较两个模型，先固定测试图片、问题、模型具体检查点、输入处理、输出长度、采样配置和评分方法；不同服务的图像缩放及上下文限制也应记录。对复杂版式、遮挡、金额、表格和中文单独分组，报告失败样本与延迟，而不是只挑选成功例子。官方支持语言列表未包含中文，模型卡将超出所列语言的使用列为范围外，同时说明开发者可以在遵守许可和使用政策的前提下针对额外语言微调，并负责安全使用。因此中文发票表现需要独立验证，不能凭多语言名称做保证。

## 应用与错例：从发票错误回到数据

准备经过授权的测试图片和人工核对的字段答案，以发票模板或来源分组，并为金额、日期、税额标注各自证据位置。先让模型给出结构化结果及不确定字段，再用规则检查日期格式和金额逻辑；高风险字段由人工确认。这里的规则只是辅助，不能从格式合法推断数值真实。

如果模型把“合计 180.00”读成“1080.00”，保留原图、缩放方式、提示词、输出和模型版本，再区分是图片质量、视觉识别、字段定位还是回答生成造成的错误。可以尝试提高输入清晰度、明确要求识别合计而不是税额，或者接入专门 OCR 与核对流程；每一步都应在独立发票上重新测试。修复金额后，还要回归日期、负数和不同模板，避免只对单张图片有效。

结果中若出现未识别内容，应允许系统返回“无法确认”，并将需要人工复核的样本送回数据整理。最终分别报告字段准确率、拒答或转人工比例、延迟和成本。上述是可复现的业务流程建议，本文并未实际训练、评测或部署模型。

## 面试追问

**17B 激活就能按 17B 模型估算显存吗？** 不能。活跃计算量与总权重存储是不同概念；还需考虑量化、缓存、视觉部分、并发和部署方式。

**10M 上下文意味着模型一定能理解所有内容吗？** 不能。窗口是输入输出预算，实际容量和有效检索能力都需要按部署配置测试。

**开放权重等于 Apache 许可吗？** 不等于。Llama 4 使用自己的社区许可和使用政策，需依据实际场景核对条款。
