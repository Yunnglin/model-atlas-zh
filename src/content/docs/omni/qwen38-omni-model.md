## 从一段会议视频开始

假设会议中有人说“将交付时间推迟到周五”，同时另一位同事在白板上修改日期。你希望助手找出这一决定、说明是谁提出的，并把会议纪要里的旧日期改掉。

只读自动转写可能漏掉白板信息；只抽取视频帧又可能看不到说话时的声音。Qwen3.8-Omni-Flash 的目标，是让模型结合文字、画面和声音判断，再视任务需要调用工具找到证据。这里有一个很重要的边界：模型可以提出“读取某段视频”或“修改文档”的请求，真正读取、写文件和保存仍由外部程序执行。模型说“已经改好”，不等于文件确实保存成功。

下面的视频、人物、结果和测试数字都是为了帮助理解而构造，不是实测输出。讨论对象是报告中的 **Qwen3.8-Omni-Flash**；带 Realtime 的服务有单独的语音输出与系统配置，不能把两种接口的能力混为一谈。

## 结构：三个感知入口与一个 Thinker

### 文字、画面和声音怎样汇合

文字先分成 token；图片和按策略抽取的视频帧进入视觉编码器；普通音频进入 AuT 音频编码器。它们产生的向量经过各自的投影接口，进入 Thinker 可以处理的共同表示空间。可以想成会议资料来自录像、录音和文字，各自先整理成统一格式，再放进同一份工作记录；这不是说模型先把所有模态准确转写成一篇文字稿。

报告中普通音频输入先重采样至 16 kHz，转换成梅尔频谱，再由四层二维卷积及后续注意力处理。编码输出的时间步约为 **6.25 Hz**，大约每 160 毫秒一个表示。这个数字是编码后的表示频率，不是麦克风采样率，也不意味着模型每 160 毫秒就必定输出一个字。

例如会议里“周五”被噪声遮住，模型可能需要回看字幕、白板或更清晰的音频。只要原始录音完全没有那两个字，编码器也不会凭空恢复出真实证据；一个回答说得流畅，并不能证明素材里真的有相应内容。

### Spatial AuT：声音从哪里来

本代引入单独的 Spatial AuT 路径处理多声道空间音频。报告把空间音频表示为一阶 Ambisonics 格式，再保留频谱的实部和虚部，使声道之间的幅度与相位关系可以参与判断。普通 AuT 更侧重声音内容与语义；空间路径补充来源方向等线索，两者的输出可以并行送入 Thinker。

打个比方：普通路径更像在问“说了什么”，空间路径提供“声音可能从哪个方向来”的线索。会议室里两个人同时说话、扬声器反射或者输入只有单声道时，这些线索未必足够；空间表示不等于准确识别说话人，更不能保证声源定位一定正确。实际还要记录麦克风、声道布局与音画同步情况。

### 长上下文：工作板与查资料配合

Thinker 的骨干结合 Gated DeltaNet 与注意力层，并使用混合专家。前者可以粗略想成不断更新的工作板，用状态概括此前信息；它不是一份能无损保存每个字的会议逐字稿。注意力层提供直接查找历史内容的路径；专家路由则决定当前 token 使用哪些前馈计算模块，与寻找历史信息是不同职责。

报告中的 Qwen Sparse Attention（QSA）通过轻量索引器对压缩后的历史块打分，选出相关块；真正注意力计算再读取选中块里的原始 token。就像先翻目录挑章节，再看章节原文。目录可能选错：如果“周五”出现在低分块，后续看不到该证据。长上下文上限是允许输入的预算，不是模型一定能正确使用每个细节的保证。

### 视频和声音怎样对时间

视频帧、普通音频与空间音频表示按时间组织，并保留明确时间戳。模型因此有机会判断“说到周五时白板上写了什么”，但时间戳只提供对齐线索，不能替素材修复音画不同步，也不能补回没有采集到的事件。测试时应保存原视频、实际抽帧、音频采样和时间偏移，才能知道错在输入还是判断。

## 训练：从对齐编码器到任务反馈

报告将该模型的预训练分成四阶段。第一阶段固定语言骨干，分别对齐视觉、AuT 和 Spatial AuT 路径；编码器适配器先训练，再训练相应编码器。第二阶段解冻全部参数，用文字、音频、图片、视频及视频加音频等材料共同训练。报告在这一阶段列出约 **2.5 万亿 token** 的混合数据量：文字 1.1 万亿、音频 0.7 万亿、图片 0.35 万亿、视频 0.15 万亿、视频加音频 0.3 万亿。这些数字是报告的训练材料口径，不是参数量，也不是去重后用户数。

这些分项均为约数，直接相加约为 2.6 万亿，与报告所写的约 2.5 万亿总数不完全一致；因此不宜拿表述出的数字推断精确占比，具体统计与取整方式应以进一步公开说明为准。

第三阶段固定骨干，用原本的密集注意力分布教 QSA 索引器挑选历史块；第四阶段启用稀疏注意力，同时优化骨干和索引器。先教目录怎样找资料，再让整个系统适应只读取部分资料的方式。它有助于理解训练动机，但不能保证每次检索都选中真正证据。

后训练先进行多教师蒸馏：围绕通用指令、推理、代码、智能体、视觉与音频训练专门教师，由教师生成不同领域的训练轨迹，再训练一个学生模型学习这些能力。接着把文字、视觉、音频和多模态任务混合，继续做强化学习，奖励同时考虑任务正确性与交互质量。[蒸馏](/training/distillation/) 解释教师与学生，[RLVR](/training/rlvr/) 介绍部分可检查奖励；这里不应将报告中的所有反馈都简化成“答案只有对错两个分数”。

比如要让模型整理会议纪要，训练样本不仅需要最终纪要，还需要对照原始音视频、时间戳和是否实际完成工具操作。教师生成的答案可能误认发言人，自动评分也可能只奖励格式漂亮；因此数据筛选、标签审核和独立测试同样重要。报告没有公开每个子任务的完整数据明细，不应把教学例子当作官方训练样本。

## Realtime：为什么能边听边说

Realtime 版本沿用 Thinker–Talker 分工。Thinker 根据输入形成文字与较高层的表示；Talker 负责逐步产生语音 token；多码本预测和 Code2Wav 把这些 token 持续变成音频。ARIA 用来协调文字和语音推进，避免要求一个字严格对应一个声音帧。系统可以在整段回答完成前发送声音，但依然需要缓冲和处理时间。

报告还说明，Realtime 的 Code2Wav 在波形重建时增加了上采样路径，把输出采样率从 24 kHz 提升到 48 kHz，用于改善高频细节。可以把它理解成语音播放器收到更密的波形采样，并不意味着每一段声音都会自动变得自然：发音、节奏、首块等待和播放设备仍要分别评测；输入的 16 kHz 与输出的 48 kHz 也不是同一个配置。

例如用户问“这张图的第二列是什么”，模型可能先理解图表，再开始说“第二列是……”；如果随后发现图像模糊，前面已经播出的声音很难撤回。系统还要决定如何处理用户打断、工具返回延迟、说话人与声音变化；这些不是仅靠输出一段音频就能完成的功能。

## 评测：先看任务和条件

报告在 WorldSense 音视频理解任务中给出 Flash **68.5**、Qwen3.5-Omni-Plus **63.9**，属于作者报告的特定任务结果，并不表示现实会议都能达到相同正确率。前代 [Qwen3.5-Omni 报告](/omni/qwen35-omni-model/)的 Plus WorldSense 数字是 62.8，而本报告列 63.9；现有资料不足以确认差异原因，应分别引用，不能直接混用。其他任务有不同趋势：在报告列出的部分视频推理任务上，其他模型仍有更高分数。比较时应固定视频抽帧、音频输入、提示、上下文限制及评分方式。

同一报告把 OmniVideoBench 的直接理解与使用 Qwen Code 的智能体模式分开：直接理解为 **63.4**，智能体模式为 **67.8**；每题报告的 token 消耗分别为 **145,736** 与 **79,117**。后者会规划、调用工具并逐步查找证据，且跨轮保留上下文，所以比较的是模型加工作流，而不是只改变模型权重。token 消耗下降也不能直接推导端到端时间或费用同比下降，工具等待、重试和计费口径都会影响实际成本。

实时语音要分开看“多久开口”和“后面说得多快”。报告对 6 秒音频输入测到首个音频块约 **978 毫秒**：从客户端提交输入后开始计时，包含网络与服务处理，但不包含建立连接、输入上传或播放；每种条件预热后统计十条有效回复。同一测试中的语音生成实时因子（RTF）为 **0.1538**，按首尾音频块的时间间隔除以生成语音时长计算。打个比方，这相当于生成 10 秒声音所用的持续生成时间约 1.54 秒，首块之前的等待需要另算。这个测试结果是特定 API 和输入条件下的测量。

## 从错例回到数据与应用

如果会议摘要把“周五可能交付”写成“周五确定交付”，先保留原始视频、音频、抽帧时间、实际提示和模型版本；再看录音中是否有“可能”、转写是否丢失条件、模型是否误解，或者工具取回的旧纪要覆盖了新内容。来源缺失时先修输入；证据清楚但判断有误，再考虑标注同类样本或训练。

为测试准备相互独立的会议片段，覆盖单人、多人、背景噪声、音画不同步、发言人重叠与没有明确结论的场景。分别统计关键事实、时间定位、说话人归属和不确定性表达，再检查工具是否真正修改了正确文件。按会议或项目划分训练与测试，避免同一段录像的不同切片同时进入两边。以上是建议的评测和改进方案，尚未执行训练或验证。

## 面试追问

**标准 Flash 与 Realtime 一定都输出语音吗？** 不一定。官方标准服务列文字输出，Realtime 接口还支持实时语音；应按具体接口核对。

**QSA 的索引器直接生成答案吗？** 不是。它辅助选择历史块；所选内容还由注意力与后续网络处理，索引器可能漏掉重要证据。

**空间音频就是说话人识别吗？** 不是。空间路径提供方向等线索，识别哪个人、说了什么还需要结合内容与上下文。

**多教师蒸馏意味着推理时必须运行所有教师吗？** 不一定。报告将教师轨迹用于训练统一学生；部署时具体工具和服务另需按系统配置确认。

**Agent 模式准确率更高，能证明模型参数变强吗？** 不能。工具、素材抽取、上下文保留和运行预算也发生变化，需要做受控对照。
