## 要解决什么问题

普通照片、密集表格和长视频的信息密度不同。Qwen2.5-VL 用动态分辨率、视觉编码和时间位置设计处理这些输入。本页限定 2.5-VL 的报告和模型卡；后续 Qwen-VL 系列不自动使用同一配方。

## 结构与数据流

图像或视频帧先经视觉编码器变成视觉 token，整理后接入语言模型。动态分辨率让输入不必一律压到同一个小尺寸；但 token 数、显存与推理时间也会随输入规模变化。

视频不只是一叠无序图片，还要表达帧的时间位置。报告讨论动态帧率与时间相关的位置编码，帮助模型联系视觉事件与时刻；这不等于任何时间问题都能答对。

## 数据与训练

预训练需要图文、文档、视频等配对材料；指令训练再教模型回答问题、提取结构和描述位置。识别文字、理解表格和按格式输出，是相关但不同的能力。

以发票提取为例，训练数据需要把金额、日期和字段位置对应准确，不能只用一段笼统图片描述替代细粒度监督。保留跨模板和跨来源测试，避免只记住版式。

## 评测怎么看

文档可测字段正确率和结构有效性，定位要固定坐标与缩放约定，视频要测事件时间与长程关系。不同输入像素预算和抽帧策略不能当成同一实验；[多模态评测](/evaluation/multimodal-evaluation/)给出相应拆分。

## 应用与错例

发票总额提取错，先检查图片缩放是否丢字、字段位置是否混淆，再看输出 JSON 与单位。视频答错则对照实际送入的帧，确认关键片段是否缺失。补充开发难例后，用新模板和独立视频回归。

## 比较与面试追问

[LLaVA](/omni/llava/)适合理解视觉编码器接语言模型的基本路线；Qwen2.5-VL 展示更复杂的输入组织。[Qwen2.5-Omni](/omni/qwen-omni/)还要理解声音并生成语音，不能只把 VL 改个名字。

**更高分辨率是否总更好？** 可能保留更多细节，也会增加 token 与成本，需要按任务验证。

**模型支持长视频就一定逐帧看过全部内容吗？** 不能这样推断，要记录解码与抽帧后的实际输入。
