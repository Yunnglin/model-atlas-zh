## 要解决什么问题

一段操作视频中，按钮出现、被点击、界面跳转是不同事件。Qwen3-VL 不只识别画面里的物体，还要组织空间、时间与操作关系。[系列历史](/omni/qwen-vl-family/)。

## 结构与数据流

官方概括三个关键设计：Interleaved-MRoPE 组织多模态位置；DeepStack 将多层视觉特征注入语言网络；视频使用文本形式的时间信息。大白话说，就是把“看见了什么、在哪里、在什么时候”更好地交给语言模型。

下方是教学简图；想看视觉编码器、多个 Merger 和语言模型的完整连接，可以打开[技术报告 Figure 1 官方原图](https://arxiv.org/html/2511.21631v1/figures/qwen3vl_arc.jpg)。

系列有 Dense 和 MoE 两类语言骨干，也有面向快速回答的 Instruct 与面向推理的 Thinking 版本。

### 一个短暂弹窗，怎样决定答案

构造教学视频：第 2.0 秒出现“保存失败”，第 2.4 秒消失，第 3 秒界面恢复。问题是“刚才保存成功了吗？”要答对，模型先得收到包含弹窗的帧，再读出失败文字，最后联系事件顺序。如果抽帧错过了弹窗，模型就没有这条关键信息。

DeepStack 可以类比看材料时同时保留字迹细节和整页主题：视觉网络不同深度的信息，通过对应连接注入语言网络，而不是只把最终视觉层交过去。这些不同层次都是模型学习到的表示。

Interleaved-MRoPE 将时间、高、宽的位置维度交错安排到相应频率分量，帮助同时组织不同方向的信息。文本时间戳则把帧对应的真实时间作为可读条件加入，让模型有依据回答何时发生。

相比 2.5-VL，这一代同时调整了视觉特征融合、位置编码和视频时间表示。

### 把一张图片变成语言模型能处理的材料

假设你给模型看一张车站时刻表，问“去杭州的车几点发车”。图片先由视觉编码器切分并提取特征；视觉—语言融合器把局部特征压缩、投影成语言模型可以接收的视觉 token；问题文字也被分词。语言模型再根据视觉信息和问题逐步生成回答。这里的“视觉 token”是向量。输入尺寸、图像切块和 token 预算会影响模型能看到的细节。

技术报告中的基础结构包括视觉编码器、融合器和语言模型。报告说明视觉编码器使用 SigLIP 2 架构，并通过动态分辨率继续训练；融合器用两层 MLP 将相邻 2×2 的视觉特征压缩成一个视觉 token。可以把它理解成先看局部，再把几份小笔记合并成一份交给后续模型；压缩节省计算，代价是必须权衡细节。不同型号采用不同大小的视觉编码器和语言骨干。

### DeepStack 多送了什么

只看最终视觉特征，像让同事交一份总结；DeepStack 则额外递上几份不同阶段的笔记。报告选取视觉编码器三个不同层次的特征，经过各自的融合模块，分别加到语言模型前三层的对应隐藏状态中。这些特征经不同融合器后进入同一个语言模型。

这里的“加进去”值得注意：这三份特征是在对应视觉位置的隐藏状态上做加法，不是把三份图片 token 接在文字后面。因此，报告指出 DeepStack 不会因为这三路注入而额外拉长上下文。假设一张图原本占 100 个视觉位置，加入 DeepStack 后不是自动变成 400 个位置；融合器和特征相加仍需要计算，不能因此认为完全没有额外开销。

报告表 9 比较了内部 15B-A2B 模型在相同预训练 token 预算、未进行后训练时的表现：加入 DeepStack 后，平均分从 74.7 升至 76.0，TVQA 从 80.6 降至 80.5。这个例子说明总体收益与单项变化可以不同。

这里还有型号差异：报告默认使用 SigLIP2-SO-400M 视觉编码器，较小的 2B、4B 语言模型则使用 SigLIP2-Large 300M。视觉编码器的参数量与语言骨干的参数量分别计算。

### 位置和时间为什么要分开说

图片上的字既有内容又有位置：左上角“出发”与右下角“到达”交换，答案可能就不同。视频多了时间：先出现故障，再出现恢复提示，和先恢复后故障含义也不同。Interleaved-MRoPE 让时间、高、宽的位置分量交错分布于不同频率范围，服务于多模态位置表示；文字时间戳则把采样帧组的实际时刻作为文本条件。两者互补：一个组织位置，一个提供实际时间。

## 数据与训练

图文、视频与文本共同建立基础能力，后训练再改善指令、推理和工具操作。训练 GUI 助手时，需要屏幕、动作、结果反馈等轨迹，而不仅是静态截图问答。完整训练集并未随权重一同公开。

### 四个阶段，先接线再扩展上下文

官方报告给出预训练流程：先冻结视觉编码器和语言模型，只训练连接两者的融合器；接着解冻全部模块，在约 8K 的序列长度下混合图文和纯文本；再增加到约 32K；最后用约 256K 的长序列做适配。后两个阶段增加长文档和视频等材料。把这个过程想成先给两位专家配翻译，再让整个团队合作，最后练习阅读更长的材料。视频能保留多少内容，还取决于抽帧与视觉 token 预算。

报告表 1 给出了四个阶段的训练量：第一阶段约 670 亿 token，第二、第三阶段各约 1 万亿 token，最后的超长上下文适配约 1000 亿 token。这里统计的是各阶段处理的 token 数；长序列训练既要读得更长，也要兼顾普通长度的任务。

### 后训练：示范、蒸馏和反馈

报告介绍的 SFT 数据约 120 万条，其中约三分之一为纯文本，其余为图文和视频文本样本。SFT 先训练 32K 长度，再扩展到 256K；非思考与思考模型使用不同格式的示范。假设训练题是一张时刻表和问题“去杭州几点出发”，示范既要指出正确时间，也要与图中同一行对应，才能教模型把视觉证据和答案联系起来。

接下来，小模型通过强到弱蒸馏学习教师能力：先学习教师生成的回答，再让学生自己生成并对齐教师给出的分布。报告中的这一蒸馏阶段使用纯文本数据训练语言骨干；它与预训练中的图文融合各司其职。

在推理强化学习阶段，团队构造约 3 万条文本和多模态问题，用规则或代码执行器验证数学、代码、定位等任务，并使用 SAPO 策略优化方法。比如视觉定位题需要模型返回目标位置，验证器依据标注判断答案是否符合要求；反馈来自答案和任务规则，而不是人工逐字改写每次回答。报告还描述了面向指令遵循和通用多模态任务的另一阶段强化学习。

### 把任务示范拆成三类

图文问答教它读取和联系画面；视频材料教它利用顺序和时间；GUI 轨迹还要教屏幕状态与动作后果。问“弹窗说了什么”与问“下一步怎么办”需要不同标签，前者正确不保证后者正确。

可构造“保存成功／保存失败”只有一个词不同的样本，并保留无弹窗视频作为对照，避免模型一见保存按钮就猜成功。这组对照可以用来检查模型是否依赖画面中的关键信息。

## 评测怎么看

固定分辨率、视频帧率、长度和思考预算，测 OCR、定位、时间顺序、视觉推理与 GUI 任务完成。同时记录视频采样方式，才能知道模型实际看到了哪些帧。比较 Thinking 和 Instruct 时同时记录成本。

### 指标必须配上输入预算

以报告中 Qwen3-VL-235B-A22B-Instruct 的视频评测为例：每段视频最多输入 2048 帧、视频 token 总数不超过 224K；VideoMMMU 和 MMVU 每帧最多 768 个视觉 token，其余基准最多 640 个；Charades-STA 使用每秒 4 帧，其他基准每秒 2 帧。VideoMMMU 还使用模型裁判。论文还说明，受资源及 API 限制，部分对手使用的输入帧数不同，比较分数时需留意这一条件。

按每秒 2 帧计算，2048 帧相当于约 17 分 4 秒的视频画面；更长的视频需要在帧数和 token 预算中取舍。这个算例展示预算怎样约束输入，实际选择帧和分辨率的方式应随评测配置记录。

以时刻表问答为例，可以同时统计整句答案准确率、时间字段准确率和“证据不清时拒答”的表现。若模型把 08:05 读成 08:50，语句再流畅也不算答对；如果图片压缩后两位数字已经不可辨，问题可能出在输入预算而不是语言推理。评测表应记录原图与实际输入尺寸、裁剪方式、输出格式、提示词、采样参数及模型版本。对于涉及乘车的系统，还要让人核验高风险输出。

报告里的长视频找针实验提供了具体测试方法：论文将关键帧插入视频，以每秒 1 帧均匀采样，并动态调整帧分辨率以维持视觉 token 预算，再问相关问题。关键事件持续时间、采样密度和画面质量会影响测试结果；不到一秒的弹窗可能正好落在两次采样之间。

### 按输入、理解、行动分段核对

先检查采样帧是否包含弹窗；包含时单独做 OCR，再问事件结果，最后才测试操作。加密抽帧后成功，提示输入覆盖可能是问题；原帧已含清楚文字却答错，才继续分析条件理解。

坐标也有两条尺度：处理后图片中的位置与真实屏幕位置。例如把宽 1920 的图缩到 960，横坐标 480 对应原图 960；这是简单等比缩放算例，若还有裁剪、填充就需完整变换。保存变换，比只记一组输出坐标更便于定位。

## 应用与错例

模型点错按钮，先检查缩放后坐标与真实屏幕坐标是否一致；漏掉短暂弹窗，再查抽帧；看到了仍选择错误操作，再补动作决策样本。将感知错误与执行错误分开，能避免盲目重训整个模型。

### 从错例回到一轮可检验的改进

把误答分成看不清、看错字、找错行、时间顺序错和答案编造五类，并记录每类是否可复现。假设二十个错误里，多数来自小字而非推理：先尝试增加局部裁剪或输入分辨率，在独立样本上对比准确率和成本；如果相同清晰输入仍经常串行，再补充带行列对应关系的训练样本。这样可以对照判断问题来自输入细节还是行列关系。

数据拆分按车站表格模板或来源分组：同一张表稍作缩放不能分别放进训练和测试，否则模型可能记住版式。回归时既看新表格，也看原有通用视觉任务，避免修一个切片却损害整体。保留匿名化的原始输入、处理版本和预期证据，才能让下一次复现真正可比较。

## 比较与面试追问

[2.5-VL](/omni/qwen-vl/)是代际比较入口，[视觉问答案例](/cases/visual-qa/)给出数据到改进的方案。

**视觉 token 多就一定更好吗？** 更多 token 可能保留细节，也会增加上下文、计算和延迟；关键是以同等预算比较任务收益。

**时间戳能解决所有视频问题吗？** 不能。它告诉模型被采样内容对应的时间，采样没覆盖事件、图像模糊或音画错位时仍会失败。

**DeepStack 为什么可能有帮助？** 不同视觉层保留不同抽象程度的信息，模型可以利用更丰富的特征；收益仍需消融实验证明。
