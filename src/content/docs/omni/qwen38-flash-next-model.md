## 它想解决什么问题？

想让助手检查一份长合同和其中的表格截图。它一方面要记住早先定义的付款条件，另一方面要在几十页条款中找到与图片金额相关的那一小段，最后给出能追溯来源的解释。上下文越长，逐层比较所有历史位置所需的计算与缓存越多；把一个模型做得更大，还会让权重占用和设备间搬运变得更难。

Qwen3.8-Flash-Next 尝试从多个方向改善这些成本：用 Gated DeltaNet 压缩部分历史，用 QSA 挑选需要精读的片段，用稀疏专家控制每一步参与的计算，再通过额外查表记忆提供常见局部组合的信息。可以把它理解为“先整理摘要，再带着目录查细节”，但机器里的状态是数字表示，不是可直接读懂的可靠摘要。

合同、图片、下文数字和测试流程都是教学构造，没有实际运行模型。它能接收图片不意味着理解无误，更不等于自动拥有修改文件或执行付款的权限。系统调用工具、访问文件及执行操作需要另行配置。

### 两种历史处理方式怎样分工

官方模型卡描述 48 层按十二组排列：每组中三层是 Gated DeltaNet，第四层使用 QSA；这些层的前馈部分使用专家网络。Gated DeltaNet（GDN）持续更新一个固定大小的状态，可以高效处理历史，但不能把它当作逐字无损保存的原文。QSA 则仍有从历史上下文中选取内容并精细计算注意力的路径。[注意力机制](/foundations/attention/)可以帮助理解为什么不同位置需要交换信息。

以合同为例：GDN 层处理到“发票须在验收后开具”时，会把有关信息融入状态；当问题涉及一笔付款时，QSA 层还可以从历史中选择相关片段，计算更细的关系。它不是检索系统的绝对保证：如果索引没有选中关键例外，或者原材料本身被截断，模型仍可能漏掉条件。

QSA 先把历史压缩成较小的 micro-block 表示，再由轻量索引器给块评分；挑中块后，核心注意力使用所选块内的原始 token，而不是仅对压缩摘要作最终计算。模型卡列索引预算为 512 个块或 2048 个 token；这描述该配置的设计，不能简单推断每一层、每个任务都一定能找对证据。

### MoE：只激活部分专家，不只保存这部分

每个 token 经过专家层时，路由器从 512 个路由专家中选 10 个，并配合一个共享专家。好比一个工厂有很多工作台，一次订单只让部分工作台参与；这些专家是可训练的网络模块，不是人为指定的“合同专家”或“图片专家”。

125B 主模型和约 6B 激活量回答的是两个不同问题：前者约束需要管理的主体参数，后者描述一次 token 计算中参与的规模。模型卡另外列 51B 的 N-gram 嵌入及 4B 的多 token 预测模块；不能把它们说成已经包含在 6B 激活数里，也不能认为下载或部署只需要容纳 6B 权重。实际内存还受精度、分片、缓存和运行框架影响。

### N-gram 查表和四路残差

普通 token 嵌入大致根据单个 token 查表示；N-gram 嵌入还结合附近若干 token 的组合查表。比如常见的“付款 条件”组合可能获得一份额外表示，让模型不必只靠每一层重新计算常见局部模式。51B 是额外表的参数规模，不是 51B 条知识结论；查表增加了内存需求，论文讨论将表放在主机内存并提前搬运，实际效果受硬件和框架支持影响。

报告还比较了查表放在不同网络层的位置：在其固定参数预算的实验里，浅层和更深层各有表现，没有一种深度在所有任务上都占优。研究者最终选择第 2 层，让第一层计算时有机会提前搬运查表数据。这体现了效果与系统开销的共同取舍；也不能据此认为加大查表一定让所有下游指标持续改善。

Gated Residual 把残差信息通道扩成四条，利用门控决定各层从这些通道读取和写入多少信息。可以类比笔记本里保留多栏草稿，再由当前任务决定参考哪一栏；它不意味着某一栏固定负责某种语义，也不能保证早期信息一定被保留。多 token 预测模块则服务额外预测及可选推测解码；是否加速需要看实现和接受率。

图片处理方面，视觉编码器先把图像变成表示，再与文字一起交给语言模型；能送入图片不表示它可以生成图片。官方模型卡也给出视频输入示例，框架将视频抽帧后处理；具体抽帧能力和参数依赖服务框架，不能把它等同于原生音频输入。照片缩放、图中文字模糊或表格被裁掉时，语言模型未必能弥补丢失的细节。具体图片预处理及帧数限制以所用检查点和服务实现为准。

## 训练：结构与优化器一起设计

技术报告描述对模型架构、优化器与训练稳定性的多项实验。它采用 Muon 处理适合二维线性映射的一部分权重；输入嵌入、输出头、专家路由器等指定参数使用 AdamW，N-gram 嵌入表则使用关闭权重衰减的 Adam，N-gram 层中的键值投影使用 Muon。这些位置的更新规则并不相同，不是整个网络只使用一个优化器，也不能把所有与嵌入有关的参数都归到 AdamW。对于工程上拼在一起的矩阵，报告先按实际线性映射拆开再做相关处理。其目的在于让不同权重的更新适合各自形状和计算方式，具体细节应回查报告与实现。

报告说明，混合骨干在继续预训练时用 QSA 替换原有的全注意力层，并进行相应训练；不能把稠密模型直接切到稀疏模式的结果等同于训练后结果。另有架构消融发现，直接应用初始化的稀疏索引器会造成性能下降，短时间联合训练能让骨干适应稀疏模式；这是报告中对应实验的观察，不保证所有设置都如此。

模型发布资料也介绍根据新结构拟合训练规模与超参数，并在指定应力实验中检查训练稳定性；不能从单个训练过程没有异常推断所有硬件、批量和数据都一定稳定。公开资料没有逐项披露所有训练语料与后训练配方，不能把其他 Qwen 型号的完整数据清单写成该检查点已证实的训练事实。

假设公司希望它处理采购合同，可以先收集获授权的条款、问题和正确证据位置，按合同来源划分开发与独立测试。针对“金额正确但漏掉验收条件”的错误，补充正反例并明确标注引用位置，再选择提示、检索或适配训练；模型本身并不替你验证资料是否最新。[SFT](/training/sft/) 和 [LoRA](/training/lora/)分别解释示范学习和参数高效更新，但这里是改进思路，不代表官方为此任务执行过训练。

## 评测：看清计算范围与比较条件

技术报告在 100 万 token 上下文的特定测试中，报告 QSA 的注意力模块相对稠密注意力在 prefill 和 decode 阶段分别达到约 **7.6 倍**和 **4.9 倍**加速。这里比较的是所描述条件下包含索引的注意力算子或模块，不是整个服务的吞吐必然提高同样倍数。论文注明 prefill 使用 16K 分块、批量为 1；decode 使用批量 4 及额外 MTP 步骤。硬件、输入、输出长度、并发、内存搬运及其他层都会影响端到端结果。

官方模型卡还列出不同基准：例如 SWE-bench Pro 为 62.5。该成绩采用 Claude Code 工具框架、256K 上下文、temperature 1.0 和 top-p 0.95；官方修正了部分有问题的任务并重新评测对照模型。它不意味着任意真实软件项目的修复成功率均为 62.5%；与其他结果比较时，还要核对题集版本、工具、运行次数和预算，也不能把带工具智能体的成绩和只回答一次的模型直接相减。

假设要验证合同问答，准备独立文档和人工标注的证据片段，分别测答案准确性、引用是否包含关键条件、图片表格数字是否正确，以及原文缺失时是否承认未知。将关键例外放在不同位置、改变干扰条款，并记录实际输入长度、框架与生成预算。若 20 道题中 15 道的答案和引用都正确，联合通过率是 75%；这是算术示例，不是模型实测。

## 应用与错例：先定位，再决定是否训练

如果助手说“可以立即付款”，但合同要求先验收，保存原文、图片预处理结果、模型版本、提示、输入长度和输出。先检查相关页是否被截断、OCR 或截图是否清晰、系统是否选错了版本，再检查模型是否看到了例外却推理出错。对不同原因，应分别改善切分和检索、图片输入或训练样本；盲目增加训练轮次可能解决不了资料缺失。

补充经过授权的合同样本时，按文档和来源划分训练、开发及测试，避免相同合同改写后同时出现在两边。评测要保留负例：不同合同使用相同金额但验收条件不同，或者材料根本没有说明付款日期。记录正确率、引用覆盖、缺证据时的错误断言、延迟和资源消耗，再用未参与调整的材料回归。

## 面试追问

**125B 主模型、51B N-gram 和 6B 激活分别是什么？** 前两项是不同参数统计，6B 是每 token 参与的主模型计算规模；它们不能混成一个“模型只占 6B”的结论。

**QSA 选中块后只看压缩向量吗？** 不是。压缩表示用于索引，核心注意力处理选中块的原始 token；仍可能发生漏选。

**公开权重与 Flash API 是同一套可复现环境吗？** 不必然。服务可能采用不同上下文、工具、推理框架和运行配置，应分别记录检查点与接口版本。

**内核加速 7.6 倍意味着业务整体加速 7.6 倍吗？** 不能这样推断。端到端还包括其他网络层、内存搬运、排队和输出等成本。
