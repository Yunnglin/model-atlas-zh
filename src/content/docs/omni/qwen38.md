两个模型的总参数、激活参数和模态分别统计；27B 的语言模型参数不代表包含所有视觉处理模块的总资源开销。2.4T-A95B 的[模型卡](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B)写明原生上下文为 262,144 token，经扩展最高可达 1,010,000 token；部署时要为输入和输出共同留出空间。服务端的额外视觉、工具与非思考能力不能套到 2.4T-A95B 下载权重。

## 要解决什么问题

助手要看截图、读代码、修改文件，还得根据工具结果继续工作。Qwen3.5 起的主线结合视觉语言与高效长文本，后续版本更关注任务完成。[返回系列](/nlp/qwen/)。

## 结构与数据流

同系列后续公开的 [Qwen3.8-Flash-Next](/omni/qwen38-flash-next-model/) 是另一种面向效率的架构与检查点；本页对 27B 或 2.4T-A95B 的说明不能直接套给它。

3.5 使用原生视觉语言训练与混合注意力设计。混合注意力的大白话解释见 [Next](/nlp/qwen-next/)。系列既有 Dense 也有 MoE，不能把 397B-A17B 的配置套给所有规格。

| 版本    | 可以确认的变化                                                              | 需要分清                     |
| ------- | --------------------------------------------------------------------------- | ---------------------------- |
| 3.5     | 混合注意力与多模态主线；397B-A17B、122B-A10B、35B-A3B、27B 及小规格陆续开放 | 各规格配置看各自模型卡       |
| 3.6     | 沿 3.5 基础加强代码、仓库任务与多轮思考；开放 35B-A3B、27B                  | 与 Plus 等服务区分           |
| 3.7-Max | 官方定位闭源 Agent 模型                                                     | 不补造开放检查点             |
| 3.8     | 沿 3.5 架构基础加强代码、专业工作、研究与长程任务；开放 2.4T-A95B、27B      | 核对各型号输入能力与思考限制 |

**3.8-27B 支持原生图像／视频输入；开放的 2.4T-A95B 是纯文本、始终思考的型号，不能关闭思考，也不接收多模态输入。** API 的 Qwen3.8-Max 则提供额外服务功能，不能把服务特性算给下载的权重。

`reasoning_effort` 调整思考深度，`preserve_thinking` 保留历史思考上下文；是否支持和怎样填写按具体型号文档。能看图不等于有语音输入输出，后者见 [Omni](/omni/qwen-omni-family/)。

### 跟着一次截图任务看各部件

教学任务是“把设置页的通知关掉，再报告结果”。截图先由视觉编码路径变成表示；语言骨干结合目标和历史组织下一步；它输出的工具请求交给外部执行器，下一张截图或错误结果再回到模型。模型内部生成了一段坐标文字，不代表屏幕已经被点过。

以 3.8-27B 官方卡为具体例子：语言部分是 64 层，按 16 组“3 个 Gated DeltaNet＋1 个 Gated Attention”组织，各层后面为稠密 FFN。它和 Next 80B-A3B 都有混合注意力，但这里不能照搬 Next 的 512 个专家配置。视觉支持也要看该检查点，不能仅由注意力类型推导。

### 大模型的专家怎么参与

以 2.4T-A95B 模型卡为例：它的 92 层按 23 组“四层组合”排列，每组三层 Gated DeltaNet、一层 Gated Attention，前馈部分使用专家网络。这相当于 69 层 Gated DeltaNet 和 23 层 Gated Attention；卡中列出 512 个路由专家、每个 token 选 10 个路由专家，并使用 1 个共享专家。可以把路由理解成每一步把信息交给部分专门处理的通道，但专家并不等于人类定义好的“数学专家”或“写作专家”。

总参数 2.4T 体现模型保存的整体规模，95B 是官方标注的每 token 激活量；后者不表示只要能放下 95B 的权重就一定能运行。模型加载、专家分布、跨设备通信、缓存和框架都影响硬件需求。27B 稠密型号没有同样的专家路由，虽然更小，也要结合上下文和图像处理成本实测。

两种注意力结合状态更新与注意力路径，目的之一是长序列计算的取舍。它们不是“某层永远负责事实、某层永远负责推理”的分工；同样的 262K 配置不保证模型能准确提取任意位置的信息。官方还注明 MTP 多步训练，实际推测解码是否启用、速度如何，需要在指定框架和硬件上测量。

两个型号的头数也不同：27B 的 Gated Attention 是 24 个查询头对应 4 个键值头；2.4T-A95B 是 64 个查询头对应 4 个键值头。这里的查询头不是专家数量；比较具体层的缓存或算力，还要看每头维度、层数和实现。

如果想直观比较两种开放型号的缓存，可以假设单条文本序列长 8,192 token、键和值都用 BF16 存储。27B 有 16 层 Gated Attention，每层 4 个键值头、每头 256 维，键值缓存估算约 **512 MiB**；2.4T-A95B 有 23 层这类注意力，同样每层 4 个键值头、每头 256 维，估算约 **736 MiB**。这里分别计算 `层数 × 2（键和值）× 4 × 256 × 8192 × 2 字节`。线性注意力状态、专家权重、视觉编码和运行时工作区需要另计。

可以把版本比较分成两张表：结构表记录编码器、注意力、Dense／MoE；行为表记录能看什么、能否切换思考、是否保留历史思考和工具模板。两者分开，才不会把服务端增加一个工具误认为模型内部多了一个网络模块。

## 数据与训练

预训练让模型学习输入数据中的规律；后训练进一步调整指令、推理与工具交互能力。27B 支持视觉输入，开放的 2.4T-A95B 权重则是文本模型。发布说明不等于完整训练配方：没有报告依据，不给 3.8 补写奖励模型、数据比例或某种 RL 算法。

应用微调应保留用户目标、工具参数、工具结果、失败恢复与最终输出。只训练最后答案，会丢掉最容易出错的执行过程。[训练全流程](/training/pipeline/)说明怎样组织这些数据。

### 如何避免把训练阶段猜成事实

官方对 3.8 的公开介绍强调预训练与后训练以及代码、研究和长程任务能力，但没有完整公布训练语料、数据配比、奖励设计与每轮参数更新。一个合理的业务做法，例如收集工具使用轨迹做 [SFT](/training/sft/)，并不等于官方证实模型一定采用了这一配方；[RLVR](/training/rlvr/)也不能仅凭模型会做数学题就认定已经使用。

在自己的页面自动化任务中，可以先记录“用户目标、截图、计划、工具请求、工具实际结果、复查和最终说明”。如果按钮被遮挡，训练样本应如实包含失败与恢复过程，而不是把每条轨迹都写成一次成功。数据按应用或任务来源分组，保留未用于调参的测试场景，才能检查是否真正学会处理新界面。

### 完整轨迹比一句“已完成”多教了什么

一条可学习轨迹可保留：原始目标、截图、拟执行动作、执行结果、下一张截图、失败恢复和最终确认。若按钮被遮挡，好的示范先处理遮挡，再检查开关状态；只留下“通知已关闭”，模型看不到为什么改变操作。

这是业务训练设计，不是 3.8 官方未公开配方。3.5 的原生视觉语言基础、3.6 的多轮执行改进、3.8 的长程任务能力可以按公开描述理解；没有数据和消融证据时，不能把差异定量归因于某一种奖励或某一步 RL。

## 评测怎么看

看任务完成、测试通过、产物正确与证据可追踪，同时记录工具次数、耗时与预算。模型卡分数要连同 harness 和思考设置一起读，工具环境变化也会影响结果。

### 读懂榜单的型号与条件

2.4T-A95B 模型卡中的部分对比表展示的是 **Qwen3.8-Max 服务** 的成绩，服务还提供开放权重没有的额外功能；因此不能把表中每个数字直接标成 2.4T 本地权重的成绩。例如该表中 Qwen3.8-Max 的 SWE-bench Pro 为 **67.7**；脚注说明使用 Claude Code、256K 上下文、temperature 1.0、top-p 0.95 和修正后的任务集。这个数字属于官方发布的服务评测，不能当作本地 2.4T 权重的单独实测。即使两项结果名称相同，也要核对思考预算、提示、任务集版本、外部工具和运行框架。

27B 模型卡报告 SWE-bench Pro 为 61.7：相应脚注说明采用 Claude Code 工具框架、256K 上下文、temperature 1.0 与 top-p 0.95，且修正有问题的任务后重新评测。这个分数属于该模型方报告及其环境，不是模型离开工具框架自行完成所有软件任务的成功率，也不能直接与使用不同题集或预算的数字排名。

同一张官方表把 Qwen3.6-27B 列为 53.5，把 Qwen3.8-27B 列为 61.7，相差 **8.2 个百分点**。模型卡称两者都用 Claude Code、相同采样设置和经过修正的任务集评测。这个对照说明版本在报告设置下的表现变化；要分析变化来自数据、后训练还是其他因素，还需要对应消融实验。

看图推理也要把工具条件拆开。27B 模型卡在 MathVision 上分别给出不使用代码解释器的 **90.0** 和使用代码解释器的 **94.6**。前者是模型直接处理题目，后者允许它借助代码执行：比如从图中读出边长后，可以写代码计算面积。两种成绩相差 4.6 个百分点，但这不能说明代码工具会让每道题都更容易：读错图或写错代码仍可能失败。模型卡还说明题集有少量标注经人工核实后修正，27B 使用固定提示，而其他模型从两种提示中取较高结果；因此比较时要带上这些条件。

例如用户给一份 50 页财报并要求找出现金流变化：对 27B，可以同时测试图表阅读、数字抽取、计算和报告；对纯文本 2.4T 权重，必须先由外部系统把图片或 PDF 内容转换为文字，识别器的错误也可能传给模型。两个任务的输入管道不同，结果不能简单归因于模型参数大小。

### 一条任务怎样才算完成

本例至少核对三份证据：工具确实执行、最终截图中开关状态正确、报告与状态一致。只要“点击请求合法”不够；点完没生效、重复切回去、没有检查结果，都应算不同失败。

比较模型时给相同的工具、权限、页面初始状态、最大步骤和总预算。另设弹窗、加载延迟、按钮换位置等扰动；任务重复运行用于估计稳定性，不能挑一次成功录像当成功率。把失败定位到感知、规划、执行或验收，再决定补哪类数据。

## 应用与错例

助手反复修改却不测试，先查工具是否可用、反馈是否进入上下文；反馈存在仍重复出错，再查轨迹数据与终止条件。把长任务定位到具体失败步骤，补相应样本并回归，而不是笼统标记“模型不够强”。

## 比较与面试追问

**总参数 2.4T、激活 95B 就只需加载 95B 参数吗？** 不能这么推断。每次使用一部分专家不意味着其余专家不需要存储或按需要调度；实际部署仍要考虑权重、通信和缓存。

**原生多模态意味着所有输入用同一个编码器吗？** 不意味着，要查具体配置与输入路径。

**架构基础相近为何还能提升？** 数据、后训练、规模与推理系统都可能改变，需要受控对照才能分解贡献。
