## 要解决什么问题

助手要看截图、读代码、修改文件，还得根据工具结果继续工作。Qwen3.5 起的主线结合视觉语言与高效长文本，后续版本更关注任务完成。[返回系列](/nlp/qwen/)。

## 结构与数据流

3.5 使用原生视觉语言训练与混合注意力设计。混合注意力的大白话解释见 [Next](/nlp/qwen-next/)。系列既有 Dense 也有 MoE，不能把 397B-A17B 的配置套给所有规格。

| 版本    | 可以确认的变化                                                              | 需要分清                     |
| ------- | --------------------------------------------------------------------------- | ---------------------------- |
| 3.5     | 混合注意力与多模态主线；397B-A17B、122B-A10B、35B-A3B、27B 及小规格陆续开放 | 各规格配置看各自模型卡       |
| 3.6     | 沿 3.5 基础加强代码、仓库任务与多轮思考；开放 35B-A3B、27B                  | 与 Plus 等服务区分           |
| 3.7-Max | 官方定位闭源 Agent 模型                                                     | 不补造开放检查点             |
| 3.8     | 沿 3.5 架构基础加强代码、专业工作、研究与长程任务；开放 2.4T-A95B、27B      | 核对各型号输入能力与思考限制 |

**3.8-27B 支持原生图像／视频输入；开放的 2.4T-A95B 是纯文本、始终思考的型号，不能关闭思考，也不接收多模态输入。** API 的 Qwen3.8-Max 则提供额外服务功能，不能把服务特性算给下载的权重。

`reasoning_effort` 调整思考深度，`preserve_thinking` 保留历史思考上下文；是否支持和怎样填写按具体型号文档。能看图不等于有语音输入输出，后者见 [Omni](/omni/qwen-omni-family/)。

### 跟着一次截图任务看各部件

教学任务是“把设置页的通知关掉，再报告结果”。截图先由视觉编码路径变成表示；语言骨干结合目标和历史组织下一步；它输出的工具请求交给外部执行器，下一张截图或错误结果再回到模型。模型内部生成了一段坐标文字，不代表屏幕已经被点过。

以 3.8-27B 官方卡为具体例子：语言部分是 64 层，按 16 组“3 个 Gated DeltaNet＋1 个 Gated Attention”组织，各层后面为稠密 FFN。它和 Next 80B-A3B 都有混合注意力，但这里不能照搬 Next 的 512 个专家配置。视觉支持也要看该检查点，不能仅由注意力类型推导。

可以把版本比较分成两张表：结构表记录编码器、注意力、Dense／MoE；行为表记录能看什么、能否切换思考、是否保留历史思考和工具模板。两者分开，才不会把服务端增加一个工具误认为模型内部多了一个网络模块。

## 数据与训练

预训练建立语言、视觉和知识基础；后训练改善指令、推理与工具交互。发布说明不等于完整训练配方：没有报告依据，不给 3.8 补写奖励模型、数据比例或某种 RL 算法。

应用微调应保留用户目标、工具参数、工具结果、失败恢复与最终输出。只训练最后答案，会丢掉最容易出错的执行过程。[训练全流程](/training/pipeline/)说明怎样组织这些数据。

### 完整轨迹比一句“已完成”多教了什么

一条可学习轨迹可保留：原始目标、截图、拟执行动作、执行结果、下一张截图、失败恢复和最终确认。若按钮被遮挡，好的示范先处理遮挡，再检查开关状态；只留下“通知已关闭”，模型看不到为什么改变操作。

这是业务训练设计，不是 3.8 官方未公开配方。3.5 的原生视觉语言基础、3.6 的多轮执行改进、3.8 的长程任务能力可以按公开描述理解；没有数据和消融证据时，不能把差异定量归因于某一种奖励或某一步 RL。

## 评测怎么看

看任务完成、测试通过、产物正确与证据可追踪，同时记录工具次数、耗时与预算。模型卡分数要连同 harness 和思考设置一起读，工具环境变化也会影响结果。

### 一条任务怎样才算完成

本例至少核对三份证据：工具确实执行、最终截图中开关状态正确、报告与状态一致。只要“点击请求合法”不够；点完没生效、重复切回去、没有检查结果，都应算不同失败。

比较模型时给相同的工具、权限、页面初始状态、最大步骤和总预算。另设弹窗、加载延迟、按钮换位置等扰动；任务重复运行用于估计稳定性，不能挑一次成功录像当成功率。把失败定位到感知、规划、执行或验收，再决定补哪类数据。

## 应用与错例

助手反复修改却不测试，先查工具是否可用、反馈是否进入上下文；反馈存在仍重复出错，再查轨迹数据与终止条件。把长任务定位到具体失败步骤，补相应样本并回归，而不是笼统标记“模型不够强”。

## 比较与面试追问

**原生多模态意味着所有输入用同一个编码器吗？** 不意味着，要查具体配置与输入路径。

**架构基础相近为何还能提升？** 数据、后训练、规模与推理系统都可能改变，需要受控对照才能分解贡献。
