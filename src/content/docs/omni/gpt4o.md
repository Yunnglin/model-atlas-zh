这里把 GPT-4o 作为 2024 年多模态技术的学习案例。**模型研究能力、某个 API 的输入输出、ChatGPT 产品功能是三件事**，不能直接划等号。

## 定位与公开范围

假设你拿着一道几何题，对着手机拍照片，指着角落说：“这个角为什么是 60 度？”一个好的助手不仅要读文字，还要理解你指的是图中的哪一处，并用语音讲解。GPT-4o 的“o”是 omni，强调文字、声音、图像等信息能够在同一交互中发挥作用。

OpenAI 的系统卡称它在文字、视觉、音频上端到端训练，输入输出由同一神经网络处理。它没有公开完整结构、参数量、各模态 token 的具体编码方式或完整训练流程。公开的输入、输出与实验设计可以作为学习材料，但不能凭演示反推有多少层、哪些编码器或专家。

2024 年发布时，公开提供的是文字和图片输入、文字输出；音视频能力分阶段推出。随后 Realtime API 提供专门的语音交互版本。当前 `gpt-4o` API 模型页列出的接口是文字、图片输入和文字输出；音频、视频支持需查具体模型与接口，而不是因为名称里有 o 就认定每个接口都支持。

## 值得理解的思路

### 从串联到联合：一张“中间纸条”的区别

传统语音助手常由三个部件串起来：**ASR 把声音转文字 → 语言模型理解并回答 → TTS 把回答读出来**。好处是每一段都能单独替换、调试：转写错了看 ASR，声音不自然看 TTS。

问题是中间的纸条通常只留下字。两个人都说“真不错”，一个真心夸奖、一个语气讽刺，转写可能一模一样；呼吸、停顿、重音也可能消失。仅看这张纸条的下游模型很难恢复原本没有写下的声音线索。

端到端多模态模型在联合训练中处理声音和其他信息，有机会利用更多线索。注意这只是**有机会**：它仍可能把讽刺听错、把噪声当说话，或者自信地给出错误回答。串联系统也可以增加韵律或其他旁路信息，因此不能说串联必定丢失全部非文字信息，也不能说联合模型必然更准确。

### 端到端不等于应用里没有其他模块

实际应用还要录音、检测用户是否说完、传输数据、播放声音；也可能有审核、检索和工具调用。即使核心模型直接处理声音，外部系统仍有很多工作。比如用户说“等等”时，播放器需要停下正在播放的语音，系统还得判断新话属于打断还是背景电视声。模型能力和应用流程各有责任。

语音输出的自然、答案正确和可以被打断也不是一个指标。一个声音很流畅的回答仍可能读错图表；能在一句话中间停下，也不代表它真正记住了用户刚才的修改。

## 数据与训练

系统卡公开了训练材料的大类：公开网页、代码和数学数据、多模态图像音视频，以及来自数据合作的非公开材料。它还介绍了训练数据过滤、后训练中对人类偏好的对齐、红队测试和产品层防护。完整数据清单、配比、损失函数、计算量、模型结构和各阶段超参数未公开，不能将一般多模态模型的常见做法写成 GPT-4o 已证实的训练配方。

**端到端训练是学习路径，不是说完全没有人工标注或后训练。** 可以把它想作：声音、画面与文字被放进同一套学习任务，模型逐渐学会把它们联系起来；公开资料并未说明每一种数据如何采样或所有训练目标如何组合。简单的“下一个文字 token 预测”能够帮助理解自回归生成，但不能据此断言它的音频表示和损失细节。

以图片加提问为例，理想训练样本可能让模型在看图后回答“红色曲线在哪一月下降”，但这是帮助理解的假设，并非公开样本。后训练可能改善遵循指令与安全行为；系统卡确实说明了偏好对齐与针对声音风险的后训练，但没有给出足以复刻模型的具体数据及完整算法。

## 如何比较

### 不只测听写：把一次交互拆成几种能力

1. **听懂内容**：用有参考转写的录音测字词错误，覆盖安静、噪声、口音、数字和专有名词。中文常用字符错误率，英文可用词错误率；数字错一个字符可能改变整个订单金额，因此还要单列关键字段正确率。
2. **理解与推理**：用同一句话不同语气、同一语气不同文字的成对录音，分别问“说了什么”和“表达了什么”。情绪可能有多种解释，需要多位标注者和可表示不确定的答案，不应把语气判断当作对人格或身份的事实判定。
3. **图文关联**：换掉图表标签或指出不同区域，检查回答是否引用正确曲线和单位。模糊小字、图片裁剪、视觉误读与推理算错应分开记录。
4. **说出回答**：先核对答案事实，再听语音是否漏字、重复、读错数字，以及是否可以清楚理解。口音和自然度可以做人工盲听，但不能以单一主观分数代替事实检查。
5. **交互体验**：分别记录用户停止说话到首个音频、到完整回答的时间，以及打断后的停止与恢复情况。平均值会掩盖慢请求，还应看分布和尾延迟。

OpenAI 在 2024 年系统卡中报告音频响应最快 232 毫秒、平均 320 毫秒，这是当时描述的模型响应指标，**不是任何网络、设备或业务条件下的端到端保证**。采集、网络、排队、语音播放及工具调用都可能增加等待。

### 安全评测也有具体测法和边界

[2024 年系统卡](https://openai.com/index/gpt-4o-system-card/)展示了一组有意思的安全评测：用户要求根据声音辨认具体人物时，模型应拒绝；用户问一段著名引言关联的人物时，模型则应根据内容回答。后训练前的早期版本，正确拒绝率为 **0.83**，该回答时正确配合的比例为 **0.70**；部署版本分别为 **0.98** 和 **0.83**。这组数字看的是两类请求的处理，而不是识别声音的准确率。

这也说明评测不能只看「拒绝得够不够多」：把所有问题一律拒绝可以避免一些风险，却会误伤正当问题。实际设计测试集时，应同时准备该拒绝和该回答的例子，分别计算两类比例，再抽查错例。

系统卡还比较了不同输入声音上的表现：研究者使用语音合成生成相同任务的输入，对照 3 种官方声音和来自不同国家、不同性别的 27 段英语声音，在 TriviaQA、部分 MMLU、HellaSwag 和 LAMBADA 上测试。报告称两组能力差异在这些任务上没有达到统计显著水平。这是对该样本和任务的观察，不能据此认为所有语言、口音或真实环境都没有差异。做自己的评测时，可以固定文字内容、只更换授权的说话声音，先排除题目不同造成的干扰，再补充真实噪声和口音样本。

做对比时应固定模型快照、输入音频、提示词、音量、噪声、请求设置和工具权限；分别报告自动指标与人工判断。对照开放的 [Qwen-Omni](/omni/qwen-omni-family/) 或 [语音识别](/audio/qwen-asr/)与 [语音合成](/audio/qwen-tts/)串联方案时，尽量给相同任务及预算。商业产品随时间变化，旧演示、旧价格和不同版本的得分不宜直接当作现状。

## 同一句话，文字转写可能丢掉什么

一位顾客说“我没说要退款”，其中“不”在嘈杂环境里很轻。若识别错成“我说要退款”，下游助手可能直接进入错误流程；如果只看最终回答，容易误以为是推理问题。保存经授权的音频、参考转写、模型回答与时间戳，才能判断是听错、理解错还是业务流程执行错。

同样的一段录音可以做三种对照：给模型原音；只给人工正确转写；给错误转写。如果原音出错、正确转写答对，感知环节值得重点检查；若正确转写也答错，单纯增加 ASR 数据可能不能解决问题。此处是推荐的排查方法，不是已运行的测试。

## 把一次语音回答分成可验收的几步

以家电售后为例：用户展示机器上的错误代码，并说“这声音比昨天响，要不要停机？”系统先确认画面能否读清代码、声音是否足够清楚，再按可核验的说明书解释；缺证据时提出补充问题。若出现危险征兆，应给出明确的人工服务入口，而非把听起来肯定的语音当成可靠判断。

复盘错例时区分采集问题、感知错误、事实依据不足、推理错误、声音生成错误及业务操作错误。针对每类收集有代表性的样本，清除个人信息后形成待改进数据，再用独立样本复测；测试应覆盖此前有效的场景，避免修好噪声题却损坏安静环境的表现。闭源服务通常无法自行检查或更改模型内部权重，可以先改善采集、提示词、检索和转人工策略。

## 比较与面试追问

**语音到语音一定没有文字吗？** 不一定。系统可能显示字幕、保存转写、用文本做审核；核心模型可直接处理音频，不代表产品没有任何文本。

**视频理解等于连续实时理解所有帧吗？** 不等于。视频输入如何采样、接口限制与延迟会影响可见信息；应在实际接口上验证短时动作和遗漏帧。

**能提供图片或语音，就证明某接口都有这些功能吗？** 不证明。核对具体模型 ID、版本、输入输出模态和产品文档；系统卡描述的研究能力不能替代接口契约。

**为什么语音回答很自然仍可能不可靠？** 声音质量、事实正确性和工具执行正确性不同；要拆开评测，且要求答案能被证据核对。
