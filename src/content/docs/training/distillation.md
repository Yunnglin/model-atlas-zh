## 先想清楚：教师的经验怎么交给学生

请一位经验丰富的老师教新员工处理客户投诉。老师不只给“通过”或“拒绝”的结论，还能解释哪些证据支持判断、哪些地方容易误判。新员工看过大量例子、反复练习后，或许能独立处理常见情况，也可能仍在复杂案例上犯错。

知识蒸馏就是让**学生模型在训练中学习教师模型提供的信号**。常见目标是在保留足够能力的前提下使用更小的学生模型，减少部署成本；教师和学生的大小并非定义蒸馏的唯一标准。学生要经过训练，不是把老师的参数裁掉一部分，也不会自动继承老师全部知识。下面用投诉场景和简单数值说明常见做法。

## 经典方法：软标签包含什么

图片分类中，教师看见一张动物照片，除了给出“猫”，还可能输出猫 0.70、狗 0.25、汽车 0.05。只有正确答案“猫”的硬标签告诉学生最终类别；完整概率还表达教师认为“猫和狗更容易混淆”。学习这组软标签，可能帮助学生理解类别之间的相似性。

原始论文通过温度参数调整 softmax：温度较高时概率分布通常更平缓，小概率类别也更容易显露。学生与教师在相同温度下比较输出分布；训练时也可以结合真实标签的损失。温度是改变训练中用于对齐的概率分布，不意味着测试时一定要高温采样。教师的概率本身可能不准，对齐不等于获得经过校准的置信度。

比如教师对两个候选词给出的原始分数是 2 和 0：温度为 1 时，经过 softmax 的概率约为 0.88 和 0.12；温度为 2 时，先把两个分数各除以 2，概率就变为约 0.73 和 0.27。第二个候选词没有被忽略得那么厉害，学生更容易看到教师对它的相对偏好。教师和学生使用相同温度，便于在同一温度下比较分布。

### 训练时怎样组合两种信号

假设一个动物分类样本的真实标签是“猫”，教师也给出“猫 0.70、狗 0.25、汽车 0.05”。可以同时让学生靠近教师的软分布，也让它根据真实标签学习“猫”；两项各有权重。真实标签告诉学生任务要求的结果，软分布提供教师对其他选项的相对看法。如果教师错得很自信，真实标签和可靠验证仍然重要。

写成常见形式，学生优化的目标可以表示为：

$$
L = \alpha T^2 L_{\text{soft}}(p_T, q_T) + (1-\alpha)L_{\text{hard}}(y,q_1)
$$

这里 $p_T$ 和 $q_T$ 是教师与学生在温度 $T$ 下的分布，$y$ 是真实标签，$q_1$ 是学生在普通温度下的输出；$L_{\text{soft}}$ 可用教师到学生的交叉熵等方式，$L_{\text{hard}}$ 常用真实标签的交叉熵。原论文建议软目标项乘以 $T^2$，用于补偿温度改变对梯度尺度的影响，便于调整软硬信号的权重。不同实现对损失的归一化、温度、掩码和权重有所不同，上式是一种常见写法，不代表所有蒸馏算法都必须这么做。

例如选择 $T=2$、$\alpha=0.5$ 只是设置训练配置，不能保证软标签与真实标签对训练产生完全相同的影响；要监测两项损失及验证集表现。只有教师生成的示范文本而没有概率分布时，仍可用示范做 SFT，但上面的软分布损失无法照搬。

### 大语言模型怎样蒸馏

语言模型每一步预测下一个 token。如果拿得到教师的完整概率分布，可以对对应位置的学生分布做匹配；但教师与学生分词器、词表和上下文的差异会增加对齐难度，远程服务也不一定开放完整概率。

另一种常用做法是让教师对问题生成示范答案或推理过程，筛选后用它们进行[监督微调](/training/sft/)。例如让教师给出投诉归因和处理建议，再根据规则或人工检查过滤不合规答案。这时学生学的是生成文本，不是完整的教师概率分布；同样叫蒸馏，监督信号、成本和适用条件不同。[DeepSeek-R1](/nlp/deepseek-r1/) 的公开蒸馏模型是具体例子：团队用 R1 生成的推理样本微调 Qwen 和 Llama 等学生底座，并非把 R1 大模型的权重直接缩小。不同学生的基座与结果要分别核对。[官方仓库](https://github.com/deepseek-ai/DeepSeek-R1)列出了各检查点。

图为原创教学简图，展示先准备教师答案、再训练学生的一种方式；部署时新问题可以只交给训练后的学生。筛选有助于减少教师错误，但不能保证示范全部正确。其他方法也可能在训练中在线调用教师并比较概率，详见下文的 GKD。

## 进一步认识几种蒸馏方法

| 方法                      | 学生看什么                           | 教师提供什么                        | 一个需要留意的地方                                                            |
| ------------------------- | ------------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------- |
| 经典软标签蒸馏            | 训练数据中的输入及其上下文           | 每个类别或 token 的概率分布         | 需要获取可比较的概率，词表不同可能难以直接对齐                                |
| 序列级蒸馏（Sequence-KD） | 教师生成的完整答案                   | 一条或多条候选序列作为训练目标      | 学生容易接触到教师的答案，但未必充分练习自己生成时会遇到的前缀                |
| GKD                       | 可以混合原始数据和学生自己生成的文本 | 在这些上下文下提供 token 级概率分布 | 在线询问教师有成本；偏差度量可以选择，不能把 GKD 等同于某一个 KL 方向         |
| MiniLLM                   | 学生采样的回答                       | 教师对回答的概率信号                | 优化反向 KL，有助于限制学生偏向教师低概率区域，但不是所有任务必然胜过其他蒸馏 |

### 从教师示范到学生自己练习

原始序列级蒸馏工作以机器翻译为例：让教师先翻译训练输入，用教师给出的句子训练学生。它像老师先写好一份解答，学生照着练。真实应用中往往还要检查教师答案是否正确、有无泄漏，不能默认生成内容就是标准答案。

但独立作答时，学生可能先写错一步，接下来的上下文就不再是教师示范里那条。GKD 考虑让学生自己生成一段文本，再让教师对学生遇到的上下文给出概率指导；训练中也可以混合原数据。比如学生把“未批准”误写成“已批准”，后面继续写下去时就会进入错误前缀；在这样的前缀下比较教师与学生的下一步分布，可以让训练更贴近学生实际遇到的情况。这个例子只解释数据从哪里来，不能保证教师会自动纠正每一种事实错误。

**谁生成上下文**与**怎么衡量分布差异**是两个问题。GKD 探索学生生成或混合数据，也探索正向 KL、反向 KL 和广义 JS 等不同差异度量。MiniLLM 则研究用学生采样并优化反向 KL；它的论文还使用了与优化相关的技巧。两者并非“只要让学生生成就是同一个算法”，也不能只凭 KL 的名字判断训练是否采用学生生成数据。

再把训练的一步拆开：GKD 先让学生写出一个回答，把采样得到的文本当成当前这一步的固定上下文，再在这些位置比较教师与学生的下一 token 分布；梯度更新学生预测分布，不穿过生成文本的离散采样过程。MiniLLM 则从**整条回答的反向 KL** 出发，用策略梯度处理学生采样的影响，还引入教师混合采样和长度归一化等技巧。两者都可能用学生写出的文本，但优化目标和梯度处理并不相同。[GKD 论文第 3 节](https://arxiv.org/html/2306.13649)和 [MiniLLM 论文第 2 节](https://arxiv.org/html/2306.08543)分别给出了具体做法。

如果把教师概率记作 $p$、学生概率记作 $q$，两种常见写法是 $D_{KL}(p\|q)$ 和 $D_{KL}(q\|p)$。它们的方向不同，通常会对遗漏教师可能答案与学生把概率放在教师不认可的答案上产生不同的惩罚；实际效果受数据、有限模型容量和实现影响。无需先背推导，先问清楚：概率在哪些上下文计算、由谁采样、谁更新、教师需要提供什么接口。

例如，学生在一道题的解答中先写错了数字。离线示范可能只包含教师的正确前缀；在线蒸馏则可以让学生走到自己写错后的前缀，再询问教师在这个前缀下如何分配下一 token 的概率。这个过程中通常更新的是学生参数，教师提供训练信号；教师能否识别前面的错误，仍要靠独立验证检查。

用两个候选答案做个小算例：教师分布 $p=(0.9,0.1)$，学生分布 $q=(0.6,0.4)$。按自然对数计算，$D_{KL}(p\|q)\approx0.226$，而 $D_{KL}(q\|p)\approx0.311$。同一对分布换个顺序，差异值就变了；但这两个数字不能单独证明哪一种训练方法更好，也不能忽略训练时使用的上下文和采样方式。

反向 KL 更倾向让学生集中在教师较认可的区域，也可能漏掉教师分布中其他合理答案；这在需要多样表达的任务里尤其值得检查。MiniLLM 还报告直接优化时可能出现重复、过短或无意义文本，并使用教师混合采样、长度归一化等技巧稳定训练。因此选用反向 KL 并不自动保证答案更真实、更长或更好。

## 一个真实例子：DeepSeek-R1 的答案蒸馏

DeepSeek-R1 团队使用约 80 万条整理后的样本，对 Qwen 和 Llama 等学生模型进行监督微调。论文在数据准备部分描述，其中约 60 万条是推理模型生成并筛选的推理样本，约 20 万条是沿用 DeepSeek-V3 流程准备的非推理样本。例如 `DeepSeek-R1-Distill-Qwen-7B` 的学生基座是 Qwen2.5-Math-7B：学生学习的是问题和教师生成的回答，而不是从大模型复制权重，也不需要得到完整词表的教师概率。

[论文初版表 5](https://arxiv.org/html/2501.12948v1)报告，7B 蒸馏模型在 AIME 2024 上的 pass@1 为 55.5%，在 MATH-500 上为 92.8%。这里的 pass@1 关注单次回答的成功率；官方对需要采样的基准每题生成 64 次回答来估计它。论文同时报告的 AIME `cons@64` 为 83.3%，它将 64 次回答用于一致性投票，和单次回答的使用预算不同。比较不同学生时，还要看它们的原始基座、训练数据和评测设置：这组成绩展示的是蒸馏后模型的表现，并非与未蒸馏学生的单变量对照。

## 再看一个例子：Qwen3 的两阶段蒸馏

[Qwen3 技术报告](https://arxiv.org/html/2505.09388)介绍了先用教师生成的回答训练学生，再让学生自己生成回答、由教师提供概率指导的做法。前一阶段让学生先熟悉思考与非思考两种回答方式；后一阶段则让教师评价学生实际会写出的前缀。对于小模型，可以把它想成先看老师示范，再做自己的练习并逐步获得反馈。

报告表 21 使用同一个经过离线蒸馏的 Qwen3-8B 检查点，对数学与代码任务分别继续做强化学习和在线蒸馏。AIME 2024 上，报告列出的强化学习结果为 67.6，在线蒸馏结果为 74.4；对应新增训练成本分别是 17,920 和 1,800 GPU 小时。这是论文中该模型和训练设置下的比较，准备教师模型与原先离线阶段的成本也需要单独考虑。

看这张表时，可以把离线蒸馏后的 55.0 作为共同起点：继续在线蒸馏后为 74.4，即提高 19.4 个百分点；而表中括号里的 pass@64 从 90.0 到 93.3，衡量的是多次采样中至少一次成功，与单次回答的成绩不是一回事。两个方法也使用各自的训练配置与预算，这组结果展示了一次具体比较，不能直接推出在线蒸馏在所有模型和任务上都比强化学习更省、更好。

[一只路过的烧鸡的在线蒸馏文章](https://zhuanlan.zhihu.com/p/2023108953026883794)把学生生成上下文与教师给出指导的过程放在一起解释。阅读时可将其中的正向 KL、反向 KL 和具体训练方法分开看：它们是可选的设计，教师信号及数据采样方式也会影响结果。

## 动手时有哪些关键选择

1. **确定目标**：希望降低延迟、压缩显存，还是让学生擅长某项业务？先定义输入、输出和不可接受的错误。
2. **选择学生和教师**：记录各自版本、许可和能力边界。学生基础语言能力、上下文窗口和参数容量会限制能吸收的内容；老师越强也不保证学生必然更好。
3. **准备问题及信号**：覆盖常见和困难场景，记录生成提示、采样方式和原始输出。可结合真实标签、规则检查、独立验证器或人工抽检；验证器自己也可能误判。
4. **训练并保留对照**：同样的学生基座和数据预算下，比较不蒸馏的基线、真实标签训练和教师信号训练。调节数据混合比例，防止模型只模仿话术而遗忘基础能力。
5. **在独立测试集验证**：按来源、时间或问题模板划分，检查近重复，并尽量识别与教师训练数据或示范生成过程重合的题目；如果教师训练数据未公开，不能保证已排除其所有潜在污染。既看总体指标也检查不同难度、语言和错误类型。

教师生成的详细推导可能包含错误中间步骤：即使最终答案正确，学生仍可能学会错误理由。对于能执行验证的代码或数学题，可用独立测试或答案检查辅助筛选；对于服务建议等开放任务，还需审查事实、规则及是否引用了不存在的证据。涉及个人信息或授权内容时，也要检查数据是否适合被发送给教师服务和保存为训练集。

## 怎样评价蒸馏是否值得

如果学生回答速度快了，但投诉升级或误拒率显著上升，可能只是把成本转移到了人工复核。评测要同时记录任务效果、错误类型、单次延迟、吞吐、显存、训练成本和生产输入长度。学生与教师比较时，明确工具、提示词、采样及输出预算；当学生没有教师使用的工具时，要把差异写清楚。

别只比较蒸馏后学生和大教师：最关键的对照是**同一学生未经蒸馏时**的表现。假设独立样本上任务成功率从 70% 到 78%，只是示意，不是实际测量；如果样本太少、某类投诉只占几条，也不能断言每类都改善。上线后归类错例，补充困难样本，再用未参与调整的独立样本验证，防止不断针对测试集调参。

## 蒸馏、微调和量化怎么区分

SFT 描述训练方式：给定输入和示范输出来训练。教师生成的示范也可以用于 SFT，因此两者可以同时发生。蒸馏强调信号从教师向学生迁移；量化则改变权重或其他数值的表示精度，通常针对同一个模型减少存储或计算成本。可以先蒸馏出学生，再对学生进行[量化](/training/quantization/)，但两步误差都会影响最终结果，要评测最终版本。

## 面试追问

**为什么软标签有价值？** 它包含除最高类别外的相对概率，可能揭示类别相似性；如果教师错得很自信，也可能把错误传给学生。

**学生能否超过教师？** 在特定任务和评测条件下可能，比如结合额外真实标签或更适合任务的数据；但不保证全面超越，也不能从一次样本结果推断。

**答案蒸馏和概率蒸馏有什么差别？** 前者常用生成答案做序列监督；后者直接对齐概率分布，信息和所需教师接口不同。训练数据、成本和评测需要分别说明。
