## 为什么数据要先分组再切分？

假设要训练一个客服语音识别模型。小王打了一通电话，录音被切成十段；如果随机把其中八段放进训练集、两段放进测试集，模型在考试时可能又听到熟悉的声音、背景和话题。这个分数更像是在考“同一通电话里的其他片段”，而不是考它能否听懂新用户。

先想清楚上线后要面对什么，再确定分组单位：要测新说话人，就把同一人的录音放在同一个集合；要测新会话，就按会话切分。时间变化明显的业务，还可以用较早的数据训练、较晚的数据测试，观察新术语和场景带来的变化。

![语音数据按说话人分组，训练和开发数据用于改进；独立测试集留待方案确定后评估。](/figures/training/data-quality.svg)

图中展示的是说话人级切分。训练集用来学习，验证集帮助选模型和调整方案，测试集留到方案确定后做最终检查。为了了解上线表现，还要让测试集包含实际会遇到的噪声、口音和设备。

## 一个具体的切分方案

假设有 100 名说话人，每人录音数量不同。可以按说话人分成 80 人用于训练、10 人用于验证、10 人用于测试，再检查每组的音频时长、噪声条件和口音分布。这里 80／10／10 指人数比例，由于每个人的录音数量不同，录音条数未必也是这个比例。

切完后做几项检查：

1. 按评测目标检查分组是否跨集合：评估陌生说话人时，不能让同一人跨集合；评估已知说话人的新会话时，允许同一人出现，但同一会话和原始录音不能跨集合。片段应保留来源标识，方便追溯。
2. 三个集合分别有多少人、多少小时？较小群体是否在测试中有足够样本？
3. 标签与音频是否对得上？抽查漏字、多人重叠、静音片段和专有名词。
4. 将识别错误按噪声、口音、设备和词类分组，看看平均字错率掩盖了哪些问题。

[GroupShuffleSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupShuffleSplit.html) 可以按给定组标识生成切分；它按组数决定比例，实际样本条数和类别分布需要另外统计。要同时满足多个条件时，可以设计分组规则并检查结果。

如果要固定出训练、验证、测试三份，可以先按说话人留出测试集，再只在剩余说话人中切出验证集，并保存随机种子和最终名单。不要把 `GroupShuffleSplit` 多次独立产生的测试折直接当作互不重叠的验证集与测试集：不同次随机切分之间允许出现相同说话人。固定名单后，还应检查说话人、会话和原始录音的交叉情况。

## 文本、图片和音频各要查什么

| 数据       | 常见问题                                       | 一个实用检查                                         |
| ---------- | ---------------------------------------------- | ---------------------------------------------------- |
| 文本       | 同一篇文章的转载、改标题版本或切片重复出现     | 按原文来源和近似内容聚合，检查训练集与测试集是否重合 |
| 图片与视频 | 同一张图片的裁剪、缩放版本进入不同集合         | 按原图或视频来源分组，抽查相似图和图文是否匹配       |
| 语音       | 同一通电话被切成多个片段，转写与音频错位       | 保留会话、说话人、时间范围，抽听并核对转写           |
| 指令与偏好 | 同一道题有多个改写，或偏好标签与评审标准不一致 | 按题目来源分组；抽样复核标签，记录评审分歧           |

这些检查服务于不同目标。例如语音助手面向已登记的固定说话人时，需要评估已知说话人的新会话；面向陌生用户时，还要单独评估未见过的说话人。两组成绩回答的是不同问题，可以同时报告。

## 去重和切分怎样配合

去重是找出重复或高度相似的材料；切分是决定哪些材料用于训练、选型和最终评估。完全相同的文本可以用标准化后的哈希寻找，改了少量文字的转载则需要相似度方法和抽样复核。音频切片、视频帧和图片裁剪最好结合来源信息一起判断。

例如，一篇新闻被切成三个段落，另一个网站又转载了全文。只按段落文件名随机切分，两边仍可能共享大量内容。先把同源版本归成一组，再决定这组属于哪个集合，测试才更接近阅读新文章的场景。[文本去重研究](https://arxiv.org/abs/2107.06499)讨论了训练文本重复及训练、验证数据重合对记忆和评估的影响。

一个实际做法来自 [RETRO 论文](https://proceedings.mlr.press/v162/borgeaud22a/borgeaud22a.pdf)：团队把文档拆成连续 13 个 token 的片段，用 MinHash 近似比较训练文档与验证、测试文档的片段集合；相似度达到 0.8 的训练文档被移除。可以把它想成比较两份文章的“短句指纹”：原文略作改动，仍可能被找出来。这是论文在特定语料中采用的规则，0.8 不是万能阈值，换写法、翻译和短文仍可能漏检；上线前还要结合来源检查和人工抽样。

### 找到相似文章后，还要决定怎么分组

大语料不方便把每篇文章和其他所有文章逐一比较。一个常见流程是先用 MinHash 和局部敏感哈希（LSH）找出可能相似的候选对，再计算候选对的实际 n-gram 集合相似度，决定哪些连接成组。LSH 是快速筛选，不是精确裁判：它可能漏掉相似对，也可能把不够相似的文章送来复核。候选数量、阈值和抽样检查结果都值得记录。

分组还有一个容易忽略的细节：相似关系不一定能一路传下去。假设 A、B 的相似度为 0.6，B、C 也是 0.6，但 A、C 只有 0.33；如果阈值设为 0.6，按照“通过相似文章连成一组”的规则，三篇仍会因为 B 而被归在一起。这方便让同源内容不跨越训练集与测试集，却不意味着 A 和 C 本身达到阈值。应抽查特别大的组，防止常见模板把不同文章串成一大串，并记录每组保留哪一份、为什么保留。

[BigCode 的去重实践](https://huggingface.co/blog/zh/dedup)展示了候选生成、复核和连通分组的工程流程；要评估自己的流程，除了看删掉多少，还要抽查误删、漏检以及跨集合的重复。

## 真实案例：去重之后，为什么还要换题型检查？

[DeepSeek LLM](/nlp/deepseek-llm-model/) 的研究团队做过一个对照：给 7B Chat 模型的对齐阶段增加 2000 万道中文选择题。论文说，他们针对 C-Eval 验证集和 CMMLU 测试集做了去重。结果中，C-Eval 从 47.0 提高到 71.3，CMMLU 从 49.7 提高到 73.8；但需要直接生成答案的 TriviaQA 在两组都是 57.9，内部 ChineseQA 则从 75.0 变为 74.4。具体模型、数据和分数见[论文表 13](https://arxiv.org/html/2401.02954)。

这像让学生专门练选择题：即使考题与练习题不完全相同，熟悉选项格式也可能帮助拿分，却不一定让他更擅长自己组织答案。去重能减少已知的重复，**不能代替对任务和题型是否贴近实际需求的检查**；这些数字只描述论文中的对照，不说明所有选择题数据都会产生同样效果，也不能证明不存在任何遗漏的重合。

做自己的评测时，可以保留同一知识点的选择题和开放问答两类题，分别报告成绩；先按题目来源或知识材料分组，再检查题干改写和答案是否跨集合重复。不要因为开放问答分数低，就把它的标准答案加入训练后继续把原题当最终测试。

## 从错例回到数据

假设测试发现嘈杂环境下，语音助手经常把商品名称听错。先抽查音频和转写，判断是噪声、口音、切分位置还是标注错误；然后在开发数据中补充对应情况，更新标注规范或训练样本。如果这些错例来自原测试集，它们已经参与了方案设计，不应再把同一批题的成绩当作完全独立的最终结果。方案确定后，用未参与调参的新测试样本评估嘈杂场景，同时检查安静环境中的表现是否变化；旧测试集可留作回归检查。

每次改动记录数据来源、筛选规则、标注版本、切分方式和评测结果。这样发现退化时，可以回到具体数据版本，而不是只知道“上次训练效果好一些”。

## 面试追问

**随机切分和分组切分有什么区别？** 随机切分按样本分配；分组切分把关联样本作为整体分配，适合评估面对新用户、新会话或新来源的表现。

**训练集去重后，测试集就一定独立吗？** 还要检查跨集合的相似内容及共同来源。去重算法、相似度阈值和人工抽查都影响检查结果。
