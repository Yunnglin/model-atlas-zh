## 用大白话理解

一位老师给学生示范一道题，是告诉他“这个答案怎么写”；老师比较两个答案，则是在表达“哪个更合适”。人类反馈强化学习（RLHF）利用人对模型输出的评价来构造训练信号。这里重点讲 InstructGPT 的代表性路线：示范微调、学习偏好评分，再用强化学习更新模型；实际系统的反馈形式和算法可能不同。

这条思路早于 InstructGPT：2019 年已有研究用人类偏好训练语言模型，2020 年又被用于摘要任务。InstructGPT 将类似的流程用于更广泛的指令，并不意味着它发明了人类反馈强化学习。

## 一个问题怎样变成训练信号？

假设用户问“什么是过拟合”。当前模型生成两个候选：A 解释训练表现好但新数据效果差，并给例子；B 声称训练损失降低就一定能泛化。标注者按正确、清楚等规则选择 A。多条同题候选及排序用于训练奖励模型，让它学习人通常更认可哪种回答。

有了评分器，策略模型针对新问题采样回答，奖励模型给分，强化学习算法再调整策略，使获得较高评分的回答更可能出现。训练通常加入参考策略约束，避免策略只追逐评分而偏离原模型太远。奖励模型不是万能裁判：若它错误地把“篇幅长”当成“质量高”，生成模型就可能学会堆字，而非解释得更好。

<summary>想深入：偏好评分与策略目标</summary>

$$
P(y_w \succ y_l\mid x)=\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)
$$

这里 $x$ 是同一问题，$y_w$ 和 $y_l$ 是标注较优和较差回答，$r_\phi$ 是奖励模型评分，$\sigma$ 将分差变成偏好概率。比如分差为 0 时该模型预测两者各有一半被偏好的概率；分差增大时预测较优答案被选中的概率增大。这是常见成对偏好建模方式，不代表人的所有分歧都可简化为同一个分数。

策略优化的简化目标可以写为：

$$
\max_{\theta}\;\mathbb E_{x\sim D,\,y\sim\pi_\theta(\cdot|x)}\!\left[r_\phi(x,y)-\beta\log\frac{\pi_\theta(y|x)}{\pi_{ref}(y|x)}\right]
$$

$D$ 是问题分布，$\pi_\theta$ 是待训练模型，$\pi_{ref}$ 是参考模型；对回答取期望时，对数概率比对应条件 KL 偏离，$\beta$ 调整约束强度。这里省略采样、回合和具体算法细节；实际训练实现可能对逐 token 估计、奖励与约束采用不同形式。

这个约束应按期望理解：某一条回答的对数概率比可以是负数，不代表 KL 本身为负。$\beta$ 控制的是偏离的惩罚权重，也不是给每条回答或每一步更新设置一个绝对不能超过的距离上限。偏离太大或奖励遭利用时，仍要结合实际采样与独立评测检查。

例如仅有 A、B 两种回答，当前策略概率为 $(0.2, 0.8)$，参考策略为 $(0.5, 0.5)$。如果采样到 A，单条对数比为 $\log(0.2/0.5)\approx-0.916$；将两条回答各自的对数比按当前策略概率加权，得到 KL 约为 $0.2\log(0.4)+0.8\log(1.6)\approx0.193$。单个样本为负，与总体 KL 非负并不矛盾。这个例子是教学计算，不是论文的实测分数。

## InstructGPT 的三个训练数据集

[InstructGPT](/nlp/instructgpt-model/) 是一条具体的 RLHF 路线。论文把数据分成三部分：约 **1.3 万条训练提示**配人工示范用于 SFT，约 **3.3 万条训练提示**及其候选排序用于训练奖励模型，约 **3.1 万条训练提示**用于 PPO 阶段让模型继续生成并优化。前两部分的提示既有标注员编写的，也有来自早期 API Playground 的；PPO 部分使用 API 提示。

这三种数据分别承担不同任务：示范告诉模型怎样回答，排序告诉评分器人更喜欢哪个回答，PPO 提示则为策略提供练习题。对于 API 提示，论文按用户 ID 划分训练、验证和测试数据，方便评估面对新用户提示时的表现。

### 一次排序能做出多少条比较？

InstructGPT 的标注者对同一个问题的 4 到 9 个回答排序。假设四个回答按质量排成 A、B、C、D，就能得到 A 胜 B、A 胜 C、A 胜 D、B 胜 C、B 胜 D、C 胜 D 共六组比较。但这六组来自同一个问题和同一次排序，**不是六个互相独立的问题**：一旦标注者误解了题意，多组比较都可能一起受影响。

论文发现，若把这些高度相关的比较逐条打散、反复用于模型更新，奖励模型容易过拟合。因此它将同一个问题下的所有比较作为一个批次元素，复用各回答的评分并计算成对损失。这样既减少重复计算，也降低论文实验中观察到的过拟合；别把增加比较对数直接等同于增加独立标注问题数。[论文的奖励模型章节](https://arxiv.org/html/2203.02155)给出了具体方法。

奖励模型输出的分数也不是“这个回答有多少分的客观质量”。成对损失关心的是同一问题下的**分差**：A 得 2、B 得 1，与 A 得 12、B 得 11，分差相同，对应的偏好概率也相同。论文在强化学习前，用偏置将人工示范的平均奖励调整为 0，便于后续训练；这不意味着 0 分就是回答合格线。比较不同奖励模型的原始分数时，不能不加校准就直接比较。

在论文的人工评估中，175B InstructGPT 的回答相对于同规模 GPT-3 更受标注员偏好，比例为 **85% ± 3%**；给 GPT-3 提供少量示例后，对照结果为 **71% ± 4%**。这些数值反映的是论文所用提示、采样和标注规则下的偏好比较。想看这一模型的任务和训练细节，可继续读 [InstructGPT 模型页](/nlp/instructgpt-model/)。

## 人类反馈和奖励模型各有什么作用？

人提供评价标准与候选偏好，奖励模型学习近似这些判断，策略模型再利用评分探索。这样能把有限人工标注扩展到更多候选，但评分器只能学习数据覆盖到的偏好。它不直接知道人真正想要什么，也可能对训练时没见过的领域、语言或恶意答案判断失准。

比较数据需要记录问题、候选、标注要求及分歧。若评审只看到答案没有看到上下文，就可能把流畅但不符合需求的回答选为较好；如果总把 A 放在左边，位置偏好也可能影响选择。应平衡候选顺序，允许不确定或都不合格，并审查不同标注者对尺度的理解。

人也会有不同判断。InstructGPT 报告，在其标注安排中训练标注者两两意见一致率约为 72.6%；奖励模型在未参与训练的一组标注者上的偏好预测准确率约为 69.6%。这两个数字衡量的不是同一件事，不能拿一个减去另一个当成“模型落后人类多少”。论文也强调，标注者群体、任务说明和问题来源共同决定了被学习的偏好；换一个用户群，仍需要重新评估。

## 训练、评测与错例

奖励模型需要自己的训练和验证划分，策略优化期间应监控奖励、输出长度、参考偏离及多样性。但奖励上涨只是说明模型更能获得这个评分器的高分；模型可能找到评分器漏洞。最终仍需在独立问题集上盲评，并与事实检查、业务通过率、安全与误拒绝等指标一起看。

例如解释过拟合时，模型输出了很长的例子，却仍把验证集当训练集。先确认标注规则是否过度看重长度，抽查奖励模型在事实错误和简洁正确候选上的排序，再核对是否对相同来源问题泄漏。修正标准和数据后重新训练，并用未参与改动的题集检查；不要只把奖励提高视为修复。该流程为建议方案，未实际运行。

## 容易混淆的几件事

[SFT](/training/sft/)利用示范答案进行监督学习；经典 RLHF 的奖励建模路线利用人类比较训练评分器，再用强化学习更新策略。[DPO](/training/dpo/)也可利用同样的偏好对，但经典形式不必单独训练显式奖励模型并运行在线 RL。[RLVR](/training/rlvr/)强调结果可以由验证器给出反馈。反馈从哪里来与采用什么更新算法是不同维度，也可以在系统中组合。

**面试追问：奖励模型分数高就证明人更满意吗？** 不一定。评分是代理指标，可能偏离人真正的需求，须在独立样本上验证。**用 AI 代替人工比较就消除偏差吗？** 不能；评审模型也有盲区，应核对它与目标用户及事实评价的一致性。
