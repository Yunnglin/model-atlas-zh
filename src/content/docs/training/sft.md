## 先看一个问题

一个已有语言模型能续写文字，但未必会按你的要求把会议记录整理为三点。怎样让它学会“看到指令后，给出符合要求的回答”？监督微调（Supervised Fine-Tuning，SFT）给它看一批输入与示范输出，再根据示范计算训练误差。

## 用大白话理解

像带新人做工单，先给他看“客户说了什么”和“合格工单怎么写”。他不是只背下这一条，而是希望从许多不同例子里学到可迁移的规律。示范若把客户没有说过的内容填进去，他也可能学到这种坏习惯。SFT 的成果因此不仅取决于训练程序，也取决于数据质量和任务定义。指令微调通常是 SFT 的一种：示范数据特别强调根据指令完成任务；SFT 的范围还包括其他有监督的任务数据。

对生成式语言模型，SFT 常仍然使用[下一 token 预测](/foundations/next-token/)：在问题和已给出的正确答案前缀条件下，预测示范答案的下一个 token。它改变了训练材料和目标位置，不要求换掉 Transformer 结构。SFT 可以全量更新参数，也可以与 [LoRA](/training/lora/) 结合，只训练适配器参数。

## 把一条数据走完整

假设对话为：用户说“今天讨论了预算、排期和下周评审，请总结为三点”，助手示范“1. 确认预算；2. 制定排期；3. 下周评审。”示范应忠实保留会议原意。

数据准备时先保留角色和消息边界，按目标模型的聊天模板拼成模型能识别的 token 序列。训练时把真实答案作为目标：例如已经给出“1. 确认”，就让模型预测正确的下一段；接着把正确的后续内容也加入前文，继续预测下一位置。这叫教师强制：训练看到的是示范前缀，实际生成时前文则包含模型自己生成的内容，所以错误可能累积。

对话里用户问题通常作为条件，助手答案作为需要学习的目标。助手内容、结束标记和工具调用是否计入损失，由任务与训练配置决定。输入中的用户 token 不计损失，也仍会影响模型预测答案；掩码只是说这些位置不直接贡献训练目标，并非把问题从上下文中删除。

### 掩码到底遮住了什么？

把一轮对话想成下面三段。下面展示“只监督助手回答”的一种配置；实际 token 切分由分词器决定。

| 片段                 | 仍是模型输入吗？       | 直接计入损失吗？ |
| -------------------- | ---------------------- | ---------------- |
| 用户：什么时候评审？ | 是                     | 否               |
| 助手：周五评审。     | 是，训练时提供示范前缀 | 是               |
| 回合结束标记         | 依模板和配置而定       | 依模板和配置而定 |

这里有两种容易混淆的“遮住”：**损失掩码**决定哪个目标位置参与评分；**注意力掩码**决定当前位置可以看哪些输入，另外还可能屏蔽填充位置。把用户内容排除在损失外，不代表模型看不到用户问题。因果语言模型需要让前面的内容预测后面的目标；标签与输出的错位有时由模型或训练器内部处理，不能看见序列就额外手动移动一次，否则可能错位两次。

例如 Hugging Face TRL 提供 `assistant_only_loss=True`，它需要对话数据和能标出助手生成区域的聊天模板。开训前抽几条处理后的样本，把解码出的输入、实际参与损失的标签和结束标记并排检查，比只看配置名可靠。

另一种常见数据是 `prompt` 加 `completion`：前者是问题，后者是期望续写。TRL 的 `completion_only_loss` 决定是否只对 completion 计分；它关注的是**数据中问题和续写的边界**。`assistant_only_loss` 关注的则是**对话中哪些内容属于助手**。对于包含多轮角色的 prompt-completion 数据，两者可以组合；具体支持和默认值应以使用版本的[训练器文档](https://huggingface.co/docs/trl/sft_trainer)为准。

例如有一条多轮数据：用户问“什么时候评审？”，助手发起日程查询工具请求，工具返回“周五”，助手答“周五评审”。如果目标是教会工具调用和最终回答，需要明确助手的工具请求和回答如何标记、工具返回如何输入。误把工具输出当成助手示范可能让模型学着冒充工具；误把所有助手内容掩掉，则几乎没有有效监督。特别要检查截断、填充和结束标记，避免答案被截掉或永远学不到何时停止。

<summary>想深入：训练损失是什么意思</summary>

$$
L = -\frac{1}{|M|}\sum_{t\in M}\log p_\theta(y_t\mid x,y_{<t})
$$

$x$ 是问题及可用上下文，$y_t$ 是示范答案在位置 $t$ 的 token，$y_{<t}$ 是此前的正确示范 token；$p_\theta$ 是当前模型给正确 token 的条件概率。$M$ 表示选中参与损失的答案位置，$|M|$ 是这些位置的数量。模型越不给正确 token 高概率，损失通常越大；训练通过调整参数使损失下降。实际实现的样本与 token 平均方式、掩码和辅助损失可能不同。

比如简化为两个计分位置，模型给正确 token 的概率分别是 0.8 和 0.5，平均负对数损失约为 0.458（自然对数）。这个算例帮助理解损失的计算方式。训练损失下降说明更容易预测训练示范，还要结合独立测试集判断模型是否能回答新问题。

</details>

## 一次更新里，长答案会占多大比重？

假设一批数据只有两条回答：第一条有三个需要计分的 token，损失分别为 0.1、0.1、0.1；第二条只有一个计分 token，损失为 1.0。如果按所有计分 token 求平均，批次损失是 `(0.1 + 0.1 + 0.1 + 1.0) ÷ 4 = 0.325`。如果先求每条回答的平均，再让两条回答各占一半，则是 `(0.1 + 1.0) ÷ 2 = 0.55`。

两种汇总方式回答的问题不同：前者让每个计分 token 权重相同，长答案通常贡献更多；后者让每条回答权重相同。训练时还可能使用梯度累积或分布式计算，具体归一化由训练器实现决定。比较实验时，除了数据条数，也应记录有效监督 token 数与损失归约方式。

## 真实案例：InstructGPT 怎样准备示范

[InstructGPT](/nlp/instructgpt-model/) 的论文先从 API 提示及标注人员编写的提示中收集约 1.3 万条 SFT 训练提示，并让标注人员提供示范答案；之后分别使用另一批比较数据训练奖励模型，再用 PPO 继续训练。示范、比较和 PPO 提示是不同用途的数据，SFT 只是整条后训练路线的第一步。

例如有的用户请求摘要，标注人员需根据给定文本写出示范；有的请求则要求生成内容。模型学到的行为受到提示分布和标注规范影响。论文用人工评价等方法考察模型回答，读具体成绩时应确认对比的是 SFT 模型还是经过后续步骤的 InstructGPT。

## 没有现成解题过程时：先采样，再筛选

有时只有题目和标准答案，没有人写好的推导过程。**拒绝采样微调**（Rejection Sampling Fine-Tuning，简称 RFT；有些资料也用 RFT 指强化学习微调，需结合上下文区分）可以先让模型对每道训练题尝试多个回答，再用答案检查器筛选，把通过检查的“题目＋回答”当成示范数据做 SFT。[RFT 论文](https://arxiv.org/abs/2308.01825)用这个思路扩充数学推理训练样本。

例如问题是“80 元打八折是多少”，模型生成四份回答，其中两份最终答案为 64、两份答错。如果答案提取器可靠，就先保留前两份，再将其作为监督样本训练；这两份如果只是换了标点或重复同一解法，不等于得到了两种不同的思路。数字只是教学示例，实际每题采样多少、保留多少、是否去重，都要记录。最终答对也可能只是碰巧猜中：应抽查计算过程、单位和格式，避免把错误推导当成好示范。

这和 [GRPO](/training/grpo/) 的差别在**更新方式**：RFT 把筛选结果变成 SFT 数据，学习保留下来的回答；GRPO 用同题候选的相对奖励构造优势并进行策略优化。两者都可以使用答案检查器，也可以在一个模型的不同阶段先后使用，但“筛选后做 SFT”本身不是一次强化学习更新。[DeepSeek-R1](/nlp/deepseek-r1/) 是这样的阶段组合例子：推理强化学习模型生成候选，再筛选数据，用于重新微调 V3-Base。

只保留答对的候选容易让训练集偏向模型已经会做的题：一道题采样多次都没答对，就没有成功示范可留下。可以统计每个难度的采样成功率、保留率、生成成本以及重复率，再对困难题引入经审核的示范或改进验证器。[STaR 论文](https://arxiv.org/abs/2203.14465)探索另一种办法：遇到答错的题，给模型正确答案作为提示，再尝试生成解释；这个过程依赖训练时已知答案，产出的解释仍需检查，评测时也不能把标准答案透露给模型。最后在按来源隔离的独立题集上，比较原始 SFT 和加入筛选数据后的正确率、过程错误与总采样成本，不要只看留下了多少条数据。

## 数据怎么准备？

先定义目标：会议摘要是否必须三点、能否保留原话、缺失责任人时应该写“未明确”还是不输出。然后收集合适的输入，写或审核示范答案，保留角色、模板和必要上下文；剔除敏感或无权使用的数据，并处理重复、冲突、格式错误和过期信息。样本应覆盖长短会议、口语、含糊表述和信息不足等情况，教模型保留原文的不确定性。

按会议或项目等来源分组拆分训练、开发和测试，比随机拆相似句子更能避免泄漏。开发集用于选择学习率、训练轮数及检查失败；测试集留到方案确定后独立评估。若用测试集反复挑样本或调参，就逐渐把它变成开发集，需要另留真正独立的验证数据。

通用模型也可能因过度集中于摘要数据而在其他任务上退化。可根据目标加入适当的通用示范，并用保留的通用能力集测量；混入比例可以根据目标任务和独立评测调整。对于不断变化的事实，可以配合检索或更新知识源。

## 怎么训练与评测？

先记录未微调模型基线，固定数据划分、提示模板、模型版本和生成参数。选择全量微调或 LoRA，设置学习率、批量、最大长度和训练时长；查看真实可训练参数及标签掩码，再用小批样本检查输入、目标与停止符。评估不应只看训练损失，还要在未见过的会议记录上看事实是否忠实、三点是否覆盖主要内容、是否凭空添加日期或责任人，以及格式是否合规。

对于同一批测试记录，可以让两种模型使用相同的输入和预算，先计算格式通过率，再对事实错误、遗漏和无依据补充分别标注；无法自动判定的摘要需要人工核对原文。记录样本数与失败类别，才能看清整体效果。评测和部署还应检查实际聊天模板、截断策略以及所用基础模型，避免离线结果与产品条件不一致。

## 从错例回到数据

假设模型总把“可能下周评审”写成“下周一定评审”。先复现问题：检查原文、提示、检索内容和输出，再排查是示范把可能性抹掉、样本缺少不确定性表达，还是推理模板要求过于绝对。给开发集加入不同说法，例如“暂定”“尚未确认”，并审核示范是否保留原意；调整后在未参与修改的独立测试集复测，同时检查其他摘要质量有无下降。

## 和相近概念比一比

预训练通常从大规模数据学习一般语言与知识模式；SFT 用示范指导具体回答方式。[RLHF](/training/rlhf/) 和 [DPO](/training/dpo/) 可利用偏好或反馈进一步调整行为，它们与 SFT 使用的数据和训练目标不同。[训练全流程](/training/pipeline/)展示常见组合；具体模型不一定使用相同阶段。

## 面试追问

**SFT 是否改变模型结构？** 不一定。它首先是一种使用有标签示范的训练方式；可以全量更新原结构，也可以加 LoRA 等可训练模块。

**只对助手答案算损失，用户问题还有用吗？** 有用。用户问题仍作为上下文影响答案预测；损失掩码只是决定哪些位置直接计入目标。

**训练损失很低，为什么上线仍出错？** 可能数据重复、训练和线上分布不同、示范本身错误、模板不一致或模型在自由生成时偏离示范前缀。需要独立评测和针对性错例分析。
