## 用大白话理解

模型先用旧策略写完一组答案，训练时当前策略已经开始变化，如何衡量它与产生答案时的旧策略差了多少？GRPO 原始目标按 token 计算新旧概率比；GSPO 则先看**整条回答**的新旧似然比，并按回答长度归一化，再用于序列级裁剪与优化。

这像比较两位厨师做出整道菜的可能性，而不是只盯着某一次加盐。这样做的动机是让序列级奖励与序列级更新更一致；它不代表序列中每一步都正确，也不能保证换任何模型和任务都更稳定。

## 从概率比走到序列比

对于问题 $x$ 和生成回答 $y=(y_1,\ldots,y_T)$，两个策略分别给整条回答分配概率。GSPO 论文使用长度归一化的序列比率：

$$
s(\theta) = \left(\frac{\pi_\theta(y\mid x)}{\pi_{\mathrm{old}}(y\mid x)}\right)^{1/T}
= \exp\!\left(\frac{1}{T}\sum_{t=1}^{T}\log\frac{\pi_\theta(y_t\mid x,y_{<t})}{\pi_{\mathrm{old}}(y_t\mid x,y_{<t})}\right).
$$

也就是 token 概率比的几何平均。举例来说，长度为 2 的回答中，两个 token 的比率分别为 1.44 和 1.00，序列比率就是 $\sqrt{1.44}=1.2$；不是两个比率的算术平均，也不是直接相加。实际训练在对数空间计算，减少长序列概率连乘的数值问题。

长度归一化使比率不会随 token 数简单地指数增长，但不会让长短回答天然公平；样本长度、奖励与损失汇总方式仍然影响训练。公式描述的是已采样序列在两个策略下的相对似然，不是回答正确率，也不是新策略与旧策略的总体距离。

这里还要区分一个容易混淆的细节：对整条序列而言，完整的新旧概率之比才是通常意义上的序列重要性采样权重；GSPO 实际用于裁剪和优化的是它的 $1/T$ 次方。这个长度归一化比率不应直接当成可以无偏还原任意序列期望的完整权重，论文是用它构造代理优化目标。

## 两个 token 的变化可以互相抵消

假设某条回答只有两个 token，它们的新旧概率比分别为 1.44 和 0.64。GSPO 的长度归一化序列比率是 $\sqrt{1.44\times0.64}=0.96$：整体略低于 1，但两个位置的变化并不小。若单个 token 的裁剪区间是 $[0.8, 1.2]$，两个比率分别超过上界和低于下界；序列比率却仍可能落在同样数值的区间内。这个算例说明**序列级与 token 级统计关注的对象不同**，不能从序列比率接近 1 推断每个位置都接近旧策略。

图中先相乘得到完整序列概率比，再按长度取平方根。序列比率在示例区间内，不意味着每个 token 的比率都在区间内；裁剪是否影响目标还取决于优势符号。

上面用相同区间只是方便对比。GSPO 论文指出不同粒度比率的数值分布不同，两类算法的裁剪范围通常也不相同；真实比较需要分别调参，并记录实际裁剪范围和成本。论文实验使用 GSPO 左右阈值分别为 0.0003 和 0.0004，而其 GRPO 基线分别为 0.2 和 0.27：不同数字对应不同统计对象，不能仅据此认为 GSPO 一定更保守。

## 一组答案怎样参与更新

一题采样 A、B、C 三份答案，验证器分别给 1、0、0。将奖励做组内比较得到各答案的优势；再对每条回答计算序列比率，并结合优势进行裁剪。优势决定鼓励还是抑制该样本，序列比率则表示当前策略相比采样策略对它的偏好变化。

论文的序列级目标可简写为：

$$
J(\theta)=\mathbb{E}\left[\min\!\left(s(\theta)\hat A,\ \operatorname{clip}(s(\theta),1-\epsilon_{\text{low}},1+\epsilon_{\text{high}})\hat A\right)\right].
$$

这里展示的是关键裁剪目标，组采样及平均写进期望中；原论文的算法公式用对称的 $\epsilon$ 表述，实验部分使用不同的左右裁剪范围，所以上式使用 $\epsilon_{\text{low}}$ 和 $\epsilon_{\text{high}}$ 表示更一般的形式。具体实现还可能增加约束或采用不同汇总方式。对于正优势，如果序列比率超出上界，代理目标不再奖励继续推高该比率；负优势时下界对应抑制方向。裁剪不是强制所有序列的实际概率比都落在区间内。

例如 A 的优势为正，允许的上界是 1.1，而其当前序列比率是 1.2：裁剪项按 1.1 计算这部分目标，不继续奖励超出的增长。其他样本的梯度和多次参数更新仍会影响 A，所以不能称为概率比被硬性锁住。

反过来看负优势：假设某答案的优势为 -1，下界为 0.9，当前序列比率为 0.8。未裁剪项是 $0.8\times(-1)=-0.8$，裁剪项是 $0.9\times(-1)=-0.9$；目标取两者较小的 -0.9。继续压低这条答案的比率，在这项代理目标里不再得到额外好处。正负优势关注的裁剪方向不同，所以不能只看比率是否超出区间。

如果一组答案得分全部相同，组内就没有相对好坏；论文的标准化公式此时分母为零。实际训练需要约定如何处理，例如跳过这组或在分母中加入稳定项；具体行为要看所用实现，不能假设每个训练框架都一样。

## 一条回答里，不同步骤能有不同反馈吗？

上面的 GSPO 例子给整条回答一个优势，适合奖励只评价最终结果的情况。遇到多轮工具调用时，一条轨迹里的不同动作可能得到不同反馈：例如第一次调用正确，第二次调用了不存在的工具。如果只给整条轨迹一个总分，就不容易把这两次操作区分开。

论文还提出 **GSPO-token** 变体：同一条回答的各个 token 在数值上仍使用相同的序列比率，但可以为不同 token 指定不同的优势。例如序列比率都是 1.02，第一步优势设为 +1、第二步设为 −0.5，那么两步对策略更新的方向可以不同；这只是帮助理解的构造数字，不是论文中的实验结果。论文通过停止梯度的写法保留逐 token 的梯度，而不是回到 GRPO 那样用每个 token 各自的新旧概率比作为数值权重。

如果将同一回答的所有 token 优势设成一样，论文指出 GSPO-token 与原 GSPO 在目标、裁剪条件及理论梯度上等价；把优势改成逐 token 不同则可表达更细的反馈。如何获得可靠的步骤奖励仍是另一道题：工具报错可能来自环境故障，不能未经判断就当成模型动作错误。[RLVR](/training/rlvr/) 的验证器分析可帮助检查反馈是否可信。

<details>
<summary>想深入：数值都是 1，为什么还能有梯度？</summary>

论文用 $\operatorname{sg}$ 表示“保留数值，但停止梯度”。对某个已生成 token，把它在当前策略下的概率简记为 $p$，序列比率简记为 $s$，GSPO-token 的权重可以写成：

$$
s_t = \operatorname{sg}(s) \frac{p}{\operatorname{sg}(p)}
$$

例如 $p=0.5$、$s=1.02$，前向计算时 $p/\operatorname{sg}(p)=0.5/0.5=1$，所以每个位置看到的权重都是 1.02。反向传播时，分母被当作固定的 0.5，而分子仍随模型参数变化；因此这一比值虽然数值为 1，梯度却不为零。停止序列比率的梯度，再保留当前位置分子的梯度，就能让每个 token 搭配自己的优势计算更新。

这里说的是[论文第 4.3 节](https://arxiv.org/html/2507.18071v2#S4.SS3)的构造；实际更新还要考虑裁剪是否生效。把 $p/\operatorname{sg}(p)$ 直接删成常数 1，会把这条梯度路径一并删掉。

## 为什么论文讨论 MoE

在稀疏混合专家模型中，输入经过路由选择专家；训练和生成时的路由与数值差异可能使 token 级比率不稳定。GSPO 论文报告其方法在所研究设置下改善训练稳定性和效率，并用于后续 Qwen3 训练。这个结论依赖模型、数据、奖励、训练系统与评测条件，不能直接推出所有 MoE 或所有任务都适用。

论文以 48 层的 Qwen3-30B-A3B-Base 为例：对同一条采样回答做一次强化学习更新后，新旧策略激活的专家约有 10% 不同。旧策略写答案时和当前策略重新计算概率时，部分 token 经过了不同的专家组合。这会影响 token 概率比，让更新时的比较更加复杂。

研究者先前使用 Routing Replay：生成回答时记下选中了哪些专家，训练时计算该回答的概率比再沿用这些选择。这样需要额外保存和传递路由信息。论文报告，在其对照实验中 GSPO 无需重放路由也能稳定训练；这是一组特定模型和训练设置的观察。

### 论文怎样比较两个方法

研究者以 Qwen3-30B-A3B-Base 的冷启动微调模型为起点，把每批采样数据分成四个小批次进行更新。评测包括 AIME 2024、LiveCodeBench（2024 年 10 月至 2025 年 2 月）和 Codeforces：AIME 报告 32 次采样的平均 Pass@1，LiveCodeBench 报告 8 次采样的平均 Pass@1。论文还比较了相同训练计算量和使用题目数下的训练曲线。

这类平均 Pass@1 是多次独立单次作答正确率的平均，并不是从 32 份答案中挑出至少一份正确的 Pass@32。它同时告诉我们评测做了多少次采样，便于和自己的成本一起比较。

和 [GRPO](/training/grpo/)相比，两者都能利用同题组内奖励，区别在新旧策略的概率比和裁剪粒度。与 [PPO](/training/ppo/)相比，不能只看名称，还要看优势估计、参考约束和数据复用。与 [RLVR](/training/rlvr/)相比，RLVR 说的是奖励能否核验；GSPO 是更新策略的方法，可与可验证奖励组合，也可以使用其他反馈。

## 评测和错例

把同一基座、题目、验证器和计算预算固定，比较独立题正确率、训练中断、梯度与比率分布、裁剪比例、输出长度和总采样成本。若训练曲线更平滑，但最终正确率下降，应同时检查难度、数据泄漏、奖励错误和长度变化。不同算法的训练配方可能同时变化，单次结果不能归因于某一个公式。

例如验证器只检查程序能否通过公开样例，模型可能针对样例写死答案。无论采用 token 级还是序列级优化，奖励都会鼓励这种漏洞；应该增加隔离的隐藏测试和人工抽查。一个评测指标上升，不等于现实任务已解决。

## 面试追问

**序列比率为什么取 $1/T$ 次方？** 相当于对 token 对数比率求平均，缓解整条序列概率连乘对长度的指数敏感性；不是保证长短回答完全可比。

**裁剪使所有比率不能超过阈值吗？** 不是。它改变优化目标对过大变化的激励，其他梯度和后续更新仍可能让比率超过阈值。

**GSPO 是否就是一种奖励模型？** 不是。奖励来自验证器、模型或其他信号，GSPO 规定如何利用优势和新旧策略比率优化。
