## 用大白话理解

一个助手回答问题后，奖励信号认为这次回答不错。训练应提高类似行为出现的概率，但如果一次改得太猛，模型可能为了某种分数失去原来的其他能力。[PPO](https://arxiv.org/abs/1707.06347) 是一类策略优化算法；常用的 PPO-Clip 用裁剪的代理目标，减少对过大单次概率变化的激励。

可以把它想成学骑自行车时每次根据反馈调整动作，动作可以改变，但不希望因为一次成功就猛打方向。实际更新幅度还取决于学习率、更新次数和其他训练设置。

## 四个角色和一次训练

以语言模型后训练为例，策略模型负责生成回答；奖励信号给回答打分，可能来自奖励模型或规则；价值模型估计当前状态下未来奖励，协助计算优势；参考模型有时用于约束语言模型偏离原有行为。PPO 是通用强化学习方法；语言模型实现中，这些角色可能共享网络，也可能使用不同约束。

假设用户问“如何整理一份报表”，旧策略生成一份回答，奖励模型给 0.8 分。如果价值估计认为该状态预期奖励为 0.5，简单示意下优势可理解为 0.3：比预期好，倾向于提高产生该行为的概率。实际优势由奖励、价值估计与时间步信息共同计算，评分 0.8 也只是奖励模型的分数。

常见流程是：采集旧策略轨迹，计算奖励与优势，在这批数据上进行有限次更新，再采集新的轨迹。若奖励模型把冗长空话误判为高质量，PPO 也可能学会写更多空话；优化方法不负责保证奖励定义符合用户真正需要。

## 裁剪目标怎么理解

设状态为 $s_t$、动作为 $a_t$，新旧策略对已采样动作的概率比为 $r_t(\theta)=\pi_\theta(a_t\mid s_t)/\pi_{\mathrm{old}}(a_t\mid s_t)$。优势 $\hat A_t$ 表示该动作相对基线好多少。PPO-Clip 的关键代理目标为：

$$
L^{\mathrm{CLIP}}(\theta)=\mathbb E_t\left[\min\left(r_t(\theta)\hat A_t,\ \operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat A_t\right)\right].
$$

![PPO-Clip 正负优势算例：分别计算未裁剪和裁剪后的目标，取较小值；裁剪不是概率比的硬约束。](/figures/training/ppo-clipping.svg)

图中两组数字展示了裁剪目标如何改变已采样动作的优化激励。

如果优势是 +1、$\epsilon=0.2$，当前比率是 1.5，未经裁剪项为 1.5，而裁剪项是 1.2，目标取较小的 1.2；对这条样本来说，超过 1.2 后不会继续奖励更大的增长。若优势为负，裁剪在过度降低概率的方向起类似作用。

再看负优势：若优势是 −1、比率是 0.5，未裁剪项是 −0.5，裁剪后的比率是 0.8、对应项为 −0.8；目标取较小的 −0.8。此时继续压低该动作的概率不会让这条样本的裁剪目标继续变好。注意必须先将比率乘上带符号的优势再比较：优势为负时，简单说“始终取较小的比率”会得出错误结论。

**换个方向再算一次。** 正优势仍为 +1，但如果比率降到 0.5，未裁剪项是 0.5，裁剪项是 0.8，目标取 0.5；负优势为 −1、比率升到 1.5 时，两项分别是 −1.5 和 −1.2，目标取 −1.5。这两种情况下，虽然比率都已经超出裁剪区间，目标仍保留继续纠正这个变化的激励。换句话说，裁剪不是把所有区间外的样本都变成零梯度，而是只在目标所奖励的过度变化方向上截住收益。

裁剪作用在目标函数上，实际概率比仍可能超出区间。学习率、更新轮数、优势估计和批次也会影响更新；语言模型训练中还可能另加参考策略 KL 项。

两者看的“距离”不同：裁剪比率比较的是当前策略和**生成这批回答时的旧策略**对某个已采样 token 的概率；参考策略 KL 则用来衡量当前策略相对参考模型的偏离。比如每轮都重新采样并更新旧策略，但始终以同一个 SFT 模型作参考，那么每轮改动虽然不大，多轮累计后仍可能离 SFT 模型较远。具体参考模型及更新时机取决于训练配方。

## 一条回答怎样拆成训练步骤

假设助手回答“先整理数据，再画图”。生成“先”时，状态是用户的问题；生成“整理”时，状态变成问题加上已经写出的“先”；之后每生成一个 token，状态都随前文变化。策略为每一步给出下一个 token 的概率，价值模型则根据当时的状态估计后续表现。

整段回答完成后，评分器可能只给一个总分。训练程序再把总分与各步价值估计结合起来，计算各步优势：这样模型能利用完整回答的反馈更新生成过程。若模型说得流畅但关键数字错误，最终评分和价值估计都会影响各步得到的训练信号，所以评测时要把数字正确性单独拿出来看。

### 一个具体例子：整段得分怎样传回前面的 token？

一种常见做法是用广义优势估计（GAE）。可以把它看成沿回答从后向前传递“比预期好多少”的信号。假设一段回答只有三个 token，最终奖励为 1，中间奖励为 0；暂不加入 KL 等其他奖励。价值模型对三个生成前状态分别估计 0.4、0.6、0.7，回答结束后的价值按 0 计算。取折扣系数 $\gamma=1$，每一步的预测误差分别是：

- 第一步：`0 + 0.6 − 0.4 = 0.2`；
- 第二步：`0 + 0.7 − 0.6 = 0.1`；
- 最后一步：`1 + 0 − 0.7 = 0.3`。

如果取 $\lambda=0.95$，从后往前合并后，第三步优势为 0.3，第二步为 `0.1 + 0.95 × 0.3 = 0.385`，第一步约为 `0.2 + 0.95 × 0.385 = 0.566`。这只是手算示例：它说明最终反馈如何影响较早的动作，并不证明第一个 token 本身最正确。$\lambda$ 改变后续误差信号向前传播的权重；价值预测有误时，优势也会受到影响。

真实实现还要处理终止位置、填充掩码、回答截断及可能逐 token 加入的 KL 奖励。把一个被长度截断的回答当作自然结束，可能改变末尾价值估计；对比实验时应记录这一规则。[GAE 原论文](https://arxiv.org/abs/1506.02438)介绍了这种估计；[InstructGPT 的训练附录](https://arxiv.org/html/2203.02155)报告其使用广义优势估计，不能把上面数字当作该论文的实际训练记录。

## 从语言模型到 RLHF

RLHF 中，一种典型流程是先做监督微调，再收集人类偏好训练奖励模型，之后用 PPO 等方法优化策略，并使用参考策略约束以减少偏移。[InstructGPT 论文](https://arxiv.org/abs/2203.02155)是具体实例。RLHF 描述反馈来源和训练流程，PPO 描述如何更新策略：人类反馈也能与其他方法组合，PPO 的奖励也不一定来自人类。

InstructGPT 还比较了 PPO 和 PPO-ptx：后者在 PPO 更新中混入预训练数据的语言模型梯度，目的是缓解部分公开任务的能力退化。这个混合策略属于该论文的训练配方，不是 PPO 裁剪公式本身的必选部分；比较时也要考虑额外训练成本。

回答是一串 token，每一步的状态包括提示和已经生成的前文；整段回答的得分怎样分配给各步，取决于优势估计和实现。价值模型的预测误差可能让优势变得嘈杂，奖励模型本身也可能误判。生成、奖励、价值估计和参考计算都需要资源，实际成本应根据实现测量。

## 评测与错例

训练时记录奖励、价值误差、策略与参考模型的 KL、裁剪比例、响应长度和采样成本。最终还应在独立任务上检查正确性、用户偏好、格式遵循与安全行为。奖励变高但人工偏好下降时，可能是奖励模型被利用、数据分布变化或评测覆盖不足；需要抽查具体样本，不能只看训练曲线。

例如助手为了拿高分，把回答变得很长，却漏掉报表中的关键数字。应核对奖励模型是否偏好长回答，补充对数字正确性和简洁度的独立评价，再对比不同训练配置。保留未参与调参的测试集，避免把评测题直接训练进模型。

## 与 GRPO、GSPO 的联系

[GRPO](/training/grpo/) 原始方法用同一题多份回答的组内奖励估计优势，避免额外价值模型，但需要多次采样；它仍使用 PPO 风格裁剪。 [GSPO](/training/gspo/) 把重要性比率与裁剪处理在序列层面。比较成本和效果时，需要一起看候选数、长度、模型与训练系统。

## 面试追问

**旧策略和参考策略一定是同一个吗？** 不一定。旧策略生成当前批轨迹，参考策略提供约束基准，更新周期也可能不同。

**为什么要有价值模型？** 常见 PPO 用价值估计作为基线，帮助估计优势和降低方差；它不是奖励模型，也不是所有 PPO 实现都必须拥有独立大模型。

**裁剪是否确保模型不退化？** 不能。奖励有漏洞、数据太窄或更新过强都可能造成退化，仍需独立评测与监控。
