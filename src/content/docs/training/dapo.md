## 先看问题

训练数学推理模型时，同一道题会生成多个答案，验证器给出对错，再用相对奖励更新模型。听上去简单，实际会遇到一些棘手情况：题目太简单时所有答案都对，太难时所有答案都错；推理过程很长时，截断可能造成不公平扣分；过于保守的更新可能让模型越来越只尝试一种写法。

[DAPO 论文](https://arxiv.org/abs/2503.14476)公开了一套针对长推理强化学习的算法和训练系统。论文将 **非对称裁剪、动态采样、token 级损失聚合和超长回答处理**组合起来，主要用数学任务检验这套方法。

## 同一道题的四个回答

假设验证器对四个候选给出 1、0、1、0，[GRPO](/training/grpo/)可以从组内对比中产生正负优势；若是 1、1、1、1 或 0、0、0、0，组内没有区分信号。这里用 1 和 0 只是教学示意：论文中的基础正确性奖励是答对 +1、答错 −1，后续还可能叠加长度惩罚。在论文的二元正确率设定中，**动态采样**会过滤全对和全错的题组，继续采样直到得到足够多有差异的组。

如果只看二值正确性奖励，全对和全错的题组没有组内差异。论文按正确率过滤这些组；即使加入长度奖励后组内总分可能不同，过滤条件仍然看正确率。筛选会增加采样量，也会改变训练题目的分布，可以同时统计过滤比例和生成开销。

## 四个设计分别在改什么

1. **Clip-Higher**：在 PPO 风格的概率比裁剪目标中，对上、下边界使用不同阈值，论文试图给概率上升留下更多空间。裁剪调整目标函数的激励，为概率上升留出更大空间。
2. **动态采样**：按正确率过滤全对或全错的题组，继续采样以凑够训练批次。需要记录额外抽样和过滤的成本。
3. **token 级损失聚合**：论文公式先在同题组内求所有回答的 token 损失之和，再除以该组 token 总数，最后对题组取期望；它不同于先对每条回答长度求平均再平均各回答。因此长、短回答在组内占的权重不同。
4. **超长回答处理**：论文先分析了对截断样本屏蔽损失的做法，随后引入软惩罚：回答超过预期长度后，在额外的缓冲区内随长度增加惩罚；在论文叠加的截断过滤设置中，被截断样本的策略损失被屏蔽。到达长度上限与是否真正截断并不总是同义，结束标记和框架的停止原因也要核对。预期长度、缓冲区和截断上限是不同配置。

**为什么要按 token 聚合？** 假设同题有两个回答，短回答 100 个 token、长回答 900 个 token。按回答分别求平均再平均，两个回答各占一半；短回答里的每个 token 在聚合中的系数为 1/200，长回答里的每个 token 为 1/1800。按组内所有 1,000 个 token 汇总后平均，每个 token 的系数都是 1/1000，短回答和长回答分别占 10% 与 90%。这只说明聚合权重，实际梯度还要乘以每个 token 的优势和概率变化。论文希望这样更充分地学习长答案中的有用模式，也能对重复等不良模式给予更充分的惩罚。

举个裁剪例子：论文的一组实验使用下界阈值 0.2、上界阈值 0.28，也就是比率的裁剪区间为 0.8 到 1.28。假设某 token 的优势为 +1，新旧策略概率比为 1.25，那么非对称区间中这一项仍按 1.25 计；如果换成上界同为 0.2 的对称区间，该项则按 1.2 计。这只是在比较这一个样本的代理目标，不表示实际概率一定会停在这些数字。

例如，在论文实验的 16,384 token 期望长度和 4,096 token 缓冲区设置下，若一条完整回答长 18,432 token，正好超过期望长度 2,048 token，线性长度惩罚为 −0.5；假设其正确性奖励是 +1，二者相加得到 +0.5。这个数字是按论文公式构造的例子，不是模型实测。**惩罚的是奖励，而不是先判成答错**；截断屏蔽则是另一项操作。即便某条截断样本的策略损失被屏蔽，它的奖励是否仍参与组内均值和标准差，要看具体实现及处理顺序。

图中的 −0.5 是长度奖励；是否屏蔽损失由截断处理决定。

论文的 DAPO 目标还去掉了与冻结参考策略之间的 KL 惩罚项；训练时仍需观察策略变化和独立评测表现。

把四项串起来看：一道题生成 16 个回答后，先按正确率判断这组是否留下；留下的回答结合对错和长度得到奖励，再计算组内优势。更新时，每个 token 的策略比率经过非对称裁剪，并按组内 token 总数聚合；被截断样本在论文的相应过滤设置下不贡献策略损失。这样可以分别定位“题组如何选”“奖励如何算”和“梯度如何汇总”。

比如要求模型解一道证明题，规定最多生成一定数量的 token。某条回答接近上限仍未完成，简单地判零分可能把“没有生成完”和“证明逻辑错误”混在一起。长度处理希望减轻这类噪声，但无法自动判断推理步骤是否正确；长度上限也可能影响最终答案。

## 数据、训练与评测

论文使用 Qwen2.5-32B 基座及数学训练数据，在 AIME 2024 上按温度 1.0、top-p 0.7 重复评测 32 次，并报告 avg@32；该统计是多次结果的平均，不是“32 次中至少一次正确”的 pass@32。该结果属于其特定模型、数据、验证器、生成预算与评测设置，不能理解为任意任务上提升固定比例。比较方法时要同时核对训练题和评测题隔离、是否有污染、采样次数、温度、上下文上限和算力。

论文从同一基座出发逐步加入方法，AIME 2024 的 avg@32 从基础 GRPO 的 **30**，经过截断过滤、Clip-Higher、软长度惩罚、token 级聚合，分别变为 **36、38、41、42**；再加动态采样后为 **50**。这是逐项叠加的结果，例如 42 到 50 比较的是“已有前几项”时增加动态采样，并非它在任意训练中的独立收益。

训练使用 DAPO-Math-17K，共约 1.7 万道答案为整数的数学题；论文将一些原本答案为表达式的问题改写成整数答案，以便使用规则验证器。每题采样 16 个回答，规则验证器检查答案，并结合长度惩罚形成奖励。整数形式方便自动检查，但也影响训练题目的分布；用到其他领域时，需要设计对应的验证方式。

论文设置每批使用 512 道提示、每题采样 16 个回答，对应 8,192 条回答；训练小批次为 512 条回答，所以一个采样批次可分成 16 次梯度更新。这是计算一批有效数据如何被利用，不是说总共只生成 8,192 条回答：动态采样可能过滤整组并继续采样，实际生成量要另外统计。

训练中除了正确率，建议同时记录每题全对／全错／有差异组的比例、有效 token 数、输出长度、截断率、奖励分布、训练总生成量与独立题的正确率。如果奖励上涨而真实评测下降，应检查验证器是否容易被格式或答案提取漏洞欺骗、筛选是否过度集中于某类题目、答案长度是否异常，以及模型是否失去其他任务能力。

## 与其他方法的关系

DAPO 处在策略优化与训练系统层面；[RLVR](/training/rlvr/)描述可验证奖励的来源，两者可以搭配。与 [GRPO](/training/grpo/)相比，DAPO 论文围绕组内采样、裁剪、损失聚合和超长处理作了一组改变；不能把它当成一种新的奖励模型，也不应认为换个算法名称就自动拥有相同训练数据和验证器。

## 面试追问

**为什么全对组也可能被过滤？** 论文按正确率过滤全对组：如果只使用正确性奖励，这一组没有差异信号；加入长度等奖励时总分可能不同，但过滤条件仍然是正确率。这不是说全对回答没有价值。

**非对称裁剪能保证模型始终稳定吗？** 不能。它调整代理目标，稳定性还依赖奖励、数据、采样、学习率和系统实现。

**论文成绩是否可以直接与其他榜单比较？** 应先核对模型版本、训练数据、采样次数、提示词和评分方式；口径不同的数字不能直接归因于算法。
