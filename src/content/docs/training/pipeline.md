## 用大白话理解

同一个模型可以先大量阅读，再看回答示范，接着根据反馈调整行为。模型结构说明信息怎样处理；学习目标说明怎样计算错误；数据说明模型练什么。把这三个层次分开，很多术语就能放对位置。

## 每一阶段在学什么

| 环节          | 主要材料           | 学习信号                    | 需要检查什么                   |
| ------------- | ------------------ | --------------------------- | ------------------------------ |
| 自回归预训练  | 文本或离散模态序列 | 下一 token 预测             | 覆盖、去重、泄漏、能力迁移     |
| SFT           | 指令与示范答案     | 预测示范输出，按掩码计分    | 模板、答案质量、任务完成       |
| 偏好学习      | 同题候选与偏好     | 奖励模型＋RL，或 DPO 等目标 | 评审质量、长度偏差、泛化       |
| 可验证奖励 RL | 可采样题目与验证器 | 答案或测试等可检查反馈      | 验证器漏洞、采样预算、隐藏测试 |

这不是所有模型必须依次完成的固定流水线。具体模型可以采用其中部分步骤，或组合其他目标。

下一 token 预测只是自回归路线的代表目标。掩码预测见 [BERT](/nlp/masked-modeling/)，图文表示见[对比学习](/training/contrastive-learning/)，图像和连续语音生成还可用[扩散／流匹配](/training/diffusion-flow/)。生成模型不是都在做下一 token 预测。

## 一个真实例子：InstructGPT

[InstructGPT](/nlp/instructgpt-model/) 把预训练后的 GPT-3 用于指令任务。研究者先让标注员为问题写示范答案，用这些样本进行 SFT；再让标注员对同一问题的多个回答排序，训练奖励模型。最后，模型生成回答，奖励模型给回答评分，PPO 根据评分和对参考策略的约束更新模型。

![InstructGPT 的三个阶段：人工示范训练 SFT，人工排序训练奖励模型，再由 PPO 利用奖励更新策略](/figures/training/rlhf-pipeline.svg)

这张教学图概括了 [InstructGPT 论文](https://arxiv.org/abs/2203.02155)中的一种后训练路线。论文还尝试在 PPO 更新中混入预训练数据的梯度，形成 PPO-ptx，以缓解部分原有任务上的表现下降。

### 一道题怎样变成三种训练材料？

假设题目是“向新员工解释什么是过拟合”，示范阶段让标注员写一份清楚、准确的答案，用它教模型怎样回答。奖励模型阶段则让模型给同一题生成多个候选，由标注员排序：如果有 4 个回答，一共可以组成 6 对比较。PPO 阶段提供提示，让当前模型自己生成回答，再由奖励模型打分并结合参考模型约束更新。题目相同不代表这三阶段的数据格式或损失相同；这个问题只是教学构造。

InstructGPT 论文实际让标注员给同一提示的 4 至 9 个回答排序。研究者发现，把同题产生的比较对拆开并随意打乱，重复使用相同回答会让奖励模型过拟合；他们把同一提示下的比较作为一个批次元素处理。直觉上，6 个比较对并不是 6 道互不相关的新题。设计自己的偏好数据集时，应按提示或更大的来源组划分训练与验证，再检查改写题是否跨集合重复。[论文第 3.5 节](https://arxiv.org/html/2203.02155)详细说明了这个处理。

这三步也可能出现不同的问题：示范答案写错会影响 SFT；标注员偏好与实际需求不一致会影响奖励模型；PPO 过度追求奖励模型的高分，则可能放大评分器的漏洞。排查时可以先分别抽查示范、偏好对和高奖励回答，再决定该修哪一环，而不是只盯着最终训练曲线。

评测时，研究者让标注员比较模型回答。在论文的提示分布和评审条件下，1.3B InstructGPT 的回答比 175B GPT-3 更受偏好；这反映的是该项人工偏好比较。评估应用时，还应结合自己的任务检查准确率、格式和错误类型。

## 跟着例子走

模型会续写数学题，但不会按格式答题，先用 [SFT](/training/sft/)示范；能给多种解法后，可以通过 [RLHF](/training/rlhf/) 等方法利用偏好区分帮助程度，也可用 [RLVR](/training/rlvr/)检查结果。算法如 [GRPO](/training/grpo/)决定怎样利用反馈更新参数。

SFT 仍常用[下一 token 预测](/foundations/next-token/)，变化在训练材料、对话模板和计分位置。[LoRA](/training/lora/)控制参数如何更新，与这些目标可以组合。

把这个区别放到一条训练样本里看：问题是“2 加 3 等于多少？”，示范答案是“5”。做 SFT 时，模型看到按对话模板拼好的问题和答案前缀，预测答案中的下一个 token；如果设置了只对助手回答计分，问题部分仍提供上下文，但不计入这条样本的损失。答案可能由多个 token 构成，因此实际会逐个预测，具体边界取决于分词器和模板。

之后如果用可验证奖励做强化学习，可以让模型对同一问题采样多份回答，再由答案提取器检查结果。注意这里验证器不告诉模型每一步应该写什么；它只对约定的结果或过程给反馈。采样得到“答案是 5”和“答案是 6”并分别得到 1、0 分，是一个教学例子，不等于真实训练一定只用二元奖励。

同一条样本也能帮助区分 LoRA：它规定更新哪些可训练参数，并不决定答案从示范中来还是从验证器中来。能否把某个 LoRA 用于 SFT 或强化学习，还要看训练框架是否支持相应配置；切换阶段时应明确是否继续使用、合并或重新初始化适配器。

如果要让较小的模型学习较大模型的能力，可以再了解[知识蒸馏](/training/distillation/)；如果主要是降低权重存储开销，可以了解[量化](/training/quantization/)。二者作用不同，也不是这条流程中每次都必须执行的阶段。

## 面试时怎么把这些名字放到一起

先问一句：这个名字在回答什么问题？有些术语定义学习信号，有些定义参数更新或模型压缩。把它们放在同一条赛道上比较，很容易问错问题。

| 要回答的问题               | 方法或概念                                                                                                                                           | 在做什么                                                                       | 不能直接推断什么                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------- |
| 有标准示范，学什么？       | [SFT](/training/sft/)                                                                                                                                | 用示范回答的选定位置计算监督损失                                               | 一定全量更新参数，或事实一定正确         |
| 怎样利用偏好反馈？         | [RLHF](/training/rlhf/)、[DPO](/training/dpo/)、[SimPO](/training/simpo/)、[ORPO](/training/orpo/)、[KTO](/training/kto/)                            | RLHF 可通过奖励模型训练；DPO、SimPO 与 ORPO 使用成对偏好，KTO 可用单条正负反馈 | 这些方法的数据和训练过程必然相同         |
| 答案能不能自动判对错？     | [RLVR](/training/rlvr/)                                                                                                                              | 用可验证反馈作为奖励信号，具体验证器因任务而异                                 | 验证器没有漏洞，或 RL 算法只有一种       |
| 拿到奖励后，怎样更新策略？ | [PPO](/training/ppo/)、[GRPO](/training/grpo/)、[RLOO](/training/rloo/)、[GSPO](/training/gspo/)、[DAPO](/training/dapo/)、[CISPO](/training/cispo/) | 采用不同的优势估计、概率比、裁剪或数据处理方式                                 | 同名算法的不同实现细节完全一致           |
| 想少更新一些参数？         | [LoRA](/training/lora/)                                                                                                                              | 给选定权重增加可训练的低秩更新                                                 | 它本身决定了训练数据或学习目标           |
| 想让小模型学习教师？       | [蒸馏](/training/distillation/)                                                                                                                      | 用教师的输出、分布或其他信息训练学生                                           | 学生一定更好，或每种方法都需要教师概率   |
| 想降低数值表示开销？       | [量化](/training/quantization/)                                                                                                                      | 用较低精度表示权重、激活或缓存；具体范围随方案变化                             | 所有计算都用相同位宽，或每种硬件都会加速 |

还是用数学题来想：SFT 给模型看“题目和示范解答”；RLVR 使用检查器给生成结果打分；GRPO 等方法把奖励转成参数更新的训练信号。如果资源有限，可以选用 LoRA 来限制更新方式；之后还可以把教师答案用于学生训练，或对部署模型做量化。这些是可以组合的设计选择，具体顺序和是否使用都要看模型报告与实际项目。

例如有人问“GRPO 和 LoRA 哪个更好”，可以先澄清：前者讨论如何用组内反馈更新策略，后者讨论以什么形式更新参数。在训练框架支持的情况下，它们可以组合；比较时应先固定任务、数据、奖励和资源，再分别观察策略优化方法与参数更新方式带来的影响。

## 训练以外的系统

[RAG](/applications/rag/)通过检索把证据放进上下文，工具调用让程序完成某些操作。它们是应用组织方式，不等于每次请求都重新训练模型。

## 排错与面试

知识更新问题先查资料来源，格式问题先查示范与模板，数学奖励失真先查验证器。不要把所有失败都送去加一轮 SFT。改数据后保留独立测试，分别报告目标任务进步和其他能力是否退化。
