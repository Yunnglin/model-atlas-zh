## 用大白话理解

同一道数学题，让模型独立写四份答案，再用验证器给每份答案打分。GRPO 把每份答案的得分与这一组的平均表现比较：高于平均的答案获得正优势，低于平均的获得负优势，再据此调整生成概率。这像一次小组练习：四个人做同一道题，先比较这一组的表现，再决定哪些作答值得鼓励。

[DeepSeekMath 原始论文](https://arxiv.org/abs/2402.03300)提出 GRPO，避免了 PPO 中常用的单独价值模型，用同一问题采样的多份结果来估计相对优势。生成、评分和参考策略仍需要计算资源。

![奖励来源与 GRPO 更新示意：旧策略采样多个回答，可由规则或偏好模型评分，再按组内奖励构造优势并更新策略。](/figures/training/feedback-grpo.svg)

这张教学图把奖励来源和策略更新分开：左侧是 [RLVR](/training/rlvr/) 常见的规则反馈，右侧是 [RLHF](/training/rlhf/) 可能使用的偏好评分器。GRPO 可以使用其中一种反馈，再将它转成更新信号。

## 例子：四个答案怎么变成训练信号

假设题目答案是 12，采样 A、B、C、D 四份回答，验证器给分分别为 1、0、1、0。平均分是 0.5；若用总体标准差 0.5，标准化后的优势为 +1、-1、+1、-1。于是优化倾向于增加 A、C 轨迹中动作的概率，降低 B、D 的概率；实际更新还受裁剪、参考约束和参数共享影响。

公式中的一项常写成：

$$
\hat A_i = \frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)}
$$

这里 $G$ 是同一题的候选数，$r_i$ 是第 $i$ 个回答的奖励。不同实现可能对标准差口径、数值保护、是否归一化作不同选择；全组奖励相同时，分母为零，实践中必须做数值处理。此时组内没有相对奖励差异，答案即使全部正确，也不能靠这组差异区分好坏。

如果两份答案最终正确但推导有错误，结果验证器仍会给它们正奖励；如果验证器提取答案失败，明明答对也可能被打零分。组内比较不会修复评分器本身的问题。

## 更新时发生什么

旧策略先生成一组轨迹。更新时，将当前策略对每个已采样 token 的概率与旧策略相除，结合优势和 PPO 风格的裁剪目标，限制代理目标对过大概率比的激励。原始方法还包含参考策略的 KL 项，用来惩罚偏离参考分布。参考策略不一定等于生成当前批数据的旧策略：前者是约束参照，后者负责计算采样比率。原论文的迭代算法会在新的外层迭代更新参考策略；具体实现也可能选择固定参考策略，因此不能假定两者始终一致或始终不同。

通常的结果监督会给一整条回答一个奖励，再把组相对优势用于它的 token；这不等于验证了每一步推导。原论文也讨论过程监督，粒度取决于奖励设计。单个 token 的裁剪不保证所有概率比例、整个模型的 KL 或性能变化一定被硬限制。

例如同一组回答都得 0 分，按带数值保护的组内标准化，奖励优势都为 0；但如果当前策略已经偏离参考策略，原论文目标中的 KL 惩罚仍可能产生梯度，提供抑制偏离的更新信号。反过来，刚好与参考策略相同且没有其他损失时，这项梯度在该点为零。所以“没有组内奖励差异”不等于“整个训练步骤一定没有更新”；是否加入 KL 及其他损失，以实际训练配置为准。

## 只有一份答对时，信号会怎样变化？

还是四份答案，如果奖励是 1、0、0、0，组平均是 0.25。用总体标准差作为教学口径，标准差约为 0.433，标准化优势约为 +1.73、−0.58、−0.58、−0.58。和两对两错时的 +1、−1 相比，唯一答对的那份获得了更大的正向系数；这并不意味着它就比另一题的正确答案更有价值。组内标准化会改变不同题目的训练信号尺度，具体效果也受采样、长度、裁剪和实现的标准差口径影响。

反过来，如果四份都得到 0，即使其中有一份只差一步，二值结果奖励也看不出差别。与其把所有零分都当作一样的“不会”，可以先检查答案解析器是否误判、题目是否过难，再考虑经验证的部分分或过程反馈。部分分也可能被利用，需要拿独立例子检验，不是越细越好。

### 一组多少个回答才够？

仍假设奖励只有正确得 1 分、错误得 0 分。如果某道题每次独立采样的正确概率是 10%，那么一组 8 个回答既有对也有错的概率是 `1 − 0.9⁸ − 0.1⁸`，约为 57%；增加到 16 个时，按同样算法约为 81%。这里减掉的是“全错”和“全对”两种没有组内差异的情况。

这个算例说明：对不太容易但偶尔能答对的题目，多采样可以更常得到可比较的奖励；代价是每组要生成和评分更多回答。实际回答可能重复或相关，正确率也随题目和策略变化，因此公式只是独立同分布的近似。组越大也不保证一定出现正确答案；如果验证器误判，额外采样只会产生更多被错误评分的样本。

可以先统计训练题中全对、全错和有差异的组各占多少，再同时记录生成 token 数和独立测试效果。[DAPO](/training/dapo/)讨论了动态采样等处理方式，但筛选规则会改变训练题分布，比较时应把这部分成本与影响一起记录。

## 结果评分和过程评分有什么区别？

结果监督像考试只看最终答案：同一条回答的每个 token 都使用相同的组相对优势。它实现简单，但不能识别哪一步推理有问题。DeepSeekMath 论文还讨论了过程监督：为每个推理步骤的结束位置给分，并把同一问题下所有候选回答的步骤奖励一起计算均值和标准差后归一化。某个 token 的优势是该回答中结束位置不早于它的步骤归一化奖励之和；因此也包括这个 token 恰好处于步骤结束位置的情况。比如假设归一化后的第一步奖励为 +0.4、第二步为 −0.2，则第一步中的 token 得到 +0.2，第二步中的 token 得到 −0.2；这里省略了其他候选步骤的奖励，数字只用于演示归因方式。

过程评分依赖步骤切分和评分器：如果正确思路被切错，或者评分器赞赏看似合理但事实错误的过程，信号仍会误导模型。评分步骤的划分与归一化方式会影响信号。

## 真正的模型如何使用 GRPO？

[DeepSeekMath 7B](/nlp/deepseek-math-model/) 从数学指令微调模型出发，把约 14.4 万道数学训练题用于强化学习。研究者对每道题采样 64 个回答，由奖励模型评分；每次采样后进行一次策略更新。论文报告的设置包括最大长度 1024 token、策略学习率 $10^{-6}$、KL 系数 0.04。

论文表 5 给出了强化学习前后的比较：在逐步推理设置下，DeepSeekMath-Instruct 7B 的 GSM8K 和 MATH 成绩分别为 82.9% 和 46.8%，DeepSeekMath-RL 7B 分别为 88.2% 和 51.7%。这组成绩回答的是论文数据和评测设置下的效果；要估算自己的训练成本，还要计入 64 份回答的生成和评分开销。

这两项基准与强化学习阶段使用的数学题属于同一类任务，因此论文将它们视为领域内评测。要观察能力是否扩展到更广的任务，还可以看论文同表中的其他基准，并记录它们是否出现在强化学习的数据范围内。

## 与 PPO、GSPO 和 RLVR 比较

[PPO](/training/ppo/)常用价值估计作为基线；GRPO 原始形式用同题组内奖励构造基线和优势。它省去价值模型的一个代价，是每题要采样多个候选，生成与评分仍然昂贵。[GSPO](/training/gspo/)关注序列级重要性比率和裁剪；[RLVR](/training/rlvr/)描述奖励可由规则等方式验证，是奖励来源而非与 GRPO 并列的固定更新公式。

例如代码题可以用测试通过数作为奖励，再用 GRPO 更新；也可以换奖励方式或优化算法。不要仅凭“使用 GRPO”推断奖励一定由规则提供、没有参考约束，或所有实现都采用相同长度归一化。

## 评测与排错

将同源题目按来源隔离，记录组大小、温度、奖励模型或规则版本、生成预算以及裁剪参数。评测独立题的正确率、单次采样与多次采样的表现、输出长度、计算成本和错误类型。训练奖励上升而独立题不进步时，检查答案提取、奖励漏洞、难度分布与重复数据。

如果大量组全对或全错，先统计是否有组内差异：全对可能说明题目太简单，全错可能是过难、验证出错或采样多样性不足。针对错例复核标准答案与环境，再调整任务或奖励，不应只靠增大组数解决一切。

## 面试追问

**GRPO 一定比 PPO 更省总算力吗？** 不一定。少了单独价值模型，但多答案采样和评分可能更贵，应按相同数据与推理预算实测。

**组内均值为基线，是否能判断答案的绝对质量？** 不能。全错时没有优于同组的正确答案；奖励设计和采样覆盖仍然重要。

**裁剪是否保证模型不会发生大幅变化？** 不能保证。裁剪约束的是目标对样本比率的激励，不是所有模型变化的硬边界。
