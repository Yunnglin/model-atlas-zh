## 它要解决什么问题

假设你要做一张咖啡店海报：画面中央是一杯拿铁，右上角写“周五第二杯半价”，下方写营业时间。画面好看只是第一步，还要让文字清晰、信息准确、位置不乱。只要把“半价”写成“全价”，或者时间中的数字变错，即使咖啡画得再漂亮，这张海报也不能直接用。

GLM-Image 的思路是把生成任务分给两个配合工作的部分：一个自回归模型先产生描述图像内容的离散视觉 token，扩散解码器再利用这些信息生成高分辨率图像。可以把前者想成先组织内容的设计师，把后者想成完成画面质感的绘制者；这只是帮助理解的类比，真实过程并不是先输出一张人能直接检查的线稿，再由另一个模型照着描。

GLM-OCR 主要是**读**图里的文字；GLM-Image 是按指令**生成或编辑**图片，二者可以在应用中互相配合：一个出海报，另一个帮助检查，但 OCR 检查通过也不等于图片里的事实一定正确。文中海报、价格和测试流程都是教学示例，本文没有实际运行模型。

## 结构：先定布局，再画细节

### 自回归生成器：把画面压成一串视觉 token

语言模型续写一句话时，会根据前面的内容预测下一个 token。GLM-Image 将这个思路延伸到图像：它把视觉信息编码成离散 token，然后让 9B 自回归生成器结合提示逐个生成视觉 token。它由 GLM-4-9B-0414 初始化，并扩展词表以处理视觉 token。这里的 token 不是图片里单个像素，更不是简单的汉字标签；它们是模型学习得到的视觉表示。官方模型卡描述先生成约 256 个紧凑视觉 token，再扩展至约 1K–4K token，对应其 1K–2K 高分辨率输出的设置；这些是视觉表示的数量，不是图片像素数或文本词数，实际长度与实现配置有关。

为什么不直接逐个生成每个像素？一张大图有大量像素，逐点生成序列会很长，而且相邻像素包含很多重复信息。先用较紧凑的表示传递画面的语义与布局，后续再恢复细节，是一种分工。官方介绍这套表示时强调了语义与细节的划分，但“布局由前者决定、细节由后者决定”只是大致理解：两部分的职责并非完全隔离，最终效果也受它们共同影响。

模型涉及的 VQ（向量量化）可以粗略理解为：准备一本视觉词典，把一个连续的视觉特征映射到词典中的某个条目，再用条目编号表示。不同输入会产生不同编号的组合，模型学习如何预测这些编号。**这里的 VQ 与把模型权重从高精度压缩为低比特以节省显存的量化不是同一件事。**前者主要关心如何表达图像，后者主要关心如何存储和计算模型参数。

如果参考图里有一杯咖啡，提示要求“把背景换成蓝色并保留杯子”，模型需要同时利用文字指令和参考图片的信息。官方结构图显示，编辑时参考图走两条路：一条生成视觉条件 token，供自回归生成器结合文字理解；另一条通过 VAE 等组件形成视觉条件，送给扩散解码器。前者帮助组织要生成的内容，后者让解码阶段也能利用参考图。生成后仍要检查杯子和文字是否符合要求。

### 扩散解码器：从紧凑表示生成画面

第二部分是 7B 的单流 DiT 扩散解码器。它结合前面生成的视觉表示等条件，在潜空间中通过多步去噪生成图像表示，再解码为可见图片。把噪声想成一张模糊到看不清的草稿：每一步都根据条件调整，逐渐形成满足提示的结果。真实推理中“步数”和各阶段耗时由实现和配置决定，不能把两阶段的参数简单相加就当作实际显存或速度。

DiT 是将 Transformer 用于扩散模型的一类结构；“单流”描述的是此处解码器采用的结构，不等同于“整个系统只有一个 Transformer”，也不表示模型只接受一种模态。自回归部分产生的表示为扩散过程提供条件，扩散部分并不是完全独立地重新理解一遍用户要求。

扩散解码器还配有字形编码器，用来处理需要出现在图片中的文字；自回归模块输出视觉语义表示，字形条件则为文字呈现提供额外信息。对中文海报来说，“周五”和“周六”只差一个字，模型不仅要知道它是活动时间，还要尽量把相应字形画对。字形条件有助于这个任务，但长句、细小字、多语言混排仍可能出错。官方模型卡建议将希望出现在图中的文字放在引号中；这是提示方式的建议，并不是保证输出无误的规则。

## 训练：从学会表示到改善生成结果

可以把训练想成分阶段培养设计团队。第一步，图像要能变成适合生成器学习的离散视觉表示；接下来，自回归生成器学习结合条件生成这些表示，扩散解码器学习根据条件还原高质量图片。两者学习的对象不同：前者面对一串离散符号，后者需要处理图像潜空间中的生成过程。

但“基本能生成”不等于“符合用户要求”。模型卡介绍分别对自回归生成器和扩散解码器使用 GRPO 强化学习优化：前者侧重整体语义和美学等方面，后者侧重视觉细节和文字呈现等方面。理解 GRPO 时，可以想象对同一提示生成多份候选，再根据奖励信号比较候选结果，鼓励更符合目标的行为。实际奖励定义、样本组成、超参数及两阶段全部训练细节，不能仅凭这个类比推断。

例如对“周五第二杯半价”的海报，候选 A 咖啡位置好但文字错，候选 B 文字正确但画面拥挤。奖励设计要明确自己优先什么：如果只奖励美观，就可能纵容文字错误；如果只奖励文字识别分数，又可能得到生硬难看的排版。不同目标如何加权会影响结果，也可能出现模型讨好评分器而没有真正满足需求的情况。

官方没有在模型卡完整披露全部训练样本的来源、数量和清洗方法。因此不要把“训练过海报”推断成“覆盖某一家店的全部促销规则”，也不能推断训练数据不存在版权或隐私问题。使用者自行收集或微调数据时，应先确认授权、删除不需要的个人信息，并按来源或活动分组划分训练集和评测集，避免同一张模板换个颜色就同时出现在两边。

## 评测：文字写对，不等于海报可用

官方模型卡报告了多组成绩。在 CVTG-2K 表格中，GLM-Image 的 Word Accuracy 为 **0.9116**，同表 Qwen-Image 为 **0.8288**；这些是模型发布方给出的结果，比较需要结合具体模型版本、提示、采样和评分方法阅读。另一张通用图像生成的 DPG-Bench 表中，GLM-Image 为 **84.78**，同表 Qwen-Image 为 **88.32**。两张表说明不同测试可能得出不同排序，不能用一项结果宣称它在所有场景最好。

[官方使用示例](https://huggingface.co/zai-org/GLM-Image)中的文生图设置为高 1024、宽 1152、50 个扩散步数、引导强度 1.5 和随机种子 42；目标宽高都要能被 32 整除。自回归部分默认使用采样、温度 0.9 和 top-p 0.75。比较两次生成时，记录这些设置以及提示、分辨率和种子，才能分清改动来自哪里。模型卡还提到可用 CPU 卸载降低 GPU 显存需求，但通常会牺牲速度；具体占用和等待时间应按设备、版本及图片尺寸实测。

文字准确率回答的是“要求出现的字写对了吗”，但一张海报还可能有别的问题：文字被主体遮挡；“第二杯半价”对应错了商品；日期实际已经过期；布局美观却缺少必须的品牌标识。OCR 能发现一部分错字，却不能独立判断活动政策是否真实。数字指标也会受检测器、裁剪、字体大小和识别标准影响。

做自己的评测，可以准备独立样本，覆盖短标题、长中文、数字日期、英文混排、密集文字、参考图编辑等场景。每条提示生成多次，记录配置和随机种子；除了机器识别文字，还让人检查事实、布局和主体一致性。把“文字完全正确的图片比例”“活动信息完整率”和人工审美评分分开报告，比只给一个平均分更容易定位问题。官方基准是参考起点，本文没有复现上述分数。

## 应用与错例：做一张能交付的活动海报

假设店家给出正确文案、商品照片和品牌规范，应用可以先检查输入是否包含活动期限、金额与必要说明，然后生成若干张候选海报。把指定文案放在引号中，提示位置、风格及参考图的作用；输出后用 OCR 对照原文，再由人工检查图片是否符合品牌要求以及促销规则是否真实。

如果出现“周五”被画成“周六”，先把它归入文字错字，而不是直接断定是训练数据不足；如果商品没变但价格写错，重点核查文本约束与生成内容的对应关系。如果参考图里的杯子被换成另一个形状，就检查身份保持；如果文字都对但二维码不可扫，二维码应由确定性程序后期叠加并实际扫码验证，而不是指望生成模型精确绘制。

收集错例时保存提示、模型版本、推理配置、参考图授权信息和核对结果。按原因聚类后，可以改进提示、增加文字检查、调整排版方案，或在有条件时构造有授权的改进数据；然后用**未参与调参的独立样本**重新评测，检查原来的问题是否减少，其他指标有没有退步。上线时尤其不能把生成图里的金额和日期当成可信数据源。

## 面试时可以怎么讲

**问：为什么需要自回归加扩散，不能只用其中一种吗？**两种方法都可以用于图像生成，GLM-Image 的选择是让自回归部分产生紧凑的视觉表示，再由扩散解码器生成细节。这是该模型的设计取舍，不是图像生成必须采用的唯一方案。

**问：视觉 token 和权重量化有什么区别？**前者是表达图像的离散符号，便于序列模型预测；后者是压缩模型参数的数值精度，两者解决的问题不同。

**问：模型卡中文字准确率很高，就能自动上线吗？**不能。公开基准与自己的海报分布、字体和文案可能不同；还要独立核对价格日期、主体一致性和业务规则，并保留人工复核。
