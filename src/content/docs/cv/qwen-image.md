## 要解决什么问题

让模型读出海报上的字，与让它生成一张字写对、排版合理的海报，是两个任务。Qwen-Image 专注图像生成与编辑，不能与输出文字答案的 Qwen-VL 混为一谈。[返回 Qwen](/nlp/qwen/)。

做一张真实海报，光听懂“春日特惠”还不够：画面得给文字留位置，字的笔画要对，背景和主体也得协调。可以把它想成一个既要听懂客户需求又要负责绘制的设计团队。Qwen-Image 尤其重视文字渲染，但它生成的是像素图，文字并非天然可编辑的文字图层。要精确改字或制作印刷品，仍要检查甚至在排版软件中重新加字。

## 结构与数据流

初代 Qwen-Image 是 20B 的 MMDiT 图像模型，使用多模态条件控制图像生成。可以先把它理解为：提示词提供要求，图像潜空间从噪声逐步变成符合要求的内容。[DiT](/cv/dit/)和[扩散与流匹配](/training/diffusion-flow/)解释共同前置知识。

| 路线                                          | 核对到的公开入口             | 学习重点                                           |
| --------------------------------------------- | ---------------------------- | -------------------------------------------------- |
| Qwen-Image                                    | 初代生成模型开放权重         | 中文与复杂文字绘制、图像质量                       |
| [Qwen-Image-Edit](/cv/qwen-image-edit-model/) | 编辑模型及 2509、2511 等更新 | 根据原图和指令改变局部内容，保持其他部分           |
| Qwen-Image-2512                               | 官方明确发布开放权重         | 后续生成能力更新；固定完整型号比较                 |
| Qwen-Image-2.0                                | 官方发布说明与产品入口       | 统一生成与编辑等能力；发布说明本身不证明权重已公开 |

编辑需要原图条件，生成未必需要。不同版本输入接口和模型大小可能改变，不能用初代的结构参数为 2.0 补完整架构。

### 沿一张促销海报走一遍

教学要求是“米白背景，中央写春日特惠，下方写 89 元”。提示经条件编码，图像则在 VAE 压缩空间中表示，MMDiT 根据条件与噪声状态逐步预测生成方向，最后 VAE 解码成像素。它并不是先写好一份 SVG 再交给浏览器排字，所以同样四个汉字也可能有字形或布局错误。

Qwen-Image-Edit 是独立的编辑模型。技术报告介绍其编辑路径时，让原图分别经过 Qwen2.5-VL 与 VAE：前者帮助提供内容语义，后者提供保留外观细节的重建表示。可以类比“知道这是哪件商品”和“记住商品包装的具体纹理”。两路各有用途，不是把同一张图片无意义地传两遍。

后续的 [Qwen-Image-2.1](/cv/qwen-image21-model/) 使用不同的模型组成，并支持透明通道；它的权重许可也不同，不能把初代的配置和使用条件直接套过去。

要把 99 改成 89，模型既要知道改哪个文字区域，又要保留商品和背景。生成是满足新要求，编辑还多了不该改什么的约束；同一评分不能掩盖这个差别。

### 三个部件分别做什么

第一站是冻结的 Qwen2.5-VL 多模态条件编码器：纯文生图时，提示词经语言骨干得到一串条件表示；编辑任务还可以接收图片。它像把客户的要求整理成工作单，并不直接画出海报。冻结意味着这一训练设置下编码器参数不随图像生成器更新，而不是说它没有事先经过训练。

第二站是 MMDiT。文字特征与图像潜变量各有自己的处理流，又通过注意力交互：图像在逐步成形时，可以参考文字里指定的主体、布局和字句。这里的“双流”不是生成两张图片，也不能理解为文字和像素永远各走各的、互不交流。图像与文本使用的位置编码要处理不同的空间与序列结构；报告采用多模态的 MSRoPE。直观地说，位置编码给信息标记“在哪里”，但标了位置并不保证最终文字绝无错漏。

技术报告的配置表给 MMDiT 列出 60 层、24 个注意力头，每头 128 维。每一层都会继续处理图像和文字条件；画“89 元”时，不是先一次性决定所有像素，而是在多步采样中反复利用提示和当前画稿。层数是网络深度，采样步数则是推理时重复调用模型的次数，两者不是一回事。层数固定为 60，不意味着一定要采样 60 次。

第三站是 VAE：它把图片压缩到潜空间，并把生成好的潜变量解码成可看的图片。可以把潜变量想成压缩后的画稿，不是任何人都能直接读懂的 JPEG。模型主要在这个较紧凑的空间工作，节省计算；压缩也可能丢失小字的笔画，因而解码器质量很重要。报告以 Wan2.1 VAE 为基础，冻结编码器并针对文字密集图片微调图像解码器；不要把它误解成这个文生图权重已经具备视频生成能力。

### 1024×1024 图片会变成多少图像 token？

以正方形图片为例，报告中的 VAE 将高、宽各压缩 8 倍：1024×1024 像素变成 128×128 的潜变量网格，每个位置有 16 个通道。MMDiT 再把相邻的 2×2 个潜变量位置打包成一个图像 token，所以进入主干的是 64×64，即 4096 个图像 token。文字 token 还会一起参与后续计算。

这 4096 个 token 不是 4096 个独立的小图片：它们在多层注意力中与文字及其他图像位置交换信息。分辨率升高会增加图像 token 的数量，从而影响显存和计算量；实际尺寸调整按所用处理器实现。这里的 8 倍压缩、16 通道与 patch 大小来自报告表 1，也可在 [Diffusers 推理流程](https://github.com/huggingface/diffusers/blob/main/src/diffusers/pipelines/qwenimage/pipeline_qwenimage.py)看到打包方式。

### 为什么还要给文字和图像安排位置

模型同时处理一句话和二维画面：文字有前后顺序，图像有上下左右。MSRoPE 为图像使用二维位置，并把文字位置沿二维坐标的对角线安排；报告这样设计是为了兼顾图像分辨率变化和文字的一维顺序。可以把图像 token 想成按行列编号的格子，把文字 token 想成沿对角线排列的说明条，注意力仍要学习它们怎样对应。

## 数据与训练

图文配对建立语义与画面对应，文字密集场景还需要准确文本、字形和排版相关数据；编辑需要原图、修改指令与目标图。质量筛选、合成数据与后训练各有作用，公开报告范围之外的数据细节不猜测。

例如“把价格从 99 改成 89”，除了新数字，还要验证背景、字体和其他商品信息有没有被误改。只训练最终漂亮图片，学不到局部修改的约束。

### 为什么还要检查 VAE 能不能重建小字

先将真实海报编码再解码，如果“89 元”在重建后已糊成别的字，后续生成器很难补回表示没保留的细节。初代报告为文字密集材料改善图像解码重建，并逐步从简单到复杂文本训练；这与只增加文字提示长度不同。

报告表 2 还单独测试了这一步：将 256×256 的文字密集图片送进 VAE 再还原，在作者的测试集上，Qwen-Image-VAE 的 PSNR 为 36.63、SSIM 为 0.9839；Wan2.1-VAE 分别为 26.77 和 0.9386。这里输入的是**已有图片**，衡量的是压缩后能否还原，不能拿这两个数字声称模型按新提示词生成海报的成功率。就像复印机能把样稿上的小字印清楚，不等于它能从一句话自己设计出正确海报。

图文配对、图像重建和指令编辑分别提供“按描述生成”“保留细节”“改变指定内容”的学习信号。教学数据应同时保存原图、指令、目标图和保留区域；无意改变了商品 logo 的目标图，会把错误编辑当作标准答案。

### 从噪声学会往画面走

流匹配训练可以想成练习走路：先拿一张真实图经过 VAE 得到潜变量，再与随机噪声构造一个中间状态；模型看着这个状态、时间和文字条件，学习朝目标方向移动的速度。推理时没有真实目标图，便从随机噪声出发，多次按模型给出的方向更新，再解码成图片。训练里的“已知终点”与推理里的“从噪声出发”是两个不同阶段。

方向可以用一个约定来表达：令干净图像潜变量为 z、噪声为 ε，并取 x(t)=(1−t)z+tε，则从干净图走向噪声的速度是 ε−z。采样要沿相反方向求解；实际实现可能采用不同时间与符号约定。它与常见扩散方法都能从噪声生成图像，但训练目标和采样方程不能简单当成同一个公式。

把复杂潜变量先简化成一个数：若干净端 z=0、噪声端 ε=1，那么 t=0.25 时中间值是 0.25，从干净端指向噪声端的速度是 1。采样按相反时间方向走时，这个示例里的数会向 0 移动。真实模型处理的是高维图像潜变量，方向也由模型预测；这个一维算例只是帮助理解公式，不是生成图片的实测结果。

训练数据不只是“图片越多越好”。假设样本要求写“春日特惠”，配图却写成“春日特价”，模型就收到互相矛盾的监督。报告讨论了面向文字的合成与筛选、不同复杂程度和分辨率的阶段训练，以及后训练。先学简单、清晰的文字，再接触复杂背景和排版，类似先练字再做整张海报。公开报告没有完整披露全部原始样本和处理细节，不能据此保证复刻时得到同样效果。

报告还给出分辨率逐步提升的训练路线：从约 256×256 起步，再到约 640×640，最后到约 1328×1328，同时覆盖多种宽高比。可以把它理解为先学画面的大轮廓，再练细节，而不是每个阶段只出现一种固定尺寸。文中约 5% 的合成数据指用受控文字排版等方式合成，报告明确不包括其他 AI 模型生成的图片；这个比例属于报告介绍的数据构成，不是所有训练阶段均保持 5%。

后训练可以继续用高质量样本做监督微调，也可以使用偏好或奖励信号改善生成质量。报告讨论了 SFT、DPO 和 GRPO 等方法；偏好来自怎样的比较、奖励如何定义，决定模型到底被鼓励做什么。例如只奖励 OCR 识别出“89”，模型可能把数字画得很大，却忽略商品主体。报告中的不同训练变体应分别标明，不能将强化学习变体的成绩直接归给基础发布权重。

## 评测怎么看

把文字正确率、指令遵从、主体一致性、美观与编辑保真分开。OCR 检查可以帮助发现错字，但不代替人工看布局和可读性。固定种子、分辨率、步数、提示词增强与采样设置，避免把不同生成预算直接比较。

### 一张图分几步验收

先逐字核对“春日特惠”和“89 元”，再看有没有多写或漏写；再核对商品、颜色和布局；编辑时用原图检查未修改区域。OCR 识别正确只证明某个识别器能读出目标，不保证字距、美感或全部笔画都好。

固定原图和指令，按预先确定的多个随机种子评测，报告成功比例与失败类型，不只展示最好一张。若提高采样步数后更好，记录增加的预算；若只在某个字体上修好，独立测试还要包含未见字体和排版。

### 读分数时看清版本与任务

官方报告在 GenEval 上分别报告 Qwen-Image 0.87、Qwen-Image-RL 0.91；论文将它们分别称为 SFT 模型和 RL 增强模型。分数应保留这个模型阶段和评测设置，不能未经核实将其中任一分数直接写成某个下载权重的实测成绩。GenEval 更关注对象、数量、位置等组合要求；文字密集评测则要看另一组数据与度量。分数是特定数据、评测方法和采样条件下的结果，不是所有中文、所有字体都能保证准确。

报告还用 ChineseWord 测单字渲染，把常用汉字分成三个难度档；表中 Qwen-Image 的一级、三级准确率分别为 97.29 和 6.48。测试提示要求在图里生成一个汉字，不能直接当作整张海报、多字排版或任意字体的成功率；档位和任务也不能只用整体平均分代替。

假设十张海报里八张的价格被 OCR 读对，不能立刻说“质量 80 分”：其余文字是否错、商品是否正确、背景和美观如何，都要分别记录。还应留出没有参与调参的独立样本，按文字长度、字体、背景复杂度分组报告，并记录采样次数、分辨率和失败类型。用多个种子估计成功率，比只挑最好看的结果更有参考价值。

## 应用与错例

中文错字先看目标文字和长度；文字正确但排版溢出，补复杂版式测试；编辑牵连其他区域，检查条件与编辑样本。为原图保留未修改区域对照，建立独立海报和商品图回归集。

### 用错例推动下一轮改进

假设“89 元”经常被画成“8g 元”，先保存提示词、原图、种子、配置和生成图，再人工确认是字形、遮挡还是 OCR 本身误判。把类似字体与背景的案例归为一组，检查训练数据中对应文字是否清晰且标签准确；构造或筛选更可靠的样本后，再在独立字体和背景上回归。若采用 Edit 修改已有海报，还需单独检查未要求修改的 logo 和商品：目标文字改对但其他区域走样，仍然是编辑失败。

复杂案例里，可以让模型先生成无字背景，再由排版工具放置准确文字；这样更容易校对价格并保持文字可编辑。数据补充后，再用独立样本验证实际效果。

## 比较与面试追问

[Stable Diffusion](/cv/stable-diffusion/)适合先学潜空间生成；Qwen-Image 再看多模态 Transformer 与文字绘制。

**为什么视觉问答高分不代表画字正确？** 前者识别与表达已有内容，后者还要生成准确字形、位置和图像细节。

**MMDiT 和 VAE 都处理图像，它们有什么区别？** VAE 负责像素与潜空间的转换；MMDiT 根据文字和当前潜变量预测更新方向。一个像压缩和还原画稿的工具，一个像反复修改画稿的画师。

**为什么增加文字样本未必能解决所有问题？** 标签错误、图片压缩导致笔画丢失、训练分布与业务字体不同，都可能成为瓶颈。应该先按错例定位，再改变数据或模型并用独立样本验证。

**模型说能编辑，是否就能拿初代文生图权重编辑？** 不一定。应检查所用的具体模型卡与接口；原始 Qwen-Image 的文生图和 Qwen-Image-Edit 的编辑权重是不同发布物。
