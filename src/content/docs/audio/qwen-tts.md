## 要解决什么问题

同一句“欢迎回来”，可以用固定主播音色、根据文字描述设计声音，也可以参考一段录音复现音色。这些操作都属于语音生成，但条件和模型接口不同。[Qwen 分支位置](/nlp/qwen/)。

## 结构与数据流

文本与声音条件进入离散多码本语言模型，生成语音码，再由语音 tokenizer 解码成波形。Qwen3-TTS-Tokenizer-12Hz 是语音表示的一部分，12Hz 描述码序列的时间步频率，不是音频采样率，也不是每秒只有十二个波形点。

官方提供双轨混合流式生成设计，同一模型支持流式与非流式使用。它与 [F5-TTS](/audio/f5-tts/)的流匹配路径不同，不要把所有 TTS 都画成“语言模型＋DiT”。

| 权重类型       | 条件与用途                               | 开放规格                       |
| -------------- | ---------------------------------------- | ------------------------------ |
| Base           | 给参考音频进行声音克隆，也可作为微调基础 | 0.6B、1.7B                     |
| CustomVoice    | 使用预设音色；部分型号支持指令控制风格   | 0.6B、1.7B，功能以模型清单为准 |
| VoiceDesign    | 用自然语言描述想要的声音                 | 1.7B                           |
| Tokenizer-12Hz | 音频与语音码之间转换                     | 独立 tokenizer 权重            |

**这里的 Base 是 TTS 分支内部命名**，不能理解成只会文本续写的通用 Base。开放权重与在线 TTS 服务的功能、配额也要分别核对。

## 数据与训练

训练依赖文字与录音的对应，以及说话人、风格等条件；语音表示与生成模型各有训练目标。微调先核对录音质量、转写、切段和采样率，固定官方训练脚本对应的型号。声音像但漏词，可能是内容对齐问题；不应只增加音色样本。

例如训练导航播报，要包含路名、数字、停顿与多音字，训练和测试按说话人、文本主题适当隔离，不能用同一句话换文件名当独立测试。

## 评测怎么看

[语音质量评测](/evaluation/speech-quality/)同时看内容可懂度、说话人相似度、自然度、风格遵从和延迟。ASR 回识别只是内容指标，不能代替听感；首包时间不等于整句话生成耗时，流式断续也要单独检查。

## 应用与错例

数字读错先查文本规范和训练覆盖；音色漂移查参考音频、分块上下文和解码；尾部缺字则查停止条件。补对应类别数据，回归长短句和未见文本。[TTS 案例](/cases/tts/)说明怎样完成一轮排错。

## 比较与面试追问

**Tokenizer 的频率与音频采样率有何区别？** 一个是压缩码的时间步频率，一个是波形每秒采样点数。

**会克隆音色就能保证读对内容吗？** 音色一致性与文字正确性是不同维度，需要分开评测。
