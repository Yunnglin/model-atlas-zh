## 要解决什么问题

让助手读“共计一百一十四点四八元”，既要金额读对，又要音色稳定、及时开始发声。声音像参考人却漏词，与内容正确却机械，是两种不同失败。

本页以公开的 **Qwen3-TTS-12Hz** 权重为主。下面的句子、时间步计数和排错场景均为教学例子；报告中的研究分支与实际发布型号分开。[返回 Qwen](/nlp/qwen/)。

## 结构与数据流

文本与音色／风格条件进入 Qwen3 语言模型，先预测当前语音帧的主码本，再由 MTP 模块补充其他码本，最后由流式解码器还原波形。**语音编号还不是可播放声音**。

下面是报告 Figure 3；图里的 0 表示主码本，1 到 15 表示其他码本。虚线是可选条件，不能理解成所有公开型号都要求同一套参考输入。

## 先把声音变成编号

神经语音 tokenizer 先将录音压缩成一串离散码。本报告的 **“12Hz”是型号名称，实际时间步频率为 12.5Hz**，约每 80ms 一帧。每帧不只一个数字，而有多层码本：一层偏语义，另外 15 层 RVQ 逐步补充声学细节。

教学地说，4 秒声音约有 50 帧，每帧 16 个码本位置，总共约 800 个离散索引。**这不是要求主语言模型串行运行 800 个完全相同的步骤**：骨干预测主码本，MTP 补其他码本。确切生成调用还取决于实现。

官方 Figure 2 同时画了 25Hz 与 12Hz 两条 tokenizer 路线。25Hz 研究分支是单码本，并采用分块 DiT 等波形重建设计；这里重点讲的 12Hz 是多码本与轻量因果解码路径。不能把二者画成一条固定流水线。

## 一句话怎样逐步发声

### 文本 token 与语音帧，不是一一配对

文字“共计一百一十四点四八元”经过文本 tokenizer；语音使用另一种码序列。一个词可能拖长、停顿或连读，文字 token 的数量不等于声学帧数。

双轨设计把文字与声学条件组合，支持流式文字输入与语音输出。这不是字字固定 80ms，也不是必须先等整段回答全部写完才能出声音。把所有文字预先给齐的离线调用，与实际逐步输入文字的延迟，要分别测。

### 音色从哪里来，要看具体权重

| 类型           | 条件与用途                       | 公开规格与边界                             |
| -------------- | -------------------------------- | ------------------------------------------ |
| Base           | 参考录音的声音克隆，可作适配基础 | 0.6B、1.7B；具体参考文本与模式看接口       |
| CustomVoice    | 选预设音色，部分规格支持风格指令 | 0.6B、1.7B；不能把所有控制能力互相套用     |
| VoiceDesign    | 用自然语言描述想要的声音         | 1.7B；不是拿任意 Base 加一句描述就完全等价 |
| Tokenizer-12Hz | 声音与码本之间转换               | 独立权重，不单独完成任意文本合成           |

例如“温和、语速稍慢”是风格条件，目标金额是文字内容，参考音频是声音身份线索。条件混在一个调用里，职责却不同。TTS 的 Base 是分支内部命名，不是只会文本续写的通用 Base。

## 数据与训练

### tokenizer 与语音生成器，先分开理解

tokenizer 学压缩与重建。12Hz 报告描述语义教师、残差量化、波形／频谱与对抗相关目标；目的是让码既保留内容又能重建声音。它不是拿“正确汉字”给每个码本编号。

生成器学习在文字与声音条件下预测语音码。三段预训练分别建立广泛文本—语音对应、用高质量材料继续训练，以及增加长语音／长上下文。长句能力不仅是推理时把上限调大。

### 后训练怎样同时照顾听感与稳定性

报告介绍 DPO、基于规则奖励的 GSPO，以及针对声音的轻量微调。DPO 用偏好对，规则奖励可针对能检查的目标，声音适配改善身份与表现。不能把“用了 RL”当成只检查文字答案的数学 RLVR。

业务样本要同步保存文字、录音、采样率、切段和条件。金额读错先查数字文本规范与对应录音；说话人很像却漏字，增加音色样本未必对症。若比较微调收益，必须保留同权重、同条件的未适配基线。

## 评测怎么看

### 用同一句话拆出四张成绩单

| 维度 | 教学场景                         | 怎样核对                               |
| ---- | -------------------------------- | -------------------------------------- |
| 内容 | 114.48 被念成 114.8              | 人工核对，ASR 回识别辅助；数字规范固定 |
| 音色 | 前半段像参考人，后半段漂移       | 说话人相似性与盲听，检查长句切片       |
| 表达 | 内容正确但“稍慢”没执行           | 风格遵从、自然度与独立听者判断         |
| 速度 | 早出一个短声音包，随后长时间停顿 | 首包、包间断续与完整完成时间分别统计   |

识别器也会错；ASR 回识别正确，不代表发声自然。说话人相似度高，也不证明金额念对。MOS 或偏好测试需说明材料、听者与安排，跨论文直接比较可能不公平。[语音质量](/evaluation/speech-quality/)另读。

### “实时率低”为什么仍可能等很久

若教学地假设合成 4 秒声音花 2 秒，RTF＝0.5。但两秒全花在开始前，与先出首包再持续输出，用户体验不同。这个算式不是本模型实测速率，不能据此宣传延迟。

固定硬件、并发、精度、文本长度、流式输入方式、参考录音与解码配置，再报告 p50／p95 等延迟分位数。官方的低延迟结果也必须连同其测量条件阅读。

## 应用与错例

先听原始参考录音与 tokenizer 重建；重建已失真，问题可能在表示／解码。再看完整生成：漏数字查文字、对齐和停止；长句重复查分句与历史条件；音色漂移查参考质量与声音适配。不要统一写成“音质不好”。

从开发池补难例后，用未见文本和独立说话人回归，既测金额，也测普通句子。完整方案见[TTS 案例](/cases/tts/)。

## 比较与面试追问

**12Hz、12.5Hz、采样率各是什么？** 前者是型号命名，中间是码帧频率，最后是波形每秒采样点数。

**为什么 16 个码本不等于 16 倍主骨干串行步骤？** 主码本与其他码本有分层预测设计，需看骨干与 MTP 的职责。

**与 F5-TTS 有什么不同？** [F5-TTS](/audio/f5-tts/)在连续声学表示上做流匹配；本页公开 12Hz 路线主要是离散码建模，不能因为都能克隆声音就画成相同架构。
