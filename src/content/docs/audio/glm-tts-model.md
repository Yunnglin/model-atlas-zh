## 它解决什么问题

给语音助手一句文字：“您好，您预订的航班将在下午三点起飞。”一个有用的语音合成系统不仅要把它念出来，还要正确读出“三点”，声音清晰、语速自然，最好能和用户授权选择的声音相似，并尽快开始播放。如果它把“三点”读成“四点”，就算声音再悦耳，信息仍然错了。

GLM-TTS 处理的是文字到声音（TTS）。GLM-ASR 则是相反方向，主要把声音转成文字；两者可以接成语音助手，但识别错字、助手回答错和语音合成读错是三个不同环节，不能用一个总分解释。本文例子用于说明方法，没有实际调用模型。

该系统支持用短参考录音提供声音条件。可以把参考音频想成给配音员听的一小段样片：它能提示声音的大致特征，但背景噪声、情绪、口音或录音设备都会影响结果。模型卡给出 3–10 秒参考音频的使用说明，不代表任何人的三秒录音都能准确复刻声音，更不代表获得了声音所有者的使用许可。

## 结构：从文字到可播放声音

### 先生成一串语音 token

自回归语言模型习惯逐个预测 token。文字 token 是模型处理文本的离散单位；语音 token 则把一段声音压缩成一串离散编号，方便序列模型学习和生成。GLM-TTS 的第一阶段以文字及参考条件为输入，使用 Llama 架构的语言模型生成语音 token。可以把它看成先拟定一份带语音信息的“演出提示”，而不是直接输出可播放的录音。

训练时，要先把真实语音编码成可供学习的语音 token。报告基于 GLM-4-Voice 的 Whisper-VQ tokenizer 改进：码本由 16k 扩大至 32k，token 速率从每秒 12.5 个提高到 25 个，并加入基频估计相关约束。频率可以粗略联想到声音高低变化；模型希望编码保留对发音与韵律有帮助的信息。token 变多给表达更多空间，但序列更长也会增加自回归生成工作量；不能只看码本大小推断音质。

编码真实音频与生成音频是不同步骤：前者是训练和处理参考声音时所需的表示，后者是模型根据文字等条件生成 token。不要把语音 tokenizer 当成直接生成文字答案的 ASR 模型，也不要把 token 当成一段段已经录好的单词音频。

报告还将语音 tokenizer 从因果结构改为非因果结构，使它在编码已有音频时可以利用更完整的上下文。这里处理的是已有录音的编码步骤；模型支持流式输出，并不表示这一步也能不等待任何未来音频就实时处理。参考音频的准备、文字到 token 的生成和后续音频分块应分别测量。

### 再把语音 token 变成波形

第二阶段使用流匹配模型，根据语音 token 等条件生成梅尔频谱等声学表示；声码器再将这些表示转换为可播放的波形。频谱可以理解为声音在不同时间、不同频段的能量轮廓，它不是用户直接听到的音频文件。声码器要根据这种轮廓合成连续的声音，处理不好可能产生电流声、失真或不自然的尾音。

技术报告介绍 Vocos2D 声码器，对二维频率结构进行建模，并使用高质量歌声数据扩展声音频率范围。它并不是说所有输出都会唱歌，也不能据此断言某台设备的速度。官方实现支持流式输出：系统可按实现逐步返回声音，让用户先听到开头；首包延迟、整体合成速度与切块质量仍要在目标硬件和输入长度上测量。

### 多音字怎样指定读法

“银行行长”中两个“行”读法不同，“重庆”和“重要”里的“重”也不同。仅给文本时，模型需要依靠上下文判断；上下文模糊、生僻名字或专业术语会让它犯错。报告提供文字与音素混合输入（Phoneme-in），在关键处明确读音，相当于给配音员标上拼音提示，其他地方仍保留正常文本。

音素提示也可能标错，因此应先确认词典或人工标注。报告在内部多音字及生僻词难例集上，文字输入的音素错误率为 13.23%，启用混合输入后为 5.14%；这是报告特定数据和系统的结果，不是所有句子都能降到该水平。

## 训练：数据质量和多个目标一起抓

### 从录音整理出可靠样本

报告称使用约 10 万小时训练数据，并描述了音频处理流程：先统一音频格式、检测有效语音，再分离背景声音、降噪、区分说话人，将音频与文本进行检查和对齐。清洗不是为了追求绝对安静：如果把说话人的笑声、呼吸或停顿全部当噪声删掉，模型可能学不到自然表达；如果把不同人声音混在同一片段，又会给声音身份带来混淆。

作者还使用语音识别结果和错误率过滤数据，并依据对齐信息调整标点。拿“谢谢，再见”举例：逗号附近的停顿影响听起来是否自然；如果文字和声音本来就不匹配，模型会收到错误的教学信号。不过 ASR 自己也会犯错，过滤结果不能代替人工抽检。报告涉及自有数据，未完整公开来源和逐条样本；10 万小时不等于任何人都能复现同一训练集。

### 多奖励 GRPO：读对、像本人、情感合适

仅通过监督学习模仿录音，模型可以学到基本的文字与声音对应；报告还在语音语言模型的后训练中引入 GRPO。可以想象对同一句文字生成几种候选读法，用多个评分器比较：一项看转写后有没有错字，一项看是否像参考说话人，另一项看情感表达，还有一项关注笑声。训练根据组合后的反馈，鼓励较符合目标的候选。

这些目标常常互相拉扯。例如“哈哈，太好了”如果被逐字僵硬念出来，识别器可能认为它很准确，却不像真正的笑声；如果笑声太夸张，又可能听不清字。报告介绍对不同奖励做归一化、加权组合，并使用动态采样和裁剪等方法改善训练。它报告某些设置下情绪指标提高但发音或音色相似度下降，因此不能认为强化学习必然同时改善所有目标。

动态采样解决的是“这一组候选有没有可比较的学习信号”。假设同一句话生成的几条候选最终得到相同奖励，组内相对优势可能都是零，这一组就难以告诉模型哪个候选更好。报告借鉴 DAPO，对零优势批次最多重新采样三次；同时把裁剪上限和下限分别设置为 0.3 和 0.2。这些是报告实验中的训练设置，不是说相同奖励的音频一定质量相同，也不是每次重采样都能找到有用差异。

评分器也是模型，可能偏好某些口音或误判情绪。奖励升高并不等于听众体验一定更好：要抽样试听、对各类用户和句子分别统计，并警惕模型学会迎合评分器却产生奇怪声音。

### 定制声音与 LoRA

报告还讨论以 LoRA 为指定声音做参数高效定制。可以把 LoRA 看成给已有模型增加较小的一组可训练调整，而不是每次从零重训整个系统。报告在其特定实验中提到使用约一小时高质量单人音频，调整约 15% 的核心骨干参数、训练约 100 个 epoch；这里的比例以报告所指核心骨干为口径，不能直接当成整个系统的参数比例。这些都是实验条件，不是所有说话人只需一小时就能达到指定效果。零样本参考音频与 LoRA 定制也不是一回事：前者推理时提供样片，后者需要额外训练。

## 评测：文字、声音和速度分开看

在 Seed-TTS-eval 中文测试集，报告列出基础 GLM-TTS 的 CER 为 **1.03%**、说话人相似度 SIM 为 **76.1**；GLM-TTS_RL 分别为 **0.89%** 和 **76.4**。CER 通过识别文字与目标文字比较，越低通常表示漏字、错字或多字越少；SIM 是报告用 WavLM-large 提取说话人表示后计算的相似度指标，越高表示在该指标下更相似，并不等于所有听众都觉得一样。

同表还有英语 WER 和英语 SIM，它们不应和中文 CER 直接比较。模型方报告的这些数字取决于测试文本、参考音频、ASR、说话人模型及采样方式；这些结果尚未独立复现。该表中的不同模型还有不同训练资料和系统配置，排名不能直接证明所有产品场景下谁更好。

要服务航班播报，可以单独准备航班号、日期、金额、地名、多音字和中英混排的独立测试集。除了 ASR 回转核对，还要找人听数字和专业名词、检查停顿与声音是否自然；测量首包延迟、实时率、长句断句和高并发下的表现。真实姓名、时间和号码应有专门错例统计，因为偶尔读错一个数字就可能影响用户行动。

## 应用与错例：让语音助手更可靠

假设文字由上游系统产生，先把时间、数字和缩写整理成可朗读格式，再把经授权的参考音频和文本送给 TTS。生成后可用 ASR 回转识别作为自动检查，重点信息与原文比较；对重要播报，再抽样人工听。回转 ASR 和 TTS 可能犯相同错误，自动核对通过也不是绝对证明。

如果“重庆”读错，先检查文字上下文和音素提示；如果文字都对但声音忽大忽小，检查音频质量和声码器输出；如果声音像样但首句迟迟不出，检查分块方式、硬件和首包测量；如果是上游把航班时间写错，应回查原始数据而不是改 TTS。保存文本、输入版本、模型版本、参考音频授权及生成配置，按错例类型修复，再用未参与调参的独立样本重测。

语音克隆涉及个人声音：使用参考录音应取得明确授权并控制保存与传播，生成语音需避免冒充他人；这是应用设计的基本条件，而不是模型能力已经解决的问题。

## 面试时可以怎么讲

**为什么不让语言模型直接输出波形？**GLM-TTS 将离散语音 token 和声学生成分工，便于语言模型处理序列，再由流匹配与声码器生成细节；这是一种设计，不是所有 TTS 的唯一做法。

**CER 低就说明声音自然吗？**不一定。CER 主要看识别文本与目标文本的差距，还要听韵律、情感、音质并检查说话人相似度和延迟。

**零样本参考和 LoRA 定制有什么区别？**零样本在推理时提供参考声音；LoRA 需要基于数据进一步训练少量参数。效果、成本和授权要求应单独评估。
