## 先看一个问题

看到一个错例，下一步先改什么？

## 用大白话理解

先复现输入、输出与环境，再按错误类型聚类。定位根因后设计改动和回归测试。只有适合数据改进的问题才进入补采或重标；检索和评分错误应修对应环节。

## 跟着例子走一遍

假设用户说“不要关灯”，语音助手却转写成“要关灯”。这不是简单的少一个字：否定丢失会改变命令。语音漏字可能来自背景噪声、切段截断，也可能是错误参考转写或文本规范化；先听原始音频、核对切段边界与参考标注，再决定是否需要训练。下面的流程是教学例子，没有实际运行。

### 把“可能原因”变成可检查的问题

| 线索与假设                                             | 怎么检查                                                             | 检查后可能采取的行动                                             |
| ------------------------------------------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------- |
| “不”字位于切段开头，可能被截掉                         | 对比原始录音和实际送入模型的片段；只改变切段边界，保留模型和其他设置 | 调整切段或上下文重叠，再测不同边界位置                           |
| 原音频里能清楚听到“不”，实际片段里也有，可能是识别失败 | 保留原片段，检查相似口音、噪声和否定词的其他样本；对照不同识别配置   | 如果确有稳定的识别弱点，再考虑补充覆盖相应条件并审核过的训练数据 |
| 参考文字与音频不符，可能是标注错                       | 让标注人员重新听音频，保留原标注与修改记录                           | 修正标注，重新计算指标；不要把错误参考拿去训练                   |
| 模型输出正确，但评分显示错误                           | 保存规范化前后的文本，逐步检查标点、数字与切分                       | 修正评测规则，并对旧样本重新评分                                 |

每次尽量只改变一个条件，有助于缩小原因范围，但一次对照仍不一定能证明根因。比如重新切段后刚好识别正确，也可能是生成随机性或其他同时变化的配置造成的；要记录版本与参数，在一组相似样本上重复检查。

### 记录一次可以复查的错例

一条记录至少包含样本编号或允许访问的输入、参考答案、原始输出、模型版本、提示或解码设置、工具与预处理版本、发生时间，以及错误分类和复现结果。涉及隐私的音频或文本应按实际权限处理；不需要为了便于分析就把敏感原文复制到所有地方。

把“已观察到的现象”“可能原因”和“已经验证的原因”分开写。例如“送入模型的片段缺少前 200 毫秒”是可检查的现象；“因此模型必然会漏掉否定词”仍是待验证的假设。相同表面错误可能有多个原因，也可能一个原因造成多种错误。

## 和相近概念比一比

评测告诉你错了多少，错例分析尝试解释为什么错。复现条件、根因假设与已经验证的原因要分开记录；补数据只适合其中一部分问题。

## 什么时候要小心

单个样本修好不证明整体改善。验证目标切片，也检查原本正常的切片是否退化；独立测试集不直接变成训练材料。

可以把错例按原因或业务影响整理为开发集：例如切段导致首字缺失、嘈杂环境漏否定、参考标注错误。若确认某类问题适合补数据，应保留数据来源、授权、标注规则及版本，并按说话人或会话分组，避免相似片段跨训练与测试。修改后在独立的目标切片上复测，也检查普通语音和其他口音；记录样本数、错误数、总体指标以及是否新增失败。

如果团队反复盯着同一份测试集选方案，它实际上已经参与开发，不能再当作全新验收证据。应另留独立样本或按时间准备新一批数据，详见[评测协议与切片](/evaluation/evaluation-protocol/)。这就把发现问题、确定原因、修改数据或流程、再次评测连成一个可追踪的循环。

## 学习与面试

先不看正文，用自己的话回答开头的问题，并举一个例子。

**继续追问：** 怎样用一次只改一个条件的实验，区分切段问题与模型能力问题？

**识别错一个字就应该补训练数据吗？** 不一定。先看输入、切段、标注与评分；如果送入模型的音频已经被截断，改变训练集不能替代修复输入流程。

**为什么不能只汇报修好的那个例子？** 单个例子无法说明同类问题是否减少，也看不出普通场景是否退步；需要在未用于调参的样本上做切片回归。
