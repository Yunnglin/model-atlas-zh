## 用大白话理解

答错一张图的问题，可能是字没读清、物体认错、关系推错，也可能是输出格式不对。把这些错误揉成一个总分，很难知道该改模型还是输入处理。

## 按问题选择任务

DocVQA 关注文档图像问答，MMMU 提供多学科多模态理解和推理问题。视频还要看事件顺序、时间定位与跨帧证据；语音交互还需检查听懂、回答与发声。不同题集测到的是不同部分。

## 确认模型看到什么

保留实际图像尺寸、裁剪、抽帧时间、音频范围和输入模板。网页上播放了整段视频，并不代表请求把每一帧都传给模型。看不到的证据与看到了但不会用，应分开归因。

例如把图里的红杯换成蓝杯、其余内容不变，观察回答是否跟着改变。去掉图片后仍然答对，也可能说明题目能靠语言线索解决，并不能单独证明视觉理解。

## 用成对样本检查视觉证据

假设题目是“杯子是什么颜色”，准备两张只改变杯子颜色的图片，一张红色、一张蓝色。两题使用同一问题、相同裁剪和输出规则，再分别记录模型答案：

| 输入 | 参考答案 | 模型回答 | 判断 |
| ---- | -------- | -------- | ---- |
| 红杯 | 红色     | 红色     | 正确 |
| 蓝杯 | 蓝色     | 红色     | 错误 |

如果模型两次都答“红色”，可以继续检查蓝杯是否清晰可见、预处理是否保留了杯子，再比较多组颜色。单对样本可以帮助定位问题；要估计整体表现，还需要覆盖更多对象、颜色和图片来源。

也可以给同一图分别问“红杯在哪”和“蓝杯在哪”，看模型是否根据问题改变答案；或暂时移除图片，观察文字本身是否泄露答案。每组实验只改一个主要条件，更容易判断是图片内容、提问方式还是预处理影响了结果。

## 视频抽帧会改变模型看到的证据

假设十秒视频里，指示灯只在第 1.2 到 1.5 秒亮起；应用却只传入第 0、2、4、6、8 秒的静态帧，那么这些帧没有包含亮灯瞬间。若模型回答“没看见灯亮”，先查看发送给模型的实际帧，再判断模型是否未能识别已看到的证据。

评测记录应包含抽帧规则、实际时间点、图像分辨率和提示。对同一视频可以比较不同抽帧策略，并分别统计“关键证据是否被送入模型”和“证据可见时是否回答正确”。语音和视频同时出现时，还要检查时间是否对齐，例如声音发生在人物张口之前还是之后。

## 评分与回归

固定答案提取、结构校验、坐标约定及模型裁判标准。对视觉幻觉、长尾对象、小字、否定、模态冲突分别留出测试；模型裁判需要人工抽样复核。

[Qwen2.5-VL](/omni/qwen-vl/)与[多模态助手案例](/cases/omni-assistant/)展示不同环节怎样连接。

## 面试追问

**长视频大海捞针就是长程推理吗？** 不是同一问题，检索单个事件与整合多段因果关系需分别测试。

**多模态模型还需要文本评测吗？** 需要，语言生成与指令遵循依然会影响最终结果。
