## 用大白话理解

模型每接着写一个 token，都需要参考前面的内容。KV Cache 保存历史位置在注意力里用到的键和值，下次生成时重用，减少重复计算。它保存的是中间表示，不是把旧答案原文复制一份就结束。

## 跟着例子走

模型已写出“今天会议”，下一步处理新 token 时，会用新的查询去匹配历史键，汇总历史值。旧位置的键和值通常可以复用；随着序列变长，需要保留的位置也会增加。

可以把 K 想成每段已有内容的索引，V 是要汇总的信息；新的 Q 像当前需要查找的问题。这个类比只帮助理解读取关系，K、V 是模型算出的向量，不是可直接阅读的关键词或原文摘要。每一层都有自己的表示，不能把不同层的缓存简单视为同一份。

处理提示词的阶段常叫 **prefill**：模型读入已有上下文并建立缓存；随后逐步生成的阶段常叫 **decode**：每步产生新 token 时追加对应的 K、V 并读取需要的历史。不同实现可能分块处理提示或使用其他缓存策略，但这两个阶段的工作量与瓶颈通常不同。

![KV Cache 示意：提示词 A、B 建立缓存，处理新 token C 时复用并追加缓存，再预测 D。](/figures/foundations/kv-cache.svg)

把顺序展开：假设提示词是 A、B，预填充阶段为它们建立缓存并预测下一个 token C；随后处理 C 时，用 C 的查询读取已有缓存，同时将 C 的键和值加入缓存，得到下一 token D 的分布。之后再处理 D。图中只画出一层的逻辑，实际模型通常在每个注意力层分别保存缓存。

## 相关技术怎样区分

GQA 让多个查询头共享部分键值头，[Llama 3.1](/nlp/llama/)模型卡说明采用了这一设计。MLA 在 [DeepSeek-V3](/nlp/deepseek-v3/)里用更紧凑的潜在表示组织部分注意力缓存。量化改变数值精度；滑动窗口限制保留或可见范围。它们不是同一个开关。

### 分页缓存：不用给每个请求预留一整条长走廊

如果服务同时接待很多请求，每个人的回答长度都不一样。为每个请求预先划一整段连续空间，很容易留下用不上的空位。PagedAttention 借鉴操作系统分页：把一条序列的 KV 缓存分成小块，需要时再分配，并用映射表记住每块实际放在哪里。

例如，一块假设容纳 16 个 token，序列从 0 开始编号，编号为 25 的位置属于逻辑块 1、块内偏移 9；如果映射表把逻辑块 1 指向物理块 8，就可以到物理块 8 的第 9 个位置读取。块编号和映射只是便于理解的例子；各框架的具体存储布局以实现为准。

这改变的是**如何管理和读取缓存**，并不等于减少模型的 KV 头数。分页可以减少分配浪费、方便共享缓存，但块末尾仍可能有空位；实际吞吐改善取决于请求长度、并发量和运行环境。详细设计见 [PagedAttention 论文](https://arxiv.org/abs/2309.06180)。

## 评测和排错

分别记录读入提示的 prefill 和逐步生成的 decode；比较提示长度、批量、缓存精度、硬件和运行框架。服务显存不足时，权重之外还要检查并发请求的缓存总量。

**想深入：看常规缓存的粗略估算**

对于每层都使用相同 KV 头数、头维度的常规注意力，可以先估算：

$$
\text{缓存字节数} \approx 2\times L\times B\times T\times H_{kv}\times D\times b
$$

这里 $L$ 是注意力层数、$B$ 是同时缓存的序列数、$T$ 是每条序列长度、$H_{kv}$ 是键值头数、$D$ 是每头维度、$b$ 是每个缓存元素的字节数；前面的 2 表示 K 和 V 各一份。这是理想化估算，假设各序列等长且所有层都保留同样长度，不包括权重或其他开销。

例如假设 32 层、1 条序列、4096 个 token、8 个 KV 头、每头 128 维，K 和 V 都以 2 字节存储，则缓存约为 $2\times32\times1\times4096\times8\times128\times2$ 字节，即 **512 MiB**。如果其他条件不变、KV 头从 8 变成 32，估算约为 **2 GiB**。这些只是算术例子，不是某个型号的实测显存；并发序列越多或上下文越长，按这套假设估算的缓存也越大。

真实实现可能有不同长度的序列、分页分配和碎片、跨请求共享前缀、缓存量化、局部窗口或混合层；MLA 等结构的缓存方式也不同。实际资源还包括模型权重、计算中间量和运行时，需在目标框架与并发条件下测量。

### 共享头和压缩缓存有什么不同

在多头注意力中，每个查询头都有对应的键值头；GQA 让多个查询头共用一组键值头，因此可以减少需要保存的 KV 头数。它不表示查询头也被合并，更不保证延迟按头数比例下降。

DeepSeek 的 MLA 则采用低秩潜在表示与位置相关信息组织注意力，可以缓存更紧凑的表示，并借助具体推理实现计算注意力。它与 GQA 的着力点不同，缓存大小应按该模型的实际结构和代码计算，不直接套上面的常规公式。滑动窗口进一步只保留或访问设定范围内的信息时，是否能回答窗口之外的问题还取决于模型结构及其他机制。

**开缓存会让答案本身更正确吗？** 缓存首先解决重复计算；正确性变化应核对实现、精度和位置处理。
