# 002：以连续演进图组织学习

状态：历史决策，2026-10-26；当前交互由 [003：知识关系与导航树分开](003-navigation-tree.md) 替代。

## 问题

第一版把模式、模态、训练评测维度、学习路线、自测、进度和案例闭环同时放在首页。用户首先需要学习界面，当前节点还可能与筛选互相矛盾。

## 决定

首页保留一张连续地图和辅助搜索。横向大致按参考资料公开时间推进，纵向由技术联系排布。分类不冒充继承，不用模态分区、着色或提供浏览入口。

全景使用少量代表节点；点击节点后显示有数量上限的直接关联，同时打开阅读区。阅读区的相关概念在同一位置继续打开，并保留访问路径。关闭阅读区只改变阅读状态；返回上一个知识点恢复其画布和阅读位置，返回全景恢复总览。

URL 保存访问路径与阅读开关。会话存储只缓存画布和正文滚动、公式展开等界面状态；没有学习进度账户或统计。旧的节点深层链接继续可用，旧模态、模式和筛选参数不再参与展示。

正文由 Astro 从同一份 Markdown 构建成独立文章和静态片段。地图浏览时按知识点加载片段；平台层处理读取与存储，知识逻辑不依赖浏览器。

## 取舍

放弃首页的自由组合筛选和独立学习工具，换取明确的起点、连续的上下文和足够宽的正文。内容可以继续覆盖结构、训练、评测、应用和错例，界面按当前知识点逐步展开。

保留 Astro/Starlight、React Flow、ELK、d3-force、Zustand 与既有内容契约，不重新搭框架。模型关系以有来源的数据为准，静态设计稿中的箭头不替代数据事实。

## 2026-10-26：收放交互修订

用户反馈切换局部图的跳转体验不好，要求同一张知识图谱可以展开、收起。本次用展开集合控制可达节点，阅读路径仅控制正文；主干与已显示节点不重新排布。采用现有 React Flow，不在本次迁移到新的画布框架。G6 的内置收放值得在规模扩大时评估，当前不增加两套渲染实现。
