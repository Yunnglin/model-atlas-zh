# Kimi K2.5 审阅

审阅日期：2026-10-29。时间线 ID `kimi25`，通读 `src/content/docs/omni/kimi-k25-model.md`，对照技术报告 v1、模型卡、配置与配图；未运行模型或复现评测。

## 结构与模型卡

- [模型卡](https://huggingface.co/moonshotai/Kimi-K2.5)：1T 总参数／32B 激活、61 层中 1 层稠密、每 token 选 8 个路由专家和 1 个共享专家，256K 上下文，Modified MIT 许可含额外条件。图像、视频输入能力与部署接口区分，模型卡将视频对话列为实验功能并说明官方 API 支持。
- [技术报告第 4.2 节](https://arxiv.org/html/2602.02276v1)：MoonViT-3D 从 SigLIP 继续训练，最多四帧构成时空块，MLP 之前做四倍时间池化；对未采到的短暂动作不能保证恢复。MoE、MLA、外部工具分工在正文中清楚区分。

## 训练

- 报告表 3 和第 4.3 节：视觉编码器训练约 1T token，短暂训练投影器；从近训练末期 K2 检查点继续训练 15T 视觉文本 token；长上下文阶段从 32K 到 256K，分别列出 500B 和 200B。视觉编码器与语言模型在联合阶段更新；这不是从零构建全部 K2 数据。
- 报告第 4.4、3.1 节区分纯文本的 zero-vision SFT 实验和后续视觉 RL。PARL 的编排者可训练、子智能体冻结且轨迹不纳入优化；本次补充设计稿任务的串行依赖示例，解释并行带来的等待下界。
- 报告第 3 节：PARL 的并行创建、子任务完成为辅助奖励，训练中其权重逐步归零；关键步骤以并行批次最长分支为基础计量，与真实耗时不同。正文补充奖励的用途和直观例子。

## 评测与应用

- 报告表 4、6：MMMU-Pro 78.5，图像与视频评测平均 3 次；BrowseComp 单智能体 60.6、上下文管理 74.9、Agent Swarm 78.4，使用不同系统配置，不能解释为纯权重提升。
- 报告附录 E.4：短视频 128 帧、最大分辨率 896；长视频 2048 帧、448。20 个任务 16 个启动／12 个同时通过是教学示例，分别为 80%／60%，不声称实测。
