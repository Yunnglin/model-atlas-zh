# 模型内容审阅台账

[查看当前进度](review-progress.md)。进度分别统计时间线上的模型／版本和训练技术文章。 [查看近期评测数字补充复核](numeric-followup-20261029.md)。 2026-10-29 的证据范围核查见[前 50 条](ledger-evidence-first50-20261029.md)、[第 51–100 条](ledger-evidence-mid50-20261029.md)和[第 101–150 条](ledger-evidence-last50-20261029.md)。 训练技术的证据范围见[四维完成证据盘点](training-ledger-evidence-audit-20261029.md)。

## 状态含义

- `untriaged`（待整理）：还没有把已有证据按本维度确认到台账。可能已经做过局部核查，请先阅读该行历史记录。
- `targeted`（定向）：历史索引摘要称本维度核对过至少一个点；需查原记录确认具体范围，不能算完整审校。
- `complete`（完成）：本维度按下面的标准完成审阅，有可追溯的专项记录。模型五个维度均为 `complete`，才计入整篇完成。

初始整理将原 GLM 五维表的 ✓ 转成 `targeted`；其他型号只依据历史索引摘要中明确提到的维度登记 `targeted`，没有明确提到的保留为 `untriaged`。这些是整理线索，摘要本身不能替代逐篇核实。所有模型的「完整审校」从未登记开始：这不证明以前没有做过完整审校，只说明当前台账尚无按此标准确认的记录。

训练技术的[单独台账](training-review-ledger.yaml)初始全部为 `untriaged`，按原理与资料、例子与评测、配图、社区四项跟踪。它没有套用模型卡要求；核查原始论文和官方实现中的方法、训练目标和适用条件，检查数值例子及评测对照、图示与引用，再核对社区文章。历史审阅需要逐篇整理后才能更新状态。

## 五项完成标准

每篇正文先完整通读；记录模型版本、审阅日期、核对范围、发现与修改、参考资料和无法获得的一手资料。依据具体内容和公开程度核对，不要求实际训练、运行模型或复现论文分数。

1. **结构**：核对模型卡、参数规格、输入输出、主要模块与数据流；重要配置或关键计算有一手资料依据；检查模型与同名系列、不同版本的区别。
2. **训练**：按官方材料核对正文提到的训练阶段、数据、目标和方法；对官方未公开的细节检查正文没有补造。例子与官方训练配方区分。
3. **评测**：逐项核对正文具体数据的模型版本、数据集、指标、方向和关键协议；检查应用案例、错例和对照建议是否与指标对应。
4. **配图**：检查每张图与当前版本和正文一致，模块、箭头、数据流和图中文字正确；确认图片来源、署名或使用条件，检查网页实际渲染与替代文本。
5. **社区**：按型号查找并阅读相关知乎资料，记录文章链接、作者、阅读日期、可见赞同和收藏数；将关键观点与官方资料交叉核对。没有可用的匹配文章时记录搜索范围和原因，使用其他合适的公开材料，不能把不匹配的文章冒充对应版本。

完成标准针对页面中已有内容，新增或大幅修改内容后，重新评估受影响维度，必要时降回 `targeted`。历史记录中的「核查了一个数字」或「图能打开」只能作为定向证据，不能单独支持该维度完成。训练信息未公开或没有合适知乎文章时，按上面的要求记录检索与表述边界，而不是虚构资料。

## 更新步骤

1. 找到 [台账](review-ledger.yaml) 中的模型 ID，阅读 `evidence` 与 `notes` 对应的历史记录；必要时补查论文、模型卡和社区文章。
2. 将相应 `review` 字段更新为 `targeted` 或 `complete`。每项 `complete` 都在 `completedEvidence` 中按维度填写审阅记录路径，例如：

   ```yaml
   completedEvidence:
     structure: docs/reviews/example-review.md
   ```

   该记录应写明审阅覆盖、引用和结论。`evidence` 保存历史记录线索；审阅新证据也可加入该列表。不要仅凭文件存在或自动测试通过标记完成。

3. 运行 `pnpm review:progress --write` 更新 [进度表](review-progress.md)。不加 `--write` 可以只看模型汇总，`--check` 检查表是否与台账一致。脚本会检查模型 ID、训练技术文章、状态、历史记录路径和已完成维度的证据文件；它不能代替人工核实记录内容。
4. 检查台账、进度表与对应审阅记录的差异；有新模型时，补充一条记录。新的模型初始五项均为 `untriaged`；若没有历史记录，创建一份明确记载待审的记录并放入 `evidence`。

路径相对于仓库根目录；现有文章和审阅记录不因整理台账而移动。`pnpm review:progress --write` 可在模型清单更新或台账调整后重复运行。
