# 内容编写指南

## 先让人听懂

正文首先回答“它解决什么问题”。不要用一个没有解释的术语去解释另一个术语。

建议顺序：问题 → 大白话机制 → 一个完整例子 → 相近概念比较 → 适用条件与局限 → 可展开公式 → 面试追问。公式要逐一解释符号，例子不能让读者自行补全关键步骤。

例如 SFT 可以先说：“给已有模型看问题和示范答案，让它学习怎样按要求回答。”再说明常见生成式 SFT 仍然使用下一 token 预测损失；LoRA 则决定怎样更新参数，两者可以组合。

## 新增知识节点

在 `src/content/docs/` 对应目录中添加 Markdown，参考现有节点的 frontmatter。使用稳定的英文 ID；标题与别名可用中文和英文。摘要只在 `atlas.summary` 维护，避免在另一份图谱 JSON 中重复编辑。

`purpose` 是地图上最多 28 字的短用途，避免重复标题。`featured` 表示首页精选范围：仅精选模型／家族参与模型地图，连线仍必须来自有来源的关系。具体代际和闭源短介绍可设为 false，仍支持连续阅读与搜索。没有参考年份的主题可以省略 `year`；不得为了图形好看捏造提出年份。多个模态共享的方法使用 `shared`，不要复制成多个节点。

模型节点应绑定所讲解的家族或具体版本。对于闭源模型，未公开的基础模型、参数量与训练配方保持未知。

## 关系与引用

正文内部链接使用无部署前缀的根路径，如 `/foundations/next-token/`；构建时统一适配 GitHub Pages 子路径。

资料在 `sources.yaml` 中集中登记，包括一手链接、类型和核对日期。关系在 `relations.yaml` 中登记，说明方向、含义和来源。可选 `caption` 提供地图上的短标签，不能改写关系事实。

`prerequisite` 表示编辑选择的学习顺序；`uses` 表示采用某项结构或方法；`compared-with` 表示比较。来源支持的是相应机制或事实，学习顺序本身属于本项目的教学组织。

优先核对原论文、官方实现、模型卡。博客和面试库用于发现问题与查漏补缺；答案要回到一手资料验证。复用第三方图文前检查具体材料的许可和署名要求。

## 实践案例

案例正文与 `caseStages` 共同描述六步：数据、训练、评测、应用、错例分析、数据改进。每步写明要保留的产物和关联知识点。

说明性例子、复现实验和真实应用证据分开标注。没跑过的实验不能写成已经验证的结论；外部公布成绩需注明协议和版本。

错误分析先确认能否复现，再区分数据、模型、提示、检索、应用和评分错误。数据改进从开发池产生，独立测试集继续留作验证。

## 保留的题目与路线素材

首页暂不展示自测和学习路线。素材仍参与内容校验，便于日后按需求复用。题目引用已有节点，包含答案要点、一个追问和来源。鼓励解释取舍与诊断方法，不把某种话术设为唯一答案。

两条路线分别服务训练评测工程和语音多模态算法，允许共享前置知识。正文、关系和题目修改后运行检查与相关测试。

## 模型学习页与共享概念

模型学习的推荐章节是：解决什么问题 → 结构与数据流 → 数据与训练 → 评测 → 应用与错例 → 比较与面试追问 → 资料。每章先说一句人话，再用同一个例子向前推进；不要为了套模板凑空章节。公式可展开，核心解释正常显示。

知识点链接直接引用已有 Markdown，不能另写一份“模型专属注意力定义”。共享概念需要能返回使用它的模型，采用和前置等关系在 `relations.yaml` 维护。首页不把指标或方法绘制成模型。

二级标题会成为学习页章节，锚点由 Astro 编译，不手写第二份目录。章节改名时同步检查 `model-guides.yaml` 的图形放置；构建会拒绝失效章节。

## 架构图与交互资源

1. 优先采用论文、官方仓库或可核对的既有图形。先查许可、版本范围与来源，不以“是 SVG”作为结构正确的证明。
2. 把图形记录加入 `figures.yaml`，注明模型、版本、来源、核对日期、替代文本和说明；选择官方、教学简化、配置或追踪生成、执行追踪之一作为依据。
3. 本地图片放在 `public/figures/<model>/`，记录真实宽高、许可与署名，保留许可文件，并在 `docs/assets.md` 登记获取地址与摘要。构建检查文件存在；不得绕过路径校验。
4. 在 `model-guides.yaml` 中引用已有模型、图形和章节标题。正文仍只有一份。
5. 第三方交互资源先标 `external-only`；只有验证嵌入许可、实际地址、模型版本、可用性、手机与回退后才标 `verified` 并提供 `embedUrl`。组件默认不加载第三方交互内容。

教学图要写清省略了什么。配置生成的图不等于真实执行图，不能据此断言张量形状和完整计算路径已经验证。结构有变化时更新图形版本与来源，不只改页面标题。

## 家族、版本与公开程度

- 家族页用代际表串起变化，明确每行对应的版本、关键技术与官方入口。具体版本只维护一份正文，用链接互相引用。
- 优先讲有影响力的开放权重模型；闭源型号简要介绍公开思路，不为它补造层数、数据比例、训练算法。
- 参数量、Base／Instruct、量化与框架适配格式在表格归并，不默认各自是一代新模型。Audio、ASR、VL、Omni、TTS 有独立发布序列，禁止按通用主线编号自动填充。
- 明确区分权重、代码、报告、数据和在线服务的公开范围；许可证以具体权重仓库为准。同名服务增加的视觉、工具或上下文特性不能套给开放权重。
- 精选模型按问题、结构、训练、评测、应用与错例、比较与面试追问连续讲解。每节用具体例子解释，不把一串术语当成原理。
- 案例正文必须包含数据、训练、评测、应用、错例分析、数据改进六段。未实际执行就标为复现计划，不编造成绩或改进幅度。

## 深度与可读性验收

每个收录模型都要讲清一个有区分力的机制、贯穿输入到输出的例子、训练信号、对应评测与排错。家族页解释演进轴并链接详解；公开材料不足的闭源版本深入解释已公开机制与验证方法，不用猜测补齐层数和训练配方。章节齐全或篇幅变长不代表通过内容 review。

每次通读逐项检查：

- 新术语首次出现时，先用一句普通话解释，再用例子展示它起什么作用。类比要点明对应关系，不能变成模型真实结构的断言。
- 至少有一个能从输入跟到输出的具体情境。必要时增加反例、算例或控制变量对照；构造例子明确标注，不能伪装实测。
- 训练说明写清材料、目标与更新对象；没有公开的内容留作未知。区分预训练、后训练和推理时系统行为。
- 评测写出正确性的定义、协议和失败类型，不用榜单总分代替解释。检查公式、单位、分母、阈值方向与版本对应。
- 文案删去空泛形容词、重复免责声明和术语堆叠，保留必要边界；优先连贯段落，表格只用于确有可比维度的内容。

知乎搜索复用 `corrinehu-kimi-searchzhihu` 的持久有界面会话原则。候选文章同时记录标题、作者、链接、可见赞同与收藏、观察日期、采用或舍弃理由；页面未显示的数据记“未显示”，约数保留约数。先比较候选的解释、例子、源码／论文对照与纠错情况，优先阅读质量较高且有读者反馈的内容。热度不能代替事实验证，中文文章用于选讲法和发现问题，一手材料用于核对技术。禁止通过点击赞同或收藏来测试数量，禁止复制未获许可的图文。
