# 架构说明

## 当前目标

首页聚焦知识地图：主干建立脉络，逐个展开关联知识，名称单独打开正文。正文涵盖结构、训练、评测、应用与案例；模态是内容属性，不是浏览入口。原学习路线、自测、进度及常驻闭环的界面已移出当前范围。

## 四个边界

| 模块             | 职责                                              | 允许依赖                    |
| ---------------- | ------------------------------------------------- | --------------------------- |
| `core`           | 内容契约、关系查询、导航投影、引用一致性          | 自身、Zod                   |
| `build`          | Astro 集合读取、构建校验、Markdown 链接基路径适配 | core、内容框架              |
| `features/atlas` | 一个画布、搜索、探索路径、关系说明、按需阅读      | core、platform、UI 与布局库 |
| `platform`       | 静态正文读取、浏览器历史与会话状态                | 浏览器接口、Zod             |
| `app`            | 数据加载与功能组合、URL 和状态同步                | 功能入口、platform、core    |
| `components`     | Starlight 正文的标题、搜索等适配                  | 内容框架                    |
| `pages`          | 首页、静态知识数据与正文片段                      | app、build、内容框架        |

依赖方向和循环导入由 dependency-cruiser 检查。知识节点不包含 G6 类型、布局坐标或浏览器状态。

## 内容与数据流

每个节点只维护一份 Markdown，标题、短用途、摘要、年份、别名和引用保存在文档头。`purpose` 服务全景中的简短用途，正文承载完整解释。关系集中维护，含方向、类型、可选短标签、解释和来源；短标签不能改变事实含义。

Astro Content Collections 和核心校验共同检查字段、重复 ID、引用、前置知识循环和案例完整性。题目和路线素材继续被校验，但不提供界面功能。

构建结果有三类：

1. `data/atlas.json`：地图查询需要的结构化知识，不包含正文 HTML。
2. 独立的 Starlight 正文：阅读、全文搜索和无交互降级入口。
3. `readers/<id>/`：由同一篇 Markdown 编译的静态阅读片段，点击后才加载，不进入全文搜索结果。

内部正文链接使用不含部署前缀的根路径，构建插件统一添加 `BASE_URL`。阅读区识别已有知识页链接，在同一阅读区打开；独立正文中它们仍是普通文章链接。

## 学习导航树与真实技术关系

原始知识记录及关系仍是一个图，画布只投影学习导航树。`navigation.yaml` 单独维护稳定的导航出现标识、父级、排序、知识引用或分组标题；分组不是新的知识正文，也不声明历史继承。可重复引用同一个知识 ID，不复制 Markdown。

当前小样从 Transformer 的三种结构路线展开：编码器、解码器、编码器＋解码器。Whisper 进一步展开结构、训练、评测、应用四组，每次只深入一组。其他知识仍可通过搜索和关联列表阅读，本次不扩展全部模型分支。

构建时验证导航单根、重复标识、父级引用、循环和知识引用；显式 `order` 避免内容框架按 ID 排序改变阅读次序。数据版本升级为 2。

`core/projections/navigation` 计算路径、同级收放规则和可见父子边；知识数据不包含画布类型或坐标。主画布不接收原始技术关系，因此不会因为展开共享知识产生跨分支连线。原始采用、比较、前置等事实通过阅读区的关联知识列表展示，可展开查看解释和来源。

## 布局与交互适配

G6 5.1.1 的 CompactBox 负责节点空间和父子连线，原生 `collapseElement` / `expandElement` 负责收放及对齐动画；不保留 React Flow、ELK、d3-force 或空位插入代码。

`features/atlas/layouts/tree-graph` 是 G6 适配器，负责原生 HTML 按钮、布局、取景和生命周期。HTML 节点中的文字由可信内容字段通过 `textContent` 设置，不拼接用户 HTML。事件委托在画布容器内处理；原生按钮可用键盘操作，装饰性 canvas 不进入焦点顺序。React 页面只组合画布与阅读区。

展开时保持操作节点的位置，其他节点重新分配空间。窗口高度不足时使用 G6 的缩放和平移让分支完整显示；手机把当前操作节点移到左侧，为下一层留出空间。用户仍可主动平移、缩放或适配全图，减少动态效果偏好会关闭动画。

G6 对隐藏节点的全量数据更新会使其重新进入绘制；因此选中状态只刷新当前可见且受影响的节点，已收起的分支保持隐藏。异步操作串行执行，过期请求不再更新当前状态；卸载后销毁图及监听器。

## 状态与阅读恢复

Zustand 管理一条展开路径、正文阅读路径和阅读开关。默认展开根；同级分支互斥，祖先和同级标题保留。重复 `open` 参数表示导航路径，重复 `node` 参数表示阅读路径，`reader=closed` 表示关闭正文。旧知识 ID 形式的展开参数会迁移成导航路径，未知标识被忽略。刷新和浏览器前进后退可恢复。

阅读正文或正文中的概念不会改变导航分支；搜索会定位已有导航入口并开启一条新的阅读路径，没有导航入口的主题仍可直接阅读。“收起全部”回到根下的三种结构路线。

正文按需读取并缓存，支持取消旧请求、失败重试，以及按知识点保存阅读滚动和公式展开。桌面宽阅读区覆盖在画布右侧，关闭后恢复同一棵树；手机采用原生模态 dialog。浏览器存储不可用时阅读与导航仍正常工作。当前不持久化 G6 坐标或缩放。

## 工程与验收

沿用固定 Node 24、pnpm、Astro/Starlight、React、G6 和 Zustand，不新增应用框架或后台任务。CSS Modules 管理界面样式，KaTeX 展示可展开公式。

`pnpm check` 检查类型、格式、ESLint 和依赖边界；Vitest 检查内容、投影、路径与外部适配；Playwright 检查分支展开、共享节点和阅读流程、恢复、旧链接、搜索、失败重试、键盘、手机阅读、公式及子路径。

GitHub Actions 先检查、构建和浏览器验证，再允许手动发布。当前交付本地 demo，不创建公开仓库或启动线上训练评测。
