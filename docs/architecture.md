# 架构说明

## 目标

同一份知识，支持多维地图、独立正文、岗位路线和面试自测。以静态网站交付，优先保证内容质量、清晰依赖和可维护性。

## 模块职责

| 模块         | 职责                                          | 允许依赖                                 |
| ------------ | --------------------------------------------- | ---------------------------------------- |
| `core`       | Zod 契约、关系查询、视角投影、引用校验        | 自身、Zod                                |
| `build`      | 通过 Astro 集合读取资料，生成浏览器所需的数据 | core、Astro                              |
| `features`   | 地图、学习路线、自测                          | core、platform、公共展示组件及相应 UI 库 |
| `platform`   | 浏览器存储、URL 与下载等外部接口              | core、Zod、浏览器 API                    |
| `app`        | 组合功能，管理页面级路由和共享学习记录        | 各功能的入口与 platform                  |
| `components` | Starlight 扩展与通用展示组件                  | 内容框架与展示依赖                       |
| `pages`      | HTML 页面、静态 JSON 入口                     | app、build                               |

增加 `app` 组合层，是为了让地图不直接依赖自测、自测也不直接依赖地图。它们通过选中节点、题目标识和回调进行协作。目录中的职责由 dependency-cruiser 检查，循环导入也会报错。

## 内容与数据流

每个节点只维护一篇 Markdown。Starlight 的 `title` 和 `atlas` 元数据提供标题、摘要、别名、模态和引用；正文展开问题、机制、例子、限制与公式。

资料、关系、题目和学习路线分别在 YAML 中维护。资料按稳定 ID 引用；关系不会从 Markdown 超链接自动推断，也不会把所有连线解释成继承。

Astro Content Collections 加载并验证字段。`loadKnowledge` 调用同一套核心校验，检查重复 ID、失效引用、前置知识循环及案例六阶段顺序。非法内容阻止静态 JSON 的构建。

浏览器只请求 `data/atlas.json` 中的摘要和结构化信息，完整正文由独立页面提供。正文搜索使用 Pagefind 的构建结果。外部网络访问不属于运行时加载内容的必需步骤。

## 三种地图共用实现

投影函数决定当前可见节点和关系。一个 React Flow 画布负责节点、选中状态、缩放和连线交互：

- 分层技术树使用 ELK 分层布局；显示语义关系，布局方向不改变关系含义。
- 演进泳道先按模态分组，各组使用 ELK 按参考资料年份排序；不同泳道的纵坐标不是统一精确时间轴。
- 关联探索显示当前节点的一跳关系，使用停止后的 d3-force 布局，避免持续物理模拟。

React Flow 类型与布局坐标仅出现在地图模块。异步布局带请求代次和清理检查，过期结果不会覆盖新结果。

## 状态归属

地图模式、节点、观察维度和模态筛选进入 URL。浏览器前进后退恢复 URL 状态；页面级学习/自测入口也可分享。

悬停、搜索输入、暂时展开等属于本次界面状态。画布位置保存在会话存储，正文的“返回知识地图”恢复上次地图 URL 与位置。永久知识记录不存入 Zustand；派生关系通过纯函数计算。

学习状态和自测结果采用版本化数据，保存在 localStorage。访问存储失败时回退到内存，并允许导出；导入先校验，错误文件不覆盖现有记录。首版只接受版本 1，未来需要迁移时显式加入迁移函数。

## 依赖与运行环境

Node 24 和 pnpm 固定版本，所有直接依赖精确锁定。安装后检查 peer dependency 兼容性，不用忽略警告的方式组合不兼容版本。

正文复用 Astro/Starlight，图形复用 React Flow/ELK/d3-force。代码不另建插件框架、全局服务容器或通用图引擎。新增公共抽象需要已有的实际使用者。

## 验证与发布

`pnpm check` 包含 Astro 类型检查、ESLint、Prettier 和依赖方向检查。Vitest 检查真实内容契约与核心查询；浏览器测试覆盖阅读返回、三种视图、自测进度、失败恢复、键盘操作与窄屏布局。

GitHub Actions 先检查、测试和构建，再测试子路径下的静态页面。手动发布工作流依赖通过的检查。第一阶段不自动公开发布；待用户比较设计后扩充到首版。
